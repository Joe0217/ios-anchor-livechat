# 错误处理规范

- 网络请求错误统一在 `APIClient` 层处理；业务错误码通过响应 `code` 判断，非 `'0000'` 视为异常
- 错误码分流：1004 挤下线 / 1005 token 失效→登出 / 1992·1006 封禁→强制下播 / 1080 余额 / 2001 权限
- 用户可感知的错误用 SwiftUI alert/toast 展示，文案走 i18n
- `catch` 中必须有实际处理（日志/上报/UI 提示），**禁止空 catch**；`try?` 吞错前确认该错误确实可忽略
- 错误信息必须含上下文：什么操作、什么输入、为什么失败
- 区分可恢复错误（重试/重连）与不可恢复错误（登出/结束直播）
- SDK 错误（声网/云信）区分网络错误与业务错误：网络错误触发重连，业务错误按码分流
- 心跳失败不可被 `try?` 静默吞掉：须计数，连续失败 >6 次触发断连下播（`'4'`）
- `JSONSerialization` 对 `NSNull` 会抛 OC 异常且 `try?` 不捕获，序列化前先 `isValidJSONObject` 守卫
- 全局未捕获错误统一上报埋点（至少：登录、开播、下播、强制下播、崩溃）
