# 翻译风格指南（ar / tr）

## 通用原则

1. **业务语义优先**：先保业务术语一致（见 [glossary.md](glossary.md)），再追求地道
2. **UI 文案口语化**：避免正式书面语；按钮/Tab 简短有力，错误提示要明确可恢复
3. **占位符位置**：单 placeholder 保留原样；双以上若 RTL/语序冲突则改 positional（`%1$@` 等）
4. **品牌词原样保留**：见 glossary "永远不翻译"列表
5. **长度控制**：阿拉伯文常比英文长 30-40%，土耳其文略长。按钮/Tab 标签**翻译后不能超过英文 1.5 倍**，否则 UI 会挤出 frame；超长时优先用更短的同义词

## 一、阿拉伯语（ar）风格

### 1. RTL 渲染特性
- 阿语自带 RTL，**不需要**在文案里加任何方向控制字符
- iOS 的 BiDi 算法会自动处理阿+英混排（如 `"... Hily ←"`），但**避免**在阿语句中插入太多英文/数字
- 单数/复数：阿拉伯语有 dual（双数）和 plural 形式 —— Hily 当前文案不用复杂数量短语，直接 `%d مشاهد` 即可，等 J 里程碑接入 stringsdict 处理 plural

### 2. 用词风格
- **称呼用户**：用阴阳同形或男性形（默认）。**避免** "أنتِ"（仅女性），用 "أنت" 或省略主语
- **敬语**：Hily 用户多为年轻女性创作者，文案**亲切但不卑微**。比如：
  - ✅ "ادعُ الأصدقاء"（邀请朋友们）
  - ❌ "يا سيدي ادعُ أصدقاءك"（先生您邀请朋友 —— 过度敬语）
- **动词时态**：UI 行动用命令式或动名词
  - 按钮："بدء البث"（动名词）或 "ابدأ البث"（命令式）— Hily 选**动名词**统一
- **错误提示**：用陈述句，避免责怪用户
  - ✅ "فشل تسجيل الدخول"（登录失败）
  - ❌ "أنت أدخلت كلمة مرور خاطئة"（你输错了密码 —— 责怪感）

### 3. 标点
- 句号 `.`（不用阿语 `۔`）
- 问号 `؟`（阿语反问号）
- 逗号 `،`（阿语逗号）—— Hily 当前未用，沿用普通 `,` 也可接受
- 三个点用 `...`（不用 `…` 单字符，与 en/tr 保持一致）

### 4. 数字
- 数字字符用普通 ASCII（`0123456789`），**不用**东阿拉伯 `٠١٢٣٤٥٦٧٨٩`（Hily 用户跨地区，ASCII 数字辨识度最高）
- iOS 在 RTL 文本中渲染 ASCII 数字会自动 LTR 内嵌，无需特殊处理

### 5. 阿语易混术语
| 概念 | 推荐 | 避免 |
|---|---|---|
| 直播 | بث مباشر（直接 live broadcast） | تيار حي（stream，技术化） |
| 主播 | المضيف（host） | المذيع（announcer，过于正式） |
| 视频通话 | مكالمة فيديو | اتصال مرئي（过于书面） |
| 频道 | القناة | المسار（path 误用） |

## 二、土耳其语（tr）风格

### 1. 用词风格
- **敬语级别**：用 **siz**（您，敬语）级别的非正式 —— 文案直接命令式 `Yayını Başlat`，避免 sen-级别太随意，也避免 saygıdeğer 太正式
- **复合词**：土语爱用复合词，UI 短文案尽量拆短：
  - ✅ "Yayın Başlat"（开播）
  - ❌ "Yayını Başlatmak İçin Tıklayın"（点击以开始直播 —— 太长）
- **错误提示**：陈述句 + 可操作建议
  - ✅ "Lütfen kanal adı girin"（请输入频道名）
  - ❌ "Sen yanlış yaptın"（你做错了 —— 责怪感）

### 2. 元音和谐与后缀
土语后缀变化复杂，注意：
- 单词加上格/向格时元音要和谐（`Hily'ye` 而不是 `Hily'ya`，因 e/i 元音）
- Hily 当前文案少有变格场景，主要在错误信息里。复杂句翻译时由翻译团队复审

### 3. 标点
- 与英文相同（`.`, `,`, `?`, `...`）
- 千位分隔符：**不**在文案里用（数字格式由 NumberFormatter 处理）

### 4. 数字与日期
- 数字格式由 `NumberFormatter(locale: tr_TR)` 自动处理 —— 文案里**不要硬编码**千位逗号或小数点
- 货币：Hily 用钻石（虚拟币），不涉及法币本地化

### 5. tr 易混术语
| 概念 | 推荐 | 避免 |
|---|---|---|
| 直播 | Canlı yayın 或 Yayın | Akış（stream，太技术）/ Naklen（实况转播，过正式） |
| 主播 | Yayıncı | Sunucu（presenter 歧义） |
| 礼物 | Hediye | Armağan（过文学） |
| 通话 | Arama | Görüşme（meeting 歧义） |

## 三、新增 key 时的翻译流程

1. **先写 en**：业务方确认英文 source-of-truth
2. **查 glossary**：业务术语先去 [glossary.md](glossary.md) 找已有对照，没有就新增
3. **草翻 ar / tr**：参考本风格指南
4. **占位符校验**：跑 `bash .claude/skills/i18n/scripts/validate.sh`，确认数量/顺序对齐
5. **长度审视**：翻译后字符数 ≤ en × 1.5（按钮/Tab）或 ≤ en × 1.8（错误提示）
6. **真机抽验**：DEBUG 切到 ar/tr，看新文案在实际 UI 是否溢出

## 四、待翻译团队复审的已知项

下列字段我作为开发者做了占位翻译，复审优先级高：

| 类型 | 数量 | 复审重点 |
|---|---|---|
| 双 placeholder format keys | 2 处 | 升级到 positional（`%1$@ %2$@`），调整 ar 语序 |
| 阿语敬语级别 | 全部 ar | 确认目标市场（北非/海湾/Levant）对应方言/敬语 |
| 土语动词时态 | 全部 tr | 确认按钮用命令式还是动名词的一致性 |
| 长度溢出 key | 按钮/Tab 标签 | RTL 渲染下不能挤出 frame |
