## 二、必修（1 项）

### R1 preload Task 无 handle 无 cancel，retry 场景旧 Task 迟到写 loadError 覆盖新成功状态

- 文件：[MediaGalleryView.swift:495-501](../../Sources/Core/MediaGallery/MediaGalleryView.swift#L495-L501)
- 维度：Swift 并发
- 触发场景 + 概率：**中**。用户点错误占位 retry 按钮触发
- 触发链路：
  1. 用户看视频 A → asset.load 网络中断 → catch → loadError=true → 显错误占位 + retry
  2. 用户点 retry → `retryLoad()` → pool.evictVideo + player=nil + `loadError=false` + `attachPlayer` → **新 Task 启动**（Task2）
  3. Task2 asset.load 成功（网络恢复）→ 无 catch，走 item.status .readyToPlay → 视频播放
  4. **但 Task1（旧 asset.load）也仍在跑**，若晚于 Task2 抛错到达 → catch → **loadError=true 覆盖已成功状态** → 视频播放同时闪错误占位
- 严重度：**必修**（真实并发时序 + retry 是产品链路可触达）
- 修复（最小改动方案 A）：
  ```swift
  @State private var preloadTask: Task<Void, Never>?

  // attachPlayer 内：
  preloadTask?.cancel()  // 兜底
  preloadTask = Task { @MainActor in
      do {
          _ = try await asset.load(.isPlayable, .duration, .tracks)
      } catch {
          guard !Task.isCancelled else { return }
          loadError = true
      }
  }

  // retryLoad 内主动 cancel：
  preloadTask?.cancel()
  preloadTask = nil

  // onDisappear (scenePhase != .background) 分支内：
  preloadTask?.cancel()
  preloadTask = nil
  ```
- 或方案 B（更 SwiftUI 原生）：把 asset.load 放到 `.task(id: urlString)` async 版本，语义等同 view 生命周期，无需手动管理

## 三、建议（4 项）

### A1 AVAudioSession.setCategory/setActive 用 try? 静默吞错

- 文件：[MediaGalleryView.swift:467-472](../../Sources/Core/MediaGallery/MediaGalleryView.swift#L467-L472)
- 触发场景：CarPlay/AirPlay 状态异常、系统被占用等，配置失败会导致视频无声
- 复查降级理由：全项目 AVAudioSession 配置本就 try? 惯用（默认场景配失败不影响主流程）；加 Logger 只帮助排查线上偶发问题
- 违反：[error-handling.md](../../.claude/rules/error-handling.md)（禁止空 catch），但 `try?` 属"可忽略错误"语义边界
- 建议：`do { try ...; try ... } catch { logger.error("audio session failed: \(error)") }` 留日志

### A2 字号硬编码不响应 Dynamic Type

- 文件：[MediaGalleryView.swift:242, 424, 428, 434](../../Sources/Core/MediaGallery/MediaGalleryView.swift#L242)（关闭按钮 28pt / 错误文案 13pt / 重试按钮 13pt）
- 触发场景：低视力用户系统字体缩放（Larger Accessibility Text）不生效
- 复查降级理由：**全项目风格**都用 `.font(.system(size:))`（不止本组件），本组件单独改反而不一致；应作为 J 期 a11y 收尾统一改造
- 建议：文案改 `.callout` / `.title2` 等 semantic font；SF Symbol 用 `.font(.system(.title2))` 支持 SymbolConfiguration 缩放

### A3 图片/视频缺 accessibilityLabel

- 文件：[MediaGalleryView.swift:286-300](../../Sources/Core/MediaGallery/MediaGalleryView.swift#L286-L300)
- 触发场景：VoiceOver 用户滑到 MediaGalleryImageCell/VideoPlayer 只读出"图像""视频播放器"默认，无法感知第几张/共几张
- 复查降级理由：关闭按钮 + escape action 已提供退出路径，非阻塞
- 建议：`.accessibilityElement(children: .combine).accessibilityLabel("\(currentIndex + 1) / \(urls.count)")` + 视频/图片区分文案

### A4 putImage 未释放同 URL 旧 video entry（对称性缺失）

- 文件：[MediaGalleryView.swift:87-91](../../Sources/Core/MediaGallery/MediaGalleryView.swift#L87-L91)
- 触发场景：同一 URL 先 `putVideo` 后 `putImage`，旧 AVPlayer 未 `releasePlayer`（未 pause + replaceCurrentItem(nil)）
- 复查降级理由：当前 [MomentPost.isVideo](../../Sources/Profile/Moment/MomentModels.swift) 按扩展名区分同 URL 类型稳定，**无产品调用路径能触发**；但作为公共组件应 defensive
- 建议：对齐 `putVideo` 的旧实例释放模式：
  ```swift
  func putImage(url: String, image: UIImage) {
      if let existing = entries[url], case .video(let oldP) = existing {
          releasePlayer(oldP)
      }
      entries[url] = .image(image, byteSize: estimatedByteSize(of: image))
      touch(url)
      enforceByteLimit()
  }
  ```
