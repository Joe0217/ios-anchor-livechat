## 二、必修（Must-fix）

### P0-1 helper 里 `.toolbar(.hidden)` 挂到 UserProfileRoute destination 会破坏详情页 nav bar 内容

- **文件**：[Sources/Profile/UserProfile/UserProfileModels.swift:150-160](../../Sources/Profile/UserProfile/UserProfileModels.swift#L150)
- **维度**：swiftui-perf / correctness
- **风险**：`userProfileAndChatDestinations(hidesSystemNavigationBar:)` 里，**两个** destination 都套了：
  ```swift
  .toolbar(hidesSystemNavigationBar ? .hidden : .automatic, for: .navigationBar)
  ```
  但 [UserProfileView.swift:48-51](../../Sources/Profile/UserProfile/UserProfileView.swift#L48) 用 **`.toolbar { toolbarContent }`** 挂 back chevron / FOLLOW / ellipsis 菜单到 **system nav bar**：
  ```swift
  .navigationBarBackButtonHidden(true)
  .toolbar { toolbarContent }
  .toolbarBackground(Theme.Palette.profileBackground, for: .navigationBar)
  .toolbarBackground(.visible, for: .navigationBar)
  ```
  外层 `.toolbar(.hidden, for: .navigationBar)` 会覆盖内层，**强制隐藏整个 nav bar 及承载的自定义 back / FOLLOW / 菜单**。
- **触发路径（已 grep 确认真产品调用）**：
  - [LiveResultView.swift:334](../../Sources/Live/LiveResult/LiveResultView.swift#L334) `sheetChatPath.append(UserProfileRoute.userId(item.userId))` — sheet 内 gifter avatar tap → sheet 内嵌 stack UserProfileRoute destination → helper（`hidesSystemNavigationBar: true`）→ **`.toolbar(.hidden)` 生效** → profile 页 back/FOLLOW/menu 消失 → 用户被困，无法返回 sheet；同时 view 顶部内容顶到 status bar，可能被遮挡
  - 反向路径（ChatMessageRow → UserProfileRoute.userIdFromChat）在 sheet 场景同样触发同款 bug
- **严重度**：**阻塞**（sheet 场景下详情页 UX 断裂）
- **建议**：**必修**——helper 内 UserProfileRoute destination **移除** `.toolbar(hidesSystemNavigationBar ? .hidden : .automatic)` 挂载；`hidesSystemNavigationBar` 参数只对 ChatFromProfileRoute destination 生效（ChatDetailContainer 用自定义 nav bar，sheet 场景确实需要隐藏 system bar 避免叠加）。
  ```swift
  extension View {
      @ViewBuilder
      func userProfileAndChatDestinations(hidesSystemNavigationBar: Bool = false) -> some View {
          self
              .navigationDestination(for: UserProfileRoute.self) { route in
                  switch route {                              // ← 不再套 Group + .toolbar
                  case .userId(let uid):
                      UserProfileView(userId: uid)
                  case .userIdFromChat(let uid, let peer):
                      UserProfileView(userId: uid, originPeerYxAccId: peer)
                  }
              }
              .navigationDestination(for: ChatFromProfileRoute.self) { route in
                  let selfYxAccId = SessionStore.shared.user?.yxAccid ?? ""
                  ChatDetailContainer(
                      peerYxAccId: route.peerYxAccId,
                      selfYxAccId: selfYxAccId,
                      originProfileUserId: route.sourceUserId
                  )
                  .toolbar(hidesSystemNavigationBar ? .hidden : .automatic, for: .navigationBar)
              }
      }
  }
  ```
- **复查后判定**：**必修**（触发路径明确、UX 断裂已确定，非防御性洁癖）

## 三、建议（Nice-to-have）

### R-1 `hidesSystemNavigationBar` 命名可更准确

- **文件**：[Sources/Profile/UserProfile/UserProfileModels.swift:150](../../Sources/Profile/UserProfile/UserProfileModels.swift#L150)
- **风险**：修完 P0-1 后，此参数**只影响 ChatFromProfileRoute destination**（因为 UserProfileRoute 不再挂 toolbar），命名应体现"只作用于聊天页"语义。当前名字暗示"对所有 destination 都控制"，易误导后续维护者以为它也会影响 profile 页。
- **建议**：**建议**——改名 `hidesChatSystemNavigationBar` 或在 doc comment 明示"仅作用于 ChatFromProfileRoute"（修 P0-1 时顺手改）。
- **复查后判定**：**建议**（无产品触发证据，纯可读性优化）

### R-2 ChatDetailView 全屏模式外层 stack 是否有相同"system nav bar 与自定义 nav bar 叠加"隐患？

- **文件**：[Sources/Home/MainTabView.swift](../../Sources/Home/MainTabView.swift)（3 个主 stack）
- **风险**：本次改动把 ChatFromProfileRoute destination 的 `hidesSystemNavigationBar` 默认设为 `false`（主 stack 场景），意味着 push 出来的 ChatDetailContainer 会**同时**顶着 system nav bar + 自身自定义 nav bar。ChatDetailContainer 的自定义 nav bar 是 body 内容顶部 HStack（[ChatDetailView.swift:344-359](../../Sources/Message/Chat/UI/ChatDetailView.swift#L344) 附近），若 system bar 也可见，视觉上会叠加为**两条 bar**。
- **触发检测**：需要真机跑一遍"MainTabView 主 stack push ChatDetailContainer（从任何非 sheet 入口）"看是否有 system bar 叠加视觉。若历史行为无问题（说明现有 String destination 也没挂 `.toolbar(.hidden)` 且看起来正常），则新加的 ChatFromProfileRoute 保持一致即可。
- **复查后判定**：**建议**——用户此前"测试通过"应该覆盖了这条路径（真机能看到），但代码里 String destination 也没有 hidden 挂载，说明 ChatDetailContainer 自身已足够遮住 system bar 或 iOS 自动收起空 bar。**无产品链路证据说明有问题**，仅建议用户注意后续 QA。
