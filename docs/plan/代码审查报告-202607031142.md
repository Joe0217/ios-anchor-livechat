## 二、必修（3 项）

### R1 InlineVideoPlayer 切后台再回来 observer 永久失联，视频卡在 loading

- 文件：[Sources/Profile/Moment/MomentImagePreviewView.swift:339-345](../../Sources/Profile/Moment/MomentImagePreviewView.swift#L339-L345)
- 维度：Swift 并发 / SwiftUI 生命周期
- 触发场景 + 概率：**高**。用户在朋友圈预览视频过程中按 Home 键 / 收到通知切走，回前台
- 触发链路：
  1. 切后台 → SwiftUI 对 view 触发 `.onDisappear`（ScenePhase=.background 也会触发，见 [swiftui-camera-preview.md](../../.claude/rules/swiftui-camera-preview.md) §6）
  2. `onDisappear` 内 `statusCancellable = nil`，`player.pause()`
  3. 回前台 view 不 dismount，`.onAppear` 不存在
  4. `.onChange(of: isCurrent)` 因值未变不触发
  5. `.task(id: urlString)` 即便重跑，被 `attachPlayer` 内 `guard player == nil` 拦下
  6. observer 永久失联，即便 buffer 恢复 `.playing`，`isReady` 不再置 true → **ProgressView 永久转**
- 严重度：**必修**
- 已有 3 次同源坑（v5.3.3 / v5.3.5 / camera-preview 规则 6），是复刻
- 修复：
  ```swift
  @Environment(\.scenePhase) private var scenePhase

  .onDisappear {
      guard scenePhase != .background else { return }  // 切后台不清
      player?.pause()
      statusCancellable?.cancel()
      statusCancellable = nil
  }
  ```
  或者更简单：把 `attachPlayer` 内 `guard player == nil` 改为兼容"有 player 无 observer"场景：
  ```swift
  private func attachPlayer() {
      if player == nil { /* 新建 */ }
      else if statusCancellable == nil {
          attachStatusObserver(to: player!)
          player?.play()
      }
  }
  ```

### R2 AVPlayerItem status 未监听，视频 URL 失效导致永久 loading

- 文件：[Sources/Profile/Moment/MomentImagePreviewView.swift:362-374](../../Sources/Profile/Moment/MomentImagePreviewView.swift#L362-L374)
- 维度：iOS 平台规范 / 错误处理
- 触发场景 + 概率：**中**。视频 URL 404 / 网络中断 / OSS token 过期 / CDN 挂 / 后端删除视频
- 触发链路：
  1. `attachPlayer` 内 `Task.detached preload asset.load` 用 `try?` 吞错
  2. `attachStatusObserver` 只监听 `timeControlStatus`
  3. `item.status` 变 `.failed` 时 `timeControlStatus` 恒为 `.paused`
  4. `isReady` 永远 false → ProgressView 永久转，用户看不到错误提示
- 违反：[.claude/rules/error-handling.md](../../.claude/rules/error-handling.md)（空 `try?` 吞错、须 UI 提示）
- 严重度：**必修**
- 修复：
  ```swift
  // attachStatusObserver 追加 status 监听
  p.publisher(for: \.currentItem?.status)
      .receive(on: DispatchQueue.main)
      .sink { status in
          if status == .failed { loadError = ... }  // 新增 @State loadError
      }
      .store(in: &cancellables)

  // preload Task 捕获错误
  Task.detached {
      do { _ = try await asset.load(.isPlayable, .duration, .tracks) }
      catch { await MainActor.run { self.loadError = ... } }
  }
  ```
  UI 层加错误占位 + retry 按钮（retry 需重建 AVPlayerItem，`.failed` 状态不可恢复；同时 pool 驱逐 failed player 避免复用重现）

### R3 CircleView @StateObject 3 store 违反 keep-alive publisher 隔离规则

- 文件：[Sources/Home/Circle/CircleView.swift:19-22](../../Sources/Home/Circle/CircleView.swift#L19-L22)
- 维度：SwiftUI 性能
- 触发场景 + 概率：**高**。任一 MomentFeedStore 状态变化都会触发
- 触发链路：
  1. CircleView 用 `@StateObject` 持 officialStore / momentStore / meStore 3 个 MomentFeedStore
  2. `@StateObject` 自动订阅 `objectWillChange`，不管 body 内是否读该 store 属性
  3. 任一 store 变化（例：不可见的 official tab 完成 lazyload / meStore 消费 `.momentPublished` / 不可见 tab 的 inflight cancel 兜底改 state）都触发 CircleView.body 重算
  4. keep-alive 架构下 CircleView 永久驻留，命中 [.claude/rules/swiftui-keepalive-publisher-isolation.md](../../.claude/rules/swiftui-keepalive-publisher-isolation.md) 反例 1（`@ObservedObject` 整个大 store）
- 严重度：**必修**（rule 已明文，此处是新增违反）
- 修复：把 3 个 store 用**普通 class 属性**持有（`private let officialStore = ...`），不参与 SwiftUI DynamicProperty 订阅；子 MomentView 内 `@ObservedObject` 订阅自身对应 store。既保状态跨切换又隔离失效。
  ```swift
  // CircleView
  private let officialStore = MomentFeedStore(source: .official)
  private let momentStore = MomentFeedStore(source: .moment)
  private let meStore: MomentFeedStore  // init 时构造
  // circleStore 保持 @StateObject（body 直接读 currentSub）
  ```
  注意：需 init 内保证 meStore 只构造一次（避免每次 body eval 重建）——用 `@State private var meStore = ...` 或 lazy holder 模式。

## 三、建议（6 项）

### A1 视频预览未配置 AVAudioSession 类别

- 文件：[Sources/Profile/Moment/MomentImagePreviewView.swift:302-391](../../Sources/Profile/Moment/MomentImagePreviewView.swift#L302-L391)
- 触发场景：**中低**。静音开关下视频静音（UGC 行业默认，微信朋友圈亦如此，非用户异常预期）；后台音乐 App 被 AVPlayer 中断（`.soloAmbient` 默认行为）
- 复查降级理由：finder 认为"与直播/1v1 通话竞争 playAndRecord"—— 但项目里直播/通话与朋友圈是**互斥入口**（同 App 里不同 tab，不能同时在直播时进朋友圈），实际触发路径 0
- 建议：`AVAudioSession.sharedInstance().setCategory(.playback, mode: .moviePlayback, options: [.mixWithOthers])`，与直播/通话切换时再切回

### A2 装饰性 SF Symbol 未标 accessibilityHidden

- 文件：[Sources/Home/Circle/MomentView.swift:87,100](../../Sources/Home/Circle/MomentView.swift#L87)
- 触发场景：VoiceOver 用户遇到空/错态时英文 systemName 与中文/阿语业务文案冗读
- 修复零副作用：两处 `Image(systemName:)` 加 `.accessibilityHidden(true)`

### A3 refreshable 触发时 ScrollView dismantle（分支切换）

- 文件：[Sources/Home/Circle/MomentView.swift:45-62](../../Sources/Home/Circle/MomentView.swift#L45-L62)
- 触发场景：用户下拉刷新 → `state=.loadingFirst`（`posts=[]`）→ content 从 `if` 切到 `else` → ScrollView 消失换 loadingCenter → 数据回来再切回 ScrollView
- 复查降级理由：视觉上"列表消失 → loading → 列表出现"是**下拉刷新的自然预期**，且滚动位置刷新时天然在顶部无关键状态可丢；虽 rule 1 精神违反但此处子 view 均为 SwiftUI 原生（无 UIViewRepresentable/MTKView），dismantle 无副作用
- 建议：保持 ScrollView 常驻，empty/loading/error 作为 overlay。参考 LiveListView P2-8 修法。**如未见抖动感受，可延后**

### A4 下拉关闭手势缺 accessibilityAction(.escape) 逃生

- 文件：[Sources/Profile/Moment/MomentImagePreviewView.swift:206-222](../../Sources/Profile/Moment/MomentImagePreviewView.swift#L206-L222)
- 触发场景：VoiceOver 用户执行不了 DragGesture 关闭；xmark 按钮已提供备用退出路径，仅是 iOS 惯例缺失
- 建议：`body` 外层追加 `.accessibilityAction(.escape) { dismiss() }`

### A5 视频缓存池未监听低内存告警

- 文件：[Sources/Profile/Moment/MomentImagePreviewView.swift:14-127](../../Sources/Profile/Moment/MomentImagePreviewView.swift#L14-L127)
- 触发场景：App 后台 / 直播占 GPU/RAM 时可能触发 memory warning；但朋友圈+直播是互斥入口，20MB 上限较小
- 复查降级理由：与 P2-10 是同一 issue（finder 未合并），触发路径少，属加固
- 建议：`MomentPreviewMediaCache.init` 内注册 `UIApplication.didReceiveMemoryWarningNotification` → `clear()`。成本极低

### A6 timeControlStatus 抖动触发 body 重算

- 文件：[Sources/Profile/Moment/MomentImagePreviewView.swift:379-390](../../Sources/Profile/Moment/MomentImagePreviewView.swift#L379-L390)
- 触发场景：弱网视频加载 `waitingToPlayAtSpecifiedRate ↔ playing` 抖动，每次翻转触发 body 重算 + VideoPlayer updateUIViewController（幂等）
- 复查降级理由：VideoPlayer.updateUIViewController 幂等无实际卡顿；仅 body diff 开销小
- 建议：sink 加 `if isReady != newValue` 守卫，或 publisher 链加 `.removeDuplicates()`

## 四、信息（2 项）

### I1 PreviewImageCell.load stale-URL 守卫写法冗余（功能正确）

- 文件：[Sources/Profile/Moment/MomentImagePreviewView.swift:281-286](../../Sources/Profile/Moment/MomentImagePreviewView.swift#L281-L286)
- 分析：`urlString == url.absoluteString` 是从同源派生值比较，恒真——守卫无功能价值
- 但 `.task(id: urlString)` 已提供 auto-cancel，`ImageCache.fetchEphemeral` 内 URLSession.data 遇 CancellationError 走 catch 返 nil，`if let fetched` 天然挡下 stale 写入 → **实际是安全的**
- 可选微调：改用 `Task.isCancelled` 检查更清晰，非必要

### I2 sink 闭包写 @State 在 Swift 6 strict 下的 Sendable 问题

- 文件：[Sources/Profile/Moment/MomentImagePreviewView.swift:381-389](../../Sources/Profile/Moment/MomentImagePreviewView.swift#L381-L389)
- 分析：Combine sink 闭包是 `@Sendable`，写 @State 在 Swift 5 mode 静默通过，Swift 6 strict 会报错
- 有 `.receive(on: DispatchQueue.main)` 保证运行时正确，编译层无法证明
- 当前 Swift 5 不阻塞，J 期升 Swift 6 时统一处理，记 backlog
