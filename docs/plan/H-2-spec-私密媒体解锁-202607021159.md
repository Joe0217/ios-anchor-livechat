## §1 H5 二次校验（v2 补齐两入口分叉）

### 1.1 数据流

```
mounted → privatePicNum() 拉限额（默认 3/3）
       → privateInfo({userId}) 拉列表 → 按 iconType 分图片/视频
       → 视频每项异步 getPrivateOssUploadParam → 签名 URL
用户 tap "+" → 上传（图片走 uploadImg / 视频走 uploadVideo 分叉逻辑）→ 弹礼物 sheet → 绑 giftId
用户 tap "-" → 本地 splice
Submit → diff 数组 → uploadPrivateInfo
```

### 1.2 接口清单

| 接口 | 路径 | 请求 | 响应 |
|---|---|---|---|
| privatePicNum | POST `/api/payPrivateMsg/privatePicNum` | 空 | `{privateNum, privateVedioNum}` 默认 3 |
| privateInfo | POST `/api/payPrivateMsg/privateInfo` | `{userId}` | `[PrivateMedia]` |
| uploadPrivateInfo | POST `/api/payPrivateMsg/uploadPrivateInfo` | `[PrivateMediaOp]` diff | null / code=0000 |
| getPrivateOssUploadParam | POST `/sts/getPrivateOssUploadParam` | **⚠️ 字段名 H5 两入口冲突** | `{cdnUrl, authorizationParam}` |
| **视频上传专用凭证**（可能）| POST `/sts/getOssUploadParam`（uploadVideo.vue:128-134，与朋友圈 STS 是否同接口未知） | 待抓包 | 待抓包 |
| 礼物列表 | POST `/api/gift/v3/getGiftList` | 空/分页 | `[Gift]` 简化 |

### 1.3 ⚠️ H5 两入口分叉（red team #1，v2 关键补齐）

`getPrivateOssUploadParam` 请求字段名 **secretSettings/index.vue vs uploadVideo.vue 完全不同**：

| 入口 | 请求字段名 | fileUrl 提取方式 |
|---|---|---|
| `secretSettings/index.vue:226`（读取解密视频 URL 时）| **`searchValue`** | `URL(url).pathname.substring(1)` |
| `uploadVideo.vue:157`（上传后立即拿签名 URL 时）| **`search`** | `result.url.split('/').pop()` |

**假设**：一个是笔误 / 一个是历史遗留。真实接口只认一个字段名。

**step 1c 真集成前必抓包确认**（spec §6 Q1 升级为 critical）。**iOS 实现暂用 `searchValue`**（secretSettings 主流程），提供 fallback 试 `search` if HTTP 400。

### 1.4 字段名不一致（响应 vs 提交）

**响应（privateInfo）**：
```ts
{ id, iconType(1|2), giftIcon(图片URL), videoUrl, gift(数字), giftName?, giftPrice? }
```

**提交（uploadPrivateInfo）** 单项：
```ts
// 新增：{ picList, videoUrl, giftId, iconType }
// 未改动：{ picList, videoUrl, giftId, iconType, id }
// 删除：{ id, removePrivate: true, ...原字段 }
```

**别名映射**：
- 图片 URL 响应 `giftIcon` → 提交 `picList`
- 礼物字段响应 `gift`（可能 Int / String，**用 `.claude/rules/ios-decode-userid-compat.md` String/Int 双兼容**）→ 提交 `giftId`
- 视频字段响应/提交都是 `videoUrl` ✓

### 1.5 提交 diff 算法（v2 red team #4 修订）

**H5 原算法用 url 匹配**（line 102/135）—— 但存在 bug：**用户先删再重传同 url 会误判为"未改动"**。

**iOS 实现**：
- 用 `id` 优先匹配（后端 id 唯一）
- 本地新增项赋前缀 `local_` 的临时 uuid（提交时不带 id 字段）
- 未改动项 = 后端 id 且未删除 → 带 id + 全字段
- 删除项 = 原有 id 在原始列表但当前列表移除 → 带 id + removePrivate=true

### 1.6 视频解密流程（读取时）

```
每个视频响应 videoUrl → getPrivateOssUploadParam(searchValue: fileUrl) → {cdnUrl, authorizationParam}
→ signedUrl = "{cdnUrl}/{fileUrl}?{authorizationParam}"
```

**⚠️ signedUrl TTL**（red team #6，v2 新增）：阿里 OSS 签名 URL 常见 TTL 1h。**iOS 兜底**：
- 记录 signedUrl 生成时间
- 播放前 check ≥55min 主动重新调 getPrivateOssUploadParam refresh
- 播放遇 403 → refresh + retry 一次

### 1.7 视频上传独特要求（v2 red team #2 补齐）

`uploadVideo.vue:139-143` 显示视频上传 **必须带 `x-oss-object-acl: private`** 头，与图片（public）不同。

**iOS 实现**：`OssMultipartBodyBuilder` 参数化改造，新增 `objectAcl: String?` 参数，视频传 `"private"`，图片传 nil（保 J 朋友圈行为不变）。

### 1.8 giftCloseOverlay H5 bug 决定（v2 red team #7）

H5 `giftCloseOverlay`（line 82-85）**只 pop `uploadFilesImg`**，无论当前上传的是图片还是视频——**是 H5 已知 bug**（视频取消会误删图片）。

**iOS 决定**：**修 bug**——按 `uploadImageOrVideo` 分类 pop 对应数组。spec §3.2 状态机对应。

## §2 接口契约 + Model

### 2.1 Codable Model（v2 修订）

```swift
// Sources/Work/GiftMessage/GiftMessageModels.swift

struct PrivateMedia: Identifiable, Equatable {
    let id: String                // 后端 id 或 "local_<uuid>"（新增本地态）
    let iconType: Int             // 1=图片 / 2=视频
    let originalUrl: String       // 图片:giftIcon / 视频:videoUrl（未签名）
    var signedUrl: String?        // 视频专用，signedAt 时间戳伴随
    var signedAt: Date?           // v2 red team #6
    var giftId: String            // v2 String/Int 兼容（rule ios-decode-userid-compat）
    var giftName: String?
    var giftPrice: Int?
    var isNew: Bool { id.hasPrefix("local_") }
}

struct PrivateMediaOp: Encodable {
    let id: String?
    let iconType: Int
    let picList: String?
    let videoUrl: String?
    let giftId: Int               // 提交时转 Int（后端契约 v1，若报错待 step 1c 抓包）
    let removePrivate: Bool?
}

struct PrivateMediaLimit: Decodable, Equatable {
    let privateNum: Int
    let privateVedioNum: Int
    static let `default` = PrivateMediaLimit(privateNum: 3, privateVedioNum: 3)
}

struct PrivateOssParam: Decodable {
    let cdnUrl: String
    let authorizationParam: String
}
```

### 2.2 Decode 关键点

- 字段别名（`giftIcon → originalUrl`, `videoUrl → originalUrl`, `gift → giftId`）用手写 `init(from decoder:)`
- **giftId 双兼容 String/Int** → 内部收为 String（rule ios-decode-userid-compat）
- iconType 严格 1/2，其他值跳过该项
- `videoUrl` **空/无效**（R-11）→ 该项 signedUrl 保 nil 显占位

### 2.3 数据层 protocol

```swift
protocol GiftMessageServiceProtocol {
    func fetchLimit() async throws -> PrivateMediaLimit
    func fetchList(userId: Int) async throws -> [PrivateMedia]
    func save(ops: [PrivateMediaOp]) async throws
    func decryptVideoUrl(originalUrl: String) async throws -> String
    func fetchGifts() async throws -> [Gift]
}

protocol PrivateMediaUploadServiceProtocol {
    /// 图片上传（复用 ImageUploader.upload(rawData:)）
    func uploadImage(_ data: Data) async throws -> String
    /// 视频上传（v2 新增：走 STS credential + acl=private）
    func uploadVideo(fileURL: URL) async throws -> String
}
```

### 2.4 请求字段名 fallback（v2 red team #1）

```swift
// GiftMessageService.decryptVideoUrl 内部
func decryptVideoUrl(originalUrl: String) async throws -> String {
    let fileUrl = extractFileUrl(from: originalUrl)   // 用 URL.pathname.substring(1)
    do {
        return try await callDecrypt(searchValue: fileUrl)   // 主流程用 "searchValue"
    } catch APIError where isBadRequest {
        return try await callDecrypt(field: "search", value: fileUrl)   // v2 fallback
    }
}
```

## §3 状态机

### 3.1 页面 LoadState
```
.idle → onAppear → .loading（并发拉 limit + list + 视频解密）→ .loaded(images:[], videos:[]) 或 .error
```

### 3.2 编辑态 + upload 状态（v2 red team #7/#8 修订）

```
+ tap → pickImage/Video → OssCredential 拉凭证 → 视频加 acl=private → upload → localUrl
    → append 到对应 uploadFiles<类别> + 记 pendingCategory=类别
    → 弹 GiftsPopup（模态）
    → 选礼物 → 关联 → close
    → 未选关闭 → pop 对应 pendingCategory 的最后一项（v2 修 H5 bug）

- tap → 本地 splice（不发后端）

Submit → 计算 id 优先 diff（v2 red team #4）→ isSaving=true → save → success back / failure toast
```

### 3.3 视频独立态（load 阶段 + TTL refresh）
```
每个 iconType=2 → 独立 Task decryptVideoUrl → signedUrl + signedAt
videoLoading = 全部解密完成前 = true
任一失败 → 该项 signedUrl=nil 占位

播放点击 → check now - signedAt ≥55min → 主动 refresh → 播放
播放遇 HTTP 403 → refresh + retry 一次（v2 red team #6）
```

### 3.4 关键不变量（v2 补 #6）

1. loading 中拒绝再触发（loadGeneration token）
2. 图片和视频独立上限守卫
3. 上传中禁用 Submit
4. 上传取消（未选礼物）必 pop 刚上传项 **对应类别**（v2 修 H5 bug）
5. submit 期间禁点重复 Submit
6. **视频 signedUrl 有 TTL 兜底**：≥55min 主动 refresh + 403 retry（v2 新增）
7. 代际 token：中途下拉刷新时 outdated 上传/解密 drop
8. **视频解密并发上限 3**（v2 red team #13）：TaskGroup with maxConcurrent
