## 三、P1（必修，本次会话代码）

### P1-3 视频扩展名硬编 `.mp4` 导致 iPhone 拍摄的 mov 上传时 contentType 错配 ✅ **已修**

- **文件**：[Sources/Work/GiftMessage/GiftMessageView.swift:78](../../Sources/Work/GiftMessage/GiftMessageView.swift#L78)
- **维度**：iOS 平台规范
- **finder 原始 severity**：P1（3 票对抗全通过，`confidence: high`）
- **复查后判定**：**必修 P1**
- **产品链路证据**：iPhone 相册视频默认 QuickTime MOV 容器（HEVC 编码），用户选 mov → tmp 存为 `.mp4` → `PrivateMediaUploadService.uploadVideo` 判 `pathExtension="mp4"` → OSS 存 `Content-Type: video/mp4` 但真实是 mov header → 其他端（web/安卓）播放失败。100% 触发。
- **同时违反 spec §R-16 白名单** —— 用户选 mov 被静默改为 mp4 而非按白名单允许 mov。
- **修复**：按 `newItem.supportedContentTypes` 判 `UTType.quickTimeMovie` → 选 `mov` 扩展名，否则 `mp4`。tmp 文件名和 OSS Content-Type 都跟真实容器一致。

### P1-4 `onDisappear` 无 `scenePhase` 守卫，切后台会误清 MediaGalleryCache ✅ **已修**

- **文件**：[Sources/Work/GiftMessage/GiftMessageView.swift:103-105](../../Sources/Work/GiftMessage/GiftMessageView.swift#L103-L105)
- **维度**：SwiftUI 性能
- **finder 原始 severity**：P1（3 票全通过，`confidence: high`）
- **复查后判定**：**必修 P1**
- **产品链路证据**：`.claude/rules/swiftui-camera-preview.md` §6 已明立同款规则（iOS 14+ SwiftUI 在 UIScene 切 background 时对当前 view 调 onDisappear）。CallView / LiveRoomView 均有守卫模式。用户在 GiftMessage 页切后台 → `MediaGalleryCache.shared.clear()` 被误触发 → 回前台缩略图全部重加载 + 白屏闪烁。
- **修复**：加 `@Environment(\.scenePhase) private var scenePhase` + `.onDisappear { guard scenePhase != .background else { return }; ... }`

### P1-5（P2-8 升级）`try?` 吞掉 loadTransferable 错误，用户点了没反应无反馈 ✅ **已修**

- **文件**：[Sources/Work/GiftMessage/GiftMessageView.swift:64,76](../../Sources/Work/GiftMessage/GiftMessageView.swift#L64)（原）
- **维度**：iOS 平台规范
- **finder 原始 severity**：P2 → **复查升级为 P1**
- **产品链路证据**：iCloud 相册尚未下载的照片 / 损坏的视频 → `loadTransferable(type: Data.self)` 抛错 → `try?` 吞掉 → picker 静默置 nil → UI 无任何反馈。用户体感"我点了 + 什么都没发生"。触发概率非低（iCloud 优化存储用户 + 老视频），违反 `CLAUDE.md` "catch 中必须有实际处理"纪律，升级 P1。
- **修复**：`try?` → `do-catch`，catch 分支 + `guard let data else` 分支都 `vm.transientError = L10n.GiftMessage.unsupportedFile`。用户看到 toast 明确反馈。
