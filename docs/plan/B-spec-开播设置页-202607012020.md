## §2 Model + 状态机

### 2.1 State（红队 🟠#6 修订：明确 `.error` 清除路径）
```swift
enum LiveSettingsState: Equatable {
    case loading                    // getMyLiveRoom 拉取中
    case editing                    // 常态：编辑简介 / 调美颜
    case starting                   // 调 startLive 中；UI 全锁（详见 §1.4）
    case error(String)              // 校验失败 or 接口失败
}
```
迁移规则：
- 非法迁移：`.loading → .starting`（必须过 editing）；`.starting → .editing 外`（starting 只能 → .error 或 → 消失（push 走人））
- `.error → .editing`：**任一以下触发点自动清除**
  1. 用户改简介 TextField（`title.didSet`）
  2. 用户调美颜滑块（`params.objectWillChange`）
  3. `startTapped()` 入口首行（防止 `.error` 卡住 startLive 不发接口）
- `.starting → .error`：startLive throws（三 catch 分流已在 §1.4）

### 2.2 LiveSettingsStore（`@MainActor final class`）
```swift
@Published state: LiveSettingsState = .loading
@Published title: String = ""       // 简介（pre-fill from server）
@Published errorToast: String?      // 校验失败短暂 toast
@Published roomInfo: LiveRoomInfo?  // startLive 成功 → 触发 navigation
private let coverUrl: String?       // 从 getMyLiveRoom 读；nil 触发 cover 校验失败
```

### 2.3 关键方法
- `load() async`：`state=.loading` → `getMyLiveRoomRaw` → `state=.editing`；失败 → `state=.error`
- `startTapped() async`：checkCanLive 4 顺序 → 全过 → `state=.starting` → `LiveService.startLive` → 成功赋 `roomInfo` / 失败 `state=.error`
