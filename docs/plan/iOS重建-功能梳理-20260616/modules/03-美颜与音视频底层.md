## 一、模块概述

主播端核心采集链路：**摄像头采集 → 相芯 NamaSDK(WASM) 逐帧美颜渲染到 WebGL canvas → 从 canvas captureStream 得到美颜后视频流 → Agora 自定义视频轨道(customVideoTrack) → 推流**。

整条管线分三段：
1. **美颜引擎**：相芯 FaceUnity Web SDK（`funamawebassembly.wasm`，约 10MB），通过 WebGL2 渲染，支持美肤/美型/滤镜/贴纸 + AI 人脸检测。运行在 Web Worker（支持 OffscreenCanvas/VideoFrame 的设备）或主线程（Safari/低端机降级）。
2. **采集编码桥接**：用 `MediaStreamTrackProcessor`(采集→ReadableStream) + `MediaStreamTrackGenerator`(WritableStream→track) 把 Agora 原始摄像头轨道喂给美颜引擎，美颜结果写回 canvas，再 `canvas.captureStream()` 产出新 track 包成 Agora `createCustomVideoTrack`。
3. **Agora RTC**：`agora-rtc-sdk-ng/esm` 动态加载，分通话(rtc 模式)、直播(live 模式 host)、观众(live 模式 audience) 三种 client。设备分档(HIGH/MID/LOW)决定采集分辨率/帧率/码率。

设计要点：美颜相机是**全局常驻组件** `g-beautyCamera.vue`，App 启动即加载，通话/直播/美颜设置页复用同一套实例与 canvas（`namaCanvas`）。

### 3.6 数值映射（reflexMap，UI 值↔相芯原始值，必须 1:1 复刻）

完整代码(取自 `src/utils/beautyTools.ts:16-28`)：

```ts
export const reflexMap = {
  1: { vtr: v => v / 100, rtv: v => 100 * v },
  2: { vtr: v => (v + 50) / 100, rtv: v => 100 * v - 50 },
  3: { vtr: v => (v * 6) / 100, rtv: v => (100 * v) / 6 },
}
```

含义对照：

```
type1: vtr = v/100         rtv = 100*v        // 0~100 → 0~1
type2: vtr = (v+50)/100    rtv = 100*v-50     // -50~50 → 0~1（双向）
type3: vtr = v*6/100       rtv = 100*v/6      // 0~100 → 0~6（磨皮）
```

未指定 reflexType 的参数默认走 type1(代码用 `reflexType || 1`)。iOS 必须严格 1:1 复刻这三个函数对,不要简化为通用数学公式。

`initValueMap`（部分参数模式相关初值覆盖）：`remove_pouch_strength_mode2=80`、`remove_pouch_strength=40`、`remove_nasolabial_folds_strength=40`、`remove_nasolabial_folds_strength_mode2=80`、`ziran2=0`。

## 四、业务逻辑与规则

### 4.1 初始化时序（g-beautyCamera.vue → NamaSDK → callApi）

1. **App 启动**：`g-beautyCamera.vue` 挂载（常驻）。
2. **触发初始化**：`appStore.isInitBeauty` 变 true → `initBeauty()`：
   - 注入 polyfills：`MediaStreamTrackProcessorPollyfills(videoId)`、`MediaStreamTrackGeneratorPolyfills(canvasId)`（参数为是否 useWorker）。
   - `NamaSDK.getInstance()`（构造单例）。
   - `beautyStore.setInitStep()` → step=1。
   - 监听 `beautyInitStep`，等到 step=2 时 `bindBeautyEvents()`。
   - `openLocalCameraAndeMic()` 创建采集轨道；`getCacheBeautySettings()` 读 localStorage 缓存。
3. **NamaSDK 构造函数内部**（`index.ts`）：
   - `downloadBundles()`：并行从 CDN 下载 `ai_face_processor(.bundle 或 _pc)` + `face_beautification.bundle`，到位后 postMessage('prepare') 给 worker / SharedLogic。
   - 判定 `isSafari = !useWorker()`：worker 路径 new Worker(worker.js)；否则主线程 new SharedLogic。
   - `fetchCert()` 拉鉴权证书 `prod-authpack.bin`（带版本号），下发 `auth` + `typeSDK`(SIMD/LOW)。
   - 下载完成后 `preLoadingBundles()` 预加载所有贴纸 bundle。
4. **WASM 加载**（`shared.js loadModule`）：按 typeSDK 选 `SIMD/funamawebassembly.js` 或根目录低版本；`fuSetup(auth)` 鉴权；`fuSetLogLevel`（生产 OFF）。
5. **采集轨道创建**（`callApi.ts _createLocalCameraAndMicTracks`）：
   - `NamaSDK.instance.resetInit()`。
   - `createMicrophoneAndCameraTracks(audioConfig, videoConfig)` 得到 Agora audioTrack + videoTrack。
   - 取 `videoTrack.getMediaStreamTrack()` 原始 track → `new MediaStreamTrackProcessor` → readableStream。
   - `new MediaStreamTrackGenerator({kind:'video'})` → writable。
   - **首次**：按设备档位计算 canvas 宽高（见 4.3），`transferControlToOffscreen()`（worker 路径）。
   - `NamaSDK.instance.setCanvasAndVideoStream(offscreen, readableStream, writable)`。
   - `canvasDom.captureStream(tierProfile.fps)` 取美颜后 track → `createCustomVideoTrack({mediaStreamTrack, frameRate, bitrateMax, optimizationMode:'motion'})` 存为 `beautyVideoTrack`。
   - step=2（触发 bindBeautyEvents）。
6. **渲染启动**（`shared.js getPrepare`）：当 `aiBundle/beautyBundle/offscreen/videoStream/writableStream` 都就绪且 `aiLoaded && beautyLoaded`，按管线类型 `BeginRender(pipe)`。
7. **inited 回调**：`aiLoaded && beautyLoaded` 时 postMessage('inited') → `initInitialBeauty()` 设产品默认美颜值 → `g-beautyCamera` 的 `namaOnInited` → `setBeautyFirstInited()` → 1s 后 `destoryCamera()`（首次初始化后释放采集，step=3）。
8. **参数应用**：`beautyCameraActive` 激活时 `initBeautyParams()` 读 localStorage 缓存逐项 `updateSDKEffects`。

### 4.2 美颜处理管线（接入 Agora 的核心）

`shared.js` 三种渲染管线（pipe）：
- `AgoraRenderPipe(0)`：有 writableStream + videoStream（**生产推流走这条**）。读 readableStream 的 VideoFrame → 上传 WebGL 纹理 → `fuRenderTextureToCanvas` / `fuRenderBufferToCanvas` 美颜 → 把美颜后的 `canvas` 作为新 VideoFrame `writer.write()` 写回 MediaStreamTrackGenerator，从而产出新 track。
- `NamaRenderPipe(1)`：仅预览（无 writable），用于美颜设置页等。
- `ImageVideoRenderPipe(2)`：图片/视频上传场景（`__upload=true`）。

`renderer.ts` 关键：
- `StreamRenderer`：reader.read() 拿 VideoFrame，`requestAnimationFrame` 驱动；HTMLVideoElement 走纹理路径，VideoFrame(buffer) 走 buffer 路径（按 RGBA/NV12/I420 选 FUFORMAT）。美颜后 `new VideoFrame(module.canvas,...)` 写 writer。
- `ImageRenderer`：用 setTimeout/accumulatedTime 控制帧率（按 1000/fps），跳帧策略避免过度渲染。
- 渲染列表 `cppItems[0]=beautyBundle, cppItems[1]=stickerBundle`；`useEmpty` 时用空列表（不美颜）。
- `OnAfterRender` 中做人脸检测回调 + `save` 截图（readPixels）。

**采集→美颜→推流的轨道桥接（iOS 需重点理解）**：
Web 上因为 Agora 不直接支持「自定义处理后的纹理」，所以用 `MediaStreamTrackProcessor`(原始 track→帧流) + canvas + `captureStream`(canvas→新 track) + `createCustomVideoTrack`(新 track→Agora 轨道) 这条绕行链路。**iOS 原生不需要这套绕行**：Agora iOS SDK 支持 `pushExternalVideoFrame` / 自定义视频源 + 相芯 iOS SDK 直接处理 CVPixelBuffer，链路是 `相机 CVPixelBuffer → 相芯 renderItemsEx → 输出 pixelBuffer → Agora pushExternalVideoFrame`，更直接高效。

### 4.3 设备分档与降级策略（beautyTools.ts，iOS 重建必看）

**低端机判定 `isLowEndDevice()`**（命中任一即低端）：
- 老内核 Chrome<86，或老系统 iOS 命中 `isLowerIOS()`：取 UA `OS (\d+)_(\d+)` 主版本段做 `Number.parseFloat(主版本) < 15.6` 比较(`src/utils/beautyTools.ts:131-134`)。由于只取主版本(整数 15/16/17...),实际等价于 **iOS 主版本 ≤ 15** 全部归低端，iOS 16+ 一律不命中本条；
- 逻辑核数 `hardwareConcurrency ≤ 4`；
- 内存 `deviceMemory ≤ 4G`（仅 Android 暴露）。

**三档 `getDeviceTier()`**（会话内模块级缓存，避免重复探测）：
- `LOW`：低端机；
- `HIGH`：iPhone 且能走 Worker（依赖 OffscreenCanvas + VideoFrame + TransformStream 可转移 + 非 Firefox，即 iOS17.4+）；或 非 iOS 且核数≥8；
- `MID`：其余（含 iOS 16 ~ 17.3 区间无 VideoFrame、被迫主线程渲染的机型）。

**档位参数表 `TIER_PROFILE`**：
| 档 | scale(canvas 缩放) | fps | bitrate(Kbps) |
|----|------|-----|------|
| HIGH | 1 | 24 | 1500 |
| MID | 0.85 | 24 | 1000 |
| LOW | 0.7 | 15 | 800 |

**Agora 编码档位 `resolveCallEncoderConfig()`**（useCallApi.js，与 TIER 对齐）：
```
HIGH: {960x540, fps24, bitrateMin600, bitrateMax1500}
MID : {960x540, fps24, bitrateMin400, bitrateMax1000}
LOW : {960x540, fps15, bitrateMin300, bitrateMax800}
```

**canvas 编码分辨率计算**（`_createLocalCameraAndMicTracks`）：
```
rawW = displayWidth
rawH = displayHeight - (Flutter包?180 : (宽高比<0.5?140:0))   // 安全区简单处理
canvas.width  = round(rawW*scale/2)*2   // 偶数对齐 H.264 宏块，避免软编绿边
canvas.height = round(rawH*scale/2)*2
```

**渲染路径降级**：
- 支持 Worker（OffscreenCanvas+VideoFrame+可转移流+非 FF）→ Web Worker 离屏渲染（不阻塞主线程）；
- 否则（Safari/低端）→ 主线程 SharedLogic 渲染。
- WASM：默认 SIMD 版（`SIMD/funamawebassembly.js`），不支持 SIMD（Chrome<91/Safari<16.4/FF<89/Edge<91）或 `__lowerSDK=true` 白名单 → 低版本 WASM；SIMD 加载失败再降级到低版本。

### 4.4 性能优化点

- **Worker 离屏渲染**：高端设备美颜跑在 worker，主线程不卡（消除 Long Task）。
- **码率封顶 + optimizationMode:'motion'**：自定义轨道默认码率偏高，按档封顶省功耗/流量；motion 模式弱网自动降码率保流畅。
- **canvas 缩放降软编像素量**：iOS canvas 软编发烫，LOW/MID 等比缩小。
- **帧率与采集对齐**：captureStream fps = 采集 fps，避免重复帧。
- **canvas 尺寸守卫**：polyfills 中仅尺寸变化才重设 canvas.width/height（赋值即清空+重分配）。
- **设备档位会话内缓存**：避免开播路径反复 `useWorker()` 探测（每次 new TransformStream+MessageChannel 开销不低）。
- **`fuSetMaxFaces(1)`**：单人自拍场景固定 1，避免多脸跟踪倍增开销。
- **生产关闭 SDK 日志**：`fuSetLogLevel(FU_LOG_LEVEL_OFF)`，消除高频字符串拼接 CPU/GC。
- **AI 算法裁剪**：`fuSetFaceAlgorithmConfig` 关闭去痣/ARMeshV2/人种识别/landmark 遮挡等不需要的算法。
- **贴纸预加载**：基础 bundle 下载完后预加载全部贴纸。
- **首次初始化后释放采集**：美颜参数就绪后销毁采集轨道，等真正通话/开播再创建。

## 七、边界与异常处理

- **摄像头权限/采集错误**：`_handleMediaPermissionError` 统一处理，AgoraRTCException 按 code 映射 `CameraErrorMessage`；忙碌中设 `beautyErrorMsg`（组件弹 confirm「Reload App」或 alert），非忙碌仅 toast。`PERMISSION_DENIED` 弹 alert。
- **轨道意外结束**：originTrack / beautifiedTrack 监听 `ended` 事件（AbortController 管理），触发错误处理。
- **通话中摄像头故障**：只 toast 不挂断；直播中故障 → `isCompelLiveEnd='99'` 强制结束直播。
- **VideoFrame 创建重试**：polyfill pull 中 VideoFrame 创建失败重试 10 次（requestAnimationFrame 等待）。
- **贴纸快速点击**：`loadingSticker` 锁 + `currentSticker` 比对，丢弃过期请求。
- **WASM 降级**：SIMD 加载失败 catch 后降级到低版本 WASM。
- **videoStream 宽高为 0**：`setCanvasAndVideoStream` 中 while 等待 requestAnimationFrame 直到有宽高。
- **未检测到人脸**：`checkNoFace` 开启且未匹配时，15s 后弹「No Face Detected」。
- **iOS 低端横竖屏反转**：`isLowerIOS()||IsLowerChrome()` 时先建临时 video 读 metadata 再设 canvas 尺寸（useNama.js，已废弃但逻辑参考）。
- **Agora token 守卫**：开播/观众 join 前确保已取 rtcToken，否则永久 loading（`_rtcJoin` 抛 "rtcToken is undefined"）。
- **销毁清理**：`destory` 关闭 audio/video/beautyVideoTrack、leave 频道；`destroyBeauty` resetInit + 停 canvas captureStream track + destoryCamera；renderer.destroy 取消 RAF、reader.cancel、释放纹理。
- **空 catch 警示**：`beautySettings/index.vue` 的 `setCurSettingValue` 有空 catch（违反错误处理规范，iOS 重建勿照搬）。

## 八、iOS 重建注意事项（相芯 SDK 原生集成要点）

1. **链路简化**：Web 的 `MediaStreamTrackProcessor + canvas captureStream + createCustomVideoTrack` 绕行链路在 iOS 不需要。直接用 **AVCaptureSession 采集 CVPixelBuffer → 相芯 FURenderKit 处理 → Agora `pushExternalVideoFrame`**（自定义视频源模式 `setExternalVideoSource` / pushExternalVideoFrame）。

2. **相芯参数 1:1 复刻**：第三节所有 fuKey + reflexType + rawRange + initValue 直接搬到原生。注意：
   - 磨皮特殊：先 `blur_type=2` 再 `blur_level`（reflexType=3，0~100→0~6）；
   - 下巴/额头是 `mode2` 双向参数（reflexType=2，-50~50→0~1）；
   - 部分项 UI 无 fuKey，用 panelData/panelConfig 的 `use` 值（去黑眼圈/去法令纹/大眼/嘴型）；
   - 滤镜用 filter_name + filter_level 两步设参。

3. **鉴权证书**：iOS 用相芯 iOS 版 authpack（与 Web 的 `prod-authpack.bin` 不同包，找相芯要 iOS bundleId 对应的证书）。参考用户记忆「native-ios-integration-facts」中相芯 SDK 来源/签名/踩坑。

4. **bundle 资源**：iOS 用相芯 iOS 版 bundle（face_beautification / ai_face_processor 的 iOS 资源），不是 Web bundle。贴纸 bundle 同理。CDN 下载或打进包。

5. **设备分档**：iOS 原生用 `UIDevice` 机型/`ProcessInfo.processorCount`/物理内存判档，比 UA 嗅探精确。建议沿用三档 scale/fps/bitrate 表，但 iOS 硬编(VideoToolbox)远好于 Web canvas 软编，发烫问题缓解，可适当放宽 scale。

6. **编码配置**：Agora iOS `AgoraVideoEncoderConfiguration`，按档位对齐 960×540 / fps / bitrate(min,max)，`orientationMode` 注意竖屏；优化模式对应 `setVideoEncoderConfiguration` + degradationPreference=maintainFramerate(对应 motion)。

7. **镜像与朝向**：前置默认水平镜像；相芯有 `setInputCameraMatrix` 相关 API，对应 Web 的 `fuSetInputCameraTextureMatrix`，需按相机朝向/镜像正确配置，否则画面翻转。

8. **单人脸**：`fuSetMaxFaces(1)` 必设，主播自拍单人。

9. **人脸检测回调**：相芯 iOS 也有人脸数查询，复刻「无脸 15s 提示」逻辑。

10. **client 角色**：通话 rtc 模式、直播 host(vp9 优先，iOS 注意 vp9 硬解兼容，可能需 h264)、观众 h264。

11. **录制**：Web 的 vedioRecorder/useRecord 是废弃 Demo，**无生产录制功能**，iOS 重建无需移植录制；若产品需要再单独评估 AVAssetWriter。

## 九、SDK 懒加载封装（整合）

> 本章节内容整合自《D-基建与配置补遗》六。Web 端所有重型 SDK 走统一懒加载入口，加载失败带 3 次重试，加载结果挂到 `appStore`。iOS 原生 SDK 无需懒加载，但需保留「登录后再连 IM、美颜按需初始化、贴纸/AI bundle 按需下载」的时序，避免冷启动阻塞。

### 9.1 useLoadThirdParty 统一封装

源码：`src/use/useLoadThirdParty.js`。所有重型 SDK 走同一加载入口，每个加载方法内部带 3 次重试，最终挂载点统一落到 `appStore`：

| 加载方法 | 加载模块 | 挂载点 |
|----------|----------|--------|
| `loadAgoraRtmWrap` | `agora-rtm` | `appStore.agoraRtmWrap` |
| `loadAgoraRtcEsmWrap` | `agora-rtc-sdk-ng/esm` | `appStore.agoraRtcEsmWrap` |
| `loadAgoraJsWrap` | `@agora-js/report` | `appStore.agoraJsWrap` |
| `loadNimWrap` | `nim-web-sdk-ng` | `appStore.nimWrap` |
| `loadNimChatRoomBrowserWrap` | `nim-web-sdk-ng/dist/v1/CHATROOM_BROWSER_SDK` | `appStore.nimChatRoomWrap` |
| `loadAllAgoraWrap` / `loadAllNimWrap` | 批量 `Promise.allSettled` 聚合上述方法 | — |

### 9.2 重试与失败兜底

- 每个 `loadXxxWrap` 方法内部循环最多 3 次 `import()`，第 1/2 次失败后直接重试，第 3 次仍失败抛出 reject。
- 批量加载用 `Promise.allSettled`：单个 SDK 加载失败不阻塞其他 SDK，调用方在拿到结果后按需做降级判断。
- 业务侧调用前先判断挂载点是否已存在（`appStore.agoraRtcEsmWrap`/`appStore.nimWrap`），避免重复加载。

### 9.3 iOS 复刻要点

1. iOS 原生 SDK（AgoraRtcEngineKit、Agora RTM iOS SDK、NIM iOS SDK、相芯 FURenderKit）随 App 打包，不存在「懒加载 JS bundle」一说，但**初始化时序仍要复用 Web 端的设计**：
   - 登录成功后再 `AgoraRtmKit.login` / NIM 长连接，避免未登录态构造无效连接。
   - 美颜引擎初始化与摄像头采集解耦：首次进入需要美颜的场景（通话/直播/美颜设置）才走 `FURenderKit` 初始化。
2. **贴纸/AI bundle 的按需下载** 必须沿用：iOS 同样要做「基础 bundle 跟随首次美颜初始化下载，贴纸 bundle 按用户选择按需下载」，避免冷启动 10MB+ 资源阻塞。下载完成后写本地缓存目录，下次直接读盘。
3. **失败重试** 沿用 3 次：网络抖动场景（弱网/4G 切换）多次重试可显著提升初始化成功率。三次仍失败时给出明确错误码（区分网络失败 vs 鉴权失败 vs 资源损坏）。
4. 弃用代码不复刻：`utils/nimLib.js` 已空文件、`use/useRecord.js` 已整体注释（canvas 录屏停用），iOS 端不需要对应实现。
