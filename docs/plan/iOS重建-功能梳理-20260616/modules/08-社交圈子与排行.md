# 08 - 社交圈子 / 动态 + 关注粉丝 + 排行榜 + 用户资料

> 适用范围：iOS（Swift）原生重建参考。基于 H5 真实源码梳理（master-0616 分支）。
> 涉及模块：朋友圈/动态（circle）、关注粉丝（followList / news-follow）、排行榜（rank / pointsRank / CP榜 / 游戏任务榜 / Big-R 大R榜）、用户资料（userProfile 他人 / profile 本人编辑）、转盘（roulette，归属直播玩法）。

---

## 一、模块概述

本模块覆盖主播端「社交互动 + 荣誉激励 + 资料展示」四大子域：

1. **朋友圈/动态（circle）**：主播浏览官方动态、好友动态、自己的动态，并可发布图文动态、点赞、评论、删除。是主播端唯一的"动态信息流"功能。
2. **关注/粉丝（followList）**：以 Following / Followers / Friends 三种类型分页展示用户列表，可进入用户主页、关注/取关、通话/私聊。
3. **排行榜（rank 等）**：包含五类榜单——魅力榜(Charm)、财富榜(Wealth)、CP情侣榜(Couple)、积分榜(pointsRank)、游戏任务榜(gameTask)，外加 Big-R 大R贡献榜。周期分日榜/周榜/月榜。
4. **用户资料（userProfile / profile）**：他人主页（含礼物墙、点赞收藏数、关注/拉黑/举报）与本人资料编辑（头像/昵称/简介/图片/视频/来电视频/问候语，含审核态）。

技术依赖：Vue3 + Vant4 + Pinia + vue-virtual-scroller(虚拟列表) + IntersectionObserver(无限滚动) + ali-oss(媒体上传) + browser-image-compression(图片压缩) + 数数埋点(reportShuShuCustomEvent)。

## 三、功能点清单

### 3.1 朋友圈/动态
- 三 Tab 信息流：official(officalType=1)、moment(officalType=2)、me(officalType=3)，me 传 keyword=自己 userId。
- 列表分页：pageSize 20，`IntersectionObserver` 监听底部哨兵元素触发加载更多；首页 <20 条不监听。
- 虚拟滚动：`DynamicScroller`（动态高度），key-field=id，size-dependencies 含 textContent/imgUrls/comments。
- 发布动态：纯图文，文本≤500 字、至少 1 张图、最多 9 张图，固定 `displayRange:1`，**朋友圈不支持发视频**（posts 页 accept 限定 image/*）。
- 点赞：`like` 接口，optionType 1=赞/0=取消，本地乐观更新 likeNum 与 likeFlag。
- 评论：弹出输入框（蒙层 overlay），提交后回调刷新该动态评论列表。
- 评论懒加载：每条动态首次进入视口（提前 600px）才拉取评论，时间窗口固定为「近 7 天」。
- 删除：仅"我的"Tab 显示删除按钮，二次确认弹窗，删除后本地 filter 移除。
- 翻译：`CTranslate` 组件对动态文本翻译，结果写入 `translateText`。
- 图片/视频预览：`showImagePreview`，视频用透明占位图 + 动态替换为 `<video>` 标签（根据扩展名 .mp4/.mov 等或 url 含 "video" 判定）。

### 3.2 关注/粉丝
- 三类型：Following=3 / Followers=2 / Friends=1（`enumType` 映射）。
- 分页 pageSize 20，返回 `{ count, friendData }`，虚拟列表 `RecycleScroller`（固定 item 高度，按窗口宽自适应）。
- 列表项展示：头像、昵称、用户等级徽章(userLevelName)、VIP 标(vipExpireTime > 当前时间)、国家、年龄；右侧通话/私聊按钮(`CCommunicationBtns`)。
- 点击列表项 → 设置 chatStore.userInfo → 跳转 `/userProfile`。
- 关注/取关：`CFollowButton` 统一组件，followType 1=关注/2=取关，成功后更新 `userStore.mineInfo.upsNum`。

### 3.3 排行榜
> 以下接口入参均已与源码逐一核对（行号给出便于追溯），iOS 端按本清单接入即可。

- **魅力榜 Charm**：`POST /api/ranking/getRankingList`，rankType `ANCHOR_DAY/ANCHOR_WEEK/ANCHOR_MON`，配 `pageSize/currentPage/key`（`src/views/rank/index.vue:77-90`）。
- **财富榜 Wealth(honor)**：同上接口，rankType `USER_DAY/USER_WEEK/USER_MON`。
- **CP 情侣榜 Couple**：`POST /api/ranking/v2/userRank`（`getRankingListV2`），入参 `{ currentPage, pageSize: 50, rankType: 'ANCHOR_USER_COUPLE', dailyType: 'daily' | 'weekly' }`（`src/views/rank/components/cp-rank-list.vue:71-76`）。双头像(主播+用户)、神秘用户(无 userId 显示 Mystery)、奖励弹窗(anchorRewards/userRewards 按 itemType 分组)。
- **积分榜 pointsRank**：`POST /api/ranking/anchorIntegralRankingList`，入参仅 `{ searchValue: 'week' }`（`src/views/pointsRank/index.vue:16-25`），返回 `items[]` 与 `myIntegral`，每周结算重置，前端固定只展示周榜。
- **游戏任务榜 gameTask**：`from=gameTask` 进入 rank 页，调 `apiGameTaskGetRanking({ type: 'day'|'week', page, size })`（`src/views/rank/index.vue:94-110`），右侧展示 expectedReward(预计奖励钻石)。
- **Big-R 大R榜**：本周/上周 Tab，展示主播汇总钻石(totalDiamond)及单大R用户明细(直播钻石 liveStreamDiamond + 私通钻石 privateCallDiamond)；入口可见性由探针接口控制。
- 通用：Top3 特殊展示(`rank-top3` 中间为第1名)、底部固定"我的排名"(未上榜显示 99+)、用户名片卡弹窗(`UserCard`)、帮助规则弹窗、数数曝光/离开埋点(h_rank_view / h_rank_leave，含停留时长)。
- 周期 Tab：日/周/月，月榜可由 `hideMonthTab=1` 隐藏；游戏任务榜恒隐藏月榜。

### 3.4 用户资料
- **他人主页 userProfile**：头像(三色光环 `CAvatarRing`)、昵称、性别、uid、国家、年龄、接通率(connRate)、点赞数(like=thumbs[0])、收藏数(favorite=thumbs[1])、礼物墙(giftList)；操作：关注/取关、私聊/通话(`CCommunicationBtns`)、举报(`CFeedbackPopup`)、拉黑(`blockUser`)。
- **本人编辑 profile**：头像、昵称(≤15)、自我介绍(≤200)、图片(≤9)、视频(≤6)、来电视频(callVideoUrl 单个)、问候语(greetMsgs，≤50字/条)；均带审核态(vaild：1有效/2审核中/3被拒)。提交时做新增/删除 diff 计算。

## 四、业务逻辑与规则

### 4.1 动态发布流程（图文上传 ali-oss）
1. posts 页用 `CUploadImg`（封装 Vant `van-uploader` + `useOssUpload` hook）。
2. 选图后 `afterRead`：图片若 >300KB 先用 `browser-image-compression` 压缩(maxSizeMB 2 / 最大边 960 / jpeg / quality 0.7 / WebWorker)，视频不压缩。
3. 上传 OSS：`getOssKey()`（GET /sts/getkey）拿 STS 临时凭证 → `parseOssHost` 解析出 bucket/region → `new OSS({region, accessKeyId, accessKeySecret, stsToken, bucket, secure})` → `client.put(\`${Date.now()}.${ext}\`, file)`。
4. 单次上传 **10 秒超时**(Promise.race)，`Promise.allSettled` 并发，失败项自动从列表移除并 toast。
5. 成功 url 通过 `uploadChange` 回传，posts 页 push 到 imgs 数组。
6. 校验：文本非空 + 至少 1 图 → 调 `postCreate({displayRange:1, textContent, imgUrls})`。
7. 发布成功 → `sessionStorage.setItem('fromBack','true')` → router.back()，circle 页 `onActivated` 检测到该标记后刷新"我的"Tab。

> **关键**：ali-oss 凭证是 STS 临时 token，需每次上传前获取；iOS 端应使用阿里云 OSS iOS SDK + STS 临时授权方案（AccessKeyId/AccessKeySecret/SecurityToken）。

### 4.2 圈子缓存机制（circleCache，半废弃缓存层 ⚠️）
- `useCircleCacheStore`（持久化 persist）：`{ cacheId, cacheData }`，`setCache(data)`。
- 设计思路（见源码注释）：进入详情前缓存列表项数据，详情页先渲染缓存（列表带过来的），再请求接口更新；下次进详情按 id 判断命中缓存则直接用缓存(详情接口的)再更新。
- **现状（半废弃）**：`detail/index.vue` 实际只渲染 `circleCacheStore.cacheData`，详情接口 `momentsDetail` 已定义但未在详情页调用；列表的 checkDetail 跳详情逻辑已被注释。模块整体处于「定义完整但调用链断开」的半成品状态，仅持久化字段还在占据本地存储。
- **iOS 重建结论**：**不要照搬 circleCache 这套半废弃缓存层**。直接做标准「列表传参 + 详情接口(`/api/expand/friendsCircle/v2/detail`)」模式，更干净，也避免持久化无意义数据。

### 4.3 排行榜计算周期与类型
- 周期由前端传 rankType 后缀决定：`_DAY`/`_WEEK`/`_MON`；积分榜固定 `searchValue='week'`；CP 榜用 `dailyType: 'daily'|'weekly'`；Big-R 周维度 `week: 'current'|'last'`(返回 weekCode/weekStart/weekEnd)。
- 参数命名规则不统一是历史遗留（不同后端服务各自定义），iOS 端**必须按各榜单各自的字段精确传参**，不要尝试"统一抽象"。
- 排名值：魅力/财富用 `num`，CP 用 `costNum`，积分榜用 `integralAmount`，游戏任务榜用 `expectedReward`。
- 奖励：榜单项可带 rankingReward(钻石奖励)；CP 榜奖励为道具列表(itemId/itemIcon/itemName/durationDays)。
- "我的排名"：接口返回 `rankingMineVo`，onRank=false 时排名显示 99+。
- 实际计算/结算在服务端，前端只展示。**iOS 端无需实现计算逻辑，只需对齐 rankType 枚举与字段。**

### 4.4 资料编辑 diff 与审核
- 提交时仅传变更字段：头像/昵称/简介各自比对且排除审核中态(checkUserDetail 命中则跳过)。
- 图片/视频：对比原列表(photoArr/videoArr)与编辑后列表(uploadPhoto/uploadVideo)——新增项(只有 url 无 id)进 `pics/videos`，被删项或 vaild===3(被拒)进 `picsDel/videosDel`(传 id)。
- 来电视频：单个，新增传 callVideoUrl，删除传 callVideosDel。
- 问候语：新增 `addGreetList`(contentDetail)，删除 `delGreetList`(id)，`findMissingIds` 计算差集。
- 无任何变更 → 直接 back。提交后弹"提交审核"弹窗 → 刷新 mineInfo → back。审核态来源 `checkUserInfo` 与 mineInfo.latestIconAndCallVideo(businessType=2 为头像)。

### 4.5 关注关系判定
- followFlag/followed：1=已关注。CFollowButton 根据当前态翻转 followType(1/2)。
- userProfile 关注后回调 `followAfter(newFlag)` 更新本地 followFlag，按钮文案/图标 follow ↔ following 切换。

## 七、边界与异常处理

- **上传超时**：单文件 10s 超时即判失败，自动从列表移除并 toast「部分上传失败，请重试」；成功项仍逐个回传。
- **OSS 凭证过期**：每次上传重新 `getOssKey`，iOS 端注意 STS token 时效(Expiration)，建议每次上传前刷新。
- **审核态拦截**：昵称/简介/头像处于审核中(checkUserDetail 命中)时禁止编辑/提交该字段，展示 In Review；被拒(vaild=3)的媒体在提交时进删除列表。
- **空状态**：列表统一 `CEmpty`；CP 榜 4+ 列表与底部"我的排名"分别有空态(Not on the list yet / 鼓励文案)。
- **神秘用户**：CP 榜无 userId 的项显示 `Mystery` + 默认头像，禁止点击进主页。
- **Big-R 私聊**：列表仅返回 userId，私聊前必须先 `getUserDetail` 换取 yxAccid（云信 accid），否则 p2p 发送失败；带 chatLoading 防抖。
- **VIP 判定**：`vipExpireTime > 当前时间(Date.now())` 才显示 VIP 标，列表数据变化时刷新 curTime。
- **iOS 自动聚焦**：源码注释明确「iOS 无法自动聚焦」评论输入框，原生端需手动调起键盘。
- **拉黑**：blockUser 需带 `isLive`(是否直播中) 与 yxAccid；成功后移除菜单拉黑项。
- **空 catch**：部分列表请求 `.catch(() => {})` 静默，iOS 端建议补错误提示/重试。
- **错误码**：统一由 axios 拦截器按 code !== '0000' 处理（见全局错误规范）。

## 八、iOS 重建注意事项

1. **朋友圈是图文-only**：发布不支持视频（H5 posts 锁死 image/*）；但列表/详情渲染需兼容 imgUrls 中混入视频 url（按扩展名判断），因为官方/好友动态可能含视频。
2. **三 Tab 用同一接口**：仅 officalType(1/2/3) + keyword 区分，me Tab keyword 传自己 userId。统一一个列表组件 + 参数即可。
3. **circleCache 不必照搬**：详情缓存机制在 H5 已半废弃，iOS 做标准「列表传参 + 详情接口(momentsDetail)」更干净。
4. **排行榜枚举要精确对齐**（已与源码逐一核实，参见 3.3 段）：
   - 魅力榜/财富榜：`POST /api/ranking/getRankingList` + `rankType: ANCHOR_DAY/WEEK/MON | USER_DAY/WEEK/MON`
   - CP 榜：`POST /api/ranking/v2/userRank` + `rankType: 'ANCHOR_USER_COUPLE'` + `dailyType: 'daily'|'weekly'`（**有 dailyType**）
   - 积分榜：`POST /api/ranking/anchorIntegralRankingList` + `searchValue: 'week'`（**有 searchValue，固定 week**）
   - 游戏任务榜：`apiGameTaskGetRanking` + `type: 'day'|'week'`
   - Big-R：`POST /api/anchor/bigr/list` + `week: 'current'|'last'`
   - 榜单 query 参数(nav/from/hideMonthTab/path)决定 UI 形态与数据源，需在路由设计时保留。
5. **CP 榜 UI 复杂度最高**：双头像+翅膀+徽章+玫瑰装饰+奖励道具弹窗，全部绝对定位叠加切图。iOS 建议用 CDN 切图 + 容器约束布局复刻，注意 RTL(项目支持阿语)。
6. **资料提交是 diff 模式**：原生端务必复刻新增/删除差集逻辑（pics/picsDel、videos/videosDel、callVideoUrl/callVideosDel、addGreetList/delGreetList），并处理三态审核(1/2/3)。
7. **OSS 上传链路**：STS 凭证 → 压缩(图) → 时间戳命名 put → 超时/失败重试 → url 回写。这是动态发布与资料编辑共用的核心链路，建议封装统一上传服务。
8. **埋点契约**：rank 页进入/离开有曝光与停留时长上报，资料提交有 add_type 区分(1详情视频/2打招呼视频/3群发)，需对齐安卓与数数后台。
9. **转盘(roulette)与 Big-R 实际归属直播/收益模块**，本模块仅顺带覆盖；若 iOS 排期独立，可移至直播玩法模块。
10. **关注数同步**：关注/取关成功后本地维护 upsNum，原生端注意主页与资料页数据一致性（建议成功后重拉或本地自增/减）。
