# 07 - 任务/成长体系 + 新手引导 + 数据统计 + 埋点

> 适用于 iOS(Swift) 原生重建。基于真实源码梳理，覆盖：任务中心（新版 taskCenter + 旧版灰度 fallback）、活动型新主播任务（newBie）、平台级新手任务（robotTask，含 driver.js 引导）、工作台（work）、数据统计（dataStatistics）、直播数据（liveData）、数数(ThinkingData/ShuShu)埋点。

---

## 一、模块概述

本模块由四个相对独立的子系统组成，分别对应不同后端服务与产品形态：

1. **任务中心（Task Center，`/task`）**：主播的日常/每周任务面板。当前处于**新旧双轨灰度期**：
   - 新版「任务中心」(`/api/taskCenter/*`，需求 DM-20260527-005)：模块分组 + 多档阶梯任务 + 一键领取。`listTaskCenter({ cycle: 'DAILY'|'WEEKLY' })` 实际两个 cycle 都打同一个新接口 `/api/taskCenter/list`，若 Weekly 后端不支持才回退旧版。iOS 按新接口实现，Weekly 兼容由后端决定。
   - 旧版 fallback (`/api/task/*`)：限时/全天/每周任务平铺列表。
   - 顶部「Rank Progress」(全球收益榜 + 积分榜入口)、活跃大R任务(DM-20260429-002)。

2. **活动型新主播任务（newBie，`/newBie`）**：限时运营活动，分紫色（初级）/红色（高级）两组任务，完成解锁宝箱奖励 + 周排行榜。后端 `/api/anchor/newTask/*`。入口可见性由后端控制。

3. **平台级新手任务（robotTask + 引导）**：嵌入工作台与房间内的「新手平台任务」横条（`c-newbieTask` 浮标 / `newbieTask.vue`），任务进度横向进度条 + 节点。首次进入 `/work` 用 **driver.js** 做三步高亮引导。奖励通过云信 `attachType=135` 系统消息异步触发领取。后端 `/api/anchor/robotTask/*`。

4. **数据统计**：
   - **数据预览（`/dataStatistics`）**：不喜欢率、等级周数据、当前等级权益、不喜欢抵扣。后端 `/api/chat/*`、`/api/anchor/anchorAutoLevelUpInfo`。
   - **直播数据（`/liveData`）**：周/月维度的时长与收益看板 + 明细。后端 `/api/anchor/live/authorLiveData`。
   - **工作台（`/work`）**：聚合等级、今日收入、在线时长/均时/好评率等指标卡 + 工具宫格 + 在线状态切换。

5. **埋点**：全站统一 ThinkingData（数数，全局变量 `window.ta`），封装 `reportShuShuCustomEvent(evName, data, immediately)`。

> WorkingGuide(`/WorkingGuide`) 仅是一个内嵌 Google Docs 的 iframe 操作手册，无业务逻辑。

## 三、功能点清单

### 3.1 任务中心（/task）
- 顶部 Rank Progress：奖杯(全球收益 `myIncome`，点击→`/rank`) + 奖牌(积分 `myIntegral`，点击→`/pointsRank`)，数值用 K/M 紧凑展示。
- Daily/Weekly tab 切换；下拉刷新（CPullRefresh，整页）。
- Task Reset 倒计时条：Daily 显示当日剩余(北京日末)，Weekly 显示「N days + 时分秒」(北京周日末) + Total Points 行。
- **新版 Daily**：按 module 分组（可折叠），每任务为阶梯进度条（多档）或紧凑卡片（单档）。
- **多档任务**：阈值刻度行 + 节点（locked/可领/已领）+ 各档奖励 chip + 阶梯进度填充。支持「单档领取」(点节点) 与「一键领取」(领全部已达标档)。
- **领取成功弹窗** `ClaimRewardPopup`：图标 + `+数值` + 品类文案 + OK（`grant_pending` 发奖在途时降级为 toast）。
- **红点逻辑**：任一档位 `tierStatus !== 2` 即显红点，全部已领取才消失（任务级、模块级同源）。
- **活跃大R任务**（Weekly tab 顶部）：进度条 + 钻石奖励，独立于模块分组。
- **灰度 fallback**：新接口不可用时回退旧版「限时任务/全天任务」平铺列表（旧 `taskItem` 走 `getReward` 单任务领取）。
- 骨架屏 `TaskCenterSkeleton`：首次加载中占位，避免旧→新硬替换闪屏。

### 3.2 活动型新主播任务（/newBie）
- 两 tab：`Receive a reward`（领奖）/ `Ranking list`（周榜）。
- 倒计时（活动结束倒计时，`countdownTimestamp`）。
- 紫色（初级）/ 红色（高级）两任务组：奖励展示区（钻石/头像框/座驾）+ 宝箱（满进度开箱）+ 进度条 + 任务列表。
- 任务项状态：去完成(Go)/已完成(Done)/已结束(End)/未开始；点击按 `taskType` 跳转或弹 toast（房间内 vs 房间外行为不同）。
- 任务组奖励领取：`Go Claim`(带小手动效 + 领取倒计时) / `Claimed` / `End`。
- 规则弹窗、奖励记录弹窗（分页 van-list，钻石/有效时长道具）。
- 活动结束弹窗（每天首次进入且活动已结束时弹一次，按 `userStore.todayShowNewbieEndPopup` 日期去重）。
- 直播权限校验：taskType 5-10 跳开播前先 `checkLiveBroadcastPermission`（code 2001 无权限 / 1992 被禁播则弹提示）。
- PK 活动任务(taskType=1)：弹 H5link iframe。

### 3.3 平台级新手任务 + 引导（work 内）
- 横条 `newbieTask.vue`：标题 + 倒计时(`DD:HH:mm:ss`，到期隐藏入口) + 规则按钮（图片规则页，`belongAct:2`）+ 进度条任务列表。
- 进度条 `taskList.vue`：横向节点（每节点固定 20% 宽，超出滚动），节点显示奖励图标(已领/未领) + 状态点 + 奖励值。
- 任务详情弹窗：任务说明（数字高亮，`splitByNumbers`）+ 进度条 + 奖励区 + Go/Claimed 按钮。
- 点击 Go 按 taskType 行为：0 保持在线（切 IM 在线）/ 1,2 去首页 list / 3 去首页 match。
- **driver.js 三步引导**（首次进 work，`isFirstWork=true`）：
  - step1 高亮 `#newbie-task-container`（整个横条）。
  - step2/3 高亮 `#task-icon-{firstTaskId}`（首个任务节点）。
  - `taskGuidance.vue` 渲染 Teleport 蒙层 + 小手 + 文案（三步）。
  - 通话中(`appStore.isCalling`)暂停引导，通话结束恢复。引导走完置 `isFirstWork=false`（持久化）。
  - ⚠️ 引导触发依赖 **taskList 非空**（`taskList.vue:64-67`），首次进 /work 时若任务列表未加载或为空，引导不触发。iOS 复刻须加载失败/空列表降级处理。
- 浮标 `c-newbieTask.vue`：右下角，倒计时，文案图片每 4s 在 official-boost/newbie-task 间切换。

### 3.4 数据统计（/dataStatistics）
- 不喜欢率卡：Likes / Dislikes / Dislike Rate（含 tips 弹窗）。
- 不喜欢抵扣（Offset Dislike）：用积分抵扣一次 dislike，弹窗显示当前积分 + 本周剩余次数，`checkCondition` 校验 + `deduction` 提交。
- 等级周数据表：本周/上周对比，4 行（答复率/平均时长/通话数/更新时间）。
- 当前等级权益：已拥有(`gradeEquityHave`)勾 / 未拥有(`gradeEquityNone`)叉。

### 3.5 直播数据（/liveData）
- 维度：周(本周/上周) / 月(本月/上月/两月前)，共 5 个 `queryType`(0-4)。
- 总数据卡：总时长 + 总收入(可展开看 直播收入 / 私 call 收入)。
- 本周/月含倒计时(`remainingTime`)。
- 明细列表：按日 statDate + 时长 + 收入(可展开 直播/私call)。
- 浮动钱袋子(`van-floating-bubble`)：显示待领取奖励(`sureGetAward`，来自 task 接口)，点击→`/task`。

### 3.6 工作台（/work）
- 头像 + 周等级徽章(SS/S/A/B/NEW/C/D 7 档配色)；等级提示文案按等级/通话目标动态生成。
- 三指标卡：在线时长(`callNum`) / 平均通话时长(`weeklyDiamonds`) / 好评率(`positiveRating`)。
- 今日收入卡：总/通话/礼物/任务/邀请/托管 6 项（`anchorIncomeMap`）。
- 工具宫格：Hi/GoLive/Match/Task/Beauty/Points/Gift Message/Profile/Invite/Working Guide/Backpack/Live Data/newBie/bigR；newBie 与 bigR 入口由后端可见性接口过滤。
- 在线/离线切换（下线需二次确认弹窗）。

## 四、业务逻辑与规则

### 4.1 任务中心数据模型（新版 taskCenter，关键）
```
TaskCenterModuleGroupVO { moduleCode, moduleName, moduleSort, tasks[], moduleHasClaimable }
TaskCenterItemVO {
  taskId, taskCode, taskName, taskDesc?, taskModule, taskCycle, targetType,
  taskIcon?, targetExtJson?, progress, cycleKey, tiers[], hasClaimable
}
TaskCenterTierVO {
  tier, threshold, rewardType, rewardValue, propId, validHours,
  tierStatus  // 0=未达 1=可领 2=已领
}
```
- **rewardType 映射**：1=钻石 / 2=宝石(gem) / 3=道具 / 4=座驾 / 5=头像框 / 6=积分。
- **moduleCode → 图标**：含 `live`→live / `party`→party / `one_v_one|call`→call / `limited`→limited / 其余→common。
- **阶梯进度填充算法**（`computeTierFillPercent`）：节点等距分布，按当前区间内 `(progress-prevThr)/(nextThr-prevThr)` 线性插值；<2 档返回 0（走紧凑卡片）。
- **领取按钮态机**：loading > claim(有可领档) > claimed(全已领) > incomplete(未达标，置灰不可点)。可领档≥2 显示「一键领取」，=1 显示「领取」。
- **倒计时口径**：后端按北京时间(UTC+8)重置，Daily 每日 00:00、Weekly 每周一 00:00；前端按 UTC+8 显式计算剩余 ms 规避 iOS Safari 时区差异（`countdown1.vue`）。

### 4.2 任务领取流程（新版）
1. 单档：点节点 → `claimTaskCenter({taskId, tier})`。
2. 一键：`claimAllTaskCenter({taskId})` → 返回 `claimed[]`（每档明细）+ `claimedCount`。
3. 领取成功：埋点 `h_task_tier_claim`（按返回的每档 `rewardValue` 逐档上报）；同类奖励聚合进 `ClaimRewardPopup`，多类型用 toast。
4. 页面级互斥锁 `claimLoading`（一键领取 tier 置 -1 占位）；领取后重新拉列表刷新到「已领取」再解锁，避免按钮回闪。

### 4.3 旧版任务（fallback）数据
- `getAnchorRankingV2` 返回：`allDayTask`(全天)、`isLimitTask`(限时)、`sureGetAward`(待领奖励)。
- `getTaskInfo` 返回：`taskVos`(周任务列表)、`myIntegral`(本周期累计积分=Total Points)。
- 旧 taskItem：`rewardStatus` 1=可领(`getReward`)、3=已领(Claimed)；`rewardType` 1=钻石/2=积分；`taskType==='matchNum'` 有「20s 才算完成」tips。

### 4.4 活动型新主播任务规则（newBie）
- `getNewTaskListApi` 返回：`canComplete`(活动进行中)、`countdown.countdownTimestamp`、`taskGroups[0/1]`(紫/红组)、`pkActivityUrl`。
- 任务组：`completedCount/totalCount`、`rewardClaimed`、`rewards[]`(type 1钻石/其它道具，含 `diamondAmount`/`validHours`/`propIcon`)、`tasks[]`。
- 任务项 `taskType`：1 已读消息/2 完善资料/3 发动态/4 涨粉/5 直播时长/6 引导私call/7 PK胜/8 礼物人数/9 礼物收益(>24h用户) 等；`extraInfo` 为阈值。
- 领取组奖励：`getClaimRewardApi({groupId})`，成功置 `rewardClaimed=true`。
- 周榜：`getNewTaskRankListApi({searchValue: '1'本周/'0'上周})` → `rankings[]`(top3 + others) + `myRankInfo`。

### 4.5 平台级新手任务规则（robotTask）
- `getNewbieTaskListApi` 返回任务列表：`id`、`status`(2=已领)、`rewardValue`、`taskName`、`taskType`、`taskTarget`/`phoneCount`(类型1,3用phoneCount)、`progress`。
- 入口可见：`qAnchorTaskStore.isShowTaskEntry()` = `mineInfo.newAnchorCountdown`(有倒计时) && 后端配置 `anchor_call_task_open === '1'`。
- 倒计时 = `mineInfo.newAnchorEndTime - now`（北京时间），到期 `isShowQNewAnchorTask=false` 隐藏入口。
- ⚠️ **隐藏 bug**（已与源码核实，`src/stores/modules/qAnchorTask.js:20-25`）：
  ```js
  getRemainingTime() {
    const userStore = useUserStore()
    const now = getBeijingTime()                       // 取了北京时间 Date
    const newAnchorEndTime = userStore.mineInfo.newAnchorEndTime
    return Math.max(0, newAnchorEndTime - Date.now(now)) // ❌ Date.now() 不接受参数
  }
  ```
  - `Date.now()` 是静态方法，**根本不接受参数**（MDN 规范），传入的 `now` 被静默忽略，调用等价于 `Date.now()`，返回的是当前 UTC 毫秒戳。
  - 也就是说作者本意是"按北京时间计算剩余时间"，但实际计算用的是真实 UTC 时间——`now = getBeijingTime()` 这一行完全是死代码。
  - 由于 `newAnchorEndTime` 实际是后端下发的 UTC 毫秒戳，`UTC毫秒戳 - UTC毫秒戳` 结果反而是正确的时长差，**视觉上看不出错**，但代码意图与实现完全脱节。
  - **iOS 复刻直接写**：`max(0, newAnchorEndTime - Date().timeIntervalSince1970 * 1000)`，不要照搬这段 H5 死代码。同时与后端确认 `newAnchorEndTime` 的时区基准（当前判断是 UTC 毫秒戳，符合"H5 显示正常"的现状）。
- **奖励发放（异步）**：云信系统消息 `attachType=135` → `message.js#handleQNewAnchorTaskReward(attach)` → `qAnchorTaskStore.getClaimNewTaskReward(taskId)` → `POST /api/anchor/robotTask/claim` → 置 `canClaimTaskId`，`taskList.vue` watch 该字段后刷新列表。
- `handleQNewAnchorTaskReward` 接收的 `attach` 对象需含 `taskId` 字段（`src/stores/modules/message.js:1178-1180` 提取 `attach.taskId`），iOS 接收 attachType=135 时必须按此 schema 解析。
- 规则页：`getNewbieTaskRuleApi({belongAct:2})` 返回图片 URL。

## 七、边界与异常处理

- **任务中心灰度**：`init` 失败保持 `useTaskCenter=false` 走旧版 fallback；单 cycle `list` 失败不翻转开关；首次加载用 `resolvedByCycle` 标记，加载中显骨架避免旧→新闪屏。各旧接口失败仅 `console.warn` 不弹错。

- **领取并发**：页面级 `claimLoading` 互斥；`grant_pending` 在途降级 toast。
- **引导中断**：通话中销毁 driver 实例，通话结束恢复；组件卸载 `onBeforeUnmount` 销毁实例；监听 `route.path` 仅在 `/work` 且 `isFirstWork` 时引导。
- **newBie 权限**：开播类任务(5-10)先校验 `checkLiveBroadcastPermission`，code 2001/1992 弹被禁提示并阻断跳转。

- **入口可见性**：work newBie/bigR 用 `Promise.allSettled` 并发拉可见性，失败不阻塞其它宫格。
- **空 catch 风险**：`qAnchorTask.js#getTaskEntryVisible/getClaimNewTaskReward` 为空 catch（仅置 false/null），iOS 重建应补充日志上报。
- **抵扣边界**：积分不足 toast 拦截，`before-close` 钩子返回 Promise 控制弹窗关闭。

## 八、iOS 重建注意事项

1. **任务中心双轨须保留灰度逻辑**：新版 `/api/taskCenter/*` 仅 Daily 启用，Weekly 与旧 Daily fallback 走 `/api/task/*`。iOS 应实现「新接口可达即切换、不可达回退旧版」的同款灰度，且 Daily 才有模块分组/阶梯/一键领取，Weekly 是平铺周任务 + Total Points。优先与后端确认是否已可全量切新接口，能简化则简化。
2. **倒计时时区**：所有任务/直播倒计时按**北京时间 UTC+8**计算（Daily 日末、Weekly 周一），Web 端为规避 Safari 时区问题显式用 UTC 基准换算。⚠️ iOS 倒计时**禁止用 `TimeZone(identifier: "Asia/Shanghai")` 字符串初始化**(会引入夏令时浮动)，应用 **固定 UTC+8 偏移**(`BEIJING_UTC_OFFSET_MS = 8*60*60*1000`)与 H5 行为对齐。H5 用 `Date.UTC(y,m,d,15,59,59,999)`(UTC 15:59:59 = 北京 23:59:59)计算日末，iOS 必须同样用固定偏移。
3. **奖励发放是异步 IM 链路**：平台新手任务(robotTask)奖励经云信 `attachType=135` 推送后才调 `robotTask/claim`，再刷新列表。iOS 必须在 IM 消息回调里接 135 分发，不能仅靠主动轮询。
4. **rewardType 语义统一**：1钻石/2宝石/3道具/4座驾/5头像框/6积分，多处图标与文案依赖此映射，iOS 建立统一枚举。
5. **红点规则**：`tierStatus !== 2` 即红点（含未达标与可领），全部已领才消失；模块红点=任一子任务红点。
6. **指标字段语义核对**：work 页 `dataStatistics.weeklyDiamonds` 实际展示为「平均通话时长」、`callNum` 为「在线时长」，字段名与含义不一致，重建前务必与后端确认真实语义。
7. **三种"任务"勿混淆**：①任务中心(taskCenter)②活动新主播任务(newTask/newBie)③平台新手任务(robotTask)，分属不同后端服务、不同入口与生命周期，数据模型不互通。
8. **埋点对齐**：事件名、参数(hostid/taskdia/step/path 等)、全局超级属性(n_level 等)需与数数后台一致，否则报表断裂。`app_version` 当前硬编码 `H52.0`，iOS 应替换为原生版本号。
9. **入口可见性后端控制**：newBie/bigR/新手任务横条均由后端开关(`anchor_call_task_open`、`checkEntryVisible`)控制，iOS 须实现同款开关拉取与降级。
10. **可忽略项**：`template.js`(空壳)、`task/conten.vue`(注释标明未使用)、`api/sign/*`(本端未接入)、WorkingGuide(纯 iframe 文档)。
11. **RTL 适配**：newBie/引导大量按 `$language==='ar'` 切换图片与定位，iOS 需做 RTL 镜像。

### 9.1 iframe 活动页容器（iframePage / h5link / postMessage 协议）

iOS 端需实现两套并存的 iframe 容器，对应 H5 的 `iframePage` 与 `h5link`，两者通信协议不同，业务场景互补。

**iframePage 活动页（独立路由，抽奖/游戏任务等核心载体）**

- 源码：`src/views/iframePage/index.vue`
- iframe URL 取自 `appStore.iframeUrl`，`watchEffect` 监听；卸载时**不清空**（活动页跳 `/wallet`、`/rank` 再返回需复用）。
- iframe ↔ 原生壳 `postMessage` 协议（消息 `type` 全集）：
  - `getAppParams`（iframe → 壳，握手）：壳回传 `{ type:'getAppParams', token, appId, clientType:'anchor', platform:'web', roomId, roomType, reportParams, acceptLanguage }`；token 取 `tokenManager.getLoginUuid()`，acceptLanguage 取 i18n 当前 locale。
  - `SET_NAV`：`payload.visible` 控制是否显示原生导航栏。
  - `CLOSE`：关闭活动页（`history.length>1` 则 back，否则 `router.replace('/')`）。
  - `JUMP_WALLET`：跳 `/wallet`。
  - `JUMP_RANKING`：跳 `/rank`，带 `from=gameTask`（游戏任务榜模式）、`hideMonthTab=1`（隐藏月榜 tab）。
  - `REPORT_SHUSHU`：活动页转发埋点，壳侧统一以 `anchor_event` 上报，`eventName` 进 data（避免污染漏斗）。
  - `GO_PROFILE` / `GO_LIVE_OF_ANCHOR` / `GO_LIVE` / `GO_ROOM`：主播端**显式占位不处理**（仅 web 用户端使用）。
  - 未知 type → 上报 `c_log` 留痕。
- 安全与时序要点（必须严格复刻）：
  - 身份校验：仅处理 `event.source === iframeRef.contentWindow` 的消息，避免与 `messageScroller`、`liveActivitySwiper`、`h5link` 多个 message 监听器互相串扰。
  - 下发 token 的 `targetOrigin` 必须用 `event.origin` 或解析 iframe URL 的 origin，**禁止用 `'*'`**（防 token 泄露）。
  - 握手由 iframe 主动发起（最多 10×300ms 重试）；壳侧 `onMounted` 后 3500ms 兜底：未收到握手则主动推一次鉴权 + 留痕。
  - lottery 活动专属：URL 里的 `roomId/roomType/reportParams` 被剥离到运行期 plain 对象 `pendingRuntime`（避免 postMessage 结构化克隆失败），其余活动保持 URL 拼参。

**h5link 活动页组件（嵌入式，PK 活动等次要场景）**

- 源码：`src/views/h5link/index.vue`
- 以组件形式嵌入（非独立路由），接收 `activityUrl` prop。
- URL 拼参：`${activityUrl}?token={loginUuid}&appid={localStorage.appId}&env={VITE_APP_ENV}&language={detectLanguage()}&userId={userId}`（去空白）。
- postMessage 协议仅 SET/GET localStorage：
  - `type:'SET'` → `localStorage.setItem(key,value)`
  - `type:'GET'` → 读 localStorage 后 `e.source.postMessage({type:'SET',key,value})` 回传。
- 导航：`showCNavBar` prop 控制是否显示导航栏，标题硬编码 `'Livestream Guide'`，自定义返回 emit `clickBack`。
- 监听器是 `window` 级且无 source 校验，与 iframePage 共存时靠 type 字段区分。

**通用 iframe 跳转封装（c-goToIframe）**

- 源码：`src/components/common/c-goToIframe.vue`
- 决定跳转走应用内原生路由还是 WebView 的统一入口：
  - 空 url 直接 return（防 iframe 白屏 loading）。
  - URL 含 `isHuanNiuOwnH5` → 视为内部页，剥离域名后 `router.push` 进应用内路由（如 CP/couple 榜 `/rank?nav=couple&isHuanNiuOwnH5=1`），**不进 WebView**。
  - 否则：将 url 写入 `appStore.iframeUrl`，`router.push('/iframePage')`；**token 不再注入 URL**，由 iframePage 的 `getAppParams` 握手下发。
  - URL 含 `isPkActive` 自动上报 `hostPK_activity`；支持 `reportEvent`/`reportData` 自定义点击埋点。
- iOS 复刻要点：保留「内部标记 `isHuanNiuOwnH5` 走原生页、否则走 WKWebView」的分流规则；WebView 容器需实现 `getAppParams` 握手向 H5 下发 token，而非 URL 拼接。

### 9.9 通用计时器与轮播组件

**正向计时器 `c-calculagraph.vue`**

- 用途：从 `startTime` 起的累加计时（通话时长、任务时长展示）。
- 关键逻辑：HH:mm:ss 格式；`timeStop` 暂停/恢复（恢复时重置 startTime）；每秒触发 `updateCountdown`，秒数为 00 时调 `secondsToZero()`，秒数 `%10===0` 时调 `tenSecondsCB(seconds)`。卸载清 interval。
- iOS 复刻要点：是**正向累加**而非倒计时，且暴露 0 秒/每 10 秒两个回调钩子（被收益、任务等逻辑挂载使用）。

**通用轮播 `v-swiper.vue`**

- 用途：项目所有 swiper 的底层封装（跑马灯、Banner、卡片轮播均基于它）。
- 关键逻辑：
  - **IntersectionObserver** 控制：组件不可见时 `autoplay.stop()`、可见 `start()`（省电）。
  - **懒加载**：`lazyLoadSaver(Set)` 仅渲染已访问 slide + `preloadAdjacent` 相邻 slide。
  - **滑动区域限制** `enableSwipeArea`+`swipeArea{minX/maxX/minY/maxY}`：触点超区禁滑。
  - 引导进行中（`userStore.driverInstanceLoad` 为真，driver.js 新手引导期间）禁止滑动；卸载销毁 observer 与 swiper 实例。
- iOS 复刻要点：原生 `UIScrollView`/`UICollectionView` 需复制「不可见暂停自动播放、相邻预加载、引导期禁滑」三条行为，与新手任务引导联动。
- `c-marquee.vue` 是 `v-swiper.vue` 的垂直跑马灯薄封装，逻辑同上。
