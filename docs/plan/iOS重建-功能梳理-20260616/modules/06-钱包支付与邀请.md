# 06 - 钱包/收益/提现 + 支付 + 邀请返佣

> 适用范围：iOS(Swift) 原生重建。基于 H5 主播端真实源码梳理。
> 关键结论：本模块「主播视角」核心是**收益钱包 + 提现**和**邀请返佣**；「充值/支付」（Airwallex/USDT）大量代码为历史遗留/已注释，主播端实际不承担用户充值，重建时优先级低。

---

## 一、模块概述

主播端钱包支付与邀请模块由三大块组成：

1. **钱包/收益**：展示主播钻石余额、今日收益、收益明细（按来源分类：通话/礼物/任务/邀请/私信/互动/其他）。
2. **提现**：收款方式管理（USDT/Digifinex/Epay）→ 输入提现钻石 → 费用试算弹窗 → 人脸活体检测（条件触发）→ 交易密码（首次设置/校验）→ 提现申请 → 提现记录（审核状态机）。
3. **邀请返佣**：双维度（邀请用户 / 邀请主播），展示返佣比例、邀请码、绑定列表、累计收益、收益排行、收益明细下钻；主播维度还有「我的看板」展示被邀请主播的多维数据。

> **充值/支付（Airwallex、USDT、原生 IAP）**：源码集中在 `stores/modules/gift.js` 的 `recharge` action 与 `use/useAirwallexPay.js`，但 USDT 分支（`chainName`）在 `recharge` 内被 `return` 短路（`gift.js:335-336` 进入分支立即 return，未启用）；充值列表/支付列表的 store 调用 action（`getRechargeListData`/`getPaymentsData`）已整体注释「无调用」，但 API 函数（`getRechargeList`/`getRechargeListV4`/`getPayments`/`countryRate`）仍在 `api/wallet/index.ts` 导出（`countryRate` 当前 URL 指向 uat 环境）。这是「用户充值」逻辑，主播端不直接消费。重建时作为「了解」而非「实现」对象。

## 四、业务逻辑与规则

### 4.1 货币体系（钻石 ↔ 法币）

- **唯一内部货币是「钻石」(diamond)**。主播端不出现「金币」概念（金币是用户端余额体系，主播端收益统一以钻石计）。
- 钻石 → 美元：由 `myWallet.diamondRate` 决定，规则为 **`diamondRate` 个钻石 = 1$**（UI 直接展示 `${diamondRate}=1$`）。
- 提现金额计算（`withdrawal/index.vue` `withdrawCash`）：
  ```
  currentAmount(美元) = Math.trunc(提现钻石 / diamondRate).toFixed(2)   // 向下取整到整美元
  feeAmount           = currentAmount * 收款账户.serviceCharge / 100     // 手续费
  finalAmount         = currentAmount - feeAmount                        // 实际到账美元
  less                = 提现钻石 % diamondRate                            // 不足 1$ 的零头钻石（退回账户）
  ```
- **结论：钻石按汇率向下取整折算为美元提现，零头钻石（< 1$）退回主播账户**，手续费按所选收款渠道的 `serviceCharge` 百分比扣除。

### 4.2 提现校验规则（逐步）

入口 `withdrawCash()` 校验顺序（`withdrawal/index.vue:23-26`）：
1. 必须选中收款账号（`currentAccount.id`）
2. 必须输入提现量
3. 提现量 **不得小于 200**（钻石，硬编码）
4. 提现量 **不得小于 `diamondRate`**（即至少够兑 1$）

进入费用弹窗后 `tipDialog.confirm()` 额外校验（按收款渠道最低额，单位美元）：
- **Digifinex**：到账美元 `currentAmount` < 20 → 拦截（"cannot be lessthen $20"）
- **Epay**：`currentAmount` < 50 → 拦截（"cannot be lessthen $50"）
- **USDT**：无额外美元下限校验（addCollectionMethod 文案写「Minimum withdrawal $20」但代码未对 USDT 设额外门槛）

> 收款方式新增时的提示文案：Digifinex 最低 $20、Epay 最低 $50、USDT 默认 TRC20 链。

### 4.3 人脸活体检测（提现风控）

调度链：`tipDialog.confirm()` → 调 `faceAuthVerifiedApi`（`/api/face/auth/verified`，传 `deviceId + anchorId`）判定是否需要人脸：

> `faceAuthVerifiedApi` 入参：`{ deviceId, anchorId }`；出参：布尔值（是否需人脸）。判定规则（设备风险/首次提现/金额阈值）**在后端，前端透传**（`tipDialog.vue:66-77`）。iOS 复刻须与后端确认完整规则书。

- 返回 truthy → 拉起 `faceLiveness.vue` 活体检测
- 返回 falsy → 直接进入交易密码流程 `getConfig()`

活体检测（`faceLiveness.vue`，**face-api.js + TinyFaceDetector + faceLandmark68Net**）：
- 三步动作状态机：`SHAKE`（摇头）→ `NOD`（点头）→ `FRONT`（正脸），每步超时 5s，连续 5 帧无人脸判失败
- 环形进度 0 → 33.33 → 66.66 → 100
- 完成后 canvas 截图 → 上传阿里云 OSS（STS 临时凭证 `getOssKey` → `/sts/getkey`）→ 调 `faceAuthScanApi`（`/api/face/auth/scan`，传 `deviceId + anchorId + imgUrl`）做比对
- 模型 CDN：`https://cdn.jsdelivr.net/gh/TsMask/face-api-demo-vue/public/models`（外部依赖，重建时应自建模型托管或改用原生 Vision/活体 SDK）
- 埋点：`h_faceID_view`（进入）、`h_faceID_sucess`（通过）、`h_real_ppl_confirm_click`（重试弹窗）

### 4.4 交易密码（`withdrawalDialog.vue`）

- 先查 `apiGetWithdrawConfig`（`getAnchorWithDrawConfig`）拿 `isSet`：
  - `isSet=false`：首次，调 `apiSetWithdrawPassword`（`setWithdrawPassWord`）设置密码（6 位数字）
  - `isSet=true`：调 `apiApplyWithdraw`（`applyWithdrawV2`）提交提现
- 提现提交参数：`accountAddress / accountName / accountType / withdrawNum(钻石) / password`
- 提交成功 → 跳 `/wallet/withdrawalRecord`
- 忘记密码 → 复制客服 WhatsApp

### 4.5 提现状态机（`withdrawalRecord/index.vue`）

记录字段 `state`：
| state | 含义 | UI |
|-------|------|----|
| 1 | 审核中 | "Under review" 橙 #E8A200 |
| 2 | 已提现 | "Paid" 绿 #22D956 |
| 3 | 审核失败 | "Rejected" 红 #F30034 |

记录展示：收款类型图标 + `withdrawNum`（钻石）+ 订单号 `billId` + 时间 `createTime` + 状态。

### 4.6 邀请返佣规则

- **两条返佣线（平级，非多层级分销）**：邀请用户 / 邀请主播。两者各有独立邀请码、链接、返佣比例。**未发现下下级（二级）分润逻辑**——是「一次邀请，长期返佣」（UI 文案 "One invitation life long benefits"），返佣来自被邀请人产生流水的固定百分比。
- 返佣比例：`invite_user_award`、`invite_anchor_award`（`getConfigByKey` 按 key 下发，UI 直接显示百分比数值）。
- 统计：`getStatisticsData`（v2，传 `userType` 1/2）→ `inviteUserNum`(人数) / `awardTotal`(累计返佣)。
- 绑定列表：`getBindUserAnchorList`（分页，传 `userType/pageSize/currentPage`）；总返佣排行：`getTotalRewardList`（一次性）。
- 邀请用户明细：`queryAnchorInviteUserDetail`（被邀请用户列表，`awardTotal/inviteTime`）→ 下钻 `queryAnchorInviteAwardRecord`（单用户每笔奖励 `awardAmount/createTime`）。
- **我的看板（主播被邀请数据）**：`inviteAnchorListV2`（按 startTime/endTime 取今日/上周/上月，返回 `anchorVos + totalReward`）→ 单主播 `inviteAnchorDetail`（uid）返回多维：累计产出奖励 `cumulativeOutputReward`、通话收益 `callIncome`、礼物收益 `giftIncome`、接通率 `averageConnectionRate`、排名 `rankingNum`、等级 `level`、累计在线 `cumulativeOnlineTime`(秒)、累计通话 `totalChatTime`(秒)、平均通话 `averageCallDuration`(秒)。

  > 看板时间区间由前端本地计算（今日 00:00–23:59、上周一~周日、上月整月），转毫秒时间戳传后端。

### 4.7 充值/支付（遗留，了解为主）

- 入口在礼物/充值场景（`gift.js` `recharge`），主播端不主要承担。
- 支付渠道 `channelType`：1/3 = H5 跳转外链（`data.action`）；2 = Airwallex（`awxDropInPay` 内嵌 dropIn 元素）；5 = PayPal（取 paylink 跳转）；`chainName` = USDT（**`gift.js:335-336` 进入分支即 `return`，未启用**）。
- 原生 IAP：`payMethod` 为 `APPSTORE`/`GOOGLEPLAY` 时通过 webview bridge 调原生（`window.webkit.messageHandlers.Pay/rechargePay`、`window.android.recharge`、`flutter_inappwebview`）。
- Airwallex 集成（`useAirwallexPay.js`）：懒加载 `airwallex-payment-elements`，env 按 `VITE_APP_ISDEV` demo/prod；支持 `redirectToCheckout`（HPP 跳转）和 `createElement('dropIn')`（内嵌），方法 card/applepay/googlepay。
- USDT 消息侧字段（NIM ext，见项目规范）：`usdtPayStatus`、`usdtOrderNo`；gift store 持久化了 `usdtPayData/usdtPay*CountDown` 等倒计时状态，但创建订单 USDT 分支未启用。

## 七、边界与异常处理

- **收益列表防死循环**：接口报错时强制 `loading=false; finished=true` 并 toast，避免 van-list 无限触发 load。
- **提现量钳制**：输入超过 `canWithdrawalAmount` 时自动改写为上限值。
- **金额计算 NaN 防护**：`currentAmount` 为 NaN 时置 0。
- **不足 1$ 钻石**：`less` 字段提示零头退回，不参与提现。
- **删除收款账户**：无账户点删除按钮 → warn 提示；删除成功/失败用 overlay tip（3s 自动关）。
- **人脸检测容错**：连续 5 帧无人脸或单步超时 5s → 失败弹窗，可重试（重置状态机）或取消（退出，回退到密码流程不触发）。摄像头权限失败 → `emit('complete', false)` 静默退出。
- **活体期间通话态保护**：进入活体时若 `matchState===MATCHING` 改为 `MATCHING_LEFT`，卸载时还原（避免误判离开匹配）。
- **OSS/比对失败**：捕获后取 `err.response.data.message || err.message` 透传到失败弹窗。
- **交易密码**：必须 6 位才可提交（`disabled`）；接口失败清空密码并 toast。
- **复制兼容**：`navigator.clipboard` 不可用时降级 `document.execCommand('copy')`。
- **支付（遗留）**：原生 bridge 都不存在时 `showNotify('no pay')`；创建订单失败上报 `result:'failed'`。

边界风险（重建注意）：
- 提现下限存在「双重口径」：前端硬编码 200 钻石 + 渠道美元下限（20/50），两者需与后端对齐。
- 客服 WhatsApp 号码硬编码，应配置化。
- 看板时间区间在前端本地时区计算，跨时区/与服务端时区不一致会有偏差。

## 八、iOS 重建注意事项

1. **货币只认钻石**：主播收益体系统一钻石，提现按 `diamondRate` 向下取整折美元、零头退回；不要引入金币概念。汇率/手续费/下限全部来自后端字段（`diamondRate`、账户 `serviceCharge`、`canWithdrawalAmount`），勿硬编码（前端现有 200 钻石硬编码应迁为后端下发）。
2. **提现是强风控流程**，务必完整复刻顺序：收款账号 → 金额校验 → 渠道下限 → 人脸（条件触发）→ 交易密码（首设/校验）→ 申请 → 记录。其中「是否需要人脸」由 `/api/face/auth/verified` 决定，不可前端写死。
3. **人脸活体**：H5 用 face-api.js 自研三动作（摇头/点头/正脸）。iOS 建议改用系统 Vision 或成熟活体 SDK，但**比对仍走后端**：截图上传 OSS（用 `/sts/getkey` 的 STS 凭证）后调 `/api/face/auth/scan`，接口契约保持不变。`facCompare.vue` 是废弃残留，无需移植。
4. **收款方式三类**：USDT(TRC20，输入链地址)、Digifinex(输入 UID)、Epay(输入名称+邮箱)，`accountType/accountName/accountAddress` 三字段统一存储，渠道决定图标、文案、最低额。
5. **邀请是平级双线返佣，非多层级分销**：用户线/主播线独立邀请码与比例，「一次邀请长期返佣」。返佣比例来自 `getConfigByKey`，勿写死。**所有邀请接口均走主接口 `http`（`src/api/invite/index.ts`）**，不要误对接到 sapi。看板时间区间计算逻辑（今日/上周/上月）需与后端时区对齐，建议改由后端返回区间或服务端时间基准。
6. **充值/支付优先级低**：USDT 分支已短路未启用（`gift.js:335-336` 进入即 return）；充值列表/支付列表的 store 调用 action 已注释（API 函数本身仍导出）。Airwallex 仅在礼物/充值场景且主要面向用户。原生 IAP 通过 webview bridge——iOS 原生重建应直接用 StoreKit，不要照搬 bridge。若确需 Airwallex，参考 `useAirwallexPay.js` 的 dropIn/HPP 两种模式与 `channelType` 分发。
7. **二级接口归属**：本模块涉及 sapi 的**仅是收益明细**——`views/wallet/index.vue` 使用 `sApiGetIncomeList`（`/sapi/anchor/v1/client/anchor/bill/list`），与背包商城共享同一套 `httpSapi`/sapiIndex。sapiIndex（`src/utils/request/sapiIndex.ts:80-104`）实现：401 自动 `getBagShopToken`（→ `apiBagShopExchangeToken`）换 token 并附带 `closeAES: true` 重放原请求（避免重复加密）；响应体 `result` 字段走 Web Crypto 异步 AES 解密（`aesHexDecryptAsync`，失败回退同步 crypto-js）。iOS 复刻原生 HTTP 层需对齐：a) sapi baseURL 独立；b) 401 触发 exchangeToken 且重放时关闭加密；c) 响应解密。**鉴权 token 与背包商城共用**——同一个 sapi token 既用于背包，也用于收益明细，无需两套 exchange。
8. **Long 精度**：sapi 返回的 `anchorId/flowValue/expectedReward` 等为字符串化的 Long（防 JS 精度丢失），Swift 侧用 String/Int64 解析，勿当普通数字。
9. **埋点齐全**：提现人脸（`h_faceID_*`、`h_real_ppl_confirm_click`）、邀请（`h_invite_page_*`、`invite_btn_click`、`h_invite_shareType`）需一并迁移。

## 九、营销与活动浮层补遗（整合）

> 本章整合补遗 B、D、E 中归属钱包/支付/邀请模块的全局浮层组件与支付细节。原"邀请返佣"主流程在第四节、Airwallex 在 4.7/六章已覆盖，此处仅补充落地 UI 与支付流程细节。

### 9.1 主播折扣池/曝光加速蒙层（g-boosting）

**作用**：主播加入 VIP 曝光折扣池后展示的全屏"Boosting Exposure，请耐心等待"等待蒙层。

- **源码**：`src/components/global/g-boosting.vue`
- **驱动方式**：受 `messageStore.showBoostingExposure` 控制——云信 IM 系统消息 `attachType=63` 加入池时置 `true`，`attachType=64` 退出池时置 `false`。**该字段持久化**，重启后状态保留，避免主播在加入折扣池期间因刷新页面而错过状态。
- **UI 结构**：`van-overlay` 全屏遮罩 + 中央动图 + 关闭按钮 `handleClose`（手动置 false 关闭蒙层，但池状态由 IM 驱动，关闭仅隐藏 UI 不退出池）。
- **业务关联**：折扣池是营销侧的"提升曝光换让利"机制，主播加入后按折扣价被推荐给用户，结算钻石按池规则计算（具体规则属后端结算逻辑，本端不参与）。
- **iOS 复刻要点**：显隐由 IM 系统消息 63/64 驱动且**需持久化**；蒙层为纯展示态，手动关闭仅影响 UI 可见性。

### 9.2 邀请信息卡片与裂变邀请弹窗

**作用**：顶部下滑式"用户邀请你聊天"卡片，承载邀请用户/已充值用户主动开聊的入口，是邀请返佣体系中**用户侧裂变消息**的客户端落地。

- **源码**：`src/components/global/g-inviteMsg.vue`
- **数据源与队列消费**：消费 `sessionStore.inviteMsgList[0]`，FIFO 队列；关闭/超时/上滑手势均触发 `shift()` 弹出当前卡片并展示下一条。
- **10s 倒计时自动消失**：卡片显示即起 10s 倒计时（`initCountdown`），归零后 shift 并继续下一条；多条连续消费。
- **上滑手势消除**：监听 `touchStart`/`touchEnd`，纵向滑动差值 >50px 提前 shift 移除当前卡片（用户主动忽略）。
- **点击跳转**：点击"Start the chat"跳 `/chat?to=userYxAccid&path=userlist`。
- **裂变埋点分型**：曝光/点击埋点按 `attachType` 区分——`attachType===103` 上报 `successRecharge`（已充值用户裂变）、`attachType===104` 上报 `noRecharge`（未充值用户裂变）。两者对应项目规范 ext 字段中的 `weakTxtType 103/104`。
- **显示条件**（App.vue `showInviteMsgPopup`）：队列非空 && 处于一级页 && 非通话中 && 匹配已结束 && app 在前台。任一不满足都不展示，保证卡片不打扰通话/匹配等核心流程。
- **RTL 适配**：倒计时角标在 RTL 语言下左右镜像。
- **iOS 复刻要点**：10s 自动消失 + 上滑手动消除 + 已充值/未充值埋点分型 + 展示前置条件链需完整保留。

### 9.3 useAirwallexPay 支付细节补充

**作用**：Airwallex 国际支付的统一封装入口，供充值/订单场景调用。第四节 4.7 已提及"渠道分发"和"懒加载"，此处补充完整支付方式映射、入口形态与回调机制。

- **源码**：`src/use/useAirwallexPay.js`
- **懒加载与环境切换**：动态 `import('airwallex-payment-elements')`，按 `VITE_APP_ISDEV` 切换 `env = 'demo'`（开发/测试）或 `'prod'`（正式）。
- **三种支付入口**：
  - `redirectHpp`：Hosted Payment Page 跳转模式，用于卡支付/applepay 通用入口。
  - `redirectHppApplePay`：纯 ApplePay HPP 跳转。
  - `awxDropInPay`：内嵌 dropIn 元素，在当前页面内承载支付 UI，无需跳转。
- **支付方式映射 `getPayMethod`**：业务侧渠道码 → Airwallex 方法名：
  | 业务渠道 | Airwallex method |
  |---------|------------------|
  | `CREDIT CARD` | `card` |
  | `AWXAPPLEPAY` | `applepay` |
  | `AWXGOOGLEPLAY` | `googlepay` |
- **ApplePay 配置**：`countryCode=HK`、`buttonType=buy`，需要 `billing` 字段携带 `postalAddress / email / name / phone / phoneticName`。iOS 原生 ApplePay 集成需对齐这些 billing 字段要求。
- **下单参数**：调用时传入 `intent_id / client_secret / customer_id / currency / successUrl`，由后端订单接口返回，前端只做透传。
- **成功回调**：支付成功置 `giftStore.awxPaymentStatus = true`。**注意状态字段散落**——`gift.js` 内的 `awxPaymentStatus` 与本封装的回调耦合，支付结果实际靠回调置位 + 业务层轮询订单状态双保险。
- **iOS 复刻要点**：可直接用原生 Airwallex iOS SDK（若仍走 Airwallex）或转用 StoreKit 内购。本封装的"渠道码映射、HPP 与 dropIn 双模式、ApplePay billing 必填项、回调状态字段"逻辑可作为下单与回调参数的参考蓝本；若改用 StoreKit，则只保留下单参数（intent_id 等）和回调状态字段，UI 层完全替换为原生。
