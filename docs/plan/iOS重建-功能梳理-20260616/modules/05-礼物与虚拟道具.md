# 05 - 礼物与虚拟道具模块（iOS 重建功能梳理）

> 来源：anchor-livechat-h5 真实源码梳理（主播端 H5，webview 内嵌）。
> 角色定位：本应用是**主播端**，主播主要"收礼"，不主动送礼；主动行为只剩"向用户索要礼物"（askFor）。`/api/gift/send` 接口虽在 `src/api/gift/index.ts` 导出，但全代码库无任何业务调用方（grep `sendGift(` 仅命中导出处），iOS 重建可不实现送礼链路。

---

## 一、模块概述

礼物与虚拟道具体系由三个相对独立的子系统组成：

1. **普通礼物（金币/钻石礼物）**：用户送出，主播端负责**接收消息 → 播放动画 → 更新收益/任务/公屏**。涵盖三种场景：1v1 通话、直播间、P2P 私信。主播侧无"送礼"入口，只有"索要礼物"（call 场景）。
2. **钻石福袋（diamondGift，DM-20260421-006）**：直播间专属玩法。用户发福袋 → 预热 → 开抢 → 瓜分 → 结算。主播端是**纯感知层**：只展示挂件、飘屏、公屏、规则弹窗与中奖名单，不可发、不可抢。
3. **虚拟道具（virtualProps）**：背包/商城合一的装扮体系，类型含座驾、头像框、聊天气泡（chatSkin）、资料卡边框（cardFrame）、进场头像。主播可在道具页穿戴/卸下；座驾/进场道具会驱动直播间与通话内的**进场动画 + 进场飘屏**。

三套系统共享同一套**动画播放队列**（在 `gift.js` store 中实现），SVGA 与 MP4(YYEVA) 统一入队、串行播放。

## 三、功能点清单

### 普通礼物
- 三场景收礼：1v1 通话（attachType 4 / -1）、直播间（attachType 50 scene=LIVE）、P2P 私信（attachType `'SEND_GIFT'` 字符串）。
- 礼物动画：SVGA(.svga) + MP4(.mp4) 两种格式，统一入队串行播放；非动画礼物走"飘浮小图"提示。
- 连击/队列：模块级原生数组 `giftQueue`，按序消费；**PK 期间**额外按价格降序+时间升序排序并限制队列最大长度（默认 15，正在播放的不参与重排）。
- 收益展示：通话每分钟预估收入（attachType 15）、通话礼物预估收入（attachType 18）、直播间收入实时刷新（`getCurrentLiveIncome` → `userJoinRoom`）。
- 礼物任务/愿望单：直播间收礼后更新 `liveTaskList`、`currentLiveInfo.wishlist` 进度。
- 幸运礼物中奖：礼物消息带 `totalReward` 时额外推公屏；带 `rewardPool.fullWinningStyle` 时进全服公告。
- 主播索要礼物：仅 call 场景，`askFor` 发起（参数 `beAskYxAccid + giftId`），被拒收到 attachType 16 toast；`rejectAskGift` 接口由用户端调用，主播端只在 api 文件定义但无业务调用。
- **主播端不送礼**：`sendGift`（`/api/gift/send`）全代码库无任何业务调用方，iOS 重建可不实现送礼 UI。

### 钻石福袋
- 三态机：1=WARMING(预热) / 2=OPEN(开抢) / 3=SETTLED(结算)；CREATED(0) 不展示。
- 同房多福袋 FIFO 队列：`activeList` 按 `giftId` 升序维护（`src/stores/modules/diamondGift.ts:262/269/432` 每次入队/合并后 `sort((a, b) => a.giftId - b.giftId)`）——即先发先入队首。挂件取队首 + 队列长度角标。
- 预热模式：1=立即 / 2=延迟；退回时长 `refundMinutes`。
- 倒计时：WARMING→openAt，OPEN→expireAt；前端 1s 时钟自算，预热结束即按 OPEN 展示（不等 1031）。
- 结算公屏变体：`all`/`expired`(有人抢) → TopShare 卡片；`no_claim`/`expired`(无人抢) → 退回公屏；`live_ended` → 静默。
- 中奖名单：金额降序、同额按抢的时间升序，含 Top Share 标。
- 主播限制：不可发、不可抢，挂件点击只弹规则。

### 虚拟道具
- 背包+商城合一列表（`isFromBag` 区分已拥有/未拥有）、分页、过期时间展示（`-1` 为永久 Prem）。
- 穿戴/卸下（ops type 1/2），本地同步 `userStore.mineInfo` 的 headFrame / chatBubble / cardFrame。
- 预览（静态图 / SVGA / MP4 或 webm）。
- 进场动画：座驾/进场道具触发直播间(attachType 80)/通话(attachType 83)进场动画 + 进场飘屏；特效开关（effectEnabled）控制是否播放，播放计数 >10 触发开关提示。
- 活跃大R 进场（DM-20260429-002）：金色专属底图飘屏，无虚拟道具也可触发（`showActiveTycoonEntrance`），`attachTypeStr='active_tycoon_enter_room'` 触发 toast。

## 四、业务逻辑与规则

### 4.1 动画播放队列机制（核心，gift.js）

队列是**模块级原生数组** `giftQueue`（刻意绕过 Pinia 响应式以避免动画卡顿，`src/stores/modules/gift.js:54`），队列项结构：
```
{ url: string, price: number, timestamp: number, userData?: object }
```

播放主流程（`handleNextAnimation`）：
1. `isPlaying` 为 true 直接返回（串行，单实例播放）。
2. `isNext` 时 `giftQueue.shift()` 弹出已播完项。
3. 取队首，按 URL 后缀判类型：`.mp4`→YYEVA，`.svga`→svgaplayerweb，其它→跳过。
4. 若队首带 `userData`，同步显示"用户进场飘屏"（`userEntranceFloat.vue`，CSS fadeLeft 5s）。
5. 动态创建全屏容器 div（fixed，z-index 9999，pointer-events none，居中），播放结束自动销毁 DOM 并 `handleNextAnimation(true)` 播放下一个。

播放器封装：
- **SVGA**：`playSVGAWithCleanup` → `new SVGA.Player + SVGA.Parser`，loops=1，AspectFit；`onFinished` 清理。
- **MP4**：`playMP4WithCleanup` → `YYEva({ container, videoUrl, hevcUrl, mute:false, loop:false })`，`onEnd/onError` 清理。
- SVGA/YYEVA 库均**懒加载**（`import('svgaplayerweb')`、`import('yyeva')`），SVGA 启动 5s 后预初始化（`gift.js:30-32`）。
- 预热 5s 内若收到首条 SVGA 动画，`playSVGAWithCleanup`（`gift.js:588-590`）有 `if (!SVGA) await initSVGA()` 兜底；同步等待初始化在高频礼物场景仍可能造成首条卡顿，iOS 实现建议在进房/进通话前 await SDK ready 或更早触发初始化。

入队（`addGiftToQueue(url, price, isInPk, userData)`）：PK 中调 `sortAndLimitPkGiftQueue`：
- 排序：价格降序 → 时间升序；
- 正在播放时保护索引0，仅重排索引1+；
- 超 `pkSettings.pkGiftsQueueLengthMax`(默认15) 截断丢弃。

清理：`forceCleanAnimation` / `clearAllTimersAndPlayers` 销毁所有 SVGA/YYEVA 实例、清空队列与定时器、隐藏进场飘屏。

> 注意：旧的 `playSVGA(svgaSrc, domId)`（固定 `chatSvgaCanvas` 容器）仍保留但基本被新队列替代；call 视图里有 `<div id="chatSvgaCanvas">` 残留。`html2canvas` 在本模块**未实际使用**（任务描述提及但代码中无引用）。

### 4.2 礼物消息 → 动画触发链路

| 场景 | 入口 | 触发条件 → 动作 |
|------|------|----------------|
| 1v1 通话 | `g-faceTime/index.vue` watch `homeStore.talkListInCall` | 取 `giftImg`：含 .svga/.mp4 → `addGiftToQueue + handleNextAnimation`；否则飘浮小图 3s |
| 通话系统消息 | `message.js onSysMsg` attachType=4 | unshift 到 `talkListInCall`（含 giftImg/smallImg/giftNum/giftId），由上面的 watch 消费 |
| 直播间 | `live.js handleLiveGiftMessage`（attachType=50 且 scene=LIVE） | giftIcon 含 .svga/.mp4 → 入队播放（PK 中带排序）；公屏 unshift；更新任务/愿望单/收入/幸运礼物 |
| P2P 私信 | `message.js` | `attach.attachType === 'SEND_GIFT'`（字符串）标记为礼物消息，不参与回复积分结算。注意这是字符串字面量（非数字编码），与 NIM 数字 attachType 体系并存，源于后端历史设计。`src/stores/modules/message.js:176` 用 `attachType !== 'SEND_GIFT'` 字符串判定。iOS 解析时类型守卫需同时处理 number 和 string |

### 4.3 钻石福袋状态机（diamondGift.ts + live.js）

驱动方式：**IM 主驱动 + HTTP 兜底**。
- IM：attachType 1030(发→WARMING入队) / 1031(开抢→OPEN) / 1032(瓜分→累加) / 1033(结算→SETTLED, 5s后移除)。
- HTTP 兜底：`/api/diamondGift/roomCurrent`，客态进房单次拉取（聊天室 IM 无离线重放）。
- **IM 乱序兜底**：1031/1033 早于 1030 到达时缓存在 `pendingHigherStates`，等 1030 来时升级状态。
- **因果守卫**（refreshCurrentByRoom）：in-flight token 防房间切换/并发；`activeListSetTs >= requestTs` 时 IM 优先；giftId merge 时本地更高阶 state 不被 HTTP WARMING 回退；本地 SETTLED 项保留待 5s timer 清理。
- **FIFO 顺序**：`activeList` 由 store 内部按 `giftId` 升序排序（小 id 先发先入队首），无需后端额外排序，与 android-anchor 实现对齐。
- 离房 `resetForLeave`：refreshToken++ 作废在飞请求、清所有 timer 与 pending、清队列。

### 4.4 虚拟道具进场动画（virtualProps.js）

`playEnterAnimation(data)`：
1. 检查 `effectEnabled` 开关，关闭则跳过。
2. 校验 `data.list` 非空，`JSON.parse(list[0])` 取 `itemImg`（动画 URL，可能 SVGA/MP4）。
3. 组装 userData（nickname/avatar/userLevel/isVip/activeTycoon）。
4. `giftStore.addGiftToQueue(itemImg, 0, isInPkMatch, userData)`——价格 0，PK 排序中优先级最低。
5. `incrementEffectCount`，计数 >10 且当次未提示则返回 true 触发开关提示。

进场特效有 `effectEnabled` 开关（`src/stores/modules/virtualProps.js:67-80`），关闭后仍播放动画但跳过额外特效提示。**动画队列入队与特效开关解耦**——队列项一定入，特效条件性触发。

进场飘屏与动画同队列，避免冲突；活跃大R 飘屏的金色底图在队列覆盖时按昵称匹配保留 activeTycoon 标识（防座驾动画消息把金图降级）。

## 六、依赖的 SDK 与原生能力

- **svgaplayerweb**：SVGA 解析与渲染（Canvas）。iOS 原生应使用 **SVGAPlayer-iOS**。
- **yyeva**：YY 开源的带 alpha 通道 MP4 播放（Web 用 WebGL）。iOS 原生应使用 **YYEVA iOS SDK**（基于 Metal/AVFoundation 的 alpha 视频合成）或自研 alpha 视频方案。
- **NIM（云信）IM**：所有礼物/福袋/进场消息均通过云信聊天室/P2P 自定义消息下发（attachType/scene/data）。
- **充值原生桥**：`recharge` 通过 `window.webkit.messageHandlers.Pay/rechargePay`（iOS）、`flutter_inappwebview`、`window.android` 调原生支付（主播端实际不承担充值，遗留代码）。
- 二级 API（sapi）独立鉴权：bag&shop 需 `exchangeToken` 换取独立 token。

## 七、边界与异常处理

- **SVGA 未加载完成**：`playSVGA` 内 `if (!SVGA) await initSVGA()` 兜底；YYEVA 加载失败则跳过当前并播放下一个。
- **播放失败**：SVGA/YYEVA 的 catch/onError 都会复位 `isPlaying`、隐藏飘屏、清理 DOM 并继续队列，保证不卡死队列。
- **不支持的格式**：非 .svga/.mp4 直接 skip 并 `handleNextAnimation(true)`。
- **PK 队列溢出**：超最大长度截断丢弃，正在播放项受保护。
- **钻石福袋 IM 乱序**：pendingHigherStates 缓存高阶状态等 1030 升级；去重防同 giftId 重复入队。
- **HTTP 与 IM 竞态**：token + 时间戳 + giftId merge 三重守卫，IM 优先。
- **roomId 过滤**：福袋/进场消息按 currentLiveInfo.id 过滤跨房间消息。
- **进场飘屏覆盖**：活跃大R 金色底图按昵称匹配保留，避免座驾消息降级。
- **道具 tab 切换竞态**：loadSeq 序号比对，丢弃过期分页响应。
- **道具操作前置校验**：未拥有(isFromBag≠1) toast "You can not equip or unequip this"；已穿/已卸重复点击 toast 提示。
- **资源清理**：组件 onUnmounted 销毁 SVGA/YYEVA 播放器并清空容器子节点；离房 resetForLeave。

## 八、iOS 重建注意事项

1. **动画队列是核心，需原生重写**：H5 用模块级数组 + 串行单实例播放（同一时刻只播一个全屏动画）。iOS 应实现一个串行队列 + 单一全屏覆盖层（fixed 全屏、穿透点击），SVGA 用 SVGAPlayer-iOS、alpha MP4 用 YYEVA-iOS，按 URL 后缀分发。PK 场景需保留"价格降序+时间升序+队列上限+保护正在播放项"的排序逻辑。
2. **进场飘屏与动画解耦但同队列**：飘屏是独立 UI（5s CSS 动画），由队列项的 userData 触发，需与动画同生命周期；活跃大R 金色底图特例（按昵称保留）必须复刻。
3. **钻石福袋状态机必须严格对齐**：三态机、FIFO 队列（按 giftId ASC 排序）、IM 乱序缓存、HTTP/IM 因果守卫、SETTLED 5s 延迟移除、结算 4 变体公屏。这是最复杂的子系统，建议直接参照 android-anchor `DiamondGiftManager.kt`（注释中已说明与之对齐）作为权威实现。
4. **礼物消息分场景分发**：通话(attachType 4/15/18/-1/83)、直播(50/56/71/80/...)、P2P(SEND_GIFT)，三套数据结构与收益累加规则不同，需分别建模。注意 `scene` 与 `attachType` 的组合判断（如 50 必须 scene=LIVE 才是礼物）。
5. **虚拟道具二级鉴权**：sapi 走独立 token（exchangeToken），iOS 需实现该换 token 流程；穿戴/卸下后需本地同步用户装扮字段（头像框/气泡/卡框）供其它 UI 实时读取。
6. **主播端不送礼**：`sendGift`/`/api/gift/send` 在主播端无业务调用，iOS 可完全跳过送礼 UI 与接口；主动行为只剩 `askFor`（索要礼物）。
7. **收益与分成展示是被动累加**：主播端不计算分成，收入来自 IM 推送（15/18）与接口（userJoinRoom 的 currentLiveIncome），原生侧只需展示。
8. **充值链路与本模块耦合**：gift store 混入了充值/Airwallex/USDT 逻辑（原生支付桥），iOS 重建时礼物动画与充值应解耦为独立模块；主播端本就不承担用户充值，相关代码主要是遗留。
9. **html2canvas 实际未使用**：本模块无截图合成需求，可忽略。
10. **道具类型映射**：1座驾 2头像框 3进场头像(已关闭) 4聊天气泡 5资料卡边框；预览渲染方式按类型+资源格式分支。
11. **懒加载策略**：H5 对 SVGA/YYEVA 做了动态 import + 延迟预热以优化首屏，iOS 可在进房/进通话前预热播放器。

## 九、虚拟道具与展示组件补遗（整合）

> 本章整合补遗 B、D 中归属礼物/道具模块的展示组件与图片处理细节。状态机内容已在第四节充分阐述，此处仅补充 UI 渲染与资源处理细节。

### 9.1 钻石福袋飘屏 UI 补充

钻石福袋飘屏组件（`src/components/diamondGift/diamond-gift-float-screen.vue`）在第二节已登记，此处补充渲染与多语言细节：

- 数据源：`liveStore.diamondGiftFloatList[0]` + `showDiamondGiftFloat`，与状态机的 `activeList` 解耦——飘屏是独立的"通知队列"，每条 5s。
- **LTR/RTL 双向飞入动画**：定义了 `dg-float-ltr` 与 `dg-float-rtl` 两套 keyframes，按当前语言方向选择，5s 完整时长，飞入方向相反。
- 展示字段：发送者昵称 `senderName`、`msg_send` 文案模板、钻石总数 `totalDiamonds`。
- iOS 复刻：需保留 RTL 镜像飞入方向；飘屏通知队列与第四节钻石福袋状态机的活跃队列是两套独立消费机制，不要混用。

### 9.2 头像框 SVGA 组件（head-frame）

`src/components/head-frame.vue` 是项目内通用的头像框渲染组件，在 g-waitingCall 等多处复用：

- **资源类型分支**：watch `userData` 变化，URL 含 `.svga` → 懒加载 svgaplayerweb，在 `publicHeadFrame{sub}{timestamp}` 唯一容器播放；否则用 `<img>` 静态渲染。
- **循环模式**：SVGA 设置 `loops=0` 无限循环（区别于礼物动画的 loops=1 单次）。
- **字段选择**：`type` prop 指定从 `userData` 取哪个字段作为头像框资源（默认 `headFrame`），便于同一个组件复用渲染聊天气泡/资料卡框等。
- **RTL 防翻转**：内部强制 `dir="ltr"`，避免 RTL 语言下头像框图像被镜像。
- iOS 复刻：用 SVGAPlayer-iOS 渲染头像框，注意**无限循环**模式与礼物动画的单次播放是两套实例池。

### 9.3 CDN 图片处理（replaceResourceUrl + cdnMeasure）

礼物图、头像框图、座驾图、活动底图等所有 CDN 资源统一走该处理链，定义在 `src/filters/general.ts` + `src/constant/cdnMeasure.ts`：

**replaceResourceUrl 处理流程（三步）**：
1. **协议归一**：http → https 强制升级。
2. **域名替换**：按 `appStore.cdnResourceUrl.needReplaceCdnDomains` 列表替换为 `defaultCdnUrl`，便于灰度切换/降级。
3. **OSS 图片处理参数**：拼接 `?x-oss-process=image/resize,{size},{model}`，`model` 常用 `m_lfit`（等比缩放，默认）与 `m_fill`（居中裁剪）。

**尺寸规格表**：

| 用途 | 常量 | 规格 |
|------|------|------|
| 头像 | `CDN_MEASURE` | s=w_60 / m=w_162 / l=w_270 / xl=w_420 / device=按屏宽（≤750） |
| 礼物图（小卡） | `CDN_GAME_MEASURE` | m=w_150 / l=w_300 |
| 挂件（钻石福袋等） | `CDN_PENDANT_MEASURE` | w_180 |

iOS 复刻：原生侧也需实现等价的"协议归一 + 域名替换 + OSS 参数拼接"管线，所有展示头像/礼物图/挂件图前都过一遍，避免直连原始 URL 浪费带宽。OSS x-oss-process 协议与 iOS 端拼接方式一致，不需要后端额外处理。
