## 一、模块概述

本应用是 H5 主播端，运行在原生 App 的 WebView 中（A 包模式），也可独立浏览器运行（WPA 模式）。核心基建特征：

1. **无独立鉴权页时序**：登录态由原生通过 URL 参数 `openParams`（AES 加密的 token 包）注入；H5 内的邮箱登录页仅在浏览器/未注入态下作为兜底入口。
2. **全链路 AES 加密**：所有业务请求体加密、响应体解密（AES-128-CBC，Hex 密文）。主接口与背包商城（bagshop）接口用不同密钥。
3. **双 API 域**：主接口 `/api/*`（VITE_APP_API_BASE_URL）+ 背包商城 `/sapi/*`（VITE_APP_API_BAGSHOP_URL），各自独立 axios 实例与密钥、独立 token 体系。
4. **自动路由 + 无路由守卫**：使用 `unplugin-vue-router` 文件路由，权限拦截全部集中在 `App.vue` 的 `checkLogin()` 中，按 `userType` 分流到主版/受限版界面。
5. **三语言 + RTL**：英(en)/阿拉伯(ar，RTL)/土耳其(tr)，英文内置打包，其余按需动态加载。
6. **数数(ThinkingData)埋点**：全局 `window.ta`，登录/启动/页面曝光等大量埋点。
7. **设备分档与降级、美颜、声网音视频、云信 IM** 等重型 SDK 全部动态 import。

> iOS 重建关键点：H5 的"登录"在原生里其实由原生完成（拿到 token 后注入 WebView 或直接调原生 API）。原生重建需要把 H5 这套加解密/鉴权头/设备信息生成逻辑完整还原成 Swift 实现。

## 四、业务逻辑与规则

### 4.1 登录鉴权完整时序 ⭐（最关键）

#### A. WebView 注入态（A 包，主流程）
原生打开 WebView 时在 URL 上拼 `openParams`（AES 加密串）和 `appId`。

`openParams` 解密后结构：
```json
{ "token": "登录接口返回的token", "timestamp": "毫秒时间戳", "loginUuid": "系统返回的UUID" }
```

`App.vue → checkLogin()` 流程（`src/App.vue`）：
1. `tokenManager.getOpenParams()` 解析 URL（`src/utils/tokenManager.ts`）：
   - 有 `openParams + appId` → AES 解密；与上次缓存的 token 对比，**不同则 `localStorage.clear() + sessionStorage.clear()`**（换号清缓存）
   - 缓存 `appId`、`openParams` 到 localStorage，调 `setDeviceInfo()` 写设备信息
   - 无注入参数 → 走浏览器兜底：从 `webParams`（`loginUuid + AES_KEY + token` 拼接串）拆解出 token
2. 有 token → `isLogin()`：`clearWindowHistory()` → `getMineInfoData()`（拉主播信息）→ 按 `userType` 分流：
   - `userType === 2`（过审主播，isHost）→ `loginedFun()` + `router.replace('/')`
   - 非 9（代理）且非主播 → `router.replace('/newsRestricted')`（未过审受限页）
3. 无 token → 白名单判断：不在 `['/login','/register','/landingPage']` 内则 `logOut(false)` + `router.replace('/login')`
4. 同时按需 `getBagShopToken()` 换取背包商城 token

#### B. 邮箱登录（H5 兜底，`src/views/login/index.vue`）
1. 邮箱格式校验、密码≥8 位
2. **密码加密**：`MD5(MD5(password + appId)).toUpperCase()`（两次 MD5、最终大写，与安卓对齐）
3. 调 `hostlLogin('/api/login/v4/login')`
4. 成功：`userStore.loginSuccess(res)` → 按 `userType` 分流（2=主播首页，非9=受限页）→ `forcePageReload()`
5. 返回 `code === '1005'`（账号未注册）→ 跳 `/register` 进入注册流程

#### C. loginSuccess（`src/stores/modules/user.js`）
1. `tokenManager.setWebParams(res, VITE_APPID)`：缓存 `webParams = loginUuid + AES_KEY + token`、`appId`
2. `reload=true` → `forcePageReload()`（兼容 WebView，保留 openParams）
3. `reload=false` → `setMineInfo()` + `setIMAccount()`（设置云信账号并 `appStore.loginAfter()`）

#### D. loginAfter（`src/stores/modules/app.js`）
- 恢复会话缓存 → 数数 `ta.login(userId)` → 连接 IM(声网+云信) → 初始化云信 NIM → 启动用户心跳 → 5 秒后拉 banner/后管配置/客服/礼物/国家列表

#### E. 退出登录 logOut（`app.js`）
- 防重复（无用户信息直接 return）
- 备份并清会话缓存（保留 `deviceInfo-V2/cacheVersion/systemLanguage`）
- `sessionStorage.clear()` + 清空 `mineInfo/myAnchorInfo`
- **若在 WebView**：`window.flutter_inappwebview.callHandler('close', 'xxxx')`（通知原生关闭 WebView）
- **否则**：`window.location.reload()`

#### F. 业务错误码（响应拦截器 `src/utils/request/index.ts`）
| code | 含义 | 处理 |
|------|------|------|
| `0000` | 成功 | 返回解密后 result |
| `1004` | 被其他登录挤下线 | 提示后 2s `logOut()` |
| `1005` | 未登录/未注册 | 登录接口返回数据；其他接口提示并 `logOut()` |
| `1080` | 余额不足 | 返回 `{ isBalanceInsufficient: true }` |
| `2001/1992/1006` | 直播权限/封禁 | 返回 `{ code, message }` 交业务处理 |
| HTTP 401 | token 失效 | 提示（bagshop 实例会自动换 token 重试） |

> `appStore.reviewPassedDialogShowing` 为真时跳过自动 logOut，防止过审弹窗被后台轮询触发的 1004/1005 关掉。

### 4.2 请求加解密协议 ⭐

**两个 axios 实例**（`request/index.ts` 主接口、`request/sapiIndex.ts` 背包商城）：

请求拦截：
1. `baseURL` 按 url 前缀路由（`/api/`→主域，`/sapi/`→bagshop 域，见 `utils/token.js getConfig`）
2. 注入鉴权头（见五·JSBridge/Header 清单）
3. `Accept-Language` = 当前 i18n locale
4. **请求体加密**：`aesHexEncrypt(config.data)`（除非 header `closeAES=true`）。bagshop 用专属密钥 `VITE_AES_KEY_BAGSHOP_URL/IV`

响应拦截：
1. **响应体解密**：`aesHexDecryptAsync(res.data.result)` —— Web Crypto 异步解密(`crypto-async.ts`)，零阻塞；失败回退 crypto-js 同步(`crypto.js`)
2. bagshop 成功码为 `'200'`，主接口为 `'0000'`

**AES 算法细节（iOS 必须 1:1 对齐）**：
- 算法：AES-128-CBC，PKCS7 padding
- key/iv：16 字节 UTF-8 字符串。key/iv 由 `VITE_AES_KEY`/`VITE_AES_IV` 注入；iOS 不保留源码 fallback，重建以服务端受控配置为准。
- **加解密编码不对称（最关键陷阱）**：`crypto.js` 函数注释写"Hex 输出"但实际不是——加密侧 `aesHexEncrypt` 返回 `encrypted.toString()`，即 CryptoJS 默认 **Base64**（Hex 输出那行已被注释掉）；而解密侧 `aesHexDecrypt` 用 `enc.Hex.parse` 按 **Hex** 解析密文。因 key 以 WordArray 传入，CryptoJS 不加 OpenSSL `Salted__` 盐前缀，故加密输出是「裸 ciphertext 的 Base64」。即：**请求体（H5→服务端）密文是 Base64，响应体（服务端→H5）密文是 Hex**，两个方向编码不同。iOS 重建需分方向对齐——上行编 Base64、下行解 Hex（或与服务端确认统一）
- 解密输入：Hex 编码密文 → `CipherParams` → AES-CBC 解密 → UTF-8 → 优先 `JSON.parse`，失败返回原始字符串（如图片 URL）

### 4.3 token 管理（`src/utils/tokenManager.ts` + `utils/token.js`）

`TokenManager` 单例：
- `getToken()` / `getLoginUuid()`：从解析后的 `deOpenParams` 取
- `setWebParams(loginInfo, appId)`：登录/注册后缓存 `webParams`
- `getOpenParams()`：解析 URL openParams 或回退 webParams 缓存
- `setDeviceInfo()`：写 `deviceInfo-V2`（deviceType/deviceId/deviceNo/osType/osVersion）

**背包商城 token（`getBagShopToken`）**：
- 用 `loginUuid` 调 `/sapi/auth/v1/client/auth/exchangeToken` 换取 `BAGSHOP_TOKEN`
- 存 localStorage，记录过期时间戳 `bagshopTokenGetTimes = now + tokenTimeout*1000`
- bagshop 请求头带 `auth_token`；401 时自动换 token 重发

### 4.4 路由与权限拦截

- `src/router/index.ts`：`createWebHistory` + `unplugin-vue-router` 自动路由 + `setupLayouts` 自动包裹布局。**全局守卫已注释，无 beforeEach 拦截**。
- 权限拦截全在 `App.vue checkLogin()`（见 4.1）。
- 一级 tab 显隐：`default.vue` 中 `tabPathArray.includes(route.path)` 决定。
- tab 切换：`router.replace(path)`（Vant Tabbar `before-change`）。
- `keep-alive` 缓存：`src/layouts/keepAliveConfig.ts`。

### 4.5 i18n 与 RTL（`src/i18n.ts` + `main.ts`）

- `vue-i18n` legacy=false（Composition API）。支持 `en/ar/tr`，`fallbackLocale=en`。
- 英文 + Vant 英文包内置静态打包；ar/tr 业务包与 Vant 包**动态 import 按需加载**（`loadLocale`）。
- 语言检测 `detectLanguage()`：优先 `localStorage.systemLanguage`（值为 `auto` 视为无）→ `navigator.language`。
- `main.ts detectSystemLanguage()`：ar → `document.documentElement.setAttribute('dir','rtl')`；设置 `lang` 属性；非英文 fire-and-forget 加载语言包。
- RTL 适配：CSS 必须用逻辑属性（ms-/me-/pis-/pie-/inset-is-/inset-ie-）；模板里按 `$language === 'ar'` 切换左右箭头图标。
- 切换语言（`settings/language`）：写 `localStorage.systemLanguage` → `forcePageReload()` 强刷生效。
- 帮助函数：`isArLanguage()`、`setLanguageImg(imgObj)`（按语言选图，保底 en）。

### 4.6 网络监控（`src/stores/modules/networkMonitor.js`）

- 基于声网 SDK 的直播网络质量回调（等级 0-6）。
- 等级 ≥5（极差/断开）累计计数：≥10 次上报埋点 `c_log/networkBad`；达 `maxCriticalCount`(默认30) 触发强制关闭直播（`liveStore.isCompelLiveEnd = NETWORK_QUALITY`）。
- 可选弹窗警告（`config.showWarning` 默认 false）。
- 状态对外只读暴露，`startMonitoring/stopMonitoring/handleNetworkQualityChange`。

### 4.7 活跃度检测与前后台（`App.vue`）

- `useDynamicInactivityTimer`：监听 mousemove/keydown/touchstart/scroll，无操作超过 `max_no_use_app_reminder_time`（后管配置，分钟）→ 置 IM 离线 + 弹窗（多语言翻译）让主播点"Go online"恢复。
- `visibilitychange`：后台 → `appOnHidden=true` + 上报 app_end；前台 → 重连 NIM + 上报 app_start + 按需刷新 bagshop token。
- 通话/直播/相机异常时停止活跃检测。

### 4.8 版本强刷 + Service Worker（`main.ts`）

- `forceReload()`：`packageJson.version !== localStorage.cacheVersion` 且无 query 参数时，追加 `?forceRefresh=true&v=版本` 强刷。
- SW（vite-plugin-pwa）：发现新版本弹"Update now"确认后强刷；激活时清理旧缓存（保留 `static-v*` 和 `html-cache`）。

### 5.3 JSBridge / 原生交互方法清单 ⭐（iOS 必读）

H5 与原生的双向通信通道**有限且明确**，三套写法对应三类容器：

#### H5 → 原生（调用原生方法）
| 业务 | Flutter (WebView) | iOS (WKWebView) | Android | 触发位置 |
|------|-------------------|------------------|---------|----------|
| 充值/支付 | `flutter_inappwebview.callHandler('recharge', batchNo)` 与 `callHandler('rechargePay', { batchNo, orderCode })` | `webkit.messageHandlers.Pay.postMessage(batchNo)` 与 `messageHandlers.rechargePay.postMessage({ batchNo, orderCode })` | `window.android.recharge(batchNo)` | `stores/modules/gift.js` |
| 关闭 WebView（退登） | `flutter_inappwebview.callHandler('close', 'xxxx')` | — | — | `app.js logOut()` |

> **原生 iOS 必须实现的 messageHandlers**：`Pay`、`rechargePay`。`close` 目前只在 Flutter 分支处理，iOS 重建若用 WKWebView 包 H5 需补 `close` handler；若是纯原生重建则等价于「关闭支付页/退出账号」原生动作。

#### 原生 → H5（注入数据）
- **唯一注入通道**：启动 URL 上的 `openParams`（AES 加密的 `{token,timestamp,loginUuid}`）+ `appId`。无其它原生主动调 JS 的回调。

#### 外部跳转（非 JSBridge，走浏览器/系统）
- 用户协议/隐私政策：`window.open(url, '_blank')`（`settings/config.js` 的 userAgreement/privacyPolicy 外链 `https://h5.livehot.site/#/agreement|privacy`）。

#### 容器判定
- `window.flutter_inappwebview` 存在 → A 包/Flutter 容器（安全区按 -180 计算，见 `callApi.ts`）。
- `getPlatformType()`：UA 判 ios/android。

## 七、边界与异常处理

1. **换号清缓存**：openParams 中 token 与缓存不同时全量清 localStorage/sessionStorage（`tokenManager`）。iOS 需对应：检测注入 token 变更则清本地用户态。
2. **WebView 刷新丢参**：H5 用 `forcePageReload()` 把 openParams/appId 拼回 URL 才能刷新不掉登录。iOS 原生无此问题，但要注意 token 持久化策略。
3. **解密降级**：Web Crypto 不可用（非 secure context）回退 crypto-js，仅上报一次埋点。iOS 用统一 CryptoKit，无降级问题。
4. **被挤下线(1004)/未登录(1005)**：自动提示并 logOut。注意 `reviewPassedDialogShowing` 期间跳过。
5. **过审弹窗竞态**：后台轮询触发的 logOut 会被审核通过弹窗拦截。
6. **bagshop 401 自动续 token**：换 token 后关闭加密(`closeAES=true`)重发，避免二次加密。
7. **OSS 上传超时**：10s 超时 race；多文件 `allSettled`，部分失败移除失败项并提示。
8. **注册校验**：头像必填、昵称≤15、生日(1970~今)、国家必选、语言 1~4 个、照片≥6 张。
9. **全局错误兜底**（`main.ts`）：Vue errorHandler + window.error（含资源加载失败）+ unhandledrejection，统一上报 `c_log/global_error`，5s 去重 + 长度截断。
10. **受限态文案分支**（`mineRestricted`）：按 `valid`(0封禁/1正常) + `type`(2主播/9代理) + `onReview` 渲染不同审核状态文案与重提按钮。

## 八、iOS 重建注意事项

1. **鉴权是重建的第一块硬骨头**：原生登录拿到 `{token, loginUuid}` 后，所有请求头注入 `loginToken/anchorToken=token`、`appid`、设备信息、网关 key、`version`。务必与 H5 完全一致，否则服务端鉴权失败。
2. **AES 加解密必须逐字节对齐**：AES-128-CBC、PKCS7、16 字节 UTF-8 key/iv。**编码分方向**：上行请求体密文为 Base64（`encrypted.toString()` 默认输出，无 OpenSSL 盐前缀），下行响应体密文为 Hex（`enc.Hex.parse` 解析）——这是最易踩坑处，重建前务必与服务端确认两方向编码。主接口与 bagshop 用不同密钥（env 注入，非硬编码默认）。
3. **密码加密链路**：`MD5(MD5(password + appId)).uppercased()`，两次 MD5 且最终大写。
4. **双 token 体系**：主 token（loginToken）+ bagshop token（auth_token，需 `loginUuid` 换取、有过期时间、401 自动续）。
5. **JSBridge 在原生重建中"消失"**：H5 的 `recharge/rechargePay/Pay/close` 都是 H5→原生的调用，原生重建里直接是原生函数调用即可。重点是把支付（Airwallex/原生内购）和退出登录逻辑接好。
6. **权限分流逻辑要还原**：`userType===2`→主播全功能；非主播/未过审→受限页（仅 news + mine）；`userType===9`→代理弹窗。底部 tab 与首页顶部 tab 都随等级/权限变化。
7. **首页顶部 tab 顺序按等级变化**：S 级 `Live/List/Match/Circle`，A 级及以下 `List/Match/Live/Circle`。
8. **RTL 必做**：阿拉伯语整体镜像，原生用系统 RTL 布局 + 资源左右镜像；语言切换需重启/刷新生效。
9. **设备分档与重型 SDK 懒加载**：H5 把美颜/音视频/IM 全部动态加载以保首屏；iOS 同样应延迟初始化美颜与音视频，登录后再连 IM。
10. **活跃度检测**：长时间无操作自动置离线并弹窗恢复，超时时长来自后管 `max_no_use_app_reminder_time`，原生需复刻。
11. **网络质量强制断播**：连续极差（≥5 级）达阈值自动结束直播，原生基于 Agora 网络回调实现。
12. **后管配置驱动**：大量行为（翻译 key、隐藏按钮、PK 参数、私聊超时、活跃提醒时长）由 `getConfigByKey` 拉取，原生需建对应配置拉取与缓存机制。
13. **OSS 直传**：客户端用 STS 临时凭证（`/sts/getkey`）直传阿里云 OSS，图片先压缩；文件名 `时间戳.ext`。私密视频访问需 `/sts/getPrivateOssUploadParam` 拿签名拼最终 URL。
14. **Apple/Google/Facebook 登录后端就绪、前端未接**：API 已定义（`/api/login/ios|google|facebook`），iOS 重建可直接对接第三方登录调这些接口（这是当前 H5 缺失、原生该补齐的能力）。
