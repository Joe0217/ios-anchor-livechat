## 一、模块概述

本模块承担主播端的全部即时通讯能力，分两条独立通道：

1. **云信 NIM（nim-web-sdk-ng 10.7）**——主力 IM 通道，承载：
   - P2P 单聊（文本/图片/视频/音频/文件/自定义）
   - 系统通知消息（`sysMsg`，按 `attachType` 分发到业务逻辑）
   - 会话列表、未读数、会话云端扩展字段（`cloudSession.ext`，用于 Flame/Stranger 分类与跨端同步）
   - 通知聊天室（`imNoticeChatRoom`，独立 NIM ChatRoom 实例，承载全站活动中奖广播 attachType=140）

2. **Agora RTM（agora-rtm 2.1.10）**——**仅用于音视频通话期间的点对点信令**（呼叫控制、通话内实时消息），不参与聊天会话列表。RTM 消息经 `encodeUint8Array/decodeUint8Array` 二进制收发，通过 `CallRtmMessageManager`（继承 `CallMessageManager`）发射 `messageReceive` 事件。

> 注意：通话内的「礼物 / 每分钟收益 / 挂断」等也会经 NIM `sysMsg`（attachType -1/4/15/18/-3 等）下发，与 RTM 信令是双通道并存关系。

会话分类（顶部三 Tab，见 `src/views/news/topTabList.ts`）：
- **Flame**：已建立关系的用户（主播关注/双向互动/收过礼/接听过通话）
- **Prime**：Prime 等级达标用户（后端 `apiBatchQueryYxPrimeFilter` 过滤）
- **Stranger**：陌生人（不在 Flame 中）

## 三、功能点清单

1. NIM 初始化、登录鉴权、断线重连、事件绑定（`initNim`）
2. 在线消息接收（`onMsg`）：单条实时处理
3. 离线/漫游消息批量构建（`onOfflineMsgs` / `onRoamingMsgs` → **throttle(leading=true) 2000ms** 节流批处理 + 去重，立即触发首条 + 周期聚合，`message.js:470` `useThrottleFn(..., onceMsgTime=2000, true)`）；会话列表更新用 **debounce 2000ms** 尾部触发（`session.js:314` `useDebounceFn(..., onceSessionTime=2000)`）。iOS 不要混淆两套策略——离线消息要「立即+聚合」,会话更新要「等用户停手再统一刷新」
4. 系统消息分发（`onSysMsg`，按 attachType 30+ 分支）
5. 离线系统消息批量同步（`onSyncSysMsgs`，仅累加关注数）
6. 发送：文本（`sendTextMsg`）、图片/视频（`sendImageMsg/sendVideoMsg`）、音频（`sendAudioMsg`）、文件（`sendFileMsg`）、自定义系统消息（`sendImMsg` → `sendCustomSysMsg`）
7. 重发失败消息（`resendMsg`）、已读回执（`setReadMsg`/`sendMsgReceipt`/`onReadMsg`）
8. 进入聊天页按需拉云端历史（`loadHistoryMsgs` → `msgLog.getHistoryMsgs`），三态返回
9. 会话列表构建/合并/排序（`onSessions`/`onUpdateSession`/`batchUpdateSessionList`）
10. 会话未读数管理与重置（`resetSessionUnreadCount`）
11. 会话云端扩展标记（Flame/Stranger 分类：`received`/`sended`/`receivedGift`/`called`）
12. 置顶会话（裂变消息 `pinMsgObj`/`pinMsgList`，到期自动取消 `autoCancelPinMsg`）
13. 付费消息体系（`msgType` free/pay，进度累加）
14. 回复积分结算（`apiSettleReplyPoints` + `im_anchor_reply` 埋点）
15. 私密图片/视频消息（`extensionType=privateMsg`，`lockStatus` 锁定态校验）
16. 客服消息本地缓存（`adminChatCache`，30 天/100 条）
17. 裂变消息（`weakTxtType` 103/104）、USDT 支付状态消息
18. 主播名片与在线状态订阅（`subscribeEvent`/`onPushEvents`，LRU 上限 100）
19. IM 会话画像（`conversationProfiles`：关注/活跃大R）
20. 群发消息（`apiBatchSendMsgToUser`/`apiBatchSend`）
21. 假用户来电/结束（attachType 133/132）
22. 通知聊天室活动中奖广播（attachType 140）

## 四、业务逻辑与规则

### 4.1 NIM 初始化与登录鉴权时序（`app.js`）

```
登录成功 → loginAfter()
  ├─ restoreSessionOnLogin()        // 恢复当前账号会话缓存（useSessionCache）
  ├─ ta.login(userId)               // 数数埋点登录
  ├─ imConnect()                    // 加载并初始化 CallApi（声网 RTC，懒加载）
  ├─ messageStore.sessionMsgs = {}  // 重置会话消息（sessionMsgs 不持久化）
  ├─ initNim()                      // 初始化云信
  ├─ useUserHeartbeatState()        // 用户心跳
  └─ setTimeout(5s){ banner/config/客服列表/礼物列表/国家列表 }  // 非关键配置延后
```

`initNim()` 关键步骤：
1. `await loadAllNimWrap()` / `loadNimWrap()`——动态 import NIM SDK（首屏不加载）
2. 4s 兜底定时器：超时强制 `sessionLoading=false`，避免会话 loading 卡死
3. `nimWrap.getInstance({ appkey, account: yxAccid, token: imToken, debug:false, quickReconnect:true }, { syncOptions:{stickTopSessions:true}, sessionConfig:{ unreadCountFilterFn } })`
   - **鉴权三要素**：`appkey`(setting.appkey) + `account`(云信 accid = yxAccid) + `token`(imToken)。token 来源见原生集成事实文档（开播 token/鉴权头）。
   - `unreadCountFilterFn(msg)`：`msg.flow !== 'out' || msg.from !== APPID`——自己发出的不计未读。
4. 先 `nim.off(...)` 解绑全部事件再 `nim.on(...)` 重绑（防重连重复绑定）
5. `await nim.connect()`——建立长连接
6. `getImNoticeRoomIdAndAddress({searchValue:2})` → `joinImNoticeChatRoom()`——加入通知聊天室
7. `sessionLoading=false; sessionLoadSuccess=true`

**事件绑定表**（`nim.on`）：

| 事件 | 处理函数 | 所属 store |
|------|----------|-----------|
| `logined` | `onConnect`（置 IMOnline=true，PK 状态同步） | app |

### 4.2 在线消息处理 `onMsg(msg)` 完整链路

按代码顺序：
1. `updateActiveTycoonFromMsgExt`——解析 `ext.activeTycoon`，写入 `conversationProfiles`/`userProfiles`（活跃大R 状态，DM-20260429-002）
2. `addAdminMsgToCache`——若收发方含客服 accid，存入 `adminChatCache`（30 天/100 条/去重 idClient）
3. `formatSecretData(msg)`——`ext`/`ext.data` 字符串 → JSON.parse；删除 `pushInfo`/`setting`
4. **裂变消息**：`type==='tip' && ext.weakTxtType` → 创建/更新 `pinMsgObj[from]`（isPin/isRecharge/createTime/topExpireValue），103=已充值，未存在则 `pushPinMsg` 置顶
5. **USDT 支付**：`ext.usdtPayStatus===true` 且 `usdtOrderNo` 匹配当前订单 → `usdtPayStatus=1` + 刷新用户信息 + `handleUsdtPay()`；`false` 则清空挂起支付数据
6. **聊天页内未读处理**：当前在 `/chat` 且 URL 含 `msg.from` → `resetSessionUnreadCount` + `handlePayMsg`（礼物消息跳过）；半屏聊天同理
7. **客服页**：在 `customer-talk` 且 from===客服 → 重置未读
8. **弹窗提醒**：满足条件（非系统业务消息、非排除路由 talk/paystatus/getcoin/match/forcePay、非自己、非通话中、`liveState` 为真）→ `useNoticeFunc`（2s 节流，attachType=70 推荐主播显示 `[Host Recommend]`）
9. **私聊收消息埋点**：在 talk 页且非系统/客服 → `getUserDetail` 后 `ta.track('msg_send_recive')`
10. `addMsgToMsgArr(msg)`——入会话消息队列
11. `markAnchorReceivedIfNeeded` / `checkAndMarkGiftMessage`——Flame 分类标记
12. **朋友圈**：`ext.extensionType==='friendMsg'` → 刷新朋友圈关注列表

`addMsgToMsgArr`：补 `chatBubble`（聊天气泡，优先 `ext.chatBubble`，兜底 `serverExtension.chatBubble`）→ push 到 `sessionMsgs[sessionId].msgArr` → 超 200 条裁剪保留最近 → `markAnchorSendIfNeeded`。

### 4.3 离线/漫游批量处理

`onRoamingMsgs`/`onOfflineMsgs` → push 到模块级 `_tmpMsgList` → `batchUpdateFunc`（**throttle(leading=true)，2000ms**，立即触发首条 + 周期聚合，`message.js:470`）→ `batchUpdateMsgList`：
- 对每条消息 `formatSecretData` + `updateActiveTycoonFromMsgExt` + 补 `chatBubble`
- **同 sessionId 在同批次可能多次出现**（漫游 vs 离线属不同事件）→ 在已累积结果上**追加而非覆盖**
- 用 `Set(idClient)` 做 O(1) 去重；`idClient==null`（部分 tip/系统消息）不参与去重直接 push
- 各会话超 200 条裁剪
- `Object.assign(sessionMsgs, newObj)`

`onSyncSysMsgs`：仅遍历，`attachType===-4` 累加 `followNum`（轻量，无需弹窗）。

**throttle 与 debounce 使用位置对照表（iOS 复刻必须严格区分）：**

| 文件:行号 | 触发入口 | API | 间隔 | 策略 | 用途 |
|-----------|----------|-----|------|------|------|
| `message.js:464-470` | `onRoamingMsgs`/`onOfflineMsgs` 喂入 `_tmpMsgList` | `useThrottleFn(fn, 2000, true)` (leading=true) | `onceMsgTime=2000ms` | 节流 + 首次立即触发 | 离线/漫游消息批量入会话消息队列：首条立即处理给用户即时反馈，后续 2s 内同步抵达的消息聚合成一批 |
| `session.js:314-319` | `onUpdateSession` 喂入 `_tmpSessions` | `useDebounceFn(fn, 2000)` (默认 trailing) | `onceSessionTime=2000ms` | 防抖 + 尾部触发 | 会话列表合并/排序/未读重算：等 2s 内无新增 session 再统一刷新，避免开播/连发场景下抖动 |
| `session.js:583` | Prime 等级增量拉取 | `useDebounceFn(..., 500)` | 500ms | 防抖 | 用户 update 累积 500ms 后批量调 `apiBatchQueryYxPrimeFilter` |
| `session.js:716` | `userProfiles` 拉取 | `useDebounceFn` | — | 防抖 | 缺失名片时合并查询 |
| `message.js:237` | 弹窗提醒 `useNoticeFunc` | `useThrottleFn(..., 2000)` | 2000ms | 节流 | 在线消息满足条件时弹站内通知,2s 内仅一次 |

iOS 复刻误区：把 `_tmpMsgList` 也改成 debounce 会丢首条即时性；把 `_tmpSessions` 改成 throttle leading 会在连发 session 时反复 reflow 会话列表，体验劣化。两套策略的差异是有意设计，不可统一。

### 4.5 发送消息封装

| 类型 | 方法 | SDK 调用 | 关键 |
|------|------|----------|------|
| 文本 | `messageStore.sendTextMsg(body, to)` | `nim.msg.sendTextMsg({scene:'p2p', to, body, ext})` | ext 透传主播 `chatBubble`；成功后 `msgAfterIntegeral(type:6)` + `trySettleReplyPoints` |
| 图片 | `sendPicture(item, type)` | `nim.msg.sendImageMsg` | 普通照片 ext=''；私密 ext=`{data, extensionType:'privateMsg'}` |
| 视频 | 同上 | `nim.msg.sendVideoMsg` | 私密走 `getSendPrivateInfo`，埋点 primsg_send_suc |
| 音频 | `sendAudio` | 先 `cloudStorage.uploadFile(type:'audio')` 再 `sendAudioMsg({attach:{url,dur}})` | |
| 文件 | `sendFile` | `sendFileMsg`/`sendImageMsg` | |
| 自定义系统消息 | `messageStore.sendImMsg(yxId, attach)` | `nim.systemMessage.sendCustomSysMsg({type:'customP2p', to, attach:JSON.stringify, pushInfo, setting:{isRoutable:true}})` | |
| 重发 | `resendMsg(tempMsg)` | `nim.msg.resendMsg({msg})` | |

**发送态机**：`onSendBefore` 回调拿到 tempMsg（先插入列表占位）→ 成功后 `addMsgToMsgArr(res)` 覆盖。失败处理：`err.error.code==='No_connected'` → 置 `sendFailed` + Notify 网络提示；`err.code===7101`（被拉黑/拒收）→ 置 `refused`。

**群发**：`apiBatchSendMsgToUser` / `apiBatchSend`（后端批量下发，非 SDK 直发），剩余次数 `apiGetAnchorDailySendCount`，文案 `apiGetCopywriting`。

### 4.6 已读回执

- `setReadMsg('all'|'current', msg)`：找会话最后一条**非 tip 类、非自己发**的消息 → `nim.msg.sendMsgReceipt({msg})`。过滤的 tip 类型：`guideTip/stimulateTip/replyPointTip/replyRemindTip/replyPointGuideTip`。
- `onReadMsg(msg[])` → `setOtherAllRead`：把自己发出且非 receipt/sendFailed 的消息状态置 `receipt`。

### 4.7 会话列表/未读/排序

- `onSessions(arr)`：取前 200 → `syncCloudSessionExtData`（拉云端 `cloudSession.ext` 写入本地 `session.extra`）→ `batchUpdateSessionList(_, 'init')`
- `onUpdateSession(session)`：`newMsg=true`；无 lastMsg/updateTime 则删除会话；`checkAndMarkGiftReceived` + `syncSessionExtIfNeeded`（从云端补 ext 标记，处理「先通话后首条消息」场景）→ push `_tmpSessions` → `batchUpdateFunc`（**debounce 2000ms 尾部触发**，`session.js:314` `useDebounceFn(..., onceSessionTime=2000)`，等用户停手再统一刷新，区别于消息侧的 throttle leading）
- `batchUpdateSessionList(arr, handleType)`：格式化 → `mergeArrays`（按 id 去重，智能合并 unread/updateTime/extra/lastMsg；系统会话保留旧未读）→ `getOrderedSessions`（按 updateTime 倒序）→ 累加 `homeStore.unReadMsgCount` → 更新 Prime 列表（update 增量 500ms debounce / init|pull 全量）→ 计算三 Tab 未读 → `newsStore.updateUnreadQuantity`
- 排序：`orderedSessionsSortByPin` = 过滤系统/客服会话后，把 `pinMsgList` 中的会话移到头部
- 重置未读：`resetSessionUnreadCount(user)` → `nim.session.resetSessionUnreadCount({id:'p2p-'+user})`
- 最大会话数 200，最大单会话消息 200。

### 4.8 Flame/Stranger 会话分类（云端 ext 标记）

通过 `nim.cloudSession.updateCloudSession({sessionId, ext})` 把标记持久化到云端（跨端同步，与安卓字段一致），读取 `session.extra`（= 云端 ext）。标记字段单调置 true：

| 字段 | 触发 | 标记方法 |
|------|------|----------|
| `received` | 主播收到用户消息 | `markAnchorReceived` |
| `sended` | 主播发出消息（flow=out, p2p-） | `markAnchorSended` |
| `receivedGift` | 收到礼物（attachType=SEND_GIFT 等） | `markGiftReceived` |
| `called` | 完成过通话（CALLING_ING 结束） | `markCallCompleted`（由 `useCallApi.checkAndMarkCallCompleted` 调用） |

**Flame 判定**（`checkSessionExtraIsFlame`）：`receivedGift===true` 或 `called===true` 或 `(received && sended)`，或主播已关注该用户（`sessionFlameUserIdList`）。Stranger = 非 Flame。

**性能优化**：模块级 `markedReceived/Sended/Gift/Called` Set 做「只增不减」缓存，命中即跳过云端 query，消除每条消息的冗余请求。退登/切号时 `resetSessionMarkerCache()` 清空；删除会话用 `forgetSessionMarker`。

`isGiftMessage` 判定（多重）：`type==='custom'` 且 `attach.attachType==='SEND_GIFT'`（或 `attchType==='gift'`/`attach.type==='gift'`）；或 `ext.type/messageType==='gift'`/`ext.isGift===true`；或 body 含 `[Gift]`。

### 4.9 置顶/裂变到期

裂变消息（weakTxtType）置顶进 `pinMsgObj[from] = {isPin, isRecharge, createTime, topExpireValue}`。`autoCancelPinMsg`：未过期保留；过期但已充值保留；过期且未充值移除。`handleInviteUserRecharge` 在 attachType=35 时把对应裂变用户置 isRecharge=true。

### 4.10 付费消息与回复积分（`chat.js` + `message.js`）

- 进入聊天页 `getPaidMessagePoints`(`pay_msg_points`) / `getFreeMessagePoints`(`free_msg_points`)
- `handlePayMsg(msg)`：当前聊天用户、开启付费体系时 → `currentUserSendPaidMessageCount++`；按 `ext.msgType`（free/无 → +freeMessagePoints；pay → +paidMessagePoints）累加 `currentProgress`；`setLastUserMsg(msgId, time, msgType, isGift)`
- `trySettleReplyPoints(to)`：主播发消息成功后调 `apiSettleReplyPoints({userYxAccid, userMsgId, msgType})`；`settled` 则更新 `currentProgress=currentTotalPoints`、清提醒计时器、置 hasHistoryReply；最后触发 `im_anchor_reply` 埋点（携带 reply_points）。礼物消息/未开付费体系不结算。
- 30 分钟会话轮次：`getOrCreateChatDepthSession`（用于 `chat_session_depth` 埋点）。

### 4.11 私密消息（`extensionType=privateMsg`）

发送：图片/视频走 `getSendPrivateInfo`，ext=`{data:{...privateId, lockStatus, iconType, videoUrl, userId}, extensionType:'privateMsg'}`。
接收/渲染（`chat/index.vue` + `msgItem.vue`）：进页面收集所有 `ext.data.privateId` → `apiCheckPrivateInfo` 批量查锁定态 → 回填 `ext.data.lockStatus`（0=锁定显示锁图标，1=已解锁）。

### 4.12 在线状态/名片/画像

- 在线状态订阅：`nim.event.subscribeEvent({type:1, accounts, subscribeTime:2592000, sync:true})`；本地 `subscribedAccounts` Set 维护 LRU，上限 100，超限 `unSubscribeEvents` 淘汰最旧。
- 推送：`onPushEvents` → 把 yxAccid 映射回 userId 写 `onLineStatusMap`。
- 名片：`updateUserProfiles`（`apiBatchQueryYxStat`/`apiBatchQueryYxStatByUid`，100/批）；getter `getOnlineStatus(userId)` 缺失时 1s debounce 触发拉取。
- IM 会话画像：`updateConversationProfiles`（`apiBatchConversationProfile`，关注/活跃大R），in-flight 去重。

### 4.13 用户心跳与主播在线态

云信长连接负责消息通道，主播自身「在线/通话/前后台/勿扰」等运行态由独立的心跳 WebSocket 上报，与 IM 通道并行存在。源码：`src/use/useUserHeartbeatState.js` + `src/constant/live.ts` 的 `LIVE_STATUS_NUMBER` + `src/utils/index.js` 的 `getStatusName`。

- **连接地址**：`config/index.js` 的 `socketUrl`，正式 `wss://ask.hily.link/webSocket`、测试 `wss://api.seain.site/webSocket`。
- **握手参数**：URL query `?ciphertext=encryptAes(JSON.stringify({ appToken: loginUuid }))`。该加密走专属算法（AES-128-ECB + 环境配置的独立 key + Hex 输出），与请求体 AES-CBC 完全不同，iOS 必须按此算法单独实现。
- **上行报文**：`{ requestId: deviceId, messageType: 1, expandParams: { channelId, onlineStatus } }`，5000ms 间隔定时上报。
- **自动重连**：retries 720 次、delay 5000ms；非直播/通话状态下连续失败 > 6 次 → 置 `IMOnline=false` + 弹窗提示 + 停定时器。
- **批量更新用户状态节流**：直播态每 6 次（30s）、普通态每 2 次（10s）触发一次 `sessionStore.timingUpdateUserState()`；通话中不触发。

`LIVE_STATUS_NUMBER` 是心跳上报的 `onlineStatus` 取值集合，与安卓对齐、刻意用大数避免与主状态冲突：

| 常量 | 值 | 含义（对应主播主状态） |
|------|-----|----------------------|
| `ONLINE` | 1 | 在线（主状态 1） |
| `OFFLINE` | 2 | 登出（主状态 3） |
| `DISCONNECT` | 3 | 断链（主状态 3） |
| `CALLING` | 10000 | 通话中（主状态 2） |
| `CALL_END` | 10001 | 通话结束（主状态 1） |
| `FOREGROUND` | 10002 | 回到前台（主状态 1） |
| `BACKGROUND` | 10003 | 退到后台（主状态 2） |
| `DO_NOT_DISTURB_MODE_OPEN` | 10004 | 开启勿扰（主状态 2） |
| `DO_NOT_DISTURB_MODE_CLOSE` | 10005 | 关闭勿扰（主状态 1） |
| `ON_MATCH_MODE` | 10006 | 匹配模式（主状态 1） |

**关键状态推导逻辑（`getOnlineStatus`）**：美颜未初始化完成 → 强制返回 `CALLING`（忙碌）；通话中或 `waitingReturnLive` → `CALLING`；否则按 `IMOnline` 返回 `CALL_END` / `BACKGROUND`。

**在线态反查**（`utils/index.js` 的 `getStatusName`）：后端列表 status → 前端文案的归类（与上面枚举不同的归类口径）：
- `online`：`[1, 10001, 10002]`
- `busy`：`[10000, 10003]`
- `offline`：`[2, 3]`
- 有 `liveUrl` 一律返回 `'live'`（优先级最高）

## 七、边界与异常处理

- `ext`/`ext.data`/`session.lastMsg.ext` 均可能是字符串或对象，使用前必须 try-parse（`formatSecretData`/`safeParseJSON`），畸形 JSON 保留原值不中断链路。
- 离线/漫游同批次同会话多事件 → 必须**追加合并**而非覆盖；`idClient==null` 不去重。
- 单会话消息上限 200、会话数上限 200，超出裁剪最近。
- 发送失败：`No_connected`→sendFailed+网络 Notify；`7101`→refused（被拒收）。
- 云端会话标记：首条消息时云端会话可能不存在（query 抛错正常忽略），update 成功后才写本地缓存，失败下条消息重试。
- `loadHistoryMsgs` 三态：`loaded`/`empty`（确无历史，提示过期）/`unavailable`（未登录或拉取失败，不提示，避免误报）。
- 退登/切号：`resetTempState`（清模块级临时数组、debounce 累积器、订阅 Set）+ `resetSessionMarkerCache`，避免上一账号数据污染。
- 在线状态订阅 LRU 上限 100，超限取消最旧订阅释放额度。
- 弹窗节流 2s、批处理节流/防抖 2s，避免一次性大量离线消息刷屏。
- 审核通过（58）需先置 `reviewPassedDialogShowing` 让 axios 拦截器跳过自动登出，否则旧 token 失效会被立即踢出 webview。

## 八、iOS 重建注意事项

1. **双通道分清**：聊天会话/系统通知 = NIM；通话信令 = Agora RTM。RTM 消息是 `Uint8Array` 二进制（UTF-8 编解码），iOS 需对齐 `encode/decodeUint8Array` 编码格式。
2. **云端会话扩展（cloudSession.ext）是 Flame/Stranger 分类的唯一可信源**，与安卓字段严格一致（`received/sended/receivedGift/called`），iOS 必须复用同字段名，否则三端分类不一致。建议同样实现「已标记缓存」减少 query/update 调用。
3. **离线/漫游消息合并去重**逻辑（同 sessionId 多事件追加、idClient 去重、null 不去重）是踩坑点，iOS 用 NIM 原生回调时要复刻。
4. `sessionMsgs` 不持久化、登录清空——iOS 进会话页需用 `getHistoryMsgs` 按需补历史（三态判断）。会话列表（sessionMap/orderedSessions）持久化以保留 7 天外旧会话。
5. **ext 字段约定要登记**：除规范已列字段，代码新增了 `chatBubble`（聊天气泡）、`activeTycoon`（活跃大R），以及自身回显的 `serverExtension`。iOS 渲染气泡需同时兼顾 ext / serverExtension 两个来源。
6. **私密消息**：发送时 ext 带 `privateMsg`，渲染前需批量 `checkPrivateInfo` 拉锁定态回填 `lockStatus`，iOS 需保持「先查锁态再渲染」时序。
7. **付费消息/回复积分**：`msgType`(free/pay) 决定积分增量；主播回复后 `settleReplyPoints` 结算并埋点 `im_anchor_reply`，礼物消息不参与。
8. **attachType 分发表庞大且分散**（本 store 30+ 分支，另有 live.js/PK store 处理 50/56/97-100/-9 等）。iOS 应建统一分发器，并把通话内（-1/4/15/18/-3/-6/90）、直播（61/62/44）、假人（132/133）、审核（58）、裂变（103/104）、充值（35）等按域拆分 handler。
9. **客服消息**走本地 `adminChatCache`（30 天/100 条，按 userId 分桶）而非 NIM 会话列表，iOS 需本地持久化缓存。站内信未读恒为 1（产品约定）。
10. **登录鉴权时序**：connect 前先 off 再 on 防重复绑定；4s 会话 loading 兜底；非关键配置延后 5s。iOS 重连后需同步 PK 状态。
11. **在线状态订阅** subscribeTime 30 天、type=1、LRU 100，iOS 同样要做订阅额度管理（云信总上限 3000）。
12. 通知聊天室（imNoticeChatRoom）是独立 NIM ChatRoom 实例，仅直播态解析 attachType=140，iOS 按需懒加入。

### 9.1 全局消息弹窗与横幅（g-message-notice / TipsDialog）

应用内消息横幅是「来消息时不打开聊天页也能看到提示」的全局通道，分两层：命令式动态挂载控制器 + 横幅 UI 组件。

**命令式动态挂载（TipsDialog）**

- 源码：`src/components/function/notice.ts`，被 `src/stores/modules/message.js` 第 7/239 行 `Notice({ data: msg })` 调用。
- 用 `createApp().mount()` 把消息横幅动态挂到 `document.body`，不走 Vue 模板渲染，便于消息侧任意时机命令式触发。
- **前置门槛**：`homeStore.forcePayConfig?.isFinished` 为真才弹，否则返回空字符串（强制支付流程未结束时不打扰）。

- `remove()` 回调负责 `app.unmount()` + 从 body 移除节点。

**消息横幅 UI 与交互（g-message-notice）**

- 源码：`src/components/g-message-notice.vue`。
- **5s 自动关闭**（`setTimeout` 5000ms）→ 暂停音频 + 从 `noticeMountNodes` 过滤移除 + 调 `remove()`。
- **拖拽消失**（`useDraggable`）：X 轴锁定为 35；Y 轴向上拖过 `-20` 触发 `remove()`，向下不超过初始 `top`。
- **错落堆叠**：`top = (本条在 noticeMountNodes 中的索引 * 10 + 20)`，多条依次下移。

### 9.5 私密媒体（照片/视频付费消息）上传与解密

私密媒体是付费消息体系的关键载体（图片/视频两类），数量上限与解锁价格由后端配置，上传走 OSS 私有 ACL + STS 临时凭证，下行二次签名解密。

**主页（secretSettings）**

- 源码：`src/views/secretSettings/index.vue`。
- 数量上限接口 `privatePicNum` → `privateNum` / `privateVedioNum`（默认各 3）。
- 进页拉取 `privateInfo`：按 `iconType`（1 图 / 2 视频）分组；视频需逐个解密（`getFinalUrl` → `getPrivateOssUploadParamApi({searchValue})` → `${cdnUrl}/${fileUrl}?${authorizationParam}`），`Promise.all` 等全部解密完才渲染（videoLoading）。
- **提交 diff 算法**：对比原始数组与当前数组——删除项标 `removePrivate=true`；未改动项带 `id`；新增项不带 `id`。图片字段 `picList`+`iconType:1`，视频字段 `videoUrl`+`iconType:2`，均带 `giftId`。
- 每张图/视频上传后弹礼物选择弹窗（GiftsPopup type='IM'，不选数量），绑定 `giftId`/`giftPrice` 作为解锁价格。

**上传组件（含 OSS 私有 ACL + 解密）**

- 源码：`src/views/secretSettings/components/uploadVideo.vue`（图片版 `uploadImg.vue`、封面 `uploadCover.vue`）。
- `ali-oss` 动态 import；`getOssKey` 取 STS 临时凭证，`parseOssHost` 解析 bucket/region。
- 图片直传公共读；**视频上传带 `x-oss-object-acl: private`（私有）**，上传后调 `getPrivateOssUploadParamApi({search})` 拿 `authorizationParam` 拼最终可访问 URL。
- 文件名 `${Date.now()}.${ext}`。
- 删除前 `checkUploadPrivateInfo({picList})` 校验是否可删。
- 视频预览走 `CVideoPlayer` 全屏；封面 `uploadCover` 叠加钻石解锁价标。
- iOS 复刻要点：OSS 私有 ACL + STS 直传 + 二次解密签名是完整链路，与公开图片不同；解密 URL 有时效（authorizationParam）；上传与列表渲染需等待全部解密完才展示，避免一闪而过。
