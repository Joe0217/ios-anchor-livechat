# iOS WebView 页面复用设计

## 决策

iOS WebView 不再维护 Anchor Guide、Wallet、Invite 的独立页面副本，直接复用 `anchor-livechat-h5` 的现有路由：

| 功能 | H5 路由 |
| --- | --- |
| Anchor Guide | `/anchorGuide` |
| Wallet | `/wallet` |
| Invite | `/invite` |

Wallet 页面内原有的提现、收款账户和提现记录路由继续由完整 H5 自己处理；iOS 不以 `/wallet/withdrawal` 作为初始入口。

## 认证

完整 H5 通过 `window.App.getAppParams()` 取得运行时上下文，其中 `apiToken` 为当前原生登录会话的主接口 token。iOS 仅在精确受信任 origin 的主框架注入该 Bridge。

```text
iOS 打开 https://ios-web.netlify.app/wallet
        |
documentStart 注入 getAppParams()
        |
完整 H5 tokenManager 读取 apiToken
        |
完整 H5 调用现有主接口、SAPI 与页面子路由
```

不通过 URL 传 token，不调用 H5 登录接口，也不将 Bridge token 写入 Web Storage。原生登出时清理 WKWebView 网站数据，避免后续账号复用既有网页业务缓存。

## 实现边界

- iOS 使用 `H5WebContainerView`、`H5Page` 和 `.trusted(.iosWeb)`。
- iOS 使用 `H5RuntimeContext.current()`，不能使用活动页限制上下文 `.activity()`。
- H5 登录完成后保留 `/anchorGuide`、`/wallet`、`/invite` 当前入口，而不是重定向到首页。
- 完整 H5 的既有页面、接口、Wallet 子路由和 Invite 子路由均不重写。
- 不再依赖 `webview.html`、`dist-webview/` 或独立的三页面 API 副本。

## 取舍

复用完整页面避免功能偏差和重复维护，但其基础包大于独立轻量入口。当前选择以功能一致性优先；若后续需要优化首屏，应从现有页面中抽取共享模块，而不是重新实现页面。
