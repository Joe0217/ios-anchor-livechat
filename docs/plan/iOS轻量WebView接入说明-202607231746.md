# iOS 复用完整 H5 接入说明

## 页面地址

| 原生入口 | 已有 H5 路由 |
| --- | --- |
| Working Guide | `https://ios-web.netlify.app/anchorGuide` |
| Wallet | `https://ios-web.netlify.app/wallet` |
| Invite | `https://ios-web.netlify.app/invite` |

三个入口复用 `anchor-livechat-h5` 现有页面及其子路由。Wallet 内的提现入口仍由已有 H5 页面跳转到 `/wallet/withdrawal`；iOS 初始入口是 `/wallet`。

完整 H5 使用 `createWebHistory`，因此**不能**使用 `#/wallet`、`#/invite` 或 `#/anchorGuide`。hash 不会参与该路由器的匹配，页面会回到首页。

## 原生接入

```swift
H5EmbeddedFeatureContainerView(
    feature: .wallet,
    title: L10n.workWithdrawal
)
```

`H5EmbeddedFeatureContainerView` 从 `HilyWebFeatureBaseURL` 读取部署入口，拼接 history 路由，并仅对该精确 HTTPS origin 注入 Bridge。完整 H5 的 `tokenManager` 从 `apiToken` 读取主接口 token；活动 H5 的接口约定是把 `loginUuid` 作为 `token` 使用，两者不能替换，否则用户资料请求会返回 `1004`。

该上下文还会下发原生请求头使用的 `deviceType`、`deviceId`、`deviceNo`、`osType` 和 `osVersion`。完整 H5 必须在 Bridge 握手后才读取这些字段设置主接口与 SAPI 请求头，不能使用 WebView 自动生成的设备标识。

这三个入口还会下发 `embeddedWebFeature: true`。完整 H5 仍复用现有页面、路由和业务接口，但在该模式下禁止调用 `setIMAccount`，从而不会进入云信、声网、心跳和 WebSocket 的全局初始化链路。该行为对齐活动 H5 的“仅业务接口、无主播端长连接”运行方式，避免与原生端同账号互踢。

## 安全与会话

- 仅 `https://ios-web.netlify.app` 的主框架获得 `window.App.getAppParams()`。
- Bridge 在 document start 注入；token 不拼接 URL，也不由 Bridge 写入 Web Storage。
- 完整 H5 为既有 Wallet 流程维护其必要的业务状态（例如 BagShop token）；iOS 登出时必须调用 `H5WebSession.clear()` 清除网站数据。
- 页面只使用原生已经登录账号的 token 发起接口请求，不调用 H5 登录接口，不会创建第二个 H5 登录会话。
- Debug 构建携带 `debug: true`，H5 会显示 vConsole；日志仅包含 token 长度、接口路径、HTTP 状态和业务码。

## 发布与联调

完整 H5 按既有发布流程执行 `pnpm run build:dev`（或对应环境的构建命令）并将 `dist/` 发布到 `HilyWebFeatureBaseURL` 指向的站点。不需要发布 `webview.html` 或 `dist-webview/`。

发布后先从该域名拉取首页和其入口 bundle，确认 bundle 包含 `embeddedWebFeature`。若仍返回旧 bundle，iOS 即使已更新也会运行旧 H5，无法获得路由和互踢保护。

1. 使用 iOS Debug 构建登录主播账号。
2. 打开 Guide、Wallet、Invite，确认地址分别为 `/anchorGuide`、`/wallet`、`/invite`，没有 `#`。
3. 在 vConsole 查看 `full.bridge.params.accepted`，确认 `tokenLength` 大于零、`hasDeviceId` 为 `true`、`embeddedWebFeature` 为 `true`；不得出现 token 或 deviceId 原文。
4. 查看 `full.embedded.im.skipped`、`full.embedded.services.skipped` 与 `full.embedded.realtime.blocked`，确认 WebView 没有启动云信、声网、心跳或 WebSocket。
5. 查看 `full.api.request.start`（Wallet 的 SAPI 请求还会有 `full.sapi.request.start`），确认 `hasDeviceId` 为 `true`，再确认 `/api/anchor/userInfo` 及页面业务接口返回成功、不出现 `1004`。
6. 从 Wallet 进入提现页、从 Invite 进入详情页，确认既有子路由正常工作。
7. 登出、换账号后重新进入，确认无上一账号的 Wallet 或 Invite 数据。

## 取舍

此方案不复制三套页面，功能与既有 H5 保持一致。声网、云信、聊天室和心跳 SDK 均不是嵌入页首屏 preload 资源，且嵌入模式不会执行其初始化；若后续仍以首屏体积为硬指标，应从现有页面抽取共享依赖，而不是复制业务页面。
