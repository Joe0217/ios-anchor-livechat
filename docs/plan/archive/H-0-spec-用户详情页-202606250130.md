## §1 H5 行为校验（已读源码）

### 1.1 数据流
```
mounted → userInfo = props.profileInfo ?? chatStore.userInfo（已含 userId）
       → getUserDetail({userId}) → UserInfoData 回填
       → 解析 thumbs[0].num → like / thumbs[1].num → favorite
       → isBlocked !== 1 时菜单插入 Block 选项（仅首次回包，session 内不再 mutate）
```

| 字段 | 来源 | 类型（H5 type.ts） | 本期用 | 备注 |
|---|---|---|---|---|
| `userId` | props 传入（必有） | string | ✅ | LiveListAnchor.userId 直传 |
| `nickname` | getUserDetail | string | ✅ | 顶部 |
| `icon` | getUserDetail | string | ✅ | 头像 |
| `gender` | getUserDetail | 1\|2 | ✅ | 1=男 / 2=女 / 其他 → 不显示 |

### 1.3 关注按钮（CFollowButton 真实 emit，v2 修正）
- 显示态 by `followed` (boolean)：
  - `false`：紫红渐变胶囊 + follow icon + "FOLLOW"
  - `true`：紫罗兰半透明胶囊 + unFollow icon + "FOLLOWING"
- 点击：调 `/api/user/followUser` body `{followUserId: Int, type: 1|2}`（type 1=关注 / 2=取关，**不是** userId 字段名，是 followUserId）
- **CFollowButton emit 真签名**（c-followButton.vue:49）：`emit('followAfter', followType, followUserId)` — 传 followType (1/2) 和 followUserId
- H5 userProfile/index.vue:89 接收 `(newFlag) => userInfo.followFlag = newFlag` 是 **H5 自身 bug**（把 followType 当 followFlag）
- **iOS 正确实现**：成功后 `newFollowed = (followType == 1)` 直接 toggle 本地 boolean，不参 H5 错误代码

### 1.4 拉黑流程（**v2 区分初始化 vs 拉黑后过滤**）
1. tap ... → 弹 CMenuPop
2. **菜单初始项判定**：在 `getUserDetail` 成功回包时一次性算（`isBlocked !== 1` → 插入 Block）；session 内不再修改菜单
3. tap Block → `showAddBlackPopup = true` → CThemePopup 二次确认
4. tap Confirm → `blockUser({userId, type:1, yxAccid, isLive})` （**非 optimistic**，等 API 回再改本地态）
5. 成功 → toast "add blacklist success" + isBlocked=1 + 关 popup + **filter 移除菜单 Block 项** + post `.blocklistChanged`
6. 失败 → toast "add blacklist fail" + 关 popup（isBlocked 不变）

### 1.5 接口字段类型契约
```ts
// blockUser body (H5 api/user/type.ts BlackOpt)
{ userId: number; type: 1; yxAccid: string; isLive: 0|1 }
// removeBlockUser body (trial #2 既有 BlockOptRequest)
{ userId: Int; type: 1; yxAccid: String }   // ← 无 isLive
// followUser body
{ followUserId: number; type: 1|2 }
```
**关键差异**：blockUser 有 `isLive`，removeBlockUser 没有。**不能复用** trial #2 的 `BlockOptRequest`，本期新建 `BlockUserRequest`（含 isLive）。

## §2 接口契约 + Model

### 2.1 接口
| 接口 | 路径 | 请求 | 响应 |
|---|---|---|---|
| getUserDetail | POST `/api/index/getUserDetail` | `{userId: Int}` | `result` 单对象 UserDetail |
| followUser | POST `/api/user/followUser` | `{followUserId: Int, type: 1\|2}` | `result=null`，code=0000 成功 |
| blockUser | POST `/api/user/blockUser` | `{userId: Int, type: 1, yxAccid: String, isLive: 0\|1}` | 同 follow |

### 2.2 iOS Model
```swift
// Sources/Profile/UserProfile/UserProfileModels.swift

struct UserDetail: Decodable, Equatable {
    let userId: String            // 严格 String（参 BlocklistItem）
    let nickname: String
    let icon: String?
    let gender: Int?              // 1=男 / 2=女 / 其他 nil
    let age: Int?
    let countryId: String?
    let connRate: String?         // H5 string 类型，宽松收
    let yxAccid: String?
    let followed: Bool            // ✅ Bool 非 Int（v2 修正）
    let isBlocked: Int?           // 1=已拉黑（H5 用 1/0/null，iOS 保 Int? 兼容）
    let like: Int                 // 解析 thumbs[0].num，nil → 0
    let favorite: Int             // 解析 thumbs[1].num，nil → 0
    // (giftList / picList / description 等占位字段本期 model 不存)
}

struct FollowUserRequest: Encodable {
    let followUserId: Int
    let type: Int                 // 1=关注 / 2=取关
}

struct BlockUserRequest: Encodable {  // ⚠️ 与 BlockOptRequest（移除拉黑）独立
    let userId: Int
    let type: Int = 1
    let yxAccid: String
    let isLive: Int               // 0|1
}

enum UserProfileRoute: Hashable {
    case userId(String)           // 多 tab 共享路由值
}
```

### 2.3 Decode 5 路 fallback（参 BlocklistService）
- 路径 1：`Data("null".utf8)` → nil
- 路径 2：顶层 UserDetail 对象
- 路径 3：wrapped `{data:{...}}` / `{result:{...}}`
- 路径 4：顶层字典无关键 key → nil + warn
- 路径 5：garbage → nil + error
- thumbs 字段解析在外层（不进 Codable，单独 helper），缺失或非数组 → like=0/favorite=0 兜底（R-4）

## §3 状态机

### 3.1 LoadState（拉资料）
```
.idle → loadUserDetail() → .loading
   ↓                          ↓
.error(msg) ←——— failure  success → .loaded(detail)
   ↑                          ↓
   └──── retry() ─────────────┘
```

### 3.2 FollowState（关注/取关）— **optimistic**
```
按钮 idle → tap → optimistic toggle detail.followed + .pending(userId)
                       ↓ API
                  success → keep optimistic
                  failure → revert detail.followed + toast + .pending 清
```

### 3.3 BlockState（拉黑）— **非 optimistic**（H5 行为：Confirm 后才请求）
```
... tap → menu open
menu Block tap → confirmPopup show
confirmPopup Confirm → .pending(userId) → blockUser API
   .pending → success → toast + isBlocked=1 + popup 关 + filter 菜单 + post .blocklistChanged
            → failure → toast "fail" + popup 关 + isBlocked 不变
confirmPopup Cancel / scenePhase!=.active → popup 关，无 API
```

### 3.4 不变量
1. **load**：loading 中拒绝再触发 loadUserDetail（参 Blocklist VM 不变量 #1）
2. **follow concurrency**：同 userId 并发 follow 守 `pendingFollowIds: Set<String>` 防双击（参 FollowList VM）
3. **block concurrency**：同 userId 并发 block 守 `pendingBlockIds: Set<String>`
4. **follow optimistic revert**：失败回退本地 `detail.followed` 到调用前值；失败前后 detail.followed 不一致 → 用调用前快照
5. **block 非 optimistic**：API 成功才改 isBlocked，确保 popup 关 + filter 菜单 + post 通知 3 项原子
6. **block 成功 post `.blocklistChanged`**：trial #2 留的钩子本期真 post；同步本期补 BlocklistViewModel observer + reload（spec §5.4）
7. **dismiss 时 cancel 进行中 follow/block Task**（参 BlocklistVM）

### 5.3 路由架构 — **多入口共享 UserProfileRoute**

**核心纪律**：UserProfileRoute 是值类型 enum 共享单一定义，**每个有详情页入口的 tab 在 MainTabView 内的 NavigationStack 根节点 register `navigationDestination(for: UserProfileRoute.self)`**。

#### 本期 H-0 实际接线（MainTabView 改动）

```swift
// MainTabView 新增 homePath：
@State private var homePath: NavigationPath = NavigationPath()

// isOnSubpageSignal 派生扩展：
private var isOnSubpageSignal: Bool {
    switch selection {
    case .home:    return !homePath.isEmpty   // ← 新增
    case .work:    return !workPath.isEmpty
    case .profile: return !profilePath.isEmpty
    default:       return false
    }
}

// .home case 包 NavigationStack：
case .home:
    NavigationStack(path: $homePath) {
        HomeView(path: $homePath)
            .navigationDestination(for: UserProfileRoute.self) { route in
                if case let .userId(uid) = route {
                    UserProfileView(userId: uid)
                }
            }
    }

// onChange(of: selection) 清空扩展：
.onChange(of: selection) { _ in
    homePath = NavigationPath()      // ← 新增
    workPath = NavigationPath()
    profilePath = NavigationPath()
}
```
