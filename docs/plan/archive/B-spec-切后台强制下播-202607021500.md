# B 里程碑增补：切后台超限强制下播 spec

> **档位**：B 档（0 接口 · 1 state case 新增 · 1 组件 · 单一入口 LiveStore）
> **依赖**：B v5.10+v5.11 已修复的"切后台误自动下播"防误触逻辑（HeartbeatController / NetworkQualityMonitor / SystemMessageRouter / CameraManager / MetalPreviewView 后台冷却）——本需求**并存不冲突**，见 §4
> **信源**：H5 无此策略（H5 `SYSTEM_FORCED='3'` 是服务端管理员操作，非客户端切后台）；用户新增需求

---

## §1 业务契约

直播态下主播出现以下**任一**情况必须自动强制下播：

| 档位 | 阈值 | sub_source |
|---|---|---|
| 累计切后台次数 | ≥ 5 次 | `bg_count5` |
| 单次后台时长 | ≥ 2 分钟 | `bg_single_2m` |
| 累计后台时长 | ≥ 5 分钟 | `bg_cumulative_5m` |

`endType` 统一用 **4**（复用 disconnected 的码；客户端"后台超限 → App 挂起 → 心跳停 → 断连"语义闭环）。

**预警**（回前台内嵌 toast，避免用户被强下播才反应）：
- 累计次数达 **4**（80%）时 toast：`You've been away 4/5 times. Live will end automatically after 5 times.`
- 累计时长达 **4 分钟**（80%）时 toast：`You've been away for 4 minutes cumulatively — approaching the 5-minute limit.`

三档同时命中时 subSource 拼接上报：`bg_single_2m+cumulative_5m+count5`（红队 🔴-3 缓解措施，避免运营埋点丢档）。

## §4 iOS 后台限制 + willEnterForeground 主路径

### 硬性限制

- 普通 App 切后台 ~10s 后进程挂起（SIGSTOP），所有 Timer/Task 停摆
- `beginBackgroundTask` 只能拿 ~30s 宽限期（iOS 13+ 收紧）
- **`Task.sleep(120s)` 在挂起进程中不到点** —— 2 分钟阈值无法保证后台自动 fire
- 唯一后台可见入口是 `UNUserNotificationCenter`（能弹，不能执行代码）

### 执行策略（三层）

1. **主路径 `willEnterForeground`**：用户回前台的那一刻结算 —— 若 `thisDuration ≥ 120` 或 `cumulative ≥ 300` 或 `count ≥ 5`，此刻 `forceEnd(.backgroundExceeded, sub: ...)`。
2. **best-effort Task.sleep(120s) + beginBackgroundTask**：进程未被冻结（用户在 App 边缘停留、不锁屏）时能直接 fire。iOS 挂起后失效。
3. **兜底服务端心跳超时**：App 挂起 → HeartbeatController tick 停 → 服务端连续 3 次心跳失败 (30-40s) → 判定 disconnected 下播 endType=4。**观众端因此不会长时间黑屏**。

三层组合覆盖：**用户回前台 → 主路径**；**用户很快回但进程仍活 → best-effort**；**用户不回 App → 服务端兜底**。

### UN 通知（best-effort 提醒）

`schedulePendingNotification()` 在 didEnterBackground 时排一个 100s 后 fire 的本地通知：
- 标题 "Return to your live now"
- 正文 "Your live will end automatically if you stay in background."

`getNotificationSettings` 先查授权状态，未授权跳过（**不弹权限对话框**——权限已在 LivePrepareView.onAppear 前置请求）。

## §5 验收清单

### 正向（真机 · 用户手工验）

- [ ] **P1 - 次数超限**：开播 → Home 键 → 回 App 循环 5 次 → 第 5 次回前台立即下播 endType=4 sub=bg_count5，主页面路由回退
- [ ] **P2 - 单次超时**：开播 → Home 键 → 等待 2 分钟 → 回 App 立即下播 sub=bg_single_2m。观察 1:40 时是否收到本地通知（若权限已授）
- [ ] **P3 - 累计超时**：开播 → 多次切后台每次 1-1.5 分钟 → 累计到 5 分钟时回前台下播 sub=bg_cumulative_5m
- [ ] **P4 - 次数预警**：切后台 4 次回前台 → 顶部 toast "You've been away 4/5 times..."（3s 自动清除）
- [ ] **P5 - 累计时长预警**：切后台 3 次每次 90s（累计 270s）→ 第 3 次回前台 toast "You've been away for 4 minutes cumulatively..."

### 反向（例外场景 + 边界）

- [ ] **N1 - 私 call 不计数**：开播 → 收到私 call → 通话期间切后台 3 次 → 通话结束回直播后 `backgroundCount` 应为 **0**
- [ ] **N2 - returnLive 不计数**：私 call 挂断 → 15s 倒计时期间切后台 → 不计入
- [ ] **N3 - forceEnding 期切后台**：让主播被 banned 触发 forceEnd 后立即切后台等 3 分钟 → 回前台**不应**弹"后台超限下播"，只有 banned 结果
- [ ] **N4 - 权限拒绝时主路径正常**：LivePrepareView 首次请求 UN 权限点"不允许" → 后续切后台 2 分钟仍能通过 willEnterForeground 结算下播（本地通知不弹但下播主路径不受影响）
- [ ] **N5 - pauseForCall 竞态**：开播 → 收到 RTM 私 call 呼入 → **RTM 到达到 `callState = 1` 写入之间**（约 <500ms）用户切后台 → 应识别为私 call 期不计数
