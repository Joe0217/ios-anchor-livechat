## 四、必修（本会话责任 + 有产品调用链证据）

### P1-1 LiveRoomView @ObservedObject `MessageSessionStore.shared` 违反 keepalive-publisher-isolation

- **文件**：[Sources/Live/LiveRoomView.swift:121](../../Sources/Live/LiveRoomView.swift#L121)
- **维度**：`swiftui-perf`
- **来源**：手工补审（Workflow swiftui-perf finder 挂）
- **风险**：`MessageSessionStore.shared` 是**大单例**（`state` / `systemInboxEntries` / `conversationProfiles` / `primeUidSet` / `flameUserIdSet` / `stationMail` 等 N 个 `@Published` 字段）。任一字段变化触发 LiveRoomView 整树重算 —— LiveRoomView 含 CameraPreview / PKArenaView / publicChatFeed / callState overlay 等重量级子组件，body 重算成本高。
- **产品调用链路证据**：主播开播中收任意 P2P 消息 → NIM delegate → MessageSessionStore.applyIncremental → `sessions` 更新 → publish → **LiveRoomView 整树重算** → CameraPreview.updateUIView + PKArenaView diff + publicChatFeed diff 全部 revisit。真机验证时可通过发一批消息给主播账号观察 CPU / body count。
- **复查后判定**：**必修**
- **修复**：按 [swiftui-keepalive-publisher-isolation.md §方案 A](../../.claude/rules/swiftui-keepalive-publisher-isolation.md) 抽派生 bridge：
  ```swift
  @MainActor
  final class LiveMessageUnreadBridge: ObservableObject {
      @Published private(set) var totalUnread: Int = 0
      init(source: MessageSessionStore = .shared) {
          source.objectWillChange
              .receive(on: RunLoop.main)
              .map { [weak source] _ in
                  guard let source else { return 0 }
                  return LiveMessageUnreadBridge.compute(source)
              }
              .removeDuplicates()
              .assign(to: &$totalUnread)
      }
      private static func compute(_ store: MessageSessionStore) -> Int {
          let all = store.sessions(in: .flame)
              + store.sessions(in: .prime)
              + store.sessions(in: .stranger)
          var seen = Set<String>()
          return all.filter { seen.insert($0.id).inserted }.reduce(0) { $0 + $1.unreadCount }
      }
  }
  ```
  LiveRoomView 只 `@StateObject unreadBridge = LiveMessageUnreadBridge()`；sheet 打开时 ConversationSheetContent 直接 subscribe `MessageSessionStore.shared`（sheet 短生命周期，重算不敏感）。
- **优先级理由**：主播端直播间是**最热 view**（camera 采集 + 声网 SDK + 云信长连接 + PK 交互）。任何多余 body 重算叠加 60Hz 相机帧 sink 都会影响推流质量。同类 keepalive rule 违反过去至少 3 次被沉淀（AnchorInfoStore 早期误用、HomeTopTab 早期误用），是**通用知识缺失高发点**。
