## 二、P0（必须改）

### P0-1 restartForRecording 未 re-addAudioIO 让二次录制无音轨

- **文件**：[Sources/Register/Camera/RegisterVideoRecorder.swift:174](../../Sources/Register/Camera/RegisterVideoRecorder.swift#L174)
- **维度**：correctness / audio pipeline
- **触发链路证据**：
  1. 用户录完 20s → push videoPreview → SwiftUI iOS 16-18 部分行为下 record view onDisappear fire
  2. onDisappear → `recorder.teardown()` → `camera.removeAudioIO(input: micInput, output: audioOutput)` 移除 audio input/output
  3. 用户点 Re-record → pop 回 record view → onAppear 检测 `state == .finished` → 调 `restartForRecording()`
  4. 旧 restartForRecording 只 restart session + 清 writer 残留，**未** re-addAudioIO
  5. 用户 tap Record 按钮 → CameraManager 帧继续送（含美颜）→ writer 写视频 mp4 OK；但 audioOutput=nil → captureOutput audio delegate 不 fire → writer.audioInput 永远没 sample → 20s 后 finishWriting → **mp4 有视频无音频**
- **复查后判定**：**必修**
- **修复**：restartForRecording 内 `if audioOutput == nil { (mic, out) = await camera.addAudioIO(...) }` 重加。已修（本审查后）

### P0-2 SessionStore resubmit 分支 refresh 失败无 fallback 让用户卡登录页

- **文件**：[Sources/Auth/SessionStore.swift:114](../../Sources/Auth/SessionStore.swift#L114)
- **维度**：correctness / error handling / UX
- **触发链路证据**：
  1. 用户登录 email/pwd → 后端返 token 非空 + userType=1(审核中)
  2. `isResubmitPath == true` → 设 `AuthToken.value = token` + `KeychainStore.setString(password, ...)`
  3. `await AnchorInfoStore.shared.refresh()` — 若 refresh 内部网络失败/APIError → `mine` 保持 nil
  4. `if let mineInfo = AnchorInfoStore.shared.mine` 分支不进 → `needsResubmit` 不设
  5. login() `return` → `defer { isLoading = false }` 触发
  6. 用户看到：Login 按钮 spinner 消失、无 error banner、path 未 push register → **卡在 login 页无任何反馈**
- **复查后判定**：**必修**
- **修复**：`else` 分支回退临时状态（清 AuthToken.value + Keychain password）+ 设 `errorMessage`（用通用网络错误文案避免误导用户 email/pwd 错）。已修（本审查后）

## 四、P2（可以改）

### P2-1 memset 每帧 dst buffer 全清 (720×1280×4 = 3.5MB) hot path 性能余量

- **文件**：[Sources/Register/Camera/RegisterVideoRecorder.swift:316](../../Sources/Register/Camera/RegisterVideoRecorder.swift#L316)
- **维度**：efficiency / pixel pipeline
- **触发链路证据**：srcRow != dstRow 分支每帧 `memset(dst, 0, dstRow * h)` 3.5MB × 30fps = 105 MB/s memset。**只有对齐差异导致 srcRow != dstRow 时才走此路径**（iPhone 32BGRA 720×1280 通常对齐良好 srcRow == dstRow 走快路径 memcpy）。**但**若某机型/iOS 版本走 padded 路径，每帧全清有余量优化空间
- **复查后判定**：**信息**（20s 短录制 hot path 内 impacts 可忽略；若长录制或电池热点观察可再优化）
- **建议**：改为只 memset 每行 tail padding（`memset(dst.advanced(by: srcRow), 0, dstRow - srcRow)` per row），或用 CVPixelBufferPool 的 pool config 强制 stride 对齐。留 P2 未修
