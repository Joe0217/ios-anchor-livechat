## 五、P2（信息 · 风格 / 洁癖 / 未来兼容）

### P2-1 `LiveSettingsStore.deinit` 访问 `@MainActor` 属性未标 nonisolated

- 文件：[Sources/Live/LiveSettings/LiveSettingsStore.swift:307-312](Sources/Live/LiveSettings/LiveSettingsStore.swift#L307-L312)
- 维度：concurrency (Swift 6 forward compat)
- 复查：Swift 5 mode 静默通过（`let lock` 不可变引用读取被容忍）；Swift 6 严格并发下 `deinit` 是 nonisolated，访问 `self.lock` 会报隔离违反
- 修复方向（未来 Swift 6 升级时）：改为 `let lockRef = self.lock` 显式 capture + `Task { @MainActor in lockRef.unlock() }`——**已经是这样写的**，只是编译期还未生效严格模式
- **信息级，无需现改**

### P2-3 `WishSettingService.getWishGiftMaxNum` 未排除 NSNumber Bool 桥接

- 参考 [.claude/rules/ios-decode-userid-compat.md](.claude/rules/ios-decode-userid-compat.md) §3
- **信息级**（洁癖）

### P2-4 `WishSettingService.parseTemplateList` 全路径静默返 `[]`

- 文件：[Sources/Live/WishSetting/WishSettingService.swift:61-83](Sources/Live/WishSetting/WishSettingService.swift#L61-L83)
- 维度：可观测性
- 复查：所有解析失败/字段命名变化 → 静默 `return []`。上层 `SharedStore.ensureCommonTemplates` 在**成功路径**才 log count；解析失败（返 []）时上层看不到区别
- 未来若后端字段命名升级（`list` → `items`），此处会静默返空 → 用户看不到任何模板 + 无警报
- 修复方向：解析失败或匹配到 candidates 但 decode 失败时 `logger.warning` 记录 raw 结构 hash（不 log 内容避免敏感数据泄露）
- **信息级**（可观测性改进）
