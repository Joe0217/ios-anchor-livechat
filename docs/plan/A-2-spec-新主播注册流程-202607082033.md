### 1.2 加解密

沿用 `APIClient.post(path, body:)` 现有加解密：JSON→AES-128-CBC/PKCS7→Base64 上行；响应 hex 密文；密钥随环境切并由本地 xcconfig 注入。无变更。

### 1.3 触发入口（对齐 §0.1）

**⚠️ v2 BLOCK-1 前置改造**：APIClient.swift L82-88 现有逻辑对 code=="1004"/"1005" 都 post `.apiSessionInvalidated` 通知，SessionStore.observer（L35-44）会走 `handleSessionInvalidated` → `logout()` + `errorMessage = L10n.authErrorSessionInvalidated`。这意味着 v1 spec 假设"login catch APIError.code=1005 → 设 pendingRegister 不设 errorMessage"**路径不通** —— 通知在 throw 前已 post，SessionStore 已开始 logout 流程。

**改造方案**（step 1c 前置，二选一）：
- **A（推荐）**：APIClient 加"通知白名单"或"path 参数控制"，login path `/api/login/v4/login` 的 1005 **不 post 通知**（1004 仍分流；1005 只 throw 让 login catch 处理）。改动收敛：APIClient 增 1 参数 `suppressSessionInvalidatedForCodes: Set<String> = []`；SessionStore.login 调用时传 `["1005"]`
- **B**：SessionStore.handleSessionInvalidated 增守卫 `guard isLoggedIn else { errorMessage = ...; return }`——已 logout 状态下 1005 只透传错误码，不再 logout 二次。风险：语义不干净，未来其它模块 login 前调其它接口误得 1005 可能吞掉需要 logout 的场景。**不采用 B**

**方案 A 落地**：`func post(_ path: String, body: ..., suppressCodes: Set<String> = [])`；`if code == "1004" || code == "1005", !suppressCodes.contains(code) { post 通知 }`；`throw` 不变。

**触发流**（改造后）：
```
LoginView.loginButton tap
  → SessionStore.login(email, password)
     → APIClient.post("/api/login/v4/login", ..., suppressCodes: ["1005"])
        → 若 catch APIError.code == "1005"
           SessionStore.pendingRegister = (email, password)   // 新增 @Published
           **不设** errorMessage（通知已不 post，SessionStore observer 也不触发）
        → 若 200 且 userType 允许
           正常登录路径 (applyLogin, §3.3)
LoginView.onChange(session.pendingRegister)
  → path.append(.basicInfo)   // NavigationStack
```

被拒重录场景不走 code=1005（此时账号已存在 userId），走**登录成功后 userType 判断**：
- `userType == 2` → 已审核 → 正常首页
- `userType == 9` → 代理 → 正常首页
- `userType 其他值`（对齐 H5 `login/index.vue:82` else 分支 `res.userType !== 9`）→ 强制刷新 → iOS 侧简化为"若 mineInfo 拉回 status=审核中/被拒" → path.append(.basicInfo) + `RegisterStore.hydrate(from: mineInfo)`

**具体触发码/字段**由 H5 login 挂"审核中"/"审核被拒"时后端返回 userType 值实测定（施工 step 0 抓包）。

**v2/v3 新增/抽出 `SessionStore.applyLogin(_ result: LoginResult) async -> Bool`**（收敛 login() 与 register 成功路径重复）：

```swift
// SessionStore.swift 新增
/// 登录/注册成功后的公共副作用链——单一入口，避免 login() 与 register 分岔重复
///
/// 职责：
/// 0. **v3 NEW-6**：token 空守卫 —— result.token 空/nil 返 false，调用方展示错误文案，不落地任何 state
/// 1. user = result；isLoggedIn = true；save()（Keychain 落 v2 store）
/// 2. AuthToken.value = result.token（供 APIClient 自动附带）
/// 3. Fire AnchorInfoStore.shared.refresh()（session-scoped rule 双入口 login refresh）
/// 4. Fire AppConfigStore.shared.activate()（同）
/// 5. 打日志（AppLogger.auth.info "[LOGIN OK]" 保留）
///
/// 副作用：**不设** errorMessage（成功路径）；**不清** pendingRegister/needsResubmit（由 View 层消费清）
/// 返回值：true=登录状态已建立；false=token 缺失，调用方决定文案
@discardableResult
func applyLogin(_ result: LoginResult) async -> Bool {
    guard let token = result.token, !token.isEmpty else { return false }   // v3 NEW-6
    user = result
    isLoggedIn = true
    save()   // 内部会 AuthToken.value = token
    AppLogger.auth.info("[LOGIN OK] userId=\(result.userId ?? -1, privacy: .private)")
    Task { await AnchorInfoStore.shared.refresh() }
    Task { await AppConfigStore.shared.activate() }
    return true
}
```

login() 与 RegisterStore.submit() 都调 `SessionStore.shared.applyLogin(result)`，消除 v1 spec 中"手动重复 setter"漂移风险；v3 补 token 守卫消除"result.token=空但 isLoggedIn=true"坏态。

### 4.2 RegisterVideoCompressor（`Sources/Register/Camera/RegisterVideoCompressor.swift`）

```swift
final class RegisterVideoCompressor {

    /// 二次压缩：1080p 原始 mov (~10MB) → 1080p H.264 ~2.5Mbps mp4 (~5-6MB)
    /// 保留分辨率（画质 80% 感受），降码率（体积压缩 50%+）
    ///
    /// - parameter sourceUrl: 录制产出的 mov
    /// - parameter progressHandler: 0.0 → 1.0 主线程回调
    /// - returns: 压缩后 mp4 的临时路径
    static func compress(
        sourceUrl: URL,
        progressHandler: @escaping @MainActor (Double) -> Void
    ) async throws -> URL
}
```

**实现方案**（选 A）：**AVAssetWriter + AVAssetReader** 精确控码率。
- reader 读原视频 sample buffers
- writer 写目标 mp4，`AVVideoCompressionPropertiesKey = [AVVideoAverageBitRateKey: 2_500_000, AVVideoProfileLevelKey: H264HighAutoLevel]`
- 音频复制不重新编码（AAC passthrough），或降码率到 96 kbps
- 输出目标 URL：`NSTemporaryDirectory() + "register-compressed-\(UUID).mp4"`
- 每 100ms 主线程回调 progress（reader progress 计算）

**备选方案 B**（AVAssetExportSession + preset）—— 更简单但码率控制不精确：
- `AVAssetExportSession(asset:, presetName: AVAssetExportPresetMediumQuality)` ≈ 1.5Mbps（可能过糊）或 `HighQuality` ≈ 4Mbps（体积压缩不够 50%）
- 一期**不采用 B**，采用 A 精确控。

**预期指标**：
- 输入：20s @ 1080p 30fps H.264 ~ 10MB
- 输出：20s @ 1080p 30fps H.264 ~2.5Mbps ~ 6MB
- 压缩率：~40%（体积压缩 40%，勉强对齐"50%+"）
- 若真机实测未达 50%，调整 videoAverageBitRate 到 2_000_000 = ~2Mbps ~5MB（体积压缩 50%）

**⚠️ 抖动/花屏风险**：AVAssetWriter 自定义参数不当会导致播放兼容问题；施工阶段真机验证 iOS 16-18 + 各机型；unit test 用 fixture 视频验证输出 mp4 可播 + 时长精度。

**并发上限**：不额外加 semaphore（`ImageUploader.upload` 内部若已有则复用；无则依赖 URLSession 默认 HTTP/2 复用）。若真机实测 6 并发触发限流，施工 step 3 加 semaphore(3) 顺序上传。

### 5.3 视频上传

见 §4 —— 二次压缩产出 mp4 → `PublicVideoUploader.shared.upload(videoData: Data(contentsOf: compressedUrl), fileExtension: "mp4")` → OSS URL

**mp4 数据读入内存**：20s 压缩后 ~5-6MB 可全部读入内存；无需分片流式。

## §6 错误处理 & 边界

### 6.1 权限边界

| 权限 | 拒绝时刻 | 降级路径 |
|---|---|---|

### 6.2 网络失败

| 场景 | 处理 |
|---|---|
| Country list 拉失败 | Page 1 Country picker 显示错误态 + Retry button |
| 头像上传失败 | Toast + 头像回滚到默认；用户可再选 |
| 单张 photo 上传失败 | Cell 显示 ❌ 图标 + tap 重试 |
| 视频压缩失败 | Page 5 Toast + "重新录制"按钮凸显 |
| 视频上传失败 | Page 5 Toast + 保持 Upload 按钮 enabled 允许重试 |
| Submit（A2/A3）失败 | Page 2 底部 error banner + 保持 Upload 按钮 enabled 允许重试 |

### 6.3 中断/退出边界

| 场景 | 处理 |
|---|---|
| Page 4 录制中 tap Back | Alert 二次确认 "Discard recording? Recording will be lost." |
| Page 4 录制中切后台 | wasInterrupted → 停录 + state=.failed + toast + 回 idle |
| Page 5 压缩中 tap Back | Alert 二次确认（压缩废弃，视频保留 rerecord/upload 选项？—— 一期简化：**直接 pop 回 Page 2，videoUrl 保持 nil，需重录**） |
| App 冷启动/kill 回到 login | RegisterStore.reset() （logout 已挂 clear，冷启动前提是有 session—未登录不进注册流程） |

### 6.4 表单验证错误文案

对齐 H5 `components/registerForm.vue:129-153`，全部走 `showToast(...)`，一期文案沿用 H5 英文原文（三语在 §7 里全 L10n 化）：
- "Please upload your avatar"
- "Please enter your nickname"
- "Please select your birthday"
- "Please select your country"
- "Please select your language"
- "You can only choose four" (language 选 5+)
- "Please upload at least 6 profile photos"
- "Please upload your video."

### 6.5 边界一致性 rule 应用

- **api-http-method-strict**：所有 A1/A2/A3 走 POST（H5 侧 `http.post`）；path 拿字面值，不推理
- **ios-decode-userid-compat**：hydrate 场景 mineInfo.userId 可能是 Int/String，统一转 String
- **toast-vs-banner-consistency**：表单校验 = 边界 → toast；Submit 接口失败 = 系统错误 → banner。§6.2 已分层
- **session-scoped-store-refresh**：RegisterStore 挂 SessionStore.logout 清 hook（不挂 login refresh，非 session-scoped 快照）
