### P0-1 `Sharer.subscribers` 数组死引用累积（`compactSubscribers()` 定义但从未调用）

- **文件**：[Sources/Core/Media/BeautyPipeline/BeautyPipelineSharer.swift:66](../Sources/Core/Media/BeautyPipeline/BeautyPipelineSharer.swift#L66) + [:161](../Sources/Core/Media/BeautyPipeline/BeautyPipelineSharer.swift#L161)
- **维度**：memory
- **触发场景**：
  - `SubscriberEntry.renderer` 是 `weak var`，renderer 释放时 weak 变 nil 但 SubscriberEntry struct 仍留在 `subscribers: [SubscriberEntry]` 数组
  - `compactSubscribers()` 是唯一清理途径（`grep -rn compactSubscribers Sources` 只有自身文件，**0 处外部调用**）
  - `detach(_:)` 里 `subscribers.removeAll { $0.renderer === renderer || $0.renderer == nil }` **顺便**清了 nil，因此**当前 3 处 attach 路径（BeautySettingsView / CallView / PartyStore）配对 detach 时不会累积**
- **具体触发路径审计**：
  - [BeautySettingsView.swift:94](../Sources/Beauty/Settings/BeautySettingsView.swift#L94) onDisappear detach ✓
  - [CallView.swift:163](../Sources/Call/CallView.swift#L163) onDisappear detach ✓
  - [PartyStore.swift:515](../Sources/Party/PartyStore.swift#L515) disableLocalVideoCapture detach ✓
  - **风险窗口**：若未来新增 attach 忘配对 detach（如 P0-2 里 LiveRoomView 若接入但没 detach）→ 死引用永远留在数组，`topRenderer` 每次访问 O(N) 扫描
- **严重度**：中（当前 3 处已配对，隐患在未来扩展）
- **复查后判定：必修**（属"预防性加固"但**结合 P0-2 一起做**：LiveRoomView 接入时若忘 detach 立即触发累积）
- **修复**：`topRenderer` computed property 内先清 nil：
  ```swift
  private var topRenderer: (AnyObject & BeautyRenderer)? {
      subscribers.removeAll { $0.renderer == nil }   // ← 加这行
      return subscribers.reversed().compactMap { ... }.max { ... }?.1
  }
  ```
  或 `attach` / `detach` 头部各清一次。

          case .success: return .ready

      }()
      guard newState != setupState else { return }

### P1-4 `reportSetupResult(.success)` 会覆盖已存在的 `.failed` 态

- **文件**：[Sources/Core/Media/BeautyPipeline/BeautyPipelineSharer.swift:128-129](../Sources/Core/Media/BeautyPipeline/BeautyPipelineSharer.swift#L128)
- **维度**：correctness
- **触发场景**：
  1. BeautySettingsView 里 `camera.isBeautyFallback=true` → report .failure → setupState=.failed
  2. 用户去 CallView：CallView.camera 是新 CameraManager 实例，FUManager.setupSync 幂等（didSetup=YES 直接返 self.beauty != nil），若上次已成功挂 beauty 则本次报 .success → setupState 从 .failed 覆盖回 .ready
  3. **但 CameraManager.isBeautyFallback 是 init 时决定的**（`self.renderer = try? FUBeautyRenderer() ?? PassthroughRenderer`），若上次 setup 失败留下 Passthrough → 本次 CameraManager 新建时也是 Passthrough → isBeautyFallback=true → report .failure（**正确不会覆盖为 .success**）
  4. 实际能触发 P1-4 的路径：不同 CameraManager 实例的 setup 结果**不一致**（罕见——除非 FURenderKit 全局状态被外部改动，或用户手动 reset FUManager.didSetup）
- **严重度**：极低（触发条件苛刻）
- **复查后判定：建议**（防御性加固，K+1 处理）
