# 美颜 / 录制 / 短视频 业务域 — 模块级业务逻辑梳理(Web / 安卓双端)

> **需求** DM-20260616-004 · **阶段二交付物**(对应需求步骤2)· 业务域 T2-10
> ⚠️ **认知澄清**:Web 的"浏览器录制"(`vedioRecorder`/`useRecord`)是**未启用的 Demo/死代码**;安卓 `ShortVideoActivity` 是**短视频播放页(ExoPlayer 播放主播视频名片)而非录制器**,`RecordBtn` 是 fu_ui Demo 控件(业务未接入)。两端真实业务重心是**实时美颜并打通直播/通话采集**;"录制+短视频拍摄"两端均尚未形成可用功能,对 iOS 属增量/可选项。

## 1. 业务目标与定位
主播端核心诉求:在视频通话/直播开播前后,对本地摄像头画面做实时人脸美化(美肤/美型/滤镜/特效贴纸等),并把美化后画面送入 Agora 推流。
- **Web(h5-anchor)**:美颜走 **FaceUnity Web 版(项目内称 NamaSDK,配合 MediaPipe/face-api 人脸检测)**,基于浏览器 `MediaStreamTrackProcessor`+`OffscreenCanvas`+Worker 的纯前端渲染管线。能力基础:美肤/美型/滤镜/特效贴纸。
- **安卓(android-anchor)**:美颜走 **FaceUnity 8.11.0 原生 SDK**,经 `io.agora.beautyapi.faceunity` 桥接接入 Agora 自定义采集。能力全面:美颜/美妆/贴纸/美发/美体/动漫(Animoji)/绿幕抠像/海报换脸/风格妆。

## 2. 核心业务流程

### 2.1 Web 端
**(A) 美颜初始化**:全局组件 `g-beautyCamera.vue` App 启动即挂载(常驻 CSS 隐藏),是所有美颜唯一载体。监听 `appStore.isInitBeauty` 触发 `initBeauty()`:注入 `MediaStreamTrackProcessor/Generator` polyfill → 动态 `import` 实例化 `NamaSDK` → `beautyInitStep`(0→1→2→3)推进 → step2 后绑定 `inited`/`onFace` 事件 → 开摄像头 + 读 `localStorage` 历史参数。采集管线:`getUserMedia(1280×720)` → track → `MediaStreamTrackProcessor` 转 ReadableStream → 高端浏览器 `transferControlToOffscreen()` 交 Worker 渲染(低端走主线程)→ `setCanvasAndVideoStream`,结果绘到 canvas。(`useNama.js` 是早期封装,**已废弃**)
**(B) 参数调节**:`views/beautySettings/index.vue` Tab(美肤/美型/滤镜)→ 数据源 `beautyCommon/defaultConfig.ts`;滑块(250ms 防抖)→ `beautyTools.ts#updateSDKEffects` 经 `reflexType` 区间映射换算原始值 → `NamaSDK.setParams(bundle,tab,key,raw)`;磨皮先设 `blur_type` 再 `blur_level`;总开关遍历置 0/还原。
**(C) 保存与应用**:`saveSettings()` 扁平化写 `localStorage`(`beautySetting`/`beautySwitchVal`/`filterKey`),**无后端**;开播/接通时 `g-beautyCamera` 监听 `beautyCameraActive` 激活 → `initBeautyParams()` 重放参数;美化后 canvas 经 `captureStream()` 作视频轨送 Agora(与 callApi 本地视频轨共用同一相机源)。

### 2.2 安卓端
**(A) 美颜初始化**:`FaceUnityBeautySDK.initBeauty(context)`:`judgeDeviceLevel` 判机型 → `registerFURender(authpack)` 鉴权 → 成功后异步 `loadAIProcessor` 加载人脸/人体模型 bundle → `configureFURenderKit()` 按 `DEVICE_LEVEL` 配算法加载策略(降级核心)。
**(B) 参数调节**:`BeautySettingsActivity` `initRtc()` → `initBeautyApi()`(`createFaceUnityBeautyAPI().initialize(captureMode=Custom)`)→ `FaceBeautyControlView` + `setData` 绑数据工厂(`FaceBeautyDataFactory`+磁盘数据源)。fu_ui 全控件统一 `bindDataFactory` 模式驱动,滑块回调写入 `FURenderKit` 对应对象属性。
**(C) 保存与应用**:采集打通 `captureMode=Custom`,`registerVideoFrameObserver` 在 `onCaptureVideoFrame` 调 `mFaceUnityApi.onFrame(videoFrame)`(POST_CAPTURER、READ_WRITE),Agora 帧送 FURenderKit 渲染后写回;`saveBeauty()` → `saveFaceBeautyData2File()` 落磁盘,总开关存 `AppCache.isBeautyEnable`;退出统一 `recycleAll()`(leaveChannel/stopPreview/注销观测器/release)。
**(D) 录制/短视频**:`ShortVideoActivity` 是 ExoPlayer 短视频**播放**页(播 `callVideoUrl` + 送礼/举报/拨打);`RecordBtn` 是 FaceUnity Demo 控件,业务未接入。

## 3. 关键接口/SDK
| 维度 | Web | 安卓 |
|---|---|---|
| 美颜 SDK | NamaSDK(FaceUnity Web 版,`utils/namaSDK/`)+ MediaPipe/face-api | FaceUnity 8.11.0 原生(FURenderKit/FUAIKit)+ MLKit |
| 核心调用 | `getInstance`/`setCanvasAndVideoStream`/`setParams`/`destroy`;事件 `inited`/`onFace` | `registerFURender(鉴权)`/`loadAIProcessor`/`onFrame` |
| 相机采集 | `getUserMedia`→`MediaStreamTrackProcessor`→OffscreenCanvas/Worker→canvas `captureStream()` | Agora 自定义采集 `IVideoFrameObserver.onCaptureVideoFrame`→`onFrame`→写回 |
| Agora 桥接 | canvas 视频轨直接作本地 track | `io.agora.beautyapi.faceunity`(`Config(captureMode=Custom)`) |
| 参数存储 | `localStorage`,无后端 | 本地文件 + `AppCache.isBeautyEnable`,无后端 |
| 参数字典 | `beautyCommon/defaultConfig.ts`(fuKey/range/reflexType/bundle) | fu_ui DataFactory + FaceBeautySource |

## 4. 状态与数据流
**Web** `useBeautyStore`(不持久化运行态):`showCamera`/`isHidden`/`beautyInitStep`(0~3)/`inited`/`faceDetected`/`beautySettings`/`beautyErrorMsg`/`beautyCameraOnPIP`;getter `beautyCameraEnable=inited&&!err`、`beautyCameraActive=enable&&showCamera&&!isHidden`。**美颜相机即通话/直播相机**:通话缩画中画、直播全屏,参数源唯一为 localStorage 开播/接通时重放。
**安卓**:运行态在 FURenderKit/DataFactory 内,开关持久 `AppCache.isBeautyEnable`,参数落磁盘;`BeautySettingsActivity` 自建独立 RtcEngine 仅预览调参(`if(LibApp.isCalling) return` 避免争用),真实通话由 call 模块复用同一 FaceUnity 单例(`FURenderKit` 全局唯一)。

## 5. 边界与异常
| 场景 | Web | 安卓 |
|---|---|---|
| SDK 加载/鉴权失败 | `beautyErrorMsg`→通话仅 toast、直播强制结束(`isCompelLiveEnd='99'`) | `registerFURender onFail` 仅日志,美颜不可用 |
| 相机权限 | `getUserMedia` catch→PERMISSION_DENIED 弹窗+上报 | `XXPermissionHelper.checkAllPermission` 拒绝阻断 |
| 模型/参数加载 | `beautyInitStep` 分阶段,过快设参会失败(需延迟重放) | `loadAIProcessor` 异步,授权后才加载 |
| 无人脸 | `onFace` 事件 + 15s 定时器弹"No Face Detected" | `setFaceDelayLeaveEnable` 离场延迟、小脸检测 |
| 低端降级 | `IsLowerChrome`/`isLowerIOS`/无 OffscreenCanvas 回退主线程 | `DEVICE_LEVEL` 四档关算法/降精度/`dynamicQualityControl` |
| 资源回收 | `destroyBeauty`(resetInit+destroy+停轨,延迟 1s) | `recycleAll` 全链路释放 |

## 6. Web vs 安卓差异提示
- **能力广度**:Web 仅美肤/美型/滤镜/特效贴纸;安卓 FaceUnity 全功能——美妆/贴纸/美发/美体/动漫/绿幕/海报换脸/风格妆/Avatar。
- **渲染管线**:Web 受浏览器能力强约束(Worker/OffscreenCanvas/WASM SIMD 多重降级);安卓 GPU 纹理直通,性能效果更优。
- **采集打通**:Web 用 canvas `captureStream` 间接接 Agora;安卓帧级读写 `IVideoFrameObserver`。
- **短视频/录制**:安卓有播放页 `ShortVideoActivity`(消费侧);拍摄录制两端均无真实业务。

## 7. iOS 实现注意点
1. **直接对标安卓而非 Web**:集成 **FaceUnity iOS SDK**(对应安卓 8.11.x),复用同一套 bundle 资源,而非移植 Web 的 NamaSDK/canvas 管线。
2. **鉴权与模型加载**:对齐 `registerFURender(authpack)`,授权成功后异步 `loadAIProcessor`,避免阻塞首帧。
3. **与 Agora 自定义采集打通**:iOS 用 `AgoraVideoFrameDelegate.onCapture` 做 READ_WRITE,CVPixelBuffer/纹理送 FURenderKit 渲染后写回(POST_CAPTURER);可参考 Agora BeautyAPI 官方 iOS 版。
4. **镜像/旋转**:前置摄像头镜像对齐 `getMirrorApplied()`,预览镜像与推流镜像分离。
5. **设备分级降级**:自建机型分级(对应 `judgeDeviceLevel`),低端关皮肤分割/去斑/降精度。
6. **参数持久化**:沿用本地存储(无后端),落沙盒文件 + `UserDefaults`(对齐 `AppCache.isBeautyEnable`),fuKey 与 reflexType 区间映射三端同字典。
7. **资源回收**:参考 `recycleAll`,页面销毁/切通话时严格 release,避免相机/GPU 争用。
8. **范围澄清**:"短视频拍摄/录制"是两端现状均未实现的增量功能,需独立设计(AVAssetWriter 或 SDK 录制),不可从现有代码复用。
