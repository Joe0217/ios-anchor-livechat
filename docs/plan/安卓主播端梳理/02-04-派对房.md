# 派对房 / 多人语音房 业务域 — 模块级业务逻辑梳理

> **需求** DM-20260616-004 · **阶段二交付物**(对应需求步骤2)· 业务域 T0-4
> **业务范围**:仅 Android 主播端(`android-anchor/partyroom` 模块 + `app` 模块的数据统计页)。
> Web 端(`h5-anchor`)经全文扫查确认 **无任何派对房实现**(详见第 6 节)。
> 技术底座:Agora RTC 4.x(多人语音/视频)+ 网易云信 NIM 聊天室(消息/通知广播)。

---

## 1. 业务目标与定位

派对房(Party Room,内部也称"多人语音房/语聊房")是一个 **多人实时音视频互动房间**,区别于直播间的"主播对观众单向直播",它是 **麦位制的多人共麦** 模式:

- 房间内有固定数量麦位(`seatIndex` 1–13,由房间模版 `roomTempId` 决定布局),分 **语音位(VOICE)** 与 **视频位(VIDEO)** 两类(`PartyRoomSeatType`)。
- 任何进房用户都是 **观众**,可申请/被抱上麦成为发言者;房主与房管负责房间秩序管理。
- 围绕麦位衍生出完整互动经济闭环:公屏聊天、送礼、表情、背景音乐、半屏小游戏、贡献/荣誉/CP 榜、PK 对战、幸运数字玩法,以及主播侧房币体系(宝石→钻石/金币兑换)与麦时收益统计。

角色模型(`PartyRoomRoleType`):`OWNER(1)` 房主、`ADMIN(2)` 房管、`AUDIENCE(3)` 普通观众;另有跨房间 `isPlatformAdmin` 平台管理员标识,权限最高。

本模块是 Android 工程中"当前最活跃的业务模块",依赖层级 `partyroom → common + call`,复用了 `call` 模块的 Agora 美颜与 1v1 通话能力(PartyCall)。

## 2. 核心业务流程(分步)

### 2.1 创建 / 进入房间
入口:列表与发现 `PartyFragment` / `AllPartyFragment` / `PartyRoomListFragment` / `RecentPartyRoomListFragment` / `FollowedPartyRoomListFragment`(对接 `getPartyRoomList`/`getRecentPartyRoomList`/`getFollowedPartyRoomList`);创建 `CreatePartyRoomActivity` + `ChoosePartyModeFragment`(先 `getCreateRoomConditions` 校验资格 → `getRoomTempList` 选模版 → `createPartyRoom`);搜索 `SearchPartyRoomActivity`。

进房统一收口在 **`PartyRoomDataManager.enterRoom()`**(全局状态单例)。串行执行:
1. `postRoomInfo` 写房间状态、`mMikeList = info.roomSeatList` 初始化麦位;
2. `loadMusicSetting` / `loadSelfUserInfo`;
3. `RtcEngineManager.initRtcEngine()` + `initBeauty()` → `joinPartyRoomChannel()` 以 **观众角色** 加入声网频道(`agoraChannelId`);
4. `loginYxChatRoom()` 进 NIM 聊天室(`yxRoomId`)→ `fetchRoomInfo`(在线人数) + `pullMessageHistory`(30 条历史) + `registerRoomChatObservers`。

> 关键:房间有 **三个 ID**——业务 `id`、声网频道 `agoraChannelId`、云信聊天室 `yxRoomId`,三者解耦。RTC 负责音视频流,NIM 负责所有信令/通知/公屏消息。

### 2.2 麦位管理(上/下/抱/闭/锁/换)
麦位操作均为 **"调接口 → 服务端广播 NIM 通知 → 客户端据通知刷新麦位与 RTC 角色"** 的闭环,客户端不直接乐观更新关键状态。操作类型 `OperatorType`:主动上麦(1)/主动下麦(2)/抱下麦(3)/抱上麦(4)/禁麦(6)/解禁(7)/锁麦(8)/解锁(9)/换麦(10)/移除管理员并抱下(11)。

- **主动上麦** `applyOnSeat`(`party/seat/onSeat`)→ 成功记 `mOnMikeStartTime`(麦时起点);失败按错误码分流(占位/封禁/等级不足)。
- **主动下麦** `applyDownSeat`(`party/seat/downSeat`)→ 结算麦时累加 `accumulatedDuration` + 埋点。
- **抱麦/抱下麦** `holdSeat`;被抱者通过 NIM `UPDATE_PARTY_ROOM_SEAT` 里 `seatOperate==HOLD_ON_MIKE(4)` 且 `currentUserId==自己` 识别,`updateMedia` 推流。
- **闭麦/禁麦** `prohibitSeat` → 服务端广播 `PARTY_ROOM_PROHIBIT_MIC` → 对自己 `switchSelfMicMute`、对他人 `muteUser/unmuteUser`。区分 `seatMicrophoneEnabled`(管理员禁麦态)与 `microphoneEnabled`(用户自己开关)。
- **锁麦/换麦/邀请上麦/上视频位**:`lockSeat`/`exchangeSeat`/`inviteUserJoinRoom`/`inviteOnSeat`(被邀请者 `respondInviteSeat` 确认,发起方 30s 防连击灰态)。
- **申请上麦排队**:房主开 `updateOnSeatEnable`,观众 `applyOnSeat` 进队列,房主 `agreeApplyOnSeat`/`refuseQueueSeat` 处理(`MicApplicationListDialog`)。

**麦位与 RTC 映射核心** 在 `PartyRoomDataManager.postMikeList()`——房间音频订阅的"对账中心",每次麦位变更全量执行:他人在麦且 `seatMicrophoneEnabled==1` → `unmuteUser`,否则 `muteUser`;自己在麦 → `upperSeat()`(切 Agora `BROADCASTER`)+ 按开关 mute;不在麦 → `stopPreview()` + `downSeat()`(切 `AUDIENCE`)。

> 设计要点:Agora 侧只有"主播/观众"二元角色,"语音位 vs 视频位"完全由 **业务层 + 推流轨道开关** 区分;远端音量通过 `adjustUserPlaybackSignalVolume` 在播放端静音,而非订阅层取消。

### 2.3 房内互动(聊天/送礼/表情/音乐/游戏)
主舞台 `PartyRoomActivity`(巨型聚合页),`ViewPager2 + FlycoTabLayout` 承载多互动 Fragment,公屏用 `PartyRoomMsgFragment`。
- **公屏聊天**:`realSendTextMsg` 构造 NIM 聊天室文本消息(`remoteExtension` 塞 userId/role/勋章/气泡),本地回显;房主房管 `deletePartyMsg` 撤回。
- **送礼**:`getPartyRoomGifts` → `sendPartyRoomGift`/`sendBackpackGiftParty`,可对多麦位批量送。服务端下发 **2049 压缩版**(gzip)作新端唯一渲染入口 + 1007 明文兼容老版;`dispatchPartyRoomGiftRecord` 拆成 **礼物动画**(SVGA/MP4 队列)+ **公屏收礼消息** 两路。
- **表情**:`getPartyRoomEmojiList`,NIM `PARTY_ROOM_EMOJI`/`_PLAY`(玩法表情)。
- **音乐**:`MusicListFragment`,`getNetMusics`/`uploadLocalMusic`/`playMusic`,NIM `ROOM_USER_MUSIC_SWITCH`/`PARTY_ROOM_PLAY_SONG`。
- **游戏**:`GameListDialog`(半屏 H5)→ `GameWebViewDialog`;中奖公屏 `GAME_WIN_PARTY_NOTIFY(136)`/`GAME_SMALL_PRIZE(138)`。
- **PK 对战**:`PartyBattleController`/`Manager` + `battle/*` 接口,NIM `attachType ∈ 1100..1112`。
- **幸运数字**:`LuckyNumberComponent` + `lucky-number/*`,NIM 1050 抽数/1051 中奖。
- **私 Call(PartyCall)**:房内向某用户发起 1v1(复用 `call` 模块),`PartyRoomDataManager` 实现 `ICallApiListener`,来电 `callerType==5` → 停预览/关麦/5s 后下麦;结束 `onCallEnd` 重新入频道恢复。

### 2.4 贡献 / 荣誉 / CP 榜
贡献榜 `getContributionRanks`、荣誉榜 `getHonorRanks`、房间/财富榜 `getRoomRanks`/`getPartyRichRanks`、CP 榜 `getCpRankListV2`(主播端 Mystery 化)。聚合页 `PartyRoomRankingActivity`。

### 2.5 房币兑换(宝石/钻石/金币)
`BalanceInfoActivity`(`getBalance` 钻石+宝石)、`GemExchangeDiamondActivity`(`exchangeDiamond` 宝石换钻石)、`GemExchangeCoinActivity`(`exchangeCoin` 宝石换金币)、`FlowRecordActivity`(`getDiamondFlowRecords`/`getGemFlowRecords`)。收礼时主播获宝石,热度前 X 房间额外发宝石。

### 2.6 数据统计(麦时)
`app` 模块下 `PartyRoomDataActivity`(收益/数据看板)、`PartyMicTimeDetailActivity`(麦时明细)、`PartyRoomDataRuleActivity`。麦时客户端计算:上麦记起点,下麦/被抱下/切模版/退房/被踢时累加 `accumulatedDuration` 并埋点。

### 2.7 退出 / 关房 / 最小化
退房 `release()`:结算麦时 → `exitPartyRoom` → `destroy`。`releaseAllResources`:`downSeat()` + `closeEngin()`(释放美颜+离频道+引擎置空) + `exitYxChatRoom()`。**最小化** `PartyRoomMinimizeHelper` 悬浮窗,再次 `enterRoom` 走轻量恢复路径(不重建引擎)。

## 3. 关键接口 / SDK 分组

### 3.1 HTTP 接口(`partyroom/http/ApiService.kt`,90+ 端点,前缀 `sapi/weidou/v1/client/party/...`)
| 分组 | 代表接口 |
|------|----------|
| 房间生命周期 | `room/create\|enter\|exitRoom\|list\|recent/followed list\|checkPassword\|updateRoom\|lockRoom\|kickOutRoom` |
| 麦位 seat | `seat/onSeat\|downSeat\|list\|holdSeat\|inviteOnSeat\|respondInvite\|prohibitSeat\|lockSeat\|exchangeSeat\|updateMedia\|agreeSeat\|getQueueSeatList\|switchRoomTemp` |
| 互动 | `gift/getPartyRoomGift\|sendGift\|sendGiftFromBackpack`、`music/*`、`room/getPartyRoomEmojis\|openEffect` |
| 榜单 | `rank/getContributionRanks\|getHonorRanks\|getRoomRanks\|getPartyRichRanks`、CP `api/ranking/v2/userRank` |
| 管理 | `room/setAdmin\|editAnnouncement\|updateOnSeatEnable\|setBgImages\|updatePartyPrivateCall` |
| 游戏/PK/幸运数字 | `api/half/geme/anchor/list`、`battle/*`、`lucky-number/*` |
| 房币 | `gem/getBalance\|exchangeDiamond\|exchangeCoin`、`diamond/flow/record` |

> 注意:部分接口走 `baseUrl:serverUrl` 打 **主站老后端**(关注/CP榜/背包礼物/游戏),其余打 **weidou 新后端**——新老架构混合。请求体 AES 加密,URL Base64 编码。

### 3.2 Agora RTC(`RtcEngineManager.kt`,object 单例)
频道 `CHANNEL_PROFILE_LIVE_BROADCASTING` + `AUDIO_SCENARIO_CHATROOM` + `AUDIO_PROFILE_SPEECH_STANDARD`(语聊优化)。上下麦 = `setClientRole(BROADCASTER/AUDIENCE)`;自己开关 `enableLocalAudio`/`enableLocalVideo`;他人音量 `adjustUserPlaybackSignalVolume(uid,0/100)`;视频位编码按 `roomTempId` 切换;美颜 FaceUnity(`CaptureMode.Agora`,与 call 共用)。回调:`onAudioVolumeIndication`(声波)、`onJoinChannelSuccess`(首次才对账)、`onConnectionStateChanged`(断线/被踢)、`onSnapshotTaken`(露脸截图)。

### 3.3 NIM 云信聊天室(`PartyRoomVM.kt`)
进房 `enterChatRoomEx`(tag `party_room`);消息分发中枢 `handleIncomingChatRoomMsgList`——所有房间信令走聊天室自定义消息的 `remoteExtension["attachType"]` 路由(见第 4 节);历史 `pullMessageHistoryExType`(text 30 条);在线状态 `observeOnlineStatus`(`LOGINED` 才首拉麦位,断连重置以支持重连重拉)。

## 4. 状态与数据流

### 4.1 全局状态单例 `PartyRoomDataManager`
实现 `ViewModelStoreOwner + LifecycleOwner + ICallApiListener`,跨 Activity/Fragment 的唯一房间状态源。维护:`mRoomInfo`、`mMikeList`(核心)、`mMusicSetting`/背景、`mOnMikeStartTime`/`accumulatedDuration`、`isApplyMic`/`isTopX`/`isJoinedChannel`、邀请灰态。对外以 **Flow** 暴露(`mInfoFlow` SharedFlow **replay=1** 防晚订阅漏更新、`mMikeListFlow`、`mOnlineUserCountFlow` 等)。约定:改房间状态必须经此类方法。

### 4.2 麦位数据结构(概念)
`PartyRoomSeat`:`seatIndex`(1-13) + `userId` + `seatType`(1视频/2语聊) + `isOccupied` + `cameraEnabled/microphoneEnabled`(用户自身) + `seatMicrophoneEnabled`(管理员禁麦) + `lockFlag` + `isHostSeat` + 用户展示信息 + `giftValueCount`。`itemType=seatType-1` 供多类型 Adapter 渲染。

### 4.3 消息驱动状态机(核心)
派对房是 **强消息驱动**:客户端操作只发请求,状态变更几乎全部由服务端经 NIM 广播回来再落地。`handleIncomingChatRoomMsgList` 按 `attachType` 分发,主要类型:
- `UPDATE_PARTY_ROOM_SEAT`(gzip 麦位更新)→ `postMikeList`;`UPDATE_PARTY_ROOM_SEAT_LIST` → 全量 `loadMikeList`
- `PARTY_ROOM_PROHIBIT_MIC`(禁/解禁)、`KICKED_OUT_PARTY_ROOM`(被踢)、`PARTY_ROOM_UPDATE_MEDIA`
- `RECEIVE_PARTY_ROOM_GIFT_COMPRESSED(2049)`(gzip 送礼)→ 双路分发
- `ROOM_USER_MUSIC_SWITCH`/`PARTY_ROOM_PLAY_SONG`(音乐)、`PARTY_ROOM_MIC_APPLY_SWITCH`/`QUEUE_ON_SEAT`(申请/排队)
- `PARTY_ROOM_SWITCH_ROOM_TEMP`(gzip 切模版,结算麦时)、`UPDATE_BG`/`VEHICLE_EFFECT_ENTER`/`EMOJI`
- `GAME_WIN_PARTY_NOTIFY(136)/SMALL_PRIZE(138)`、`INVITE_VIDEO_SEAT_*(1041-1047)`、`1100..1112`(PK)、`LUCKY_NUMBER(1050-1052)`、`ROOM_ANNOUNCEMENT(1049)`

公屏消息类型 `PartyRoomMsgType`(0公约/1文本/2礼物/3欢迎/4管理变动/.../10-13 PK/14通告/15-16幸运数字),统一经 LiveEventBus `EVENT_PARTY_ROOM_RECEIVE_MSG` 投递。跨组件用 **LiveEventBus** 大量解耦。

## 5. 边界与异常处理
- **麦位冲突**:上/下麦失败码 `ROOM_SEAT_IS_OCCUPIED`/`ROOM_SEAT_EMPTY` → `loadMikeList()` 全量重拉对账。
- **被踢/被封麦**:`KICKED_OUT_PARTY_ROOM` 校验 `userId+roomId` 双匹配才退房(防误踢);封禁码解密弹倒计时;屏审 `PartyRoomScreenNotify` 强制下麦。
- **房主/房管离开**:角色变动经 `EVENT_PARTY_ROOM_ADMINISTRATOR_CHANGES`;`REMOVE_ADMIN_AND_HOLD_DOWN_MIKE` 移除管理员同时抱下麦。
- **断线重连**:NIM `UNLOGIN/NET_BROKEN` 置 `mLoadMikeList=false`,重连 `LOGINED` 自动重拉;Agora `onConnectionStateChanged` 处理 `BANNED_BY_SERVER/JOIN_FAILED`;`isJoinedChannel` 守护只首次对账。
- **PartyCall 来电抢占**:停推流/关麦/5s 下麦再接听;`LibApp.isCalling` 守护——通话中 NIM 麦位类消息跳过 RTC 操作。
- **重复进房守护**:`LibApp.isPartying` 防重复启动;悬浮窗恢复走轻量路径。
- **送礼新老兼容**:2049 压缩 + 1007 明文双发,新端只认 2049、老端只认 1007。
- **资源泄漏防护**:`release` 严格按"结算麦时→退接口→退聊天室→关引擎→清单例"顺序。

## 6. Web 端缺失确认
对 `h5-anchor` 全量扫查(`party/room/seat/麦位/上麦/抱麦/语聊/voiceRoom` 等中英文):命中文件全为无关上下文(直播间嘉宾位"空座位"文案、云信通用库、locales 等)。唯一带 "party room" 字样的 `src/views/invite/dashboard/details.vue` 相关代码 **全部被注释**,注释明确写 `等party房开发完再放出来`。

**结论:`h5-anchor` 不存在独立派对房业务,无麦位、无 RTC 共麦、无房间舞台。派对房是 Android 主播端独占的完整业务线。**

## 7. iOS 实现注意点(若 iOS 要做派对房)
1. **双 SDK 集成**:Agora RTC iOS(语聊场景 `AgoraAudioScenarioChatRoom` + 上下麦角色切换 + 播放端静音 + 视频位编码切换)+ NIM ChatRoom iOS。三 ID(业务/agora/yx)映射照搬。
2. **全局房间状态单例**:等价 `PartyRoomDataManager`,用 `ObservableObject`/Combine(或 RxSwift),注意 `replay=1` 语义用 `CurrentValueSubject`。
3. **麦位-RTC 对账逻辑**:`postMikeList` 全量遍历对账是核心,必须完整移植。
4. **NIM 消息状态机**:约 30 种 `attachType` 分发需逐条对齐,含 gzip 解压、PK 1100-1112、幸运数字 1050-1052——工作量最大、最易出 bug。
5. **美颜**:接 FaceUnity iOS 并与 Agora 自定义采集打通。
6. **PartyCall 抢占**:与 1v1 通话来电互斥/恢复。
7. **房币/数据页**:纯 HTTP 列表,相对简单。

> **工作量提示**:这是 Android 工程体量最大、最活跃的模块。iOS 从零实现属 **重型工作量**,建议分阶段:先 MVP(进房/上下麦/聊天/送礼),再补管理/排队/PK/游戏/玩法。后端接口已就绪,iOS 侧主要是端能力与状态机复刻。
