# 连麦 / 1v1 通话 业务域 — 模块级业务逻辑梳理(Web / 安卓双端)

> **需求** DM-20260616-004 · **阶段二交付物**(对应需求步骤2)· 业务域 T0-2
> 说明:本域子代理两次受阻(超时/工具故障),由主梳理人亲自核验代码产出,所有结论来自实际源码。

## 1. 业务目标与定位

主播端 1v1 实时音视频通话,是核心营收链路之一(按分钟计费)。覆盖四种通话来源(Web `CALL_FRONT_GAME_TYPE_NUMBER`):
- **DIRECT(1)** 主播主动拨打用户 / 用户拨打主播
- **MATCH(2)** 视频匹配命中后进入通话
- **LIVE(3)** 直播间私 call(直播转 1v1)
- **BOT(4)** 机器人 / 虚拟用户通话(引流/陪聊,免费)

收入来自:通话按分钟扣费(用户侧扣、主播侧收)+ 通话内送礼。计费与收入通过 NIM 系统消息回推(`attachType` 15 每分钟收益 / 4 对端送礼),**主播端不主动扣费,只接收结算结果**。

## 2. 核心业务流程(分步)

### 2.1 Web 端(h5-anchor)
通话核心封装在 `src/callApi/`(`core/callApi.ts` 基于 Agora RTC + RTM 信令),编排在 `src/use/useCallApi.js`,状态存 `stores/myCall.js` 的 `currentCallInfo`。

**来电(被叫)**:
1. 收到 NIM/RTM 来电信令 → `joinCallGetUserInfo(roomId)`:`apiJoinCall` 拿对方信息(3s 超时兜底),写入 `currentCallInfo`(对端 id/昵称/价格/yxAccid/IM在线态);极限情况(通话已取消 `callStartTime` 清零)直接返回。
2. 拉对端进场座驾动画(`apiGetLiveAnimation`)。
3. **自动接听判定**:若 `liveState===living/liveCalling` 或 `matchState===MATCHING_CALLING`(即直播私call/匹配通话)→ 直接 `callInEnter()`;否则展示来电浮层 `g-waitingCall` 等用户操作。
4. `callInEnter()`:校验 `callGameStatus` 非通话中/已拒;若在 PK 惩罚阶段先 `endPunishment('private_call')`;若在直播 `livingEnd(false)`(暂停直播不清信息)→ `callApi.accept(callUserId)` → 上报接听率 `callRate`。接听失败则 `callApi.reject`。

**拨打(主叫)**:`openLocalCameraAndeMic('callOut')` → `handleStartCallOut` → `apiCreateCall` 创建通话 → RTM 发信令给用户 → 等待对端接受(30s 超时 `callTimeOutNum`,`signalingInviteTimeout` 自动取消)。

**接通 → 通话中**:CallApi 状态回调 `setAppStateFromCallState`(0空闲/1prepared/2calling/3connecting/4connected/10failed → app state),`connected` 开摄像头;`handleBeginCall` 重置通话收入,`apiBeginCall(beginCallV2)` 正式开始;通话中 `callDeductionFee` 心跳上报(扣费失败重试 `deductionErrMaxNum=3`);收礼/每分钟收益经 NIM `attachType` 4/15 更新 `callIncome/callGiftIncome`。

**挂断 → 结算**:`apiCallOver(overReason)` 结束(原因码见下);评价 `callEvaluation`(V2)+ 好评标签/差评类型;`updateOverCallInfo` 把 `currentCallInfo` 存入 `lastCallInfo` 并重置。直播私call挂断后进 `waitingReturnLive`,倒计时回直播。

**未接**:`apiMissCall` / `missedCallsReport` 上报(missedReason 1对方挂断/2超时未接/3我方10s内挂断/6我方10s以上挂断)。

**匹配**(单列):`home/match.vue` 进出匹配池,匹配命中后走来电流程接通。

### 2.2 安卓端(android-anchor)
主链路 `ShengWang1V1CallActivity.kt`(基于声网 `io.agora.onetoone` CallApi SDK,经 `CallServiceManager.callApi` 统一管理)。

**拨打入口** `CallMatchHelper.avchat(activity, sourcePage, userEntity)`(单例 + 策略模式):
1. `isCanCallWithTime` 校验拨打间隔(`anchorPeerToPeerInterval` 分钟,本地 `UserPreferences` 记录上次拨打时间),超限提示"X 分钟内只能拨打一次"。
2. `ShengWangCallUtils.createCall` 创建通话 → 成功 `ShengWang1V1CallActivity.start(...)`(声网主链路);失败 fallback 到 `avChatStrategy.avChat`(NERTC 备用链路 `AVChatActivity`)。
3. `sourcePage` 标记来源(1首页/2详情/3朋友圈/4匹配/5主播推荐/6私聊/7通话记录)。

**通话状态机**(声网 `onCallStateChanged(state, reason)`):
- `Calling` 呼叫中(被叫时已被 `CallServiceManager` 拦截);`Connected` 接通(主被叫都回调,展示通话页);`Prepared` 空闲态,按 reason 分流:`LocalCancelled/RemoteCancelled`(取消)、`LocalHangup/RemoteHangup`(挂断)、`LocalRejected/RemoteRejected`(拒接)、`CallingTimeout`(自己呼叫超时)、`RemoteCallingTimeout`(对方未接)、`RemoteCallBusy`(对方忙);`Failed` 失败;`Idle` 空闲。
- **自动接听**:`isLiveCall()`(直播间私call)或 `isPartyCall()`(派对房私call)→ 自动 `acceptCall()`,无需主播手动。
- `acceptCall()`/`reject()`/`hangup()` 分别触发对应 reason,经 `hAgoraOnCallStateChanged` 埋点。
- `missCall(channelId, missedReason)` 未接上报。

**策略分流**(`IAVChatStrategy` 接口,`NormalAVChatStrategy` vs `ReviewAVChatStrategy`):
- `Normal`:正常主播,`match()` 走 `checkBalance` 余额校验。
- `Review`:审核态主播,余额校验逻辑不同(审核状态放行)。
- 两者都封装 `avChat`(NERTC 通话)与 `match`(匹配)。

**其他通话变体**:`RobotCallActivity`(机器人通话,配 `RobotCallingDialog`/`RobotCallAwardDialog`)、`VirtualCallActivity`/`VirtualChatActivity`(虚拟/假人来电,引流策略)、`MatchActivity`/`MatchingActivity`(匹配池)、`CallRecordsActivity`(通话记录)、`ChatScoreActivity`(通话评分)。

### Web SDK
- **Agora RTC**(`agora-rtc-sdk-ng`):通话音视频建链,`callApi.accept/reject/destory`,本地轨道 `_createLocalCameraAndMicTracks`,美颜 NamaSDK。
- **Agora RTM**(`agora-rtm`):1v1 信令(`CallRtmMessageManager`,`rtmClient.publish` 发、`message` 事件收,Uint8Array 编解码),断线重连 `useRtmReconnect`。
- **NIM**:辅助信令(`CALL_NIM_TYPE` 0在线/1拒接/2取消/3挂断/4已连接)+ 计费/收入回推(`attachType` 4/15,支付等待 `attachType -6` 的 `CALL_PAY_NIM_TYPE` 1发起/2成功/3暂停/4取消)。

### 安卓 SDK
- **声网 CallApi**(`io.agora.onetoone`,主):1v1 信令 + 建链,`CallServiceManager` 统一管理 `callApi` 实例与状态。
- **网易 NERTC**(G2 模块,备用):`AVChatActivity` 走 NERTC + NIM avsignalling,策略 fallback 时使用。
- **Agora RTM** + NIM:信令与消息。前台保活 `StayService`(microphone|camera)。

## 4. 状态与数据流

**Web 通话状态**:`myCall.js` 的 `currentCallInfo` 是单一数据源,关键字段:`callFrontGameType`(通话来源)、`callGameStatus`(0init/1calling/2cancel/3calling_ing/4hangup/5timeout)、`channelId`/`yxAccid`/`callUserId`、计时三元组(`callStartTime` 拨出/`callConnectTime` 连接/`callingStartTime` 正式开始)、`callIncome`/`callGiftIncome`、`deductionErrMaxNum`。`isCalling` getter = 有 `callFrontGameType` 或 `callStartTime`。
**安卓通话状态**:声网 `CallStateType` 枚举(Idle/Prepared/Calling/Connecting/Connected/Failed)由 SDK 维护,业务层监听回调驱动 UI 与计费。

**计费心跳**:Web `callDeductionFee` 周期上报(扣费失败重试 3 次耗尽则系统结束,overReason=8);收入由后端经 NIM 回推,前端只累加展示。安卓同理由 CallApi/后端计费,主播端展示收益。

**通话结束原因 `CALL_OVER_REASON_NUMBER`(1-11)**:1本地挂断/2远端挂断/3用户余额不足/4心跳失败/5扣费余额不足/6用户弱网/7主播弱网/8扣费失败/9用户被踢/10 beginCall报错/11并发取消。

## 5. 边界与异常
- **未接/超时**:Web 主叫 30s 超时自动取消(`signalingInviteTimeout`);安卓 `CallingTimeout`/`RemoteCallingTimeout`。
- **断线重连**:Web RTM `useRtmReconnect` 退避重连;声网/NERTC 自带重连。
- **对方拒接/忙**:Web `callApi.reject` + `callRate`;安卓 `RemoteRejected`/`RemoteCallBusy`。
- **余额不足**:用户侧扣费失败 → overReason 3/5;`attachType -6` 支付等待状态(发起/成功/暂停/取消)。
- **人脸校验失败/拨打限制**:安卓 `CallMatchHelper.isCanCallWithTime` 间隔限制;`apiHasExceededCallLimit` 通话限制策略。
- **并发竞态**:Web `joinCallGetUserInfo` 中校验 `callStartTime` 防"通话已取消仍接听";overReason=11 并发取消。
- **直播/PK 抢占**:接私call前若在 PK 惩罚先结束惩罚、若在直播先暂停直播;挂断后回直播。

## 6. Web vs 安卓 差异提示
| 维度 | Web (h5-anchor) | 安卓 (android-anchor) |
|---|---|---|
| 通话页形态 | **全局浮层**(g-waitingCall/g-remote-pip),无独立路由 | **独立 Activity**(ShengWang1V1CallActivity) |
| RTC 栈 | Agora 单栈 | **声网(主) + NERTC(备)双栈**,策略 fallback |
| 信令 | Agora RTM 为主 + NIM 辅助 | 声网 CallApi 内置 + NIM + RTM |
| 状态机 | 自管 `callGameStatus` + CallApi state 映射 | 声网 `CallStateType` SDK 托管 |
| 拨打间隔限制 | 后端 `hasExceededCallLimit` | 端侧 `CallMatchHelper` 本地记录 + 后端 |
| 审核态策略 | 无显式策略类 | `Normal`/`Review` 策略模式分流 |
| 机器人/虚拟通话 | `fakeUserCall` store + `useCallRobot` | `RobotCallActivity`/`VirtualCallActivity` 独立页 |
| 直播私call自动接听 | `liveState` 判定自动 `callInEnter` | `isLiveCall()`/`isPartyCall()` 自动 `acceptCall` |

## 7. iOS 实现注意点
1. **信令选型**:建议对齐安卓声网 `CallApi`(1v1 信令+建链一体),iOS 有对应 SDK;NERTC 备用链路 iOS 是否保留需产品决策(安卓 NERTC 疑似退役中,iOS 可只做声网单栈)。
2. **CallKit 集成**:iOS 来电建议接 CallKit(系统级来电 UI + 后台唤醒),配合 VoIP 推送;后台麦克风/摄像头权限(Background Modes: audio/voip)。
3. **状态机**:复刻 `CallStateType`(idle/prepared/calling/connecting/connected/failed)+ reason(取消/挂断/拒接/超时/忙)分流;通话来源 DIRECT/MATCH/LIVE/BOT 四类。
4. **计费心跳**:`callDeductionFee` 周期上报,失败重试 3 次;收入经 NIM `attachType` 4/15 回推,前端只展示;结束原因码 1-11 对齐。
5. **自动接听**:直播间私call / 派对房私call 自动接听(`callerType` 判定,Web `liveState`、安卓 `isLiveCall/isPartyCall`)。
6. **抢占与恢复**:接私call前结束 PK 惩罚 / 暂停直播,挂断后倒计时回直播。
7. **拨打间隔限制**:对齐 `anchorPeerToPeerInterval` 分钟级限制 + `hasExceededCallLimit`。
8. **未接上报**:`missCall` + missedReason(1/2/3/6 区分)。
9. **机器人/假人通话**:`fakeUserCallIn/Out`(`/homeTraffic/*`),免费,业务定位需与产品确认(引流/审核)。
