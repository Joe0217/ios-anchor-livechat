# IM / 聊天 / 消息中心 业务域 — 模块级业务逻辑梳理(Web / 安卓双端)

> **需求** DM-20260616-004 · **阶段二交付物**(对应需求步骤2)· 业务域 T0-5

## 1. 业务目标与定位

主播端 IM 体系基于**网易云信 NIM**(Web 用 `nim-web-sdk-ng` 10.7,Android 用 NIM 10.7.0),承载主播与用户间的全部异步互动,是除音视频通话外的第二条核心营收/留存链路。覆盖三大场景:

- **单聊(P2P)**:文本 / 图片 / 视频 / 语音 / **付费私密图文**收发,叠加礼物、回复积分(宝箱)、裂变弱文本、亲密度等运营玩法。
- **消息中心(News)**:会话列表分类(Flame 熟客 / Stranger 陌生人 / Prime 高等级)、通话记录、关注、站内信、系统消息、CP 榜奖励通知,以及**主播群发**(批量/随机文案/付费点数图文)。
- **业务通知管道**:复用 IM 系统消息(sysMsg)下发通话控制、充值到账、合规处罚、入场动画、任务奖励等几十种 `attachType` 事件,IM 通道实质上是整个 App 的实时业务总线。

## 2. 核心业务流程

### 2.1 Web 端
**会话列表加载**:登录后 `app.js` 调 `nim.connect()` 绑定事件回调。SDK 推 `sessions` → `sessionStore.onSessions`:截断 200 条 → `syncCloudSessionExtData` 拉云端会话扩展写本地 → `batchUpdateSessionList('init')`。后者对每条 `formatSecretData` + 批量请求名片/Prime 过滤/Flame 列表 → `mergeArrays` 智能合并 → 按 `updateTime` 排序,累加未读,分类未读推 `newsStore`。增量走 `onUpdateSession`(debounce 2s)。三类分类 getter:`filterSessionsByFlame`(关注/`extra.receivedGift|called|received+sended`)、`filterSessionsByStranger`(取反)、`filterSessionsByPrimeLevelLimit`。

**进单聊**:`views/chat/index.vue` `loadHistoryMsgs(to)` 三态拉取(本地有→loaded;IM 未登录→unavailable;云端确无→empty)。进页 `checkPrivateInfo` 扫 `ext.extensionType==='privateMsg'` 的 `privateId`,批量 `apiCheckPrivateInfo` 回写 `lockStatus`。

**收发**:
- 文本 `sendTextMsg` → `nim.msg.sendTextMsg`,透传气泡 `ext={chatBubble}`,成功后积分 + `trySettleReplyPoints`;失败 `No_connected`→`sendFailed`,`7101`(拉黑)→`refused`。
- 图片/视频 `sendPicture`:`type=1` 普通(`ext=''`);`type=2` **付费私密**:先 `getSendPrivateInfo` 拿价格/privateId 组 `ext={extensionType:'privateMsg', data:{privateId,iconType,videoUrl,userId}}`。
- 语音 `recording.vue` 录制 → `nim.cloudStorage.uploadFile` → `sendAudioMsg({attach:{url,dur}})`。
- 收消息走 `messageStore.onMsg`(见 §3)。

### 2.2 Android 端
- **会话列表**:`MsgMainFragment`(Tab 容器)下挂 `MsgListFragment`(云信会话)、`NewsFragment`/`NewsMissedFragment`(记录/未接);依赖 uikit `RecentContactsFragment` + `OnlineStateEventHelper`。
- **进单聊**:`NIMMessageActivity`/`LiveNiMMessageActivity`(直播中),承载 `NimMessageFragment extends MessageFragment`(uikit `P2PMessageActivity` 基座)。
- **收发**:复用 uikit `MessageFragment` 管线,主播侧扩展埋点(`uploadInteractSendPoint`/`ReceivePoint`,12 小时窗口判断"主播回复新会话")。`NoInteractionContactsActivity` 管无互动联系人。
- **群发**:`GroupMsgDialog` → `SendGroupMsgDialog`,`isCheckLevelCanGroupSend(userLevel)` 校验等级 → `batchSend(MSG/PIC)`。`SendMyImageDialog` 选图,`PayMsgPointRecordDialog` 看付费点数记录。
- **系统消息/站内信**:`SystemMessageActivity`/`StationInfoListActivity`/`LiveNewsActivity` 独立页,走 HTTP。

## 3. 关键接口 / SDK

### NIM 事件绑定(Web,`app.js`)
统一 `off` 再 `on`:`logined`/`willReconnect`/`disconnect` → 连接态(`onConnect` 置 `IMOnline=true`);`sessions`/`updateSession` → 会话列表;`msg` → `onMsg` 在线消息总入口;`syncRoamingMsgs`/`syncOfflineMsgs` → 漫游/离线(节流 2s);`syncSysMsgs`/`sysMsg` → 系统消息;`msgReceipts` → 已读回执。

**`onMsg` 在线消息管线**(同步链关键顺序):`updateActiveTycoonFromMsgExt`(活跃大R)→ `addAdminMsgToCache`(客服 30天/100条)→ `formatSecretData`(parse ext)→ 裂变 tip(`weakTxtType` 103已充值/104未充值)→ USDT 支付状态 → 当前页 `handlePayMsg` → `useNoticeFunc`(节流 2s 弹窗)→ `addMsgToMsgArr`(push + 200 条裁剪)→ Flame/Stranger 标记 → 朋友圈刷新。

**`onSysMsg` 业务总线**(按 `attach.attachType` switch 节选):

| attachType | 含义 | attachType | 含义 |
|---|---|---|---|
| -1 | 通话内对端消息(翻译) | -3 | 通话取消/拒绝/挂断(嵌套type) |
| -4 | 关注 → followNum++ | -6 | 通话充值等待状态 |
| 4/15/18 | 通话内送礼/分钟收益/礼物收益 | 16 | 索礼被拒 |
| 35 | 用户充值成功 | 44/61/62 | 强制下播/合规警告/封禁 |
| 58 | 主播审核状态变更 | 63/64 | 进/出折扣池 |
| 83 | 私call入场座驾动画 | 90 | 通话等待充值奖励 |
| 132/133 | 假人结束/来电 | 135 | 新主播任务奖励 |

### 自定义附件类型约定(attach.attachType / type)
- **Web**:字符串型 `SEND_GIFT`(P2P 礼物)、`CP_RANK_REWARD_NOTIFY`/`CP_RANK_PRE_END_NOTIFY`、数字型 `99`(代充到账)、`70`(推荐主播)。
- **Android**(`CustomAttachParser` 双分支):
  - **数字分支**(`{type,data}`):`Gift=1`、`INVITE_JOIN_PARTY_ROOM=1002`。
  - **字符串分支**(顶层 `attachType`):`SEND_GIFT`→`NewGiftAttachment`、`MISSED_CALLS_RECORD`→`MyNetCallAttachment`、`INTIMACY_TIPS`→`IntimacyTipsAttachment`、`ITEM_GET/EXPIRED_NOTICE`→`VirtualItemAttachment`、`CP_RANK_REWARD_NOTIFY`→`CpRankRewardAttachment`、`AGENT_RECHARGE_NOTIFY=151`(代充,int,需与 H5 `99` 语义对齐)。
  - 解析失败兜底 `DefaultCustomAttachment`;渲染由 `SessionHelper` 注册 ViewHolder。

### HTTP 接口分组
- **`api/chat`**:`apiCheckPrivateInfo`/`apiGetPrivateInfo`/`apiGetSendPrivateInfo`(付费私密图文)、`apiGetAnchorMessageBox*`(宝箱)、`apiSettleReplyPoints`(回复积分)。
- **`api/news`**:`apiGetRecordList`(通话记录)、`apiGetFriendList`、`apiGetStationList`(站内信)、`apiGetAdminList`(客服)、`apiBatchSend`+`apiGetBatchSendCount`(旧群发)、`apiGetAnchorDailySendCount`/`apiGetCopywriting`/`apiBatchSendMsgToUser`(`/massMsg/*` 新群发)、`apiGetAnchorIntimacy`(亲密度)。

## 4. 状态与数据流
- **消息入 store**:`sessionMsgs[sessionId].msgArr`(**不持久化**,单会话上限 200 条 LRU 裁剪);漫游/离线经 `_tmpMsgList` 节流 2s 后去重(按 `idClient`)合并。
- **会话与未读**:`sessionStore.orderedSessions`(持久化);未读 `nim.session.resetSessionUnreadCount` 复位;分类未读聚合推 `newsStore`;客服走独立 `adminChatCache`(30天/100条)。
- **IM 在线/离线**:`appStore.IMOnline` 由 `logined`/`disconnect` 维护;`loadHistoryMsgs` 校验 `IMOnline` 才拉取;在线订阅 `subscribeEvent`(type=1,30天,**LRU 上限 100 账号**)。
- **付费私密图文解锁**:发送组 `ext.data.privateId`;接收进页 `apiCheckPrivateInfo` 回填 `lockStatus`(0解锁/1锁定),`msgItem.vue` 据此模糊/预览。
- **回复积分(宝箱)**:`isOpenPaidMessage` 开启时用户消息按 `ext.msgType`(free/pay)累加进度;主播回复 `trySettleReplyPoints`,礼物消息不计积分。

## 5. 边界与异常
- **离线消息拉取**:`syncOfflineMsgs`/`syncRoamingMsgs` 节流 2s;同批次同 sessionId **追加而非覆盖**。
- **消息撤回**:store 保留 `updateMsgInMsgArr` 占位(按 `idClient` 替换)。
- **发送失败重试**:`No_connected`→`sendFailed` + 重发 `resendMsg`;`7101`→`refused`(被拉黑)。
- **付费校验失败**:`formatSecretData` 对畸形 JSON `try/catch` 保留原值;`ext.data` 缺失判空防 NPE。
- **敏感内容/鉴黄**:前端未主动鉴黄,依赖后端审核 + IM 合规处罚(`onSysMsg` 61 警告/62 封禁/44 强制下播)回推。

## 6. Web vs 安卓差异提示
| 维度 | Web (h5-anchor) | Android (android-anchor) |
|------|------|------|
| 消息体系 | 自建 Pinia store 解析(`message.js` 巨型 onMsg/onSysMsg),UI 全自绘 | 复用 NIM uikit `MessageFragment` 基座 + ViewHolder,解析集中 `CustomAttachParser` |
| 群发 | `bulkMsgPopup`(`/massMsg`) + `randomMsgPopup`,刷新文案/每日次数/冷却 | `SendGroupMsgDialog`(`batchSend`) + 付费点数记录,等级门槛硬校验 |
| `communication` 目录 | 疑似**旧版冗余**单聊,主链路走 `chat/`,建议核对引用后清理 | 无对应 |
| 自定义附件覆盖 | 字符串/数字 attachType 散落 if 判断,无集中枚举 | 集中 `CustomAttachmentType.kt` 枚举,类型安全更好 |
| 业务总线 | `onSysMsg` 承载几十种 attachType | 分散到各 Activity + LiveEventBus + Action |

**一致性要点**:付费私密图文 `ext.extensionType='privateMsg'` + `data.privateId`/`lockStatus`、群发 `serverExtension.msgType='groupSend'`、气泡 `ext.chatBubble`、回复积分 `ext.msgType` 三端需严格对齐。

## 7. iOS 实现注意点
1. **NIM iOS SDK 对齐 10.7**:事件回调覆盖 Web 全集(onMsg/离线/漫游/sysMsg/receipts/在线订阅),离线与在线消息的**去重升序合并**要复刻(按 `idClient`/`messageId`)。
2. **自定义附件解析对齐**:同时支持 `{type,data}` 数字型(Gift=1、INVITE_JOIN_PARTY_ROOM=1002)与顶层 `attachType` 字符串型;代充 `AGENT_RECHARGE_NOTIFY=151` 是 int,注意与 H5 `99` 语义映射;解析失败需兜底不崩溃。
3. **ext / attach 二次 parse**:`ext` 与 `ext.data` 可能是嵌套 JSON 字符串,畸形数据容错保留原值。
4. **付费私密图文**:发送组 `ext`;进页批量 `checkPrivateInfo` 回填 `lockStatus` 控制模糊/解锁,与 Web 一致。
5. **会话分类(Flame/Stranger/Prime)**:依赖云端会话 `ext` + 关注名单 + Prime 接口,实现三类聚合与未读统计。
6. **IM 在线态门控**:拉历史/发送前校验连接态,区分"未登录"与"确无历史"。
7. **群发与回复积分**:群发走 HTTP(`/massMsg/*` 或 `batchSend`)+ 等级校验,非 IM 直发;回复积分按 `msgType` free/pay 累加并 `settleReplyPoints`,礼物不计分。
