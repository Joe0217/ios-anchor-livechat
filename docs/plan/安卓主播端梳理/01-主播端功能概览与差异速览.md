# 主播端功能概览与差异速览

> **需求**：DM-20260616-004 原生iOS主播端 · **阶段一交付物**（对应需求步骤 1）
> **范围**：仅文档分析，不写 iOS 代码 · **颗粒度**：模块级业务逻辑
> **对象**：Web 主播端 `h5-anchor` ⟷ 安卓主播端 `android-anchor`
> **目的**：为未来「原生 iOS 主播端」建立功能全景与差异基线，作为后续深度梳理（步骤2）与差异分析（步骤3）的索引。

---

## 1. 两端技术与架构速览

| 维度 | Web 主播端（h5-anchor） | 安卓主播端（android-anchor） |
|---|---|---|
| 技术栈 | Vue 3.4 + TS + Vant4 + Pinia + Vite5 | Kotlin/Android，Gradle 多模块 |
| 包名/标识 | webview 内嵌运行 | `com.gzxkwl.livehot`，scheme `anchorapp://` |
| 路由 | unplugin 文件式路由（目录即路由） | ARouter + 直接 startActivity + IActivityBridge 桥接 |
| 主导航 | 4 区：**首页 / 消息 / 工作台 / 我的**（无派对） | 5 Tab：**首页 / 消息 / 派对 / 工作台 / 我的** |
| IM | 网易云信 NIM（nim-web-sdk-ng） | 网易云信 NIM 10.7.0（basesdk+chatroom+avsignalling+push，独立进程） |
| RTC | Agora RTC（单栈）+ Agora RTM 信令 | Agora RTC 4.1.1（主）+ NERTC 4.6.66（备）+ Agora RTM 2.2.1 |
| 美颜 | NamaSDK + MediaPipe + face-api.js | FaceUnity 8.11（FURenderKit）+ MLKit Face |
| 支付/收款 | Airwallex；提现+人脸活体 | OSS + 多收款通道（Payoneer/EPay/Digifinex/USDT）+ H5充值回跳 |
| 埋点 | 数数 ShuShu | ThinkingData + Bugly |
| 平台特性 | webview、文件式路由 | 前台保活 StayService、Tinker 热更、FCM 推送、Adjust 归因、审核态独立壳 |

> **架构启示（对 iOS）**：iOS 端需自带原生 RTC（声网/NERTC iOS SDK）、NIM iOS SDK、FaceUnity iOS、前台音视频权限与后台保活策略；Web 的「文件式路由 + 全局浮层组件」模式不可直接移植，需按安卓的 Activity/页面边界来对标。

## 2. 统一业务域分类体系

为对齐两端，统一归入 12 个业务域：

1. 直播核心（开播 / 直播间 / 下播 / 规则）
2. 连麦 / 1v1 通话
3. 直播 PK
4. 派对房 / 多人语音房
5. IM / 聊天 / 消息中心
6. 变现（钱包 / 提现 / 收款 / 道具 / 计费 / 房币）
7. 任务 / 成长 / 工作台
8. 数据 / 排行榜
9. 账号（登录注册 / 资料 / 设置 / 认证 / 审核态）
10. 美颜 / 录制 / 短视频
11. 社交 / 内容（圈子 / 关注 / 亲密度 / 邀请）
12. 其他 / 长尾（启动 / 容器 / 活动 / 保活）

## 4. 差异速览结论

### 4.1 仅安卓有（🅐）—— iOS 需重点决策是否纳入
- **派对房/多人语音房全套**（最大变量）
- 短视频 ShortVideoActivity
- 进阶美颜（动漫/绿幕/美体/海报换脸）
- 计费定价页、房币兑换、违规记录页
- NERTC 备用通话链路、前台保活服务

### 4.2 仅 Web 有（🅦）
- 大R（bigr）高价值用户专页
- communication（疑似 news 旧版冗余，待确认是否死代码）

### 4.3 双端有但能力/形态差异显著（⚠️）
- 1v1 通话：Web 全局浮层 vs 安卓独立 Activity（iOS 倾向参考安卓页面边界）
- 直播间：Web 开播+直播间同页 vs 安卓拆分
- 代理/公会、收款通道、亲密度：安卓体系更完整
- 审核态：Web 降级页 vs 安卓独立审核壳
- 美颜：安卓 FaceUnity 全功能 vs Web 基础

### 4.4 双端高度一致（✅，可直接作为 iOS 基线）
直播 PK、IM/聊天/消息、任务成长、排行榜、圈子/关注/邀请、登录注册资料、人脸认证、提现主流程。

## 6. 疑点汇总（两端合并，待产品/后端确认）

**Web 侧**
1. `news` vs `communication` 高度重复，疑似旧版冗余。
2. `task` vs `dailyTask` 接口重叠（同 `task/v2/get`）。
3. `liveRoom` vs `liveSetting` 命名反直觉（`liveSetting` 才是直播间主体）。
4. `vedioRecorder` 纯本地录制无后端，疑似调试/工具页。
5. 路由鉴权守卫 `beforeEach` 已被注释禁用。
6. `api/gifts.js` 与 `api/gift/index.ts` 并存，疑似遗留。

**安卓侧**
1. `keep` 模块在 settings.gradle 已注释，未参与编译。
2. 双 RTC 栈并存（Agora 主 / NERTC 备），NERTC 疑似退役中。
3. 机器人/虚拟通话（Robot/Virtual Call、ReviewAVChatStrategy）业务定位待产品确认。
4. `MineFragment` / `MeFragment` / `HomeProfileFragment` 三者「我的」职责边界重叠。
5. ARouter 路由暴露极少，跨模块多直接 startActivity，解耦不彻底。

**跨端**
- 派对房是否纳入 iOS，是排期最大变量。
- communication / bigr 等单端功能，需确认是业务差异还是历史遗留。
