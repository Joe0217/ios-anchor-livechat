# 变现业务域(钱包/提现/收款/虚拟道具/计费定价)— 模块级业务逻辑梳理(Web / 安卓双端)

> **需求** DM-20260616-004 · **阶段二交付物**(对应需求步骤2)· 业务域 T1-6
> 房币(宝石/钻石/金币)兑换不在此域展开,详见 `02-04-派对房.md`。

## 1. 业务目标与定位

本域是主播侧"赚钱闭环":主播通过直播/通话/任务/邀请积累**钻石(diamond)收益** → 钱包查看余额与流水 → 绑定**收款通道**(USDT/Epay/Digifinex)→ 经**校验+人脸活体+交易密码**发起**提现**,钻石按汇率折美金到账。配套:**虚拟道具背包**(座驾/头像框/聊天气泡/资料卡边框查看与穿戴)、**计费定价**(安卓:通话单价/付费图片)、**代理/公会**(安卓:代充售钻/公会设置)。

钻石是平台统一虚拟货币:既是用户消费货币(充值得来),也是主播收益单位(提现折美金)。Web 与安卓共用同一套后端钱包/提现/人脸接口,差异主要在收款通道开关、计费定价、代理体系、转盘等增值玩法。

## 2. 核心业务流程

### Web 端(h5-anchor)
**A. 余额与收益** `views/wallet/index.vue`:`apiMyBalance`(`/api/wallet/anchor/flowList/myBalance`)拉钻石余额/折美金/今日收益;收益明细走 **sapi** `bill/list` 分页 20 条,`message` 类型映射为 `unlock`(私信解锁收益)。
**B. 提现** `views/wallet/withdrawal/`:进页拉 `apiMyWallet`(可提额/汇率/描述)+`apiGetAccountList`(已绑账户)→ 选账户+输钻石,前端校验(≥200、≥汇率)+折算(`美金=trunc(钻石/汇率)`、手续费、零头返还)→ `tipDialog` 确认 + 通道最低额(Digifinex≥$20/Epay≥$50)→ **人脸判定** `faceAuthVerifiedApi`(true 拉活体,false 直接密码)→ 活体成功 → `getAnchorWithDrawConfig` 查密码状态 → 未设则设 6 位数字交易密码,已设则输入 → `apiApplyWithdraw`(`applyWithdrawV2`)→ 跳提现记录。
**C. 收款方式** `views/wallet/addCollectionMethod/`:三通道 Digifinex(UID)/USDT(TRC20)/Epay(姓名+邮箱),`addWithdrawAccount`/`delWithdrawAccount`。
**D. 虚拟道具** `views/virtualProps/`:**sapi/marketing** `item/page` 分页,Tab `itemType`(2头像框/1座驾/4聊天气泡/5资料卡边框),`isFromBag`/`wearStatus`/`expireTime`;穿戴卸下 `item/ops`(同类型互斥并写 `userStore.mineInfo` 供气泡/资料卡实时读取);预览弹窗支持大图/动效。

### 安卓端(android-anchor,mine 模块)
**A. 钱包/提现** `WithdrawalActivity`(类注释"钱包首页",充值入口已迁 H5):`getMyWallet` 拉 `MyWalletEntity`(可提额/钻石/汇率/账户/各账户 minRequestAmount+serviceCharge)→ 选账户+输钻石(**比 Web 多**:超额自动截断、按账户最低额校验)→ `isFaceRecognition` true 则申请相机权限 + 原生 `FaceRecognitionActivity`(MLKit,RC=1032)→ 人脸 OK → `WithdrawalTipsDialog` → `getAnchorWithDrawConfig` → `SetWithdrawPwdDialog` → `applyWithdraw`(同 Web 接口,零头返还按 `inputNum-余数` 提交)。
**B. 收款通道** `AddPayKindActivity` → 子页 `AddPayOf{Usdt,Epay,Payoneer,Digifinex}Activity`;`MyPayAccountListActivity` 管理。**当前仅启用 USDT/Epay**(Payoneer/Digifinex 已注释)。
**C. 计费定价(安卓独有)**:`ChatPriceActivity`(通话单价档位 800/1000/1200/1500/2000 钻/分钟,`updateUserInfo({price})`)、`PricePictureActivity`(付费图片)、`PaidActivity`(付费消息收益按月查询)。
**D. 收益/账单**:`EstimatedIncomeActivity`/`BillingActivity`/`MyBalanceDetailsActivity`。
**E. 代理充值/公会(安卓独有)**:`ProxyChargeFragment`(代理售钻统计,无权限错误码 `1005`;创建/确认订单 + 代理交易密码;H5 充值入口 `RechargeJumpHelper`)、`ApplyForVipActivity`、`AgencySettingActivity` 系列。转盘 `TurntableGameActivity`(app 模块)。

## 3. 关键接口/SDK 分组
- **钱包/收益**(`/api/wallet/anchor/*`):`flowList/myBalance`、`myWallet`、`flowList`(Web 走 sapi `bill/list`);安卓 `getPaidDetail`。
- **提现**(`/api/wallet/*`):`applyWithdrawV2`、`getAnchorWithDrawConfig`、`setWithdrawPassWord`、`withdrawRecord`。
- **收款**:`withdrawAccountList`/`addWithdrawAccount`/`delWithdrawAccount`。
- **人脸活体**:`/api/face/auth/verified`(是否需人脸)、`/api/face/auth/scan`(提交照片比对)、`getOssKey`(OSS STS)。
- **虚拟道具**(sapi/marketing):`item/page`、`item/ops`、`exchangeToken`(背包商城 token)。
- **SDK/支付**:Web 人脸用 **face-api.js**(动态 import)+ **ali-oss** STS 直传,充值 Airwallex/三方;安卓人脸原生 `FaceRecognitionActivity`(MLKit),充值 H5。安卓接口 Base64 URL + AES 加解密。

## 4. 状态与数据流
**收益来源**:直播打赏、1v1 通话(按 `videoPrice` 钻/分钟)、付费消息/私信解锁、任务激励、邀请奖励;沉淀为钻石,在 `bill/list`/`flowList` 按 type 分类。
**提现状态机**(两端一致):`输入钻石→额度/汇率校验→通道最低额→人脸判定(verified)→[需要]活体→[成功]交易密码(config→set/apply)→applyWithdrawV2→提现记录`。金额换算:`美金=trunc(钻石/diamondRate)`、`到账=美金*(1-serviceCharge/100)`、`零头返还`。
**人脸活体流程**(Web `faceLiveness.vue`,iOS 重点参考):三动作状态机 **摇头→点头→正脸**,各 5 秒超时,环形进度;200ms 检测 `detectSingleFace+withFaceLandmarks` 按关键点几何判定(连续 5 帧);完成 `canvas` 截图 → ali-oss STS 直传 → `faceAuthScanApi` 后端比对。安卓为原生实现,回传 RESULT_OK/失败原因。

## 5. 边界与异常
- **提现风控**:必须先绑账户、设 6 位交易密码;密码错误码 `2007`(密码错)/`2008`(错误次数过多锁定),客服 WhatsApp 找回。
- **人脸失败**:无人脸/动作超时/比对不通过 → 可重试;iOS 需处理相机权限拒绝、弱光、模型加载失败。
- **余额/额度不足**:低于通道 `minRequestAmount` 或汇率拦截;安卓超额自动截断;不足 1 美金零头返还。
- **收款账户校验**:通道差异最低额;信息错误需联系客服(前端不可改)。
- **道具**:未拥有不可穿戴;切 Tab 用 `loadSeq` 丢弃过期分页响应。
- **代理**:无权限错误码 `1005`。

## 6. Web vs 安卓差异提示
| 维度 | Web(h5-anchor) | 安卓(android-anchor) |
|---|---|---|
| 收款通道 | USDT/Epay/**Digifinex** 三通道 | 仅 **USDT/Epay**(Digifinex/Payoneer 已注释) |
| 人脸活体 | face-api.js 三动作+OSS 直传+scan | 原生 `FaceRecognitionActivity`(MLKit) |
| 提现校验 | ≥200 且 ≥汇率 | 按各账户 `minRequestAmount`,零头取整返还 |
| 计费定价 | 无 | **独有**:通话单价/付费图片/付费消息 |
| 代理/公会 | 无 | **独有**:`ProxyCharge`/`ApplyForVip`/`AgencySetting` |
| 转盘 | 无 | **独有**:`TurntableGameActivity` |
| 充值 | Airwallex/三方 H5 | Google Billing 已废弃,改 H5 `RechargeJumpHelper` |

## 7. iOS 实现注意点
1. **共用后端接口**:钱包/提现/收款/人脸/道具接口两端一致,iOS 直接对接,无需新增后端;sapi 需先 `exchangeToken`。
2. **提现是强校验串行链**:额度→汇率→通道最低额→人脸判定→交易密码 完整顺序,任一环失败可回退;密码错误码 2007/2008 差异化提示;零头返还保留。
3. **人脸活体优先用原生**:iOS 建议参照安卓用原生 Vision/活体 SDK 做三动作,但**照片上传比对仍走 OSS STS + `/api/face/auth/scan`**,先 `verified` 判定触发。
4. **收款通道按线上开关**:首版对齐安卓(USDT/Epay),Digifinex 视配置再开;各通道最低额、字段照搬。
5. **计费定价/代理/转盘为安卓特性**:是否纳入按产品定义;若做,通话单价档位、`updateUserInfo`、代理 `1005` 权限码可复用。
6. **虚拟道具状态同步**:穿戴/卸下后同步本地用户资料(头像框/气泡/资料卡边框)供 IM 气泡与资料卡实时渲染,同类型互斥。
7. **交易密码**:6 位纯数字,不落地明文;提现密码与代理充值密码是两套。
