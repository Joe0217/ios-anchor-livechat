# Hily 原生 iOS 主播端 · 全量上线里程碑路线图

> 工程：`/Users/joe/Desktop/HN/ios-anchor-livechat`（Hily.xcworkspace，bundleId `com.anchor.livechat`）
> 性质：本会话产出的**总规划骨架**，每个里程碑后续独立进入 spec → plan → implement 循环
> 节奏：一次性大版本首发，开发分阶段提测，核心三轴（直播 / 1v1 通话 / 派对房）骨架先行，附加功能再丰富

---

## Context（为什么做、做到哪、要解决什么）

H5 主播端 `anchor-livechat-h5`（1v1 视频通话 / 直播 / PK / 美颜 / 礼物收益）已用 Swift 原地升级为正式工程 Hily，由 POC 升至"直播闭环已真机跑通"的 60% 基线。问题是：

1. **没有总规划**：阶段一计划只覆盖到里程碑 C，没有阶段二/三全景，无法对外承诺一次性大版本首发；
2. **范围扩张**：用户最终决策为「9 模块 + 派对房（安卓全能对齐）」，比 H5 多一整条派对房业务线，需要从零搭建；
3. **三端基线冲突**：心跳频率/强制下播编码/弱网阈值，H5 与安卓不一致，iOS 必须定一套；
4. **文档准度风险**：H5 蓝本含死代码（USDT/discount.js/视频录制/gifts.js mock 等已确认废弃），现有规划文档部分章节与现状已脱节（如"新建独立仓库""声网 SPM 4.6.2"），按文档实现而不读 H5/安卓源码会造成返工。

**本规划目标**：交付 10 个里程碑的总路线图（A→J），含依赖关系、并行策略、共享基建抽取时机、文档校验机制、风险清单与提测策略，让"未来任一会话能独立做完任一里程碑的 spec → plan → implement"。

---

## 锁定的关键决策（不可改）

1. **覆盖范围**：H5 9 大模块 + 派对房（安卓全能对齐，含麦位/9 位装扮/打圈/转盘/红包雨/场控/PartyBattle/LuckyNumber/半屏游戏/房币/麦时统计/PartyCall 抢占）
2. **发版节奏**：一次大版本首发，但开发分阶段提测
3. **架构策略**：场景驱动（不预先抽 RoomSession 通用底座），事后抓 ≥3 处重复再抽
4. **强约束场景**：直播 → 转私 call（LiveStore 必须支持 `callState` 0→1 切换，对应 H5 `callState` 0直播/1通话/2匹配/3PK）
5. **心跳与强制下播基线**：**对齐安卓**——直播心跳 10s / 失败>3 次 → 强制下播；endType 用安卓数字编码（4/2/6/7/5）；弱网阈值原"≥10 次"被 **v5 反悔为分层 10/30/5（全部"连续"语义，中间任一次质量 ≤4 清零重计）**：连续 ≥10 次降帧率 30→15fps + toast / 连续 ≥30 次下播 endType=7 / 降级期间连续 ≥5 次质量好恢复 normal，详见 `B-LiveStore状态机-spec-*.md` §4.5；采集失败 >20s 保留对齐安卓
6. **音频通话**：**不做**——C 里程碑仅做视频 1v1，与 H5 现状保持一致
7. **派对房**：以安卓为唯一基线（H5 无任何派对房代码）；MVP→完整分两个里程碑 E/F
8. **虚拟来电（独立来电响铃页）**：**不做**（依据 `04-决策规格.md`，安卓侧已是死代码）

## 三、核心三轴拆分要点

### B — 直播闭环产品化
关键改造（粗到能让后续 spec 展开）：
- **LiveStore 状态机**：`idle → preparing → starting → living → (forceEnding|ending) → ended`，外露 `callState` 字段为 D/G 留口
- **HeartbeatController**：10s 间隔（对齐安卓）、`callState` 由 LiveStore 推导回写、连续失败 >3 次 → endType=4、解析响应 1992（封禁，endType=2）/2001（无权限，endType=6）
- **NetworkQualityMonitor**（v5 分层）：监听 Agora `networkQuality`；连续 ≥10 次质量极差 → 降帧率 30→15fps + toast；连续 ≥30 次 → endType=7；降级期内连续 ≥5 次质量好恢复 normal；采集失败 >20s → endType=5；PK 期间 pause/resume 钩子（G 里程碑用）
- **强制下播分流统一收口** `LiveStore.forceEnd(reason)`：endType 数字编码统一，正常结束 + 4 类强制
- **公屏闭环**：`NIMChatroomManager` 补 `connectionStateChanged` 重连；leave 复位 `onlineCount`；`GiftMessageParser` 解析骨架（识别 50/61/63 几类，动画占位留给 H）
- **相机错误回调**：CameraManager 错误 callback → `forceEnd(endType=5)`（与采集失败同口径）
- **美颜失败 fallback**：FUBeautyRenderer 初始化失败 → 降级 PassthroughRenderer 不黑屏
- **声网 token 续期**：`tokenPrivilegeWillExpire` → 拉新 → `renewToken`
- **userType 路由守卫**：RootView 接入分流（主播可进直播 / 代理受限层 / 其余 mineRestricted）
- **工程化收尾**：清理 ~16 处 print → os.Logger；AppConfig/AgoraConfig 硬编码迁 xcconfig；API 错误码统一分流（1004/1005/1992/1006/1080/2001）

### C — 1v1 通话从 POC 升生产（仅视频）
- **删除 `CallPOCView.test_call` 硬编码**
- **CallStore 状态机**：合并 H5 双层（CallStateType + callGameStatus）为单层 + 显式 guard：`idle → prepared → calling → connecting → connected → ended; failed`
- **CallService**：`createCall`（主叫）/ `joinCall`（被叫拉资料 3s 超时）/ `callRate`（四节点接通率上报）/ `hangup`
- **RTM 信令通道**：六类 CallAction（VideoCall=0/Cancel=1/Accept=2/Reject=3/Hangup=4；AudioCall=10 不接入）；ICallMessage JSON UTF-8 → Uint8Array
- **RTM 重连大脑**：1s/2s/4s 快速 + 5s 慢；token TTL 24h 提前 30s 主动续 + 被动监听；SAME_UID_LOGIN 致命态延迟 500ms 触发登出
- **CallView UI**：g-waitingCall（30s 本地圆环）/ g-faceTime（远端全屏+本地 PIP+公屏弹幕+收入条+索礼按钮+反馈）/ topBar（计时 + 10s 自检 `checkRemoteIsJoined` + `connectionStateIsConnected`）
- **充值等待蒙层**：NIM `attachType=-6` 三态机（START_PAY/CALL_TIME_END/PAY_CANCEL）→ 锁定远端 PIP + 暂停计时 + 60s 倒计时 + 5s 兜底强制挂断；`attachType=90` PAY_SUCCESS → 补偿暂停时长 + 钻石奖励
- **通话内礼物**：NIM `attachType=4` 触发动画占位（真实动画见 H）；`attachType=15/18` 累加 `callIncome/callGiftIncome`
- **索要礼物**：`askFor`（15s 冷却）+ NIM `attachType=16` 被拒 Toast
- **异常分流**：忙线自动拒绝；并发保护；`client-banned` → forceEnd '3' 等价

### D — 直播 ↔ 通话切换（转私 call）
- **LiveStore `callState` 0→1 切换**：直播中收到私 call 邀请 → 暂停直播心跳 → 切 `callState=1` → 启动通话状态机 → 通话结束 → `callState=0` → 恢复直播心跳
- **直播暂停-保留-恢复**：相机会话保留、美颜实例共享不重建、声网通道按需切换（同房间还是另起）
- **心跳互斥**：直播心跳与通话 callRate 节点上报不能并行计费
- **私 call 入场动画**：5s 倒计时倒计时返回直播

### E — 派对房 MVP
- **PartyRoomDataManager**（ObservableObject 单例）：`mRoomInfo` / `mMikeList` / `mOnMikeStartTime` / `accumulatedDuration` / `isJoinedChannel`；用 `CurrentValueSubject` 对应安卓 `replay=1`
- **三 ID 解耦**：业务 id / agoraChannelId / yxRoomId；进房 `enterRoom()` 串行：拉信息 → init RTC → join 频道（AUDIENCE）→ IM 进房 → fetchRoomInfo + pullMessageHistory(30) + registerRoomChatObservers
- **声网语聊场景配置**：`CHANNEL_PROFILE_LIVE_BROADCASTING` + `AUDIO_SCENARIO_CHATROOM` + `AUDIO_PROFILE_SPEECH_STANDARD`
- **麦位-RTC 对账中心** `postMikeList()`：全量遍历——他人在麦切静音/取消静音用 `adjustUserPlaybackSignalVolume`（播放端而非订阅层）；自己在麦切 BROADCASTER；不在麦切 AUDIENCE
- **核心 NIM attachType 分发（MVP 子集）**：`UPDATE_PARTY_ROOM_SEAT`（gzip 麦位）/ `UPDATE_PARTY_ROOM_SEAT_LIST`（全量 loadMikeList）/ `PARTY_ROOM_PROHIBIT_MIC` 禁麦 / `KICKED_OUT_PARTY_ROOM` 被踢 / `RECEIVE_PARTY_ROOM_GIFT_COMPRESSED(2049)` 双路分发
- **公屏聊天**：复用 NIMChatroomManager 模式；`remoteExtension` 塞 userId/role/勋章/气泡
- **送礼骨架**：`sendPartyRoomGift` / `sendBackpackGiftParty`；动画占位挂入 H
- **退房与最小化**：release → 结算麦时 → exitPartyRoom → destroy；按 downSeat → closeEngine → exitYxChatRoom 顺序

### F — 派对房完整玩法
管理动作 / 申请排队 / **PartyBattle PK**（按 NIM 推送实现，不做安卓注释掉的 60s 轮询）/ **LuckyNumber**（1050/1051/1052）/ **半屏游戏**（含 NIM 136/138 公屏）/ **房币兑换**（gem/exchange）/ **麦时统计**（上麦埋点起点 → 下麦/被抱下/切模版/退房/被踢累加）/ **PartyCall 抢占**（实现 ICallApiListener 等价；`callerType==5` → 停预览/关麦/5s 下麦；onCallEnd 重入频道恢复）/ 音乐播放 / 断线重连（NIM `UNLOGIN/NET_BROKEN` 置标志位）。**PartyCall 与 C/D 三方耦合最深，必须单独 spec**。
