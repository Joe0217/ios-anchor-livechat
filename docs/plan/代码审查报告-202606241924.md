### P1-4 NIMChatroomManager 非 MainActor，onRecvMessages 在 NIM 后台线程访问 weak pkRouter + @Published
- 文件：[Sources/Live/NIMChatroomManager.swift:15-198](../../Sources/Live/NIMChatroomManager.swift#L15-L198)
- 维度：Swift 并发
- 风险：`NIMChatroomManager` 整类未标 `@MainActor`，`onRecvMessages` 被 NIM SDK 在子线程回调时直接进入函数体：
  1. 读取 `weak var pkRouter`（写入在 main 上 `LiveRoomView.onAppear`），weak 引用的 atomic load 依赖运行时实现而非 Swift 语义

- 修复：对齐 [PartyRoomChatManager](../../Sources/Party/Chat/PartyRoomChatManager.swift) 写法——`NIMChatroomManager` 整类标 `@MainActor`；`onRecvMessages / chatroom(_:connectionStateChanged:)` 标 `nonisolated`，函数体仅 `Task { @MainActor [weak self] in self?.processIncoming(messages) }`，`processIncoming` 内统一在 main actor 完成 PK payload 解析 + push + `pkRouter.route`。

- 风险：`AppLogger.im.debug(... appKey=\(AppConfig.nimAppKey, privacy: .private))` 把 NIM AppKey 全文打日志。NIM AppKey 虽不是用户级敏感字段，但属于平台凭据（云信账号绑定，可用于 IM 关键 SDK 行为推断 + 跨应用混用）。DEBUG console 可见，给逆向者免去对 dyld 字符串扫描的麻烦。

### P2-7 WS 握手日志含密文 prefix 12 字符（虽 .private 但 dev console 可见）
- 文件：[Sources/Live/WSHeartbeat.swift:131](../../Sources/Live/WSHeartbeat.swift#L131)
- 维度：安全与隐私
- 风险：`AppLogger.heartbeat.debug("📡 [WS] cipher(hex) ... head=\(cipher.prefix(12), privacy: .private)…")` 把握手 cipher 前 12 hex 字符（= 6 bytes 密文）打到 Logger。虽 `privacy: .private` 在 Release 显示 `<private>`，但 DEBUG 包 USB Console / Xcode console 仍可见明文片段。结合 AES-128-ECB + 固定 key（`9976kk4322578894`）+ 已知明文格式 `{"appToken":"<uuid>"}`，前 6 字节是 JSON 头 `{"appT` 的密文，对持续盯日志 + 同 key 重放攻击者有信息泄露价值。
- 修复：把 `cipher.prefix(12)` 日志去掉，只留 `cipher.count`。同样原则审查 ECB key 是否真有必要 12 hex 字符前缀诊断——dev 验证完后应该直接删除。如确需保留诊断，改成 cipher hash（SHA256 前 8 字节）以保证日志非可逆。

### P2-8 PartyStore.shared singleton 持有 RTC + NIM 资源，logout 无 reset 入口
- 文件：[Sources/Party/PartyStore.swift:15-44](../../Sources/Party/PartyStore.swift#L15-L44)
- 维度:内存与资源
- 风险：`PartyStore.shared` 是 singleton，持有 `PartyRTCEngine (rtc)` + `PartyRoomChatManager (chat)` + `Optional<CameraManager> (camera)`。`SessionStore.logout` 不会调 `forceLeaveRoom`，则用户登出后这些资源继续存活：RTC `AgoraRtcEngineKit` singleton 仍占据；NIM `chatroomManager` delegate 仍注册；camera 通过 `disableLocalVideoCapture` 设 nil 还好。问题是用户重新登录另一个账号，`PartyStore.shared` 状态延续，残留 `rtc.engine` 仍可能持旧 channel。
- 修复：`SessionStore.logout` 链路里调 `await PartyStore.shared.forceLeaveRoom(.userRequest)` + `WSHeartbeat.shared.clearPartyContext()`；或 `PartyStore` 提供 `func reset() async` 供 logout 链路调用。

### P2-11 PartyRoomView 双 @ObservedObject 单例 + lastError onChange String 计算每帧
- 文件：[Sources/Party/UI/PartyRoomView.swift:25-26, 77-79](../../Sources/Party/UI/PartyRoomView.swift#L25-L26)
- 维度：SwiftUI 性能
- 风险：`@ObservedObject store = PartyStore.shared` + `@ObservedObject chat = PartyStore.shared.chat` 两条订阅共存。`.onChange(of: store.lastError?.errorDescription ?? "") { msg in ... }` 把 Optional String 派生比较——每次 body re-eval（`PartyStore` 字段 11 个 @Published 任意一个变都触发，含 `onlineUserCount / isJoinedChannel / imAlive / seatList / ...`）都重新计算 `errorDescription ?? ### P2-12 PartyRoomView ScrollViewReader onChange messages.count 全 LazyVStack rebuild
- 文件：[Sources/Party/UI/PartyRoomView.swift:197-220](../../Sources/Party/UI/PartyRoomView.swift#L197-L220)

### P2-13 PartySeatItemView 每个 cell 各订阅 PartyStore 全量 @Published 触发 N 倍重渲染
- 文件：[Sources/Party/UI/PartySeatItemView.swift:13, 45-49](../../Sources/Party/UI/PartySeatItemView.swift#L13)
- 维度：SwiftUI 性能
- 风险：`PartyRoomView` 在 `LazyVGrid` 内 `ForEach(sortedSeats)` 渲染多个 `PartySeatItemView`，每个 cell 都 `@ObservedObject var store: PartyStore`。`PartyStore` 任一 @Published 变化（`onlineUserCount / imAlive / lastGiftEvent / roomState` 等都与 seat 无关）都会触发每个 cell 重渲染。8 个麦位时 = 8 倍失效计算。`lastGiftEvent` 每送一次礼物全部 seat 重渲；`onlineUserCount` 实时变化时 cell 全员重渲。

### P2-14 PKStore 长跑 Task 与 NQM 订阅未在 view 销毁兜底清理
- 文件：[Sources/PK/PKStore.swift:26-86, 477-493](../../Sources/PK/PKStore.swift#L26-L86)
- 维度：内存与资源
- 风险：`PKStore` 持有 `matchingQuickTask / matchingRetryTask / reconcileDebounceTask` + countdown 3 个倒计时 Task + `nqCancellable` + `foregroundCancellable`。`LiveRoomView.onDisappear` 内 `Task { await pkStore.teardown() }` 走与 nim 同样的 `scenePhase != .background && store.state == .ended` 守卫——非 endLive 路径 dismiss 时 teardown 不调用。无显式 deinit 兜底，`matchingRetryTask` 在 RETRY 5min 阶段会跑完那 300s 才借 weak self == nil 退出，形成游离 PKService 请求 + 不必要的服务器负载。
- 修复：
  1. 加 `deinit` 内 `countdown.cancelAll() + cancelMatchingTimers() + unsubscribeNetworkQuality()` 做兜底
  2. `LiveRoomView.onDisappear` 在 `scenePhase != .background` 时一律调 teardown，不要求 `store.state == .ended`（PK 与直播态正交，dismiss 即应清场）

### P2-15 Profile MomentPostRow dayFormatter 固定 Asia/Shanghai 不区分用户地区
- 文件：[Sources/Profile/Moment/MomentPostRow.swift:153-166](../../Sources/Profile/Moment/MomentPostRow.swift#L153-L166)
- 维度：iOS 平台规范
- 风险：解析后端字符串时间固定 `Asia/Shanghai` 符合 CLAUDE.md 业务约定（任务重置 / 倒计时统一中国时区），但**展示给用户**的 `dayFormatter.string(from:)` 也走 Asia/Shanghai → 海外用户（ar / tr 区域）刷动态会看到中国日期，与本地理解错位 1 天。CLAUDE.md 仅约束"业务时区固定 Asia/Shanghai"并未要求展示同样固定。
- 修复：区分两个 formatter：parse 用 `Asia/Shanghai`（解析后端字符串），display 用 `TimeZone.current` + `Locale.current`（或显式 `Locale(identifier: "en"/"ar"/"tr")` 跟随 DebugLocaleStore），让相对时间也按本地时区计算。同时把 `dateFormat "yyyy-MM-dd"` 改为 `DateFormatter().setLocalizedDateFormatFromTemplate("yMMMd")` 适配 RTL 与本地化日期分隔符。
