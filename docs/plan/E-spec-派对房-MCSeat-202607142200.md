# E - Party MC Seat spec (v1)

> 2026-07-14 · B 档 · 派对房「接待位（MC Seat）」

## §0 范围三圈 + H5 二次校验

### 三圈
- **内圈（本轮做）**：Tools sheet「接待位」入口接线；MC Seat 选择弹层（seat 网格 + 二次确认）；set / close 双 API；麦位 cell 视觉标识；seatList 变化时 UI 自然刷新
- **中圈（顺带 helper）**：`PartyRoomSeat.isMCSeat` computed；`PartyStore.setMCSeat(seatIndex:)` / `closeMCSeat()` 方法
- **外圈（本轮不做）**：MC 位皇冠皮肤 / 侧翼装饰 / 圆环 SPX 资源接入（视觉素材落地留 J 期收尾），本轮只做能识别的 badge 视觉；被踢用户端提示（走既有 seatList diff）

### H5 蓝本二次校验
- **字段**：`roomSeatList[i].isHostSeat`（0/未设=普通，1=MC 位），全房至多 1 个，与 `seatType` 不冲突（seatType 仍 1=视频 / 2=音频）
- **API**：`POST /sapi/weidou/v1/client/party/seat/setHostSeat` + `POST /sapi/weidou/v1/client/party/seat/closeHostSeat` — **未 grep iOS 现有 endpoint**，PartyAPI seat 域 14 个方法均无 MC 相关（sweep 已核）
- **IM**：H5 未定义 MC 专属 attachType，靠既有 seatList 广播（1001 全量替换）触发 UI 刷新；iOS PartyStore 1001 handler 已全量 replace seatList（`Sources/Party/PartyStore.swift`），**无需新增 IM 分支**；1008 updateMedia 已 forward `old.isHostSeat`（第 1539 行），够用
- **权限**：Tools sheet 入口 `Owner || PlatformAdmin` 可见（iOS `PartyRoomToolsSheet.swift:75` 已正确门控）；上麦拦截 `isHostSeat===1 && role===NORMAL` 由后端强校验，前端仅做体验拦截

## §1 业务契约 — API

**新增 2 个 endpoint，与 H5 严格对齐**（`api-http-method-strict` + `agent-recon-field-names-unverified` 双闸门，字段名/method/path 真机首拉 log 验证一次）：

| 方法 | HTTP | Path | Body |
|---|---|---|---|
| `setMCSeat` | POST | `/sapi/weidou/v1/client/party/seat/setHostSeat` | `{ roomId, seatIndex, yxRoomId, roomTempId }` |
| `closeMCSeat` | POST | `/sapi/weidou/v1/client/party/seat/closeHostSeat` | `{ roomId, yxRoomId, roomTempId }` |

Response：Envelope `code === "0000"` 成功；错误码复用 `apiPartyOnSeat` 通用分流（10012/10013 封禁 toast）。首次真机拉取后回写字段名 alias 到 Codable（若有 request/response model）。

## §2 IM 广播

**无 MC 专用 attachType**。MC 状态变更走既有链路：
1. 后端在 setHostSeat / closeHostSeat 成功后触发 seatList 广播
2. iOS `PartyStore` opcode 1001 handler 全量 replace `seatList`（现状已就绪）
3. UI 消费方（PartyRoomView 座位 cell）通过 `seat.isHostSeat` 派生刷新

**真机验证**：首次接入时抓 Console log 看广播 opcode 是否仍是 1001（或 H5 之后新增了 1041/1042 等）；若不是 1001 则新增 handler 分支。

## §3 iOS 模型 + 状态机

### 3.1 Model helper（≤10 行）
`Sources/Party/Models/PartyRoomSeat.swift`（`isHostSeat` 字段第 43 行已存在，本轮补消费）：
```swift
extension PartyRoomSeat {
    var isMCSeat: Bool { (isHostSeat ?? 0) == 1 }
}
extension Array where Element == PartyRoomSeat {
    var mcSeatIndex: Int? { first(where: { $0.isMCSeat })?.seatIndex }
}
```

### 3.2 PartyStore 方法（~40 行）
```swift
@MainActor
func setMCSeat(seatIndex: Int) async {
    // 前置：Owner 或 PlatformAdmin；roomId / yxRoomId / roomTempId 必备
    do { try await PartyAPI.setMCSeat(roomId:, seatIndex:, yxRoomId:, roomTempId:) }
    catch { showToast(error.localizedDescription); return }
    // 成功后不主动改 seatList，等 IM 1001 广播回来自然刷新
}

@MainActor
func closeMCSeat() async {
    do { try await PartyAPI.closeMCSeat(roomId:, yxRoomId:, roomTempId:) }
    catch { showToast(error.localizedDescription); return }
}
```

### 3.3 Sheet UI 交互（~150 行）

**Tools sheet 接线**（`Sources/Party/Settings/PartyRoomToolsSheet.swift:75-78` 改）：
1. `PartyRoomToolSheetKind` enum 加 `case mcSeat`
2. MC Seat cell 右上角挂 ON/OFF 徽章（`seatList.mcSeatIndex != nil` 判定）
3. tap 行为分流：
   - **已 ON**（有 mcSeatIndex）→ 直接调 `store.closeMCSeat()` + toast `L10n.Party.mcSeatClosed`（无二次确认，与 H5 对齐）
   - **OFF** → 关 tools sheet + **350ms 后** `activeRoomTool = .mcSeat`（对齐 iOS 16 双 sheet race rule）

**MC Seat setting sheet 新建组件**（新文件 `Sources/Party/Settings/PartyMCSeatPickerSheet.swift`）：
- 标题 `L10n.Party.mcSeatTitle`（"MC Seat"）
- Body = 全部麦位网格（复用现有 `PartyRoomSeatCell` 或轻量 wrapper；**preflight**：若 PartyRoomSeatCell 自持 CameraManager / ObservedObject store → 新写 `MCSeatPickerCell`，本 rule 已知项目坑）
- 选中态：绿色描边 + 右下 checkmark
- 默认选中：已有 MC → 选中它；否则第一个 `!isOccupied && lockFlag != 1` 的 seat
- 底部 CTA：`L10n.Party.mcSeatSubmit`（"Set MC Seat"），`disabled = selectedIndex == nil || selectedIndex == currentMCSeatIndex`
- Tips：`L10n.Party.mcSeatTips`（"Only owner and admin can take the MC seat"）
- 提交前二次确认弹窗（`.confirmationDialog`），文案分 3 场景：
  - `empty`（selected 位空）→ `L10n.Party.mcSeatConfirmEmpty`
  - `privileged`（selected 位是 OWNER/ADMIN，看 `roomRoleType` in [1,2] 或 `isPlatformAdmin==1`）→ `L10n.Party.mcSeatConfirmPrivileged` + user 名
  - `normal`（selected 位是普通用户）→ `L10n.Party.mcSeatConfirmNormal` + user 名（副作用："user will be removed from seat"）
- 确认 → `store.setMCSeat(seatIndex:)` + dismiss sheet

**Cell 视觉标识**（本轮 minimal）：麦位 cell 上叠加小型 "MC" text badge（左上角 8pt 圆角胶囊，橙色底），皇冠/侧翼 SVGA 素材外圈本轮不做。

## §4 验收清单

### 正向（真机必过）
- F1 Owner 打开 Tools → 见「接待位」cell，右上角显示 OFF（无 MC）
- F2 Owner 点 OFF cell → tools sheet 关闭 350ms 后弹 MC picker → 选空位 → 确认弹窗 empty 文案 → 提交后 IM 1001 广播回来 → 目标位 cell 出现 MC badge + Tools cell 变 ON
- F3 Owner 点 ON cell → 无二次确认直接调 closeMCSeat → toast + IM 回来后 badge 消失 + Tools cell 变 OFF
- F4 PlatformAdmin（非 Owner）→ 同 F1-F3 均可操作
- F5 已有 MC 时再打开 picker → 默认选中当前 MC seat，Submit 按钮 disabled（selectedIndex == currentMCSeatIndex）

### 反向（真机必过）
- R1 普通观众 role=3 → Tools sheet 不见 MC 入口（现有门控已过，回归测试）
- R2 网络断开时 setMCSeat → catch 分支 toast，不改本地 seatList
- R3 后端返 10012 封禁类 → 通用错误分流 toast，picker 保持打开
- R4 二次确认弹窗点 Cancel → 不发接口，picker 保持
- R5 选择被 `lockFlag=1` 位后 Submit → 让后端拒（前端不拦截，与 H5 对齐）；toast 后端 msg
- R6 已有 MC 时 close 途中断网 → 本地 seatList 不变，等下次 seatList 同步矫正
