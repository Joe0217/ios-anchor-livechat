## 二、P1（应该改）

### P1-1 SwipeBackEnabler 永久污染 NavigationController.interactivePopGestureRecognizer.delegate

- **文件**：[SwipeBackEnabler.swift:31-46](Sources/DesignSystem/SwipeBackEnabler.swift)
- **维度**：iOS 平台规范 + 内存与资源（合并 P1-1 + P2-1，跨维度同源）
- **风险**：UserProfileView 显示时把所属 UINavigationController 的 `interactivePopGestureRecognizer.delegate` 置 nil 并 `isEnabled = true`，**永久污染**（无 teardown 还原）。MainTabView .home tab 永驻 → 该 nav 实例的 delegate 永久 nil → 未来在该 nav 内推入"不允许左滑返回"的子页（比如某些全屏 modal）也会被强制启用左滑，触发 UINavigationController 状态错乱 / 'nested pop' assertion。当前只 H-0 用，影响有限；下次有兄弟入口扩展时必坑。
- **修复（推荐）**：保存原 delegate 引用，view willDisappear 时还原：

```swift
private final class SwipeBackHelperController: UIViewController {
    private weak var originalDelegate: UIGestureRecognizerDelegate?
    private weak var targetNav: UINavigationController?

    override func didMove(toParent parent: UIViewController?) {
        // ... 找 nav ...
        if let nav = ... {
            self.targetNav = nav
            self.originalDelegate = nav.interactivePopGestureRecognizer?.delegate
            nav.interactivePopGestureRecognizer?.delegate = nil
        }
    }

    override func viewWillDisappear(_ animated: Bool) {
        super.viewWillDisappear(animated)
        targetNav?.interactivePopGestureRecognizer?.delegate = originalDelegate
    }
}
```

- **备选**：实现自定义 `UIGestureRecognizerDelegate` 仅在 `nav.viewControllers.count > 1` 时返回 true（更稳）；或 MainTabView 根容器集中托管（最干净，重构成本高）

### P1-2 userId PII 在 os.Logger 多处明文写入

- **文件**：
  - [UserProfileService.swift:23, 35, 47, 89, 95](Sources/Profile/UserProfile/UserProfileService.swift)
  - [BlocklistViewModel.swift:94, 116, 120, 132](Sources/Profile/Settings/Blocklist/BlocklistViewModel.swift)
- **维度**：安全与隐私
- **风险**：项目在 `parseDetail:118` 已明确标 userId 为 PII 用 `privacy: .private`，但 **8+ 处其他 logger 调用**（fetchDetail/follow/block/decodeDetail wrapped key 命中 / BlocklistVM unblock 系列）默认 `privacy: .public`。Release 构建下 sysdiagnose / Console.app 真机连接能直接看到所有访问过的他人 uid → 跨用户行为关联风险，破坏了已建立的纪律。
- **修复**：统一加 `privacy: .private`：

```swift
logger.info("fetchDetail uid=\(userId, privacy: .private) ok")
logger.error("toggleFollow uid=\(self.userId, privacy: .private) error: \(String(describing: error), privacy: .private)")
```

可批量替换 UserProfileService / UserProfileViewModel / BlocklistViewModel 内所有 `\(userId)` / `\(self.userId)` 为 private 形式。

### P1-3 decodeDetail 失败时把响应体前 120 字节明文写入 os.Logger

- **文件**：[UserProfileService.swift:71-72](Sources/Profile/UserProfile/UserProfileService.swift)
- **维度**：安全与隐私
- **风险**：路径 5（非 JSON 兜底）打印 `data.prefix(120)` UTF-8 预览。`getUserDetail` 的 `data` 是 **AES 解密后的用户资料明文**（含昵称 / yxAccid / countryId / age 等 PII）。任何接口偏移导致 fail-safe 触发，这 120 字节会落 release 系统日志。
- **修复**：

```swift
logger.error("decodeDetail: cannot parse, preview=\(preview, privacy: .private)")
```

或 release 构建仅记前 16 字节模式判断（`{` / `null` / `<` 等），不带字段内容。

## 三、P2（可以改）

### P2-1 Theme.Typography 全部 Font.system(size:) 无 relativeTo，未接 Dynamic Type

- **文件**：[Theme.swift:486-504](Sources/DesignSystem/Theme.swift) — 影响 UserProfileView / LiveListUserCard / MainTabView 等多处
- **维度**：iOS 平台规范
- **风险**：所有用户可读文字硬编 pt 不响应 Dynamic Type；视障/老年用户系统放大字号 UI 不跟随；Apple a11y 提审审查近年加强。
- **修复**：用户可读文本（nickname / meta / statsValue / tabLabel）改为：

```swift
Font.system(size: 18, weight: .semibold, design: .default).relativeTo(.body)
// 或
Font.system(.headline)   // 完全语义化
```

icon-size 类（fixed dimension）不必动。

### P2-2 礼物 a11yLabel 硬编码英文 "Gift"

- **文件**：[UserProfileView.swift:531](Sources/Profile/UserProfile/UserProfileView.swift)
- **维度**：iOS 平台规范（违反 CLAUDE.md "禁止硬编码中文/英文" 项目铁律）
- **风险**：礼物 `name` 为 nil 时 VoiceOver 念英文 "Gift"，阿语/土语用户体验破窗 + 违反 CFBundleLocalizations 一致性。
- **修复**：L10n 新增 `userProfileA11yGiftFallback` + 三语翻译：

```swift
// L10n.swift
static var userProfileA11yGiftFallback: String { localize("userProfile.a11y.giftFallback", ...) }

// View
.accessibilityLabel("\(gift.name ?? L10n.userProfileA11yGiftFallback), \(gift.count)")
```

### P2-3 showingComingSoonToast 多处未结构化 Task.sleep（4 条同源合并）

- **文件**：[UserProfileView.swift:70-74, 253-259](Sources/Profile/UserProfile/UserProfileView.swift)
- **维度**：**4 维同源**（iOS 平台规范 / Swift 并发 / SwiftUI 性能 / 内存与资源 — Workflow 多 finder 同时发现）
- **风险**：`triggerComingSoonToast()` + 菜单 Report 项各开游离 Task `Task.sleep(2s) → showingComingSoonToast = false`：
  1. View dismount 后 Task 继续跑（非泄漏但浪费调度 + 持 view 闭包 capture）
  2. 快速连点会启动多个并发 Task，先到的把 toast 置 false，覆盖后开的 toast，UX 闪烁
  3. 同文件 [line 584](Sources/Profile/UserProfile/UserProfileView.swift) 的 `transientErrorToast` 已用 `.task(id: msg)` 模式正确处理 — **同 view 内实现不一致**
- **修复**：与 transientError 同款 `.task(id:)` 模式：

```swift
// View body 内
Text(L10n.commonComingSoon)
    .opacity(showingComingSoonToast ? 1 : 0)
    .task(id: showingComingSoonToast) {
        guard showingComingSoonToast else { return }
        try? await Task.sleep(nanoseconds: 2_000_000_000)
        try? Task.checkCancellation()
        showingComingSoonToast = false
    }

// triggerComingSoonToast 简化为
private func triggerComingSoonToast() { showingComingSoonToast = true }
```

删除按钮 action 内手动 `Task { Task.sleep }`。

### P2-4 礼物墙 LazyVGrid cell 内嵌 GeometryReader 触发重复布局

- **文件**：[UserProfileView.swift:496-514](Sources/Profile/UserProfile/UserProfileView.swift)
- **维度**：SwiftUI 性能
- **风险**：giftCell 内 GeometryReader 贪婪占满父级 + 反馈 size 给 image 算 80%。LazyVGrid 内 cell 用 GeometryReader 是公认反模式（lazy 失效 + invalidate 风暴）。`@Published` 字段变更（如 follow 切换）触发整 page body 重算 → 每 cell 重新跑 GeometryReader → image frame 重排 → 整 grid 二次布局。
- **修复**：去 GeometryReader，用纯 SwiftUI 自适应：

```swift
private func giftCell(gift: Gift) -> some View {
    VStack(spacing: 4) {
        giftImage(gift: gift)
            .frame(maxWidth: .infinity)
            .aspectRatio(1, contentMode: .fit)   // cell 宽自适应 + 1:1 比例
            .clipShape(RoundedRectangle(cornerRadius: 6, style: .continuous))
        Text(gift.name ?? "")...
        Text("X \(gift.count)")...
    }
    .frame(maxWidth: .infinity)
}
```

image 占满 cell 宽（grid 5 列自适应）+ 1:1 比例 → 视觉等效 80% 但无 GeometryReader 开销。

### P2-5 isLiveProvider 闭包未标 @MainActor

- **文件**：[UserProfileViewModel.swift:29-35, 179](Sources/Profile/UserProfile/UserProfileViewModel.swift)
- **维度**：Swift 并发
- **风险**：`isLiveProvider: () -> Int` 非隔离，但被 `@MainActor confirmBlock` 同步调用。当前 `{ 0 }` 注入无事；spec §6 Q2 step 2 要接 `LiveStore.state == .living`（LiveStore 是 `@MainActor` 隔离），Swift 6 / strict-concurrency=complete 下会编译报错；Swift 5 下无静态保证。
- **修复**：

```swift
private let isLiveProvider: @MainActor () -> Int

init(..., isLiveProvider: @escaping @MainActor () -> Int = { 0 }, ...) { ... }
```

VM 已 `@MainActor` 调用点无需改，外部注入位置由编译器强制 MainActor 上下文构造。

### P2-6 UserProfileViewModel 不监听 .followRelationChanged，跨页同步缺位

- **文件**：[UserProfileViewModel.swift:13-43](Sources/Profile/UserProfile/UserProfileViewModel.swift)
- **维度**：内存与资源（对称性 / 数据契约）
- **风险**：VM post `.followRelationChanged`（line 114-118）但**自身不 addObserver**。同 userId 在 FollowList tab 切 follow 后回到详情页，`detail.followed` 仍旧值，按钮态错位。和 [BlocklistViewModel.swift:49-58](Sources/Profile/Settings/Blocklist/BlocklistViewModel.swift) 同款模式不对称。
- **修复**：init 内 addObserver，模板参考 BlocklistViewModel：

```swift
// UserProfileViewModel.swift
private var followObserver: NSObjectProtocol?

init(...) {
    ...
    self.followObserver = NotificationCenter.default.addObserver(
        forName: .followRelationChanged, object: nil, queue: .main
    ) { [weak self] note in
        Task { @MainActor in
            guard let self,
                  let uid = note.userInfo?["userId"] as? Int,
                  let flag = note.userInfo?["followFlag"] as? Int,
                  String(uid) == self.userId,
                  var current = self.detail else { return }
            current.followed = (flag == 1)
            self.detail = current
        }
    }
}

deinit {
    if let obs = followObserver { NotificationCenter.default.removeObserver(obs) }
}
```
