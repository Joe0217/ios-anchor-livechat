## §2 PKStore 主态状态机

### 2.1 状态枚举

```swift
// Sources/PK/PKModels.swift
/// PKStore 9 态状态机
///
/// 映射 H5 常量（constant/livePk.ts:2-10）：
/// - idle      → OFFLINE/LIVE（H5 在非 PK 期统称 LIVE，iOS 用 idle）
/// - matching  → MATCHING
/// - inviting  → INVITING
/// - invited   → INVITED
/// - inPK      → IN_PK
/// - punishing → PUNISHING
/// - starting / endingPK / failed 是 iOS 独有细分（覆盖"接口 in-flight"与"异常"路径，H5 用布尔标志 isJoiningPk + cleanupAllPkStates 散落实现）
enum PKStateMain: Equatable {
    case idle
    case matching(startedAt: Date, isRetry: Bool, expireAt: Date)
    case inviting(targetAnchorId: String, duration: Int, expireAt: Date)
    case invited(info: PKInviteInfo, expireAt: Date)
    case starting(ctx: PKContext)          // joinPk 返回 → joinChannelEx 进行中
    case inPK(ctx: PKContext)              // 双频道 onJoined + 5s 准备完毕
    case punishing(ctx: PKContext, endAt: Date)
    case endingPK(ctx: PKContext, isActive: Int, fromStatus: Int)
    case failed(reason: PKFailReason)      // pkStatus=-1 或本端异常

    /// 便利属性：覆盖所有 .failed(...) case，避免 transition 检查时漏 case
    var isFailed: Bool { if case .failed = self { return true }; return false }
}

/// 与 inPK 的关系：starting → inPK 在 joinChannelEx 完成回调即转移；
/// **不引入 preparing 中间态**——5s 准备倒计时是 inPK 内部子状态（@Published preparingRemaining: Int），
/// UI 根据 preparingRemaining > 0 决定显示准备动画 vs 主对战 UI，避免状态机膨胀
/// （对齐 H5 livePk.js:637-659 startPk() 立即进 IN_PK + 并行启动 preparingCountdown=5）

struct PKContext: Equatable {
    let pkId: String
    let oppositeAnchorId: String
    let oppositeUid: UInt
    let oppositeAgoraChannelId: String
    let oppositeYxAccid: String?
    let pkType: PKType                      // .random / .invite
    let pkDuration: Int                     // 秒，180/300/600/900
    let endTime: Date                       // 绝对时间戳（M3 联调确认毫秒/秒）
    var scores: PKScoreUpdate = .zero
}

enum PKType: Int { case random = 1, invite = 2 }
enum PKFailReason {
    case opponentAbnormalDisconnect         // pkStatus=-1
    case matchFailed                        // 匹配超时
    case networkError                       // 接口失败兜底
}
```

### 2.4 LiveStore.callState 联动表

| PKStateMain | `liveStore.callState` | 写入时机 |
|---|---|---|
| `idle / failed` | 0 | enter 时（除非进入 failed 是因 LiveStore 已 ended，则跳过——见前置条件） |
| `matching / inviting / invited` | 2 | enter 时 |
| `starting` | 2 | 不切换（等 inPK 才切 3） |
| `inPK / punishing / endingPK` | 3 | enter `inPK` 时 |

**前置条件（critical）**：`LiveStore.setCallState(_:)` 现有实现是 `guard state == .living else { return }`（[LiveStore.swift:318-321](Sources/Live/LiveStore.swift#L318-L321)），即 LiveStore 不在 `.living` 时**静默忽略**。PKStore 内调用前必须先：

```swift
guard let ls = liveStore, ls.state == .living else {
    logger.warning("setCallState skipped: liveStore not living (state=\(...))")
    return
}
ls.setCallState(targetValue)
```

PKStore.teardown() 路径（由 LiveStore.state→.ended 触发）**不调 setCallState**——直播已结束，callState 写入无意义。

**互斥保证**：PKStore enter matching/inviting/invited/starting 后，callState=2；进 inPK→callState=3；中间即便接口失败（如 startPkMatch 重试期间），**callState 必须保持 2 不回 0**（否则 D 来电会绕过 PK 守卫创建错通话）；只有 PKStore 显式 enter idle 才 setCallState(0)。`pauseForCall` 守卫 `callState == 0`（[LiveStore.swift:242](Sources/Live/LiveStore.swift#L242)）+ §8.2 显式 PKStore 检查双重保险。

### 2.5 非法 transition guard

PKStore 内任何 transition 入口先做 `state` 检查，非合法源态直接 `return + logger.warning`，不抛错也不静默 noop。单测覆盖：

- `idle` 收到 `attachType=98/100 pkStatus=8` → 忽略（不进 punishing）
- `inPK` 收到 `attachType=97` 邀请 → 忽略（不弹 InvitedSheet）
- `matching` 收到 `attachType=100 pkStatus=8` → 忽略（必须先 `pkStatus=10 → joinPk → starting → inPK`）

## §3 声网多频道封装

### 3.1 选型结论（详见校验清单 §1.2/§1.4）

**iOS 4.x SDK 上 `joinChannelEx + AgoraRtcConnection 字典`是唯一可行方案**：
- 单 `AgoraRtcEngineKit` 实例多 connection，每 connection 一个独立 `AgoraRtcChannelMediaOptions`
- 不能创建第二个 engine：`sharedEngine(with:)` 是进程级单例第二次调用忽略新 config（[AgoraManager.swift:72-77](Sources/Agora/AgoraManager.swift#L72-L77) 已有此坑注释）；强行 `init()` 私有创建会抢 mic/camera/网络全局资源 → 黑屏
- 不能用 `channelMediaRelay`：只能"推到目标"不能"订阅目标"，语义反向

### 3.2 AgoraManager 扩展

```swift
// Sources/Agora/AgoraManager.swift（扩展）
extension AgoraManager {
    /// PK 对手频道渲染目标（PKArenaView 挂这一个）
    var oppositeRemoteView: UIView { _oppositeRemoteView }
    private var _oppositeRemoteView: UIView { /* lazy stored */ }

    /// PK 频道字典的线程安全锁
    /// 声网 SDK delegate 回调线程 ≠ MainActor；PKChannelDelegate 读 pkConnections 时必须加锁
    private var pkLock: NSLock { /* stored */ }

    /// PK 频道连接表 key=channelId（读写均经 pkLock）
    private var pkConnections: [String: AgoraRtcConnection] { /* stored */ }
    /// PK 频道独立 delegate（解耦回调，避免污染主频道 delegate）
    private var pkDelegates: [String: PKChannelDelegate] { /* stored */ }
    /// leaveChannelEx 完成 continuation（仿主频道 leaveContinuation:54 单频道模型）
    private var leavePKContinuations: [String: CheckedContinuation<Void, Never>] { /* stored */ }

    /// 公开查询方法：供 PKChannelDelegate 在 SDK 回调线程中查 connection
    /// 锁内拷贝引用、锁外返回（避免长持锁阻塞 main queue 的 join/leave）
    nonisolated func pkConnection(forChannel channel: String) -> AgoraRtcConnection? {
        pkLock.lock(); defer { pkLock.unlock() }
        return pkConnections[channel]
    }

    /// 加入 PK 对手频道，audience 角色，不发布，按 uid 过滤订阅
    /// - token: 复用主直播 rtcToken（声网 token 绑 uid 不绑 channel）
    @MainActor
    func joinPKOpposite(channel: String, oppositeUid: UInt, token: String, ownUid: UInt) async throws {
        guard let engine else { throw AgoraError.engineNotReady }
        guard pkConnections[channel] == nil else { return }    // 幂等

        let conn = AgoraRtcConnection()
        conn.channelId = channel
        conn.localUid = ownUid                                  // 仍用本端 uid（声网约束）
        let opt = AgoraRtcChannelMediaOptions()
        opt.clientRoleType = .audience
        opt.publishCameraTrack = false
        opt.publishMicrophoneTrack = false
        opt.publishCustomVideoTrack = false
        opt.autoSubscribeVideo = true
        opt.autoSubscribeAudio = true

        let delegate = PKChannelDelegate(owner: self, channel: channel,
                                         oppositeUid: oppositeUid, oppositeView: oppositeRemoteView)
        pkLock.lock()
        pkDelegates[channel] = delegate
        pkConnections[channel] = conn
        pkLock.unlock()

        let ret = engine.joinChannelEx(byToken: token, connection: conn,
                                       delegate: delegate, mediaOptions: opt, joinSuccess: nil)
        if ret != 0 {
            pkLock.lock()
            pkConnections.removeValue(forKey: channel)
            pkDelegates.removeValue(forKey: channel)
            pkLock.unlock()
            throw AgoraError.joinExFailed(code: Int(ret))
        }
    }

    /// 离开 PK 对手频道，等 didLeaveChannelExWith 回调后 resume，500ms 兜底
    @MainActor
    func leavePKOpposite(channel: String) async {
        guard let engine else { return }
        guard let conn = pkConnection(forChannel: channel) else { return }

        await withCheckedContinuation { (cont: CheckedContinuation<Void, Never>) in
            if leavePKContinuations[channel] != nil { cont.resume(); return }
            leavePKContinuations[channel] = cont
            engine.leaveChannelEx(conn, leaveChannelBlock: nil)
            // 500ms 兜底（仿主频道 leave 模型 :149-158）
            Task { @MainActor [weak self] in
                try? await Task.sleep(nanoseconds: 500_000_000)
                guard let self else { return }
                if let c = self.leavePKContinuations.removeValue(forKey: channel) {
                    c.resume()
                    logger.warning("leaveChannelEx 回调 500ms 超时 channel=\(channel)，兜底 resume")
                }
            }
        }
        pkLock.lock()
        pkConnections.removeValue(forKey: channel)
        pkDelegates.removeValue(forKey: channel)
        pkLock.unlock()
    }
}
```

> **声网 SDK API 真实签名**：以上代码示例使用的 API（`AgoraRtcConnection()` / `joinChannelEx(byToken:connection:delegate:mediaOptions:joinSuccess:)` / `setupRemoteVideoEx(_:connection:)` / `leaveChannelEx(_:leaveChannelBlock:)` / `didLeaveChannelExWith`）属声网 4.x 公开 API。**实际实现时 implementer 必须用 Xcode 自动补全 / AgoraRtcKit 头文件确认每个签名、参数顺序、回调方法名（如 `engine(_:didLeaveChannelEx:withStats:)` vs `engine(_:didLeaveChannelExWith:)`）。**spec 不保证逐字签名正确，只保证语义意图。M0-3 实施时如果签名与 SDK 不匹配，按 SDK 真相调整代码、回填本 spec。

### 3.3 PKChannelDelegate（独立 delegate 解耦 + 线程安全）

PK 频道远端渲染**必须**用 `setupRemoteVideoEx(_:connection:)`（不是主频道的 `setupRemoteVideo`）。每个 PK 频道一个独立 delegate 实例，按 channel 自然区分回调来源。SDK 回调在非主线程，访问 `AgoraManager.pkConnections` 必须通过加锁的 `pkConnection(forChannel:)` 公开方法（详见 §3.2）。

```swift
final class PKChannelDelegate: NSObject, AgoraRtcEngineDelegate {
    weak var owner: AgoraManager?
    let channel: String
    let oppositeUid: UInt
    weak var oppositeView: UIView?

    init(owner: AgoraManager, channel: String, oppositeUid: UInt, oppositeView: UIView) {
        self.owner = owner; self.channel = channel
        self.oppositeUid = oppositeUid; self.oppositeView = oppositeView
    }

    func rtcEngine(_ engine: AgoraRtcEngineKit, didJoinedOfUid uid: UInt, elapsed: Int) {
        guard uid == oppositeUid else { return }
        // SDK 回调线程 → 拿 connection 必须经加锁查询；setupRemoteVideoEx 在 main queue 调
        guard let conn = owner?.pkConnection(forChannel: channel) else { return }

            guard let self, let view = self.oppositeView else { return }
            let canvas = AgoraRtcVideoCanvas()
            canvas.uid = uid; canvas.view = view; canvas.renderMode = .hidden
            engine.setupRemoteVideoEx(canvas, connection: conn)
        }
    }

        guard uid == oppositeUid else { return }
```

### 3.5 .pkActive 编码档位（PK 期降分辨率）

```swift
extension AgoraManager {
    enum EncoderQuality {
        case normal     // 720×1280 / 30fps / Standard      ← 直播态
        case low        // 720×1280 / 15fps / 600kbps        ← 弱网降级
        case pkActive   // 480×640  / 30fps / 500kbps        ← PK 期（新增）
        case pkLow      // 480×640  / 15fps / 400kbps        ← PK 期 + 弱网叠加
    }

    func applyEncoderQuality(_ q: EncoderQuality) {
        guard let engine, currentQuality != q else { return }
        let cfg: AgoraVideoEncoderConfiguration = {
            switch q {
            case .normal:   return .init(size: .init(width: 720, height: 1280), frameRate: 30, bitrate: AgoraVideoBitrateStandard, orientationMode: .fixedPortrait, mirrorMode: .disabled)
            case .low:      return .init(size: .init(width: 720, height: 1280), frameRate: 15, bitrate: 600,                        orientationMode: .fixedPortrait, mirrorMode: .disabled)
            case .pkActive: return .init(size: .init(width: 480, height: 640),  frameRate: 30, bitrate: 500,                        orientationMode: .fixedPortrait, mirrorMode: .disabled)
            case .pkLow:    return .init(size: .init(width: 480, height: 640),  frameRate: 15, bitrate: 400,                        orientationMode: .fixedPortrait, mirrorMode: .disabled)
            }
        }()
        engine.setVideoEncoderConfiguration(cfg)
        currentQuality = q
        logger.info("encoder quality → \(q)")
    }
}
```

**档位切换时序**：
- PKStore enter `inPK` → `agora.applyEncoderQuality(.pkActive)`
- PK 期 + 弱网 → 切 `.pkLow` 而非 `.low`（拦截机制见下）
- PKStore exit `endingPK → idle` → `agora.applyEncoderQuality(networkMonitor.isInLow ? .low : .normal)`

**⚠️ 全局副作用警示**：`setVideoEncoderConfiguration` 是 **engine 级别** setter（非 connection 级别）。PK 期切 `.pkActive` 480×640 **同时影响主频道直播观众端的画质**——观众端会看到本端推流降到 480×640（而非 720×1280）。本 spec 接受此行为：(1) PK 容器只占屏幕一半，480 宽对观众端体验影响有限；(2) 双频道总带宽预算明显下降，弱网风险下降。M0 真机 DoD 1-2 时观众端肉眼验证；若产品判断画质损失不可接受，M0 阶段需调研声网 4.x 是否提供 connection-level 编码 API（如 `setVideoEncoderConfigurationEx(_:connection:)`）。

**NetworkQualityMonitor 拦截机制（M2 落地）**：NetworkQualityMonitor 当前由 AgoraManager 持 weak 引用，PKStore 无法直接订阅它的事件。spec 落地需补：
- NetworkQualityMonitor 暴露 `@Published var currentLevel: NetworkQualityLevel`（normal / weakWarning / weakSevere）或 `var onLevelChange: ((NetworkQualityLevel) -> Void)?` 闭包
- PKStore enter `inPK` 时注册自己监听 `currentLevel` 变化；exit `endingPK → idle` 时解除注册
- 弱网升级到 severe 时：若 PKStore 在 inPK/punishing → `applyEncoderQuality(.pkLow)`；否则走原 `.low` 路径
- 详见 §1.4 P0 缺口 + 实施计划 M0-5 / M2-2。**NetworkQualityMonitor 本身不暂停**（B 里程碑 v5 分层 10/30/5 阈值保持），spec §3.5 不调 `pause/resume`

### 3.6 codec 配置（不显式配，沿用 SDK 默认）

不调用 `setParameters` 强制 codec，依赖 SDK 4.5.2.9 BASIC 默认（编 h264 / 解兼容 vp8/vp9/h264）。M0 真机验证 iOS h264 ↔ H5 vp9 互通；失败时回退方案 A/B/C 见校验清单 §1.2。

### 3.7 主频道与 PK 频道的资源边界

- **token**：复用同一个 `LiveService.getAgoraRtmToken().rtcToken`（声网 token 绑 uid 不绑 channel）
- **channelProfile**：均 `.liveBroadcasting`（PK 频道当 audience，profile 不变）
- **mic/camera**：主频道继续推 customVideoTrack（CameraManager v5.8 字典本体 sink 不丢，[swiftui-camera-preview.md §3](.claude/rules/swiftui-camera-preview.md)）；PK 频道 `publishX=false`
- **token 续期**（⚠️ M0 验证项）：主频道现有 `tokenPrivilegeWillExpire` → `renewToken`（[AgoraManager.swift:207-247](Sources/Agora/AgoraManager.swift#L207-L247)）。声网 4.x 多 connection 下的标准做法是逐 connection 调 `renewTokenEx(token, connection:)`；本 spec 假设 `renewToken` 对所有 connection 生效（**未在 SDK 文档实证**）。M0-3 实施时必须验证：续期后让 PK 频道运行至少 1h（覆盖 token 30 分钟超时窗口），确认未触发 109/110 error；若失败则改为遍历 `pkConnections` 逐一 `renewTokenEx`

## §7 中断重连

### 7.1 触发时机

- 进房（LiveStore enter `.living`，PKStore.idle，但服务端可能仍有未结的 PK）
- 前后台切换：`UIApplication.willEnterForegroundNotification`
- 网络恢复：`NetworkQualityMonitor` 从弱网恢复 normal

### 7.2 同步算法 + ctx 重建缺口（M1 后端协调项）

```swift
@MainActor
func reconcileOnReconnect() async {
    let remote = try? await PKService.getPkStatus()
    let local = state
    switch (remote, local) {
    case ("INPK", .inPK), ("INPK", .starting), ("PUNISHING", .punishing):
        return                                          // 一致，无需动
    case ("INPK", _):
        // ⚠️ 本地未在 PK 但服务端 INPK → 必须重建 ctx（pkId/oppositeUid/oppositeChannel/endTime）
        // getPkStatus 仅返回字符串，不含 ctx；M1 需后端确认扩展（见下）
        await rebuildPKContext(targetStatus: .inPK)
    case ("PUNISHING", .punishing(let ctx, _)):
        return                                          // 等下次 NIM 100 推 endAt 重建即可
    case ("PUNISHING", _):
        await rebuildPKContext(targetStatus: .punishing)
    case (nil, .inPK), (nil, .punishing), (nil, .starting), (nil, .endingPK):
        await teardown()                                // 服务端已结束 → 强制清理
    case (nil, _):
        return
    default: break
    }
}
```

**关键缺口（M1 必须解决）**：`getPkStatus` 返回 `'INPK'/'PUNISHING'/null` 三态字符串，**不带 pkId/oppositeUid/oppositeAgoraChannelId/endTime/scores**——这些都是 `joinPk` 接口返回的、只在第一次入 PK 时存在。杀进程 + 重启场景下，本地 PKStore.ctx 丢失，仅靠 getPkStatus 字符串无法重建 PKArenaView 和倒计时。

三种解决方案（M1 与后端协调选其一）：
- **方案 A（推荐）**：后端扩展 `getPkStatus` 返回结构体含 ctx 字段（pkId/oppositeUid/oppositeChannelId/endTime/myScore/oppScore），iOS 解析重建
- **方案 B**：新增 `getPkDetail` 接口，PK 期返回完整 ctx；getPkStatus 仅做轻量探测
- **方案 C（兜底）**：本地 Keychain/UserDefaults 缓存 ctx（不含敏感数据），重建后用 getPkStatus 校验仍 INPK 才生效；NIM 100 在 N 秒内重推也能覆盖

`rebuildPKContext` 实现按方案选定后落地；M1 接口协调前**不实现 case ("INPK", _) 分支**，仅 logger.warning + 等 NIM 100 重推；M5 真机若漏推则视严重程度回头补方案 A/B。

### 7.3 杀进程重启

直播间从 0 重新进入 `.living` 时调一次 `reconcileOnReconnect()`。倒计时基于 `endTime` 绝对时间戳推算剩余秒数，前后台切换不漂移（[LiveStore.returnLiveTask](Sources/Live/LiveStore.swift) 同款模式）。

### 7.4 弱网恢复无副作用

`NetworkQualityMonitor` 弱网阈值不因 PK 变（B 里程碑 v5 分层 10/30/5 保持）；恢复时仅做 `applyEncoderQuality` 回切（[3.5](#35-pkactive-编码档位pk-期降分辨率) 时序表）；不触发 PK 状态机变更。

PKStore 处理：
- enter `inPK` 时：`userToggledInviteSwitch = false` + `POST /updateInviteSwitch(searchValue:1)`；接口请求 in-flight 期间防重入用 `isUpdatingInviteSwitch: Bool` 标志
- exit `endingPK → idle` 时：**判定**当前 PK 期间用户是否手动切换过邀请开关——通过 `pkStore.userToggledInviteSwitch: Bool`（PK 期 UI 切换开关时置 true）
  - 若 `userToggledInviteSwitch == false`：`POST /updateInviteSwitch(searchValue:0)` 恢复开（请求前等 `isUpdatingInviteSwitch == false`）
  - 若 `userToggledInviteSwitch == true`：尊重用户操作，不动
- 这避免了 R6 竞态（用户 PK 中手动切开关被 exit 覆盖）

**幂等性与 in-flight 防重入**（M2 落地）：

```swift
@MainActor
private var isUpdatingInviteSwitch: Bool = false
@MainActor
private(set) var userToggledInviteSwitch: Bool = false

@MainActor
private func updateInviteSwitchSafe(_ value: Int) async {
    guard !isUpdatingInviteSwitch else {
        logger.warning("updateInviteSwitch in-flight, skip value=\(value)")
        return
    }
    isUpdatingInviteSwitch = true
    defer { isUpdatingInviteSwitch = false }
    do { try await PKService.updateInviteSwitch(searchValue: value) }
    catch { logger.error("updateInviteSwitch failed value=\(value) err=\(error)") }
}
```

> **M1 与后端确认 updateInviteSwitch 幂等性**：连续两次 `searchValue:1` 是否安全？若不幂等，PKStore 需加状态机记录当前已知开关值，避免重复写。

## §10 数字编码统一表

避免 spec 散落"pkStatus=7 是什么"的歧义，G 全期统一以下编码：

### 10.1 NIM attachType

| Code | 含义 |
|---|---|
| 97 | 收到 PK 邀请 |
| 98 | PK 实时分数 + Top3 |
| 99 | 邀请状态变更（inviteStatus 1/2/4，type=3 在嵌套字段） |
| 100 | PK 状态总合（子分 pkStatus 7/8/9/10/-1） |
| -8 | 静音广播（mute 1/0） |
| -9 | 公屏通知（开始/结果/Top3 富文本） |

### 10.2 pkStatus（attachType=100 子分支）

| Code | 含义 | PKStore 动作 |
|---|---|---|
| 7 | 客态进入 PK | G 范围外仅日志 |
| 8 | PK 结束进惩罚 | `inPK → punishing` |
| 9 | 对方结束惩罚或中断 | `inPK/punishing → endingPK(isActive:0)` |
| 10 | 匹配成功 | `matching → starting` |
| -1 | 对方异常断线 | `inPK/punishing → failed` |

### 10.3 inviteStatus（attachType=99 子字段）

| Code | 含义 |
|---|---|
| 1 | 接受 |
| 2 | 拒绝 |
| 4 | 取消（主叫主动撤回） |

> ⚠️ **3 超时不在此推送**：H5 `live.js case 99` switch 仅识别 1/2/4（参 `livePk.js:1627 handleReceivedInviteTimeout`）；**超时是本端 60s 倒计时到期由本端主动调 `handleInvite(type:3)` 上报后端**，不会从后端推 99 给本端。iOS PKNIMRouter 解析 attachType=99 时只需处理 1/2/4 三个值，未知 inviteStatus 落日志。

### 10.4 handleInvite.type（请求入参）

| Code | 含义 |
|---|---|
| 1 | 接受 |
| 2 | 拒绝 |
| 3 | 超时（后端主动判定，本端不主动调） |
| 4 | 取消（主叫方撤回） |

### 10.5 isActiveDisconnect

| Code | 含义 | 触发接口 |
|---|---|---|
| 1 | 正常结束（时间到 / 惩罚倒计时到） | endPk / endPunishing |
| 2 | 主动中断 | endPk / endPunishing |
| 3 | 异常断线（对方 pkStatus=-1） | endPunishing |

### 10.6 disconnectFromStatus

| Code | 含义 |
|---|---|
| 7 | 从 inPK 中断开（fromStatus 来自 `pkStatus=7`） |
| 8 | 从 punishing 中断开（fromStatus 来自 `pkStatus=8`） |

**仅在 `endPunishing` 调用时有效**；`endPk` 不带 disconnectFromStatus 参数。Transition 表中：
- `inPK → endingPK`（自然 / 主动）→ `endPk(...)` 不带 fromStatus
- `inPK → failed`（对方 pkStatus=-1）→ `endPunishing(isActive:3, fromStatus:7)`
- `punishing → endingPK`（120s / 主动）→ `endPunishing(isActive:1/2, fromStatus:8)`
- `punishing → failed`（对方 pkStatus=-1）→ `endPunishing(isActive:3, fromStatus:8)`

## §11 对外接口契约

PKStore 是 G 唯一对外暴露的状态机入口。其他模块**禁止**直接调 PKService 或 PKNIMRouter。

### 11.1 PKStore ↔ LiveStore

| 调用方向 | 接口 | 时机 |
|---|---|---|
| PKStore → LiveStore | `setCallState(_:)` | 状态转移时按 2.4 映射写入 |
| LiveStore → PKStore | `pkStore?.teardown()` | LiveStore.state → ended 时强制调 |
| LiveStore ↑ PKStoreObserver | `pkStore(_:didEndPK:scores:)` | H 礼物 PK 期重排钩子（G 空实现） |

### 11.2 PKStore ↔ CallStore

| 调用方向 | 接口 | 时机 |
|---|---|---|
| CallStore → PKStore | `pkStore?.state` 只读 | `handleIncomingVideoCall` 判定 busy reject |

PKStore **不**调用 CallStore（避免循环依赖）。

### 11.3 PKStore ↔ AgoraManager

| 调用方向 | 接口 | 时机 |
|---|---|---|
| PKStore → AgoraManager | `joinPKOpposite(channel:oppositeUid:token:ownUid:)` | enter `starting` 时 |
| PKStore → AgoraManager | `leavePKOpposite(channel:)` | enter `endingPK → idle` 时 |
| PKStore → AgoraManager | `applyEncoderQuality(_:)` | 按 3.5 时序 |
| AgoraManager → PKStore（通过 PKChannelDelegate） | `handleOppositeJoined / handleOppositeOffline` | RTC 事件 |

### 11.4 PKStore ↔ NIMChatroomManager

| 调用方向 | 接口 | 时机 |
|---|---|---|
| NIMChatroomManager → PKRouter → PKStore | `handle97/98/99/handleMatchSuccess/handleEnterPunishing/...` | NIM 推送 |
