## §3 状态机草图

美颜设置页本身 UI 层不复杂，真状态机在**参数共享 Store**（BeautyPipelineSharer 内含）。

### §3.1 参数 Store 状态机

```
[unloaded]
   │  App 启动
   ├─ readFromDisk 成功 ──→ [ready(cached)]
   └─ readFromDisk 无数据 ──→ [ready(default)]
                                    │
                                    │  用户在美颜设置页调滑块
                                    ↓
                              [ready(dirty)]
                                    │  throttle 60ms
                                    ├─ SDK 更新（updateParameters）
                                    │
                                    │  离开页面 or App backgrounding
                                    ↓
                              [ready(persisted)] ── writeToDisk 成功 ──┐
                                    ↑                                     │
                                    │  写盘异常 alertToast + retry x3 ─┘
                                    │
                              [ready(cached)] ← 与上等价
```

**关键不变量**：
- **禁止 loading dead-state**（参照 `.claude/rules/async-state-fallback.md`）：进美颜设置页立即渲染业务默认档，读盘异步覆盖
- **共享 Store 与 SDK 解耦**：Store 只管参数值，SDK 更新由 subscriber 侧执行（LiveRoom / LivePrepare / CallView）
- **写盘节流**：滑块拖动期间不写盘，仅 SDK 更新；离开页面时统一 flush
- **恢复默认不清空持久化**：仅 reset Store 参数为业务默认，写盘同步更新

## §4 数据契约（相芯 iOS 参数完整清单 + reflex 映射）

### §4.1 反射映射（1:1 复刻 H5 `beautyTools.reflexMap`）

```swift
enum ReflexType: Int {
    case type1 = 1  // 0~100  ↔ 0~1     (vtr: v/100,        rtv: 100*v)
    case type2 = 2  // -50~50 ↔ 0~1     (vtr: (v+50)/100,   rtv: 100*v-50)
    case type3 = 3  // 0~100  ↔ 0~6     (vtr: v*6/100,      rtv: 100*v/6)

    func toRaw(_ uiValue: Double) -> Double {
        switch self {
        case .type1: return uiValue / 100.0
        case .type2: return (uiValue + 50.0) / 100.0
        case .type3: return uiValue * 6.0 / 100.0
        }
    }
    func toUI(_ rawValue: Double) -> Double {
        switch self {
        case .type1: return 100.0 * rawValue
        case .type2: return 100.0 * rawValue - 50.0
        case .type3: return 100.0 * rawValue / 6.0
        }
    }
}
```

单测覆盖：3 类 × (0, mid, max) × 双向 = 18 case，含 round-trip 精度。

```objc
// 1. Setup（已在 FUManager.m 完成，扩展加 controller_cpp bundle）
[FURenderKit setLogLevel:FU_LOG_LEVEL_ERROR];
FUSetupConfig *config = [[FUSetupConfig alloc] init];
config.authPack = FUAuthPackMake(g_auth_package, sizeof(g_auth_package));

// 3. 加载美颜 bundle + 挂到 FURenderKit
NSString *beautyPath = [[NSBundle mainBundle] pathForResource:@"face_beautification" ofType:@"bundle"];
FUBeauty *beauty = [[FUBeauty alloc] initWithPath:beautyPath name:@"face_beautification"];
[FURenderKit shareRenderKit].beauty = beauty;

// 4. 设备分档
FUDevicePerformanceLevel level = [FURenderKit devicePerformanceLevel];
if (level <= FUDevicePerformanceLevelLow) {
    [FURenderKit setDynamicQualityControlEnabled:YES];

[FURenderKitManager setMaxFaceNumber:1];

// 5. 参数应用（在此扩展 §4.2/4.3 全部 25 项）
beauty.blurType = 2;
beauty.blurLevel = ReflexType3.toRaw(uiBlur);
beauty.colorLevel = ReflexType1.toRaw(uiColor);
```

### §8.3 现有 FUManager OC 层扩展方案

现有 `FUManager.updateBlur:whiten:eyeEnlarge:faceThin:enabled:` 签名死板。扩展方式：

**方案 A（推荐）**：新增 `updateWithBeauty:(FUBeauty *)beauty` 方法，Swift 侧构造 FUBeauty 直接传入。**优点**：签名简洁；SDK 变更零改动。**缺点**：Swift 需要 import FURenderKit。

**方案 B**：`FUManager` 新增 `updateSettings:(NSDictionary *)dict` —— key 为 property 名字符串。**优点**：完全解耦。**缺点**：无类型检查，易出 typo。

**方案 C**：保留现有 `updateBlur:whiten:...` 为 legacy，新增 `updateSkin:(BeautySkinSet)set shape:(BeautyShapeSet)set filter:(BeautyFilterSet)set`。**优点**：分组清晰。**缺点**：签名膨胀 + 5 组结构体维护成本高。

**默认按 A 推进**，Swift 侧包一层 `FUBeautyRenderer.applyBeautySettings(_ settings: BeautySettings)` 内部构造 FUBeauty 挂到 renderer。
