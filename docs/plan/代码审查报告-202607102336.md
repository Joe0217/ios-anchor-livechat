## 二、必修（2 项）

### 必修-1 · `scheduleToastClear` 未 cancel 上一次 Task，与项目内 3 处已有 pattern 不一致

- **文件**：[Sources/Live/Roulette/RouletteStore.swift:237-243](../../Sources/Live/Roulette/RouletteStore.swift#L237-L243)
- **维度**：内存与资源 / 一致性
- **复查证据**：
  - grep 命中 [WishSettingStore.swift:31, 290-291](../../Sources/Live/WishSetting/WishSettingStore.swift#L288-L296) / [LiveSettingsStore.swift:43, 253-254](../../Sources/Live/LiveSettings/LiveSettingsStore.swift#L253) / [LiveResultStore.swift:30, 132-133](../../Sources/Live/LiveResult/LiveResultStore.swift#L132) **3 处 store** 都用 `toastClearTask?.cancel() + toastClearTask = Task {...}` 模式
  - WishSettingStore.swift:286 明确注释 `"重复触发 cancel 前一个任务，避免闪烁/stale 覆盖"` —— 项目一致性约定
  - RouletteStore 本次是本次新增，唯一漏做
- **触发场景（真机路径）**：用户点 Enable 报错（toast="Please Enter the Price"）→ 立即修价再点 Enable → toast="Wheel Started"。旧 Task 在 2s 后触发 `toast = nil`，把仍在展示期内的"Started" toast 提前抹掉。UX 断裂：toast 一闪即隐。
- **修复**：
  ```swift
  private var toastClearTask: Task<Void, Never>?

  private func scheduleToastClear() {
      toastClearTask?.cancel()
      toastClearTask = Task { [weak self] in
          try? await Task.sleep(nanoseconds: 2_000_000_000)
          guard !Task.isCancelled else { return }
          self?.toast = nil
      }
  }
  ```

### 必修-2 · RouletteSettingSheet 内挂 `RouletteIntroPopup` overlay，重开引导只覆盖 sheet 60% 屏

- **文件**：[Sources/Live/Roulette/UI/RouletteSettingSheet.swift:44-48](../../Sources/Live/Roulette/UI/RouletteSettingSheet.swift#L44-L48)
- **维度**：iOS 平台规范 / modal hoist
- **复查证据**：
  - 主 sheet detent 为 `.fraction(0.6)`（[LiveRoomTopPopups.swift:104](../../Sources/Live/LiveRoomTopPopups.swift#L104)），只占 60% 屏
  - `RouletteIntroPopup` 挂在 SettingSheet 的 `ZStack.overlay {}`，其 `Color.black.opacity(0.5).ignoresSafeArea()` 被 sheet presentation frame 裁掉，实际只遮盖 60% 屏
  - 首次引导已经从 [LiveRoomTopPopups.swift:107-113](../../Sources/Live/LiveRoomTopPopups.swift#L107) 挂在正确的全屏 overlay 层
  - 违反 [.claude/rules/swiftui-fullscreencover-hoist.md](../../.claude/rules/swiftui-fullscreencover-hoist.md) §规则 1：modal 类展示应 hoist 到唯一根容器
- **触发场景**：用户在设置 sheet 内点 header ? 图标 → intro 弹出但只覆盖 60% 屏，顶部/底部露出直播画面 + 底下 sheet drag indicator 仍可见，视觉断裂
- **修复**：把重开引导 state 上抛到 LiveRoomView 层（callback），复用 `TopSheetsModifier` 的 overlay 展示。SettingSheet 加入参：
  ```swift
  let onReopenIntro: () -> Void
  private func reopenIntro() { onReopenIntro() }
  ```
  LiveRoomTopPopups 层接住并 set `showRouletteIntro = true`（现有 state）+ 可选先关 sheet 或保持共存。

## 三、建议（4 项）

### 建议-1 · 错误 toast 直接显示 `String(describing: error)` 泄露技术堆栈

- **文件**：[RouletteStore.swift:200, 232](../../Sources/Live/Roulette/RouletteStore.swift#L200)
- **维度**：iOS 平台规范 / i18n
- **复查证据**：`closeWheel/save` 失败时 `toast = (error as? LocalizedError)?.errorDescription ?? String(describing: error)`。fallback 分支会直接吐英文技术信息（`URLError` / `DecodingError` 等），三语言直播 App 上给主播看是断裂 UX，同时违反 [.claude/rules/error-handling.md](../../.claude/rules/error-handling.md) "用户可感知的错误文案走 i18n"
- **触发场景**：非 `LocalizedError` 类错误（`DecodingError`、`URLError` 部分 code）→ toast 显示英文原文
- **降建议理由**：走 APIClient 主链路时 `APIError` 已带 `errorDescription`；`DecodingError` 常见于开发期，生产真机罕见。不阻塞功能，但一致性问题应改
- **修复**：`toast = (error as? APIError)?.message ?? L10n.commonNetworkError`；或统一收敛为通用 "网络错误，请重试" i18n key

### 建议-2 · `RouletteEditSheet` Confirm 按钮无 `.disabled(store.isSaving)`，快速双击会误 dismiss

- **文件**：[RouletteEditSheet.swift:138-159](../../Sources/Live/Roulette/UI/RouletteEditSheet.swift#L138-L159)
- **维度**：Swift 并发
- **复查证据**：Confirm 按钮 `Task { await store.confirmEdit(); isPresented = false }`。第二次点击进入 `store.save` 被 `guard !isSaving else { return }` 挡下立即返回 → **仍会执行 `isPresented = false`** → sheet 关闭。首次 save 仍在后台跑
- **触发场景**：手指快速双击 Confirm（真机可能，网络慢时用户容易再点）
- **降建议理由**：功能上仍能保存（first Task 完成），但 UX 层用户看到 sheet 关了、不确定是否成功；改动小（一行 `.disabled(...)`）即可根治
- **修复**：
  ```swift
  Button { ... }
      .disabled(store.isSaving)
  ```
  对齐 SettingSheet mainButton/closeButton 已有的 disable pattern

### 建议-3 · header ? 图标按钮 + Edit 项 xmark 按钮 tap target 32×32，低于 HIG 44×44

- **文件**：
  - [RouletteSettingSheet.swift:87-93](../../Sources/Live/Roulette/UI/RouletteSettingSheet.swift#L87-L93)（header ? 按钮）
  - [RouletteEditSheet.swift:76-81](../../Sources/Live/Roulette/UI/RouletteEditSheet.swift#L76-L81)（xmark 删除按钮）
- **维度**：iOS 平台规范
- **复查证据**：Apple HIG 明确要求可点击控件最小 44×44 pt；`contentShape(Rectangle())` 已加，但 frame 尺寸本身不达标
- **触发场景**：手指粗大或位置抖动时误触率上升
- **降建议理由**：视觉图标本身合适（20/18 pt），命中区略小但不至于点不到；改动只是 frame 数值调整，无副作用
- **修复**：`.frame(width: 44, height: 44)`，Image 视觉大小通过 `.font(.system(size:))` 保持不变

### 建议-4 · `handleEnable` Task.sleep(1.2s) 悬挂，边界场景可能误关新会话

- **文件**：[RouletteSettingSheet.swift:262-271](../../Sources/Live/Roulette/UI/RouletteSettingSheet.swift#L262-L271)
- **维度**：Swift 并发 / 生命周期
- **复查证据**：
  - Task capture `isPresented` binding，与 sheet 生命周期不解耦
  - 边界：用户在 1.2s 窗口内手动下拉 dismiss → 立刻再次点转盘入口重开 → 旧 Task 到期把新 sheet state 拽 false
  - 类比现有 rule [swiftui-fullscreencover-hoist.md](../../.claude/rules/swiftui-fullscreencover-hoist.md) 的"跨生命周期悬挂 Task"族问题
- **降建议理由**：场景边角（<1.2s 内下拉+重开是苛刻操作），概率极低；但若发生用户体验诡异
- **修复**：把 Task 存成 `@State private var autoDismissTask: Task<Void, Never>?`，`onDisappear` 里 cancel；或改由 Store 发 `@Published var shouldAutoDismiss` 信号，View `.onChange` 消费
