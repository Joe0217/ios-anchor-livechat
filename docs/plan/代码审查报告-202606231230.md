# Hily iOS 主播端 代码审查报告

> 审查时间：2026-06-23
> 审查范围：`Sources/` 70 个 Swift 文件，约 8168 行
> 审查方式：5 维度并行（iOS 规范 / 并发 / 内存 / SwiftUI 性能 / 安全隐私）
> 审查依据：`CLAUDE.md` + `.claude/rules/*` + Apple 平台最佳实践

## 一、概览

整体评估：**核心媒体管线（Camera/Metal/Agora）经过 v5.x 多轮修复已较稳；主要技术债集中在 4 条主线**：

| 主线 | 表现 | 风险面 |
|------|------|--------|
| **凭据持久化** | token/imToken/loginUuid 全部在 UserDefaults | 与 CLAUDE.md "Keychain" 约定背离，越狱/备份明文可见 |
| **日志治理** | 79+ 处裸 `print()` 残留，含 token 前缀和完整响应 | Release 包仍写控制台，敏感字段无 `privacy: .private` |
| **View 副作用收敛** | LiveRoomView.onAppear 大量编排、计时器在 View 内 | 与 CLAUDE.md "副作用收敛 Store" 约定背离 |
| **异常退出路径资源清理** | onDisappear guard 矫枉过正，缺 deinit 兜底 | 摄像头硬件占用、SDK 残留 delegate、内存不释放 |

P0 共 5 项、P1 共 12 项、P2 共 16 项；无运行时崩溃级风险。

## 二、P0（必须改）

### P0-1 Token / imToken / loginUuid 全部存 UserDefaults
**违反 CLAUDE.md "token 存 Keychain" 明确约定**

- 文件：`Sources/Networking/APIClient.swift:103-114`、`Sources/Auth/SessionStore.swift:13-71`
- 风险：UserDefaults 在 iTunes/Finder 备份和越狱设备明文可见；loginUuid 泄露 + AES key 已知 → 可伪造 WS 在线态心跳
- 修复：封装 `KeychainStore`（`SecItemAdd` + `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`），`auth.token.v1` 与 `session.user.v1` 全迁；deviceId 一起迁（Keychain 在卸载后默认保留，更稳定）；logout 走 `SecItemDelete`

### P0-2 APIClient 在 Release 包仍打印 token 前缀 + 完整响应
**违反 CLAUDE.md "生产不留裸 print" 明确约定**

- 文件：`Sources/Networking/APIClient.swift:38-42`
```swift
print("➡️ [API] POST \(path) | loginToken=...len\(tk.count) 前8位=\(tk.prefix(8))…")
print("⬅️ [API] \(path) | 原始响应=\(String(data: data, ...)?.prefix(300))")
```
- 风险：token 前 8 位 + 长度对 64+ 字符 base64 token 仍是显著泄露；响应体 300 字节含 envelope（错误信息、message）；Release 包通过 USB Console 仍可抓取
- 修复：迁 `os.Logger`，敏感字段标 `privacy: .private`（Release 自动 `<private>`）；token 打印 `#if DEBUG` 包裹；同步处理 `Live/`、`Call/`、`Networking/` 共 79+ 处裸 print（含 `🟣🔴🟢` 表情符号串）

### P0-3 LiveRoomView.onDisappear guard 矫枉过正，异常退出路径不清理
**v5.3.3 修复切后台坑时引入的新坑**

- 文件：`Sources/Live/LiveRoomView.swift:104-118`
```swift
guard scenePhase != .background, store.state == .ended else { return }
camera.tearDown(); Task { await agora.leave() }; nim.leave(); camera.stop()
```
- 风险：用户被踢、tab 切换、deep link 跳走、endLive 失败等任何 `state != .ended` 的 dismiss 路径下，camera/agora/nim 全部跳过清理 → 摄像头指示灯不熄、AgoraRtcEngineKit 视频编码器进程级泄漏、NIM 聊天室 delegate 残留、CameraManager 4 个 NC observer 残留
- 修复：解耦 `state == .ended` 强耦合，仅用 `scenePhase != .background` 拦截切后台
```swift
guard scenePhase != .background else { return }   // 切后台不清理
camera.tearDown(); Task { await agora.leave() }; nim.leave(); camera.stop()
```

### P0-4 LiveService 大量 `try?` 静默吞 JSON 解析错误
**违反 `.claude/rules/error-handling.md` 与同文件自带注释**

- 文件：`Sources/Live/LiveService.swift:36`、`:48`、`:114`、`:118`
- 风险：`getMyLiveRoomRaw`、`beginLiveRoomRaw`、`getChatRoomAddress` 把 `JSONSerialization.jsonObject` 用 `try?` 包起来，失败 fallback `[:]/[]`。开播链路解析失败被压成"字段缺失"假象，错误条带显示"无 channelId"而非真因
- 修复：改 `do/try/catch`，catch 块记录原始 data hex 头 + 长度 + endpoint 后抛 `APIError.decoding`；如确实兼容历史 null，用 `isValidJSONObject` 守卫并明确空对象语义

### P0-5 LiveStore.shared 单例与 @StateObject 实例共存导致状态分叉
**代码自带注释承认"待清理"**

- 文件：`Sources/Live/LiveStore.swift:64-69`
- 风险：CallStore 通过 `LiveStore.shared.*` 间接路径读到的永远是空状态机；`shared.state == .living` 检查永远 false；任何调用方误以为读单例，实际读到的是 D 里程碑早期草案占位
- 修复：删 `static let shared`，CallStore.swift L435/L437 改走已有 weak ref（`CallStore.liveStore`，由 LiveRoomView.onAppear 注入）；如担心 D 流程未完成，先把 shared 改 `fileprivate` 仅供 CallStore 兜底，并加 `#warning("D 里程碑收尾必须删除")`

## 三、P1（应该改）

### P1-1 Info.plist 缺 `ITSAppUsesNonExemptEncryption`（提审阻塞）
- 文件：`Sources/Info.plist`
- 风险：App 使用自实现 AES 加密，缺该 key 会被卡 TestFlight / 提审
- 修复：加 `<key>ITSAppUsesNonExemptEncryption</key><false/>`（声网/云信/AES 均属于 5D992 豁免）

### P1-2 主 bundle 缺 PrivacyInfo.xcprivacy（iOS 17+ 提审阻塞）
- 风险：iOS 17+ App Store 要求主 App + 所有第三方 SDK 都附隐私清单；声网/云信/相芯三方 SDK 已自带，**但本 App 主 bundle 缺**
- 修复：新建 `Sources/PrivacyInfo.xcprivacy` 声明：
  - `NSPrivacyAccessedAPITypes`：UserDefaults reason `CA92.1`、`UIApplication.applicationState`（AgoraManager 已用）
  - `NSPrivacyCollectedDataTypes`：email / userId / device id
  - `NSPrivacyTracking = false`

### P1-3 多环境密钥隔离缺失（切 prod 前必修）
- 文件：`Sources/Core/AppConfig.swift:6-21`、`Sources/Agora/AgoraConfig.swift:6-18`
- 风险：AES key / IV / OCP key / NIM appKey / 声网 appId / 长期 RTC token 全部硬编码进二进制。dev 写死可接受，但**无 xcconfig 结构** → 切 test/prod 时 prod 密钥会被钉进源码，逆向 `strings` 直接抓
- 修复：`Config-Dev.xcconfig` / `Config-Prod.xcconfig` 注入密钥；AppConfig 从 `Bundle.main.infoDictionary` 读；prod xcconfig 不入库；删除 `AgoraConfig.token` / `channelId` / `uid` POC 长期常量，POC 路径独立 `#if DEBUG`

### P1-4 AgoraManager.leave 500ms 兜底在后台不触发
- 文件：`Sources/Agora/AgoraManager.swift:150-158`
```swift
Task { @MainActor [weak self] in
    try? await Task.sleep(nanoseconds: 500_000_000)
    if let c = self.leaveContinuation { c.resume() }
}
```
- 风险：切后台后 MainActor Task.sleep 挂起，didLeaveChannelWith 也无回调 → leave() 永久挂起，pauseForCall 卡死
- 修复：用 `DispatchQueue.main.asyncAfter`（后台仍执行）；并补 willResignActive 时主动 resume

### P1-5 NIMChatroomManager 非 @MainActor 却写 @Published + 缺 deinit
- 文件：`Sources/Live/NIMChatroomManager.swift`
- 风险：`messages/onlineCount/warningToast` 是 @Published；SDK 回调依赖每个站点自觉切 main，一处遗漏即触发 SwiftUI 后台变更崩溃。全文件无 `deinit`，view 非正常 dismiss 时 leave() 未调 → NIM SDK delegate list 残留 dangling pointer
- 修复：类标 @MainActor 或所有回调统一 `nonisolated` + `Task { @MainActor [weak self] }`；补 `deinit { leave() }`（leave 已 idempotent）

### P1-6 CameraManager 缺 deinit 兜底
- 文件：`Sources/Camera/CameraManager.swift`
- 风险：observer 闭包 capture self → tearDown 未调时 CameraManager 不释放 → 间接持 BeautyRenderer 等大对象（与 P0-3 同源）
- 修复：补 `deinit { tearDown() }`（v5.3.1 提到延迟 deinit，但只要 view 路径未漏调 tearDown，deinit 兜底无害）

### P1-7 SessionStore.logout 未销毁 AgoraEngine
- 文件：`Sources/Auth/SessionStore.swift`、`Sources/Agora/AgoraManager.swift:173-176`
- 风险：`destroyEngine()` 存在但 v5.4 标 backlog 未接入；用户登出/被踢/退出 app 时 AgoraRtcEngineKit + 视频编码器 + Metal 资源进程级永驻，dev/debug 重复登录登出累积
- 修复：`SessionStore.logout` 中显式 `AgoraManager.destroyEngine()`

### P1-8 LiveStore 单一巨型 ObservableObject 引发失效风暴
- 文件：`Sources/Live/LiveStore.swift` 全文
- 风险：13+ 个 @Published 字段（state / callState / networkDebugInfo / onlineCount / warningToast / returnLiveCountdown 等）共享同一 publisher；networkDebugInfo 在每次声网 networkQuality 回调（≥1Hz）触发整页重渲染
- 修复：按"高频/中频/低频"拆三 store（NetworkDebugStore / RoomStatusStore / ToastStore），LiveRoomView 用 `@ObservedObject` 注入；或把 networkDebugInfo 提取到独立 `@StateObject` 子 view

### P1-9 LiveRoomView / RootView 顶层 `.animation(_:value:)` 污染全树 transaction
- 文件：`Sources/Live/LiveRoomView.swift:157-158`、`Sources/Home/RootView.swift`
```swift
.animation(.easeInOut(duration: 0.2), value: callStore.state)
.animation(.easeInOut(duration: 0.2), value: store.isWaitingReturnLive)
```
- 风险：CallStore.state 变化（.calling → .connecting → .connected 多次）触发整 subtree transaction 计算；与 CallView 内部 transition(.opacity) 叠加
- 修复：改 `withAnimation { ... }` 在 LiveStore/CallStore 状态切换处显式触发；或用 `.transaction { $0.animation = ... }` 精确限定

### P1-10 LiveRoomView.onAppear 在 View 内编排 6+ 步副作用
- 文件：`Sources/Live/LiveRoomView.swift:67-103`
- 风险：闭包注入、权限请求、声网 join、IM enter、callStore 注入、observer 挂载混在 37 行 onAppear；任一步骤改动都影响视图重建
- 修复：LiveStore 新增 `bootstrap(roomInfo:beauty:agora:camera:nim:callStore:)`；View 只调用 `store.bootstrap(...)` 与 `store.teardown()`

### P1-11 Timer.publish 在 View 内驱动业务计时器
- 文件：`Sources/Live/LiveRoomView.swift:28`、`Sources/Call/CallView.swift:52`、`Sources/Call/CallView.swift:120`
- 风险：View 销毁/重建时计时丢失；与 v5.5 CallView bodyContent 分支切换隐患同源
- 修复：LiveStore/CallStore 暴露 `@Published var elapsed: Int` + 内部 `Task.sleep(1s)` 循环，View 只读 `store.elapsed`

### P1-12 CallStore.swift 733 行，单类承担过多职责
- 文件：`Sources/Call/CallStore.swift`
- 风险：1v1 状态机 + RTM 信令委托 + NWPathMonitor + 计费 + 重连 + 错误文案；hardcoded 中文 lastError 散落十多处，i18n 难度倍增
- 修复：抽 `CallNetworkMonitor` / `CallSignalingBridge` / `CallErrorFormatter` 三个 collaborator；CallStore 仅持状态机 + 编排

## 六、业务约束所致不可改（已识别清单）

| 项目 | 业务原因 |
|------|---------|
| 双重 MD5 密码哈希 | 与 H5 / 安卓 / 服务端协议对齐；服务端最终验证靠服务端再 hash + salt |
| AES-128-CBC + 固定 ASCII key/IV | 与 H5 / 安卓协议对齐，服务端无法支持请求级随机 IV |
| dev 密钥硬编码（key/iv/appId/ocpKey） | 业务允许；prod 切换时改 xcconfig 隔离即可 |
| deviceId 用 UUID + UserDefaults | 卸载即换 ID 是合规友好选择；迁 Keychain 可保留跨卸载 |
| 主 token + bagshop auth_token 双 token | 服务端架构原因；原生侧只用主 token |
| 越狱检测 / 反调试 | 直播 App 非金融/支付场景，App Store 4.0 不鼓励过度检测 |
