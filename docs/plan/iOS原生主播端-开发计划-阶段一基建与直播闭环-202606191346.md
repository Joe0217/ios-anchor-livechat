# iOS 原生主播端 · 正式开发计划（阶段一：基建 + 直播闭环）

## Context（为什么做、做到哪）

H5 主播端（`anchor-livechat-h5`：1v1 通话、直播、PK、美颜、礼物收益）要用 Swift 原生重建，以摆脱 webview 的性能与美颜管线限制。目前已完成两件事：

1. **POC 验证**（`anchor-beauty-ios-poc`）：最高风险的技术点已真机跑通——AES 鉴权、相芯美颜实时管线、声网外部源推流、1v1 通话媒体、云信 IM+聊天室。"原生重建可行"这一核心假设成立。
2. **功能蓝图**（`docs/plan/iOS重建-功能梳理-20260616/`）：9 大模块深度梳理 + 风险表 + 重建顺序，已就绪。

**本计划的目标**：把验证级 POC 转为可持续演进的生产工程，并交付**第一个"真机可日常使用"的里程碑——基建骨架 + 直播闭环**。

**已定决策**：① 新建生产工程（POC 模块作已验证资产迁入）；② 首期 = 基建 + 直播闭环；③ 账号密码登录（iOS 自包含，不依赖外层原生壳注入）。

**协作模式**：Claude 全程写代码，用户只决策 + 真机测试。因此方案按"模块解耦、每步可独立真机验证"组织，支持跨多个会话推进。

> 本轮仅产出本计划文档，不新建工程、不写代码。

## 关键事实校准（基于 H5 真实源码，影响实现，务必先知）

1. **AES 编码方向已对齐**：H5 上行 `encrypted.toString()` = Base64，下行 `enc.Hex.parse` = Hex，POC `CryptoUtil` 已一致并验证。剩余风险仅"prod 是否同方向"。
2. **密钥随环境变（不只换域名）**：dev 主/bagshop 同一套；test/prod 主接口与 bagshop 各换一套密钥。多环境配置必须把**密钥**纳入 xcconfig。
3. **心跳是 6s**（源码 `setInterval(keepLiving, 6000)`，"10秒"是过时注释）。`callState`：0直播/1通话/2匹配/3PK，阶段一恒为 0。
4. **强制下播 5 原因触发条件已确认**：`'3'`系统强制(心跳 code 1992/1006 封禁)、`'4'`断连(连续心跳失败 >6 次)、`'5'`网络差(连续 ≥30 次质量≥5；≥10 次上报埋点)、`'99'`相机错误、正常结束。
5. **userType 路由守卫在 H5 已被注释**，分流发生在登录后业务层。原生阶段一只需"登录后按 userType 判定主播可进/其余受限"。
6. **双 token 拼接（loginUuid+key+token→webParams）是给 webview 传参的，原生不需要**。原生直接持有 loginUuid/token；bagshop `auth_token` 用 `loginUuid` 换、401 自动续。
7. **公屏走 IM 登录 + 聊天室普通模式**（复用 IM 长连接，非独立模式）；自定义消息 `attachType` 是**数字编码**（如 50/61/63）。

## 1. 工程架构

### 形态
新建独立仓库（建议 `anchor-live-ios`，与 POC 同级）。沿用 POC 已验证的混合依赖形态：
- **xcodegen**（`project.yml`）声明式管理工程，避免 pbxproj 冲突，适合 Claude 生成 + 用户 review
- **SPM** 装声网（`AgoraRtcEngine_iOS`，exactVersion 锁定）
- **CocoaPods** 仅装云信 `NIMSDK_LITE`，构建走 `.xcworkspace`
- **embedded framework** 相芯 `FURenderKit.framework` + OC 桥接
- iOS 16、仅 iPhone、竖屏；**bundleId 必须保持 `com.anchor.livechat`**（相芯 authpack 绑定，不可改）
- 不引入 TCA/Swinject。状态 = SwiftUI + ObservableObject；DI = 构造注入 + 薄 `AppEnvironment` 容器

### 目录结构（关键部分）
```
Sources/
├─ App/            AnchorLiveApp / AppEnvironment(DI容器) / AppRouter / RootView
├─ Core/           Config/AppConfig · Crypto/CryptoUtil · Storage/{Keychain,DeviceInfo} · Logging/Log
├─ Networking/     APIClient(主) · SapiClient(bagshop) · RequestHeaders · APIError · TokenProvider
├─ Features/
│  ├─ Auth/        SessionStore · AuthService · AuthModels · LoginView
│  ├─ Live/        LiveStore(状态机) · LiveService · HeartbeatController · NetworkQualityMonitor
│  │              · LiveModels · LivePrepareView · LiveRoomView · Components/
│  ├─ Chatroom/    NIMChatroomManager · ChatMessage · GiftMessageParser
│  └─ Media/       CameraManager · MetalPreviewView · AgoraManager · BeautyRenderer · BeautyParameters
├─ Resources/      Localizable(en/ar/tr) · Assets · Info.plist
Config/            Base + Dev/Test/Prod.xcconfig + Secrets.xcconfig(git-ignore)
Vendor/FaceUnity/  framework + bundles + 桥接 + authpack（原样迁）
```

### 状态管理（分层 Store，不用单一巨型 AppState）
- **AppEnvironment**：DI 容器，`@main` 创建一次注入根，只装配依赖、不放可变状态
- **会话级**：`SessionStore`（登录态/user/userType/token）、`AppRouter`
- **特性级**：`LiveStore`（直播状态机，统筹心跳/网络/强制下播）；`CameraManager`/`AgoraManager`/`NIMChatroomManager` 保持局部 `@StateObject`，由 `LiveStore` 协调
- 原则：全局只放跨页面共享的（登录态/路由）；直播状态收敛进 `LiveStore`；View 只读 `@Published`，副作用（计时器/心跳/强制下播）全在 Store/Controller

### 多环境（xcconfig + Scheme）
Dev/Test/Prod 三套 xcconfig 继承 Base，定义 `API_BASE_URL`/`SAPI_BASE_URL`/`AES_KEY`/`AES_IV`/`SAPI_AES_KEY`/`SAPI_AES_IV`/`NIM_APP_KEY`/`AGORA_APP_ID`/`TA_APP_ID`/`APP_ID`/`OCP_APIM_KEY`，经 Info.plist `$(VAR)` 注入，`AppConfig` 运行时强类型读出。真密钥放 `Secrets.xcconfig`（git-ignore），仓库只放 `.example`。主/sapi 用**两个独立 client** 区分（比 H5 的 url.includes 更清晰）。

## 4. 直播闭环实现拆解

由 **`LiveStore` 状态机**统筹：`idle → preparing → starting → living → (forceEnding|ending) → ended`。

- **LivePrepare**：复用 Camera/Beauty/Metal（预览不推流），点开播调 `LiveStore.start()`
- **开播组装**（复用 `LiveService.startLive()`）：getMyLiveRoomV2 + beginLiveRoom + getAgoraRtmToken 三步合并 → 频道=`agoraChannelId`、join token=`rtcToken`、uid=`userId`、心跳 roomId=`id`、聊天室=`yxRoomId`；新增失败分流（无封面/2001/1006）
- **直播间能力**：

| 能力 | 复用 POC | 新增/校准 |
|---|---|---|
| 推流 | AgoraManager(broadcaster + 外部帧) | BGRA、镜像方向 |
| 本地预览 | Camera+Metal+Beauty | 直播间自持相机 |
| **心跳(权威源)** | LiveService.heartbeat | **HeartbeatController**：6s、callState 恒0、响应 1992/1006→'3'、连续失败>6→'4' |
| **网络质量** | Agora 网络回调 | **NetworkQualityMonitor**：连续≥30 次质量≥5→'5'、≥10 上报、恢复清零 |
| 公屏/在线人数 | NIMChatroomManager | 断线重连、leave 复位 |
| 礼物解析 | NIM custom 分支 | **GiftMessageParser**：attachType 数字→礼物模型 |
| 礼物动画 | — | **GiftAnimationPlayer**：SVGA/MP4-alpha 串行队列（阶段一可先占位） |
| 美颜面板 | BeautyParameters+滑块 | sheet UI |
| **强制下播分流** | — | `LiveStore.forceEnd(reason)`：'3'/'4'/'5'/'99'+正常 |
| 下播 | endLiveRoom+leave+stop | `LiveStore.end()` 统一清理顺序：清定时器→离频道→endLiveRoom→路由结束页 |

## 5. 里程碑（每个可独立真机验证）

**里程碑 A — 基建骨架 + 登录闭环（M0–M4）**
验收：切 dev/test scheme → 邮箱+密码登录 → token 进 Keychain → 杀进程重启保持 → userType 分流 → 登出清态；AES 加解密单测对齐 H5。可独立交付（能登录的空壳）。

**里程碑 B — 直播闭环（A + M6）= 首期"真机可日常使用"目标**
范围：LivePrepare → 开播组装 → Agora 推流 → 云信公屏/在线人数 → 6s 心跳 + 强制下播判定 → 正常下播。
验收：真机开播他端能看画面+听声；公屏收发 + 在线人数变化；断网约 60s 触发心跳断连('4')；后台封禁触发('3')；正常结束。礼物动画可先占位。

**里程碑 C — 礼物动画 + sapi 双 token + 工程化收尾**
范围：GiftMessageParser 全量 attachType、GiftAnimationPlayer 队列、SapiClient 双 token 401 续、i18n(en/ar/tr)+RTL、ThinkingData 埋点、Crash 上报。
