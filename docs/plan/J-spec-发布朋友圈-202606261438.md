## §3 接口契约

### §3.1 `POST /api/sts/getOssUploadParam`

**走主接口加密通道**（`APIClient.shared.post`），AES + 双 token + envelope。

请求 body：`{}`（空对象，对齐安卓）

响应 result（解密后 JSON）：
```json
{
  "accessid": "STS-AccessKeyId",
  "policy": "Base64Policy",
  "signature": "Base64Signature",
  "host": "https://app-media-sg.oss-accelerate.aliyuncs.com",
  "cdnUrl": "https://app-media-sg.oss-accelerate.aliyuncs.com",
  "expire": "1234567890"
}
```

**字段类型**：全部 String（即使 expire 是数字，安卓也按 String 取）。`expire` 是 epoch 秒。

**凭证寿命策略**（v2 红队 #3 critical）：
- **预检**：每次进入"待上传"阶段先看 `expire - now < 300s`（5min 安全阈值）→ 重拉 STS 再发 OSS
- **重拉触发**：OSS 返 403 + body 含 `SecurityTokenExpired` / `InvalidAccessKeyId` / `RequestTimeTooSkewed` → 自动重拉 STS 并仅重传未完成的图（不重传已成功 url）
- **凭证作用域**：单次发布动作内复用同一份凭证；不持久化到 disk
- **凭证刷新最多**：单次发布最多重拉 2 次（防死循环），超出转 `failed(credentialFailed)`

### §3.2 OSS multipart POST（不走 APIClient）

URL：`<host>`（取凭证里的 host 字段）

Method：POST

Content-Type：`multipart/form-data; boundary=<random>`

**boundary 规范**（v2 红队 #2 critical）：
- 字符集严格 `[A-Za-z0-9]{32}`（避免 `=` / `+` / `/` 被代理误解）
- 例：`a8B3kF9mZqLpR4xN1cV7yW2hD5jG6tQs`

**字段顺序（OSS 文档要求 file 字段最后）**：
1. `key` = `"00000000/\(yyyyMMdd)/\(UUID).jpg"` —— Text（统一 `.jpg`，对齐 Q7 HEIC→JPEG 决策）
2. `policy` = 凭证里的 policy —— Text
3. `Signature` = 凭证里的 signature —— Text
4. `OSSAccessKeyId` = 凭证里的 accessid —— Text
5. `success_action_status` = `"200"` —— Text（让 OSS 成功时返 200 而非 204）
6. `file` = 图片二进制 —— File

**multipart body 严格合约**（v2 红队 #1 #2 critical，纯逻辑可单测）：

```
--<boundary>\r\n
Content-Disposition: form-data; name="key"\r\n
\r\n
00000000/20260626/<uuid>.jpg\r\n
--<boundary>\r\n
... (policy / Signature / OSSAccessKeyId / success_action_status 同上，header/body 间 \r\n\r\n) ...
--<boundary>\r\n
Content-Disposition: form-data; name="file"; filename="<uuid>.jpg"\r\n
Content-Type: image/jpeg\r\n
\r\n
<binary image bytes>\r\n
--<boundary>--\r\n
```

**关键不变量**（写进单测）：
- 所有换行严格 `\r\n`（CRLF）
- 终止 boundary `--<boundary>--\r\n` 末尾必须有 trailing CRLF
- file part **必须**含 `Content-Disposition` 的 `filename="..."`（红队 #1：多数 bucket/region 缺这个会 400 InvalidArgument）
- file part **必须**含 `Content-Type: image/jpeg`（INV3）
- 文本 part **不需要**自定义 Content-Type（OSS 默认按 form text 解析）

成功响应：HTTP 200，body 空或 OSS XML（iOS 不解析 body，只看 status）。

成功后 URL：`"\(cdnUrl)/\(key)"`

### §3.3 `POST /api/expand/friendsCircle/create`

**走主接口加密通道**。

请求 body：
```json
{
  "displayRange": 1,
  "textContent": "用户输入文本",
  "imgUrls": ["url1", "url2", ...]
}
```

## §4 状态机

### §4.1 发布页 ViewModel 状态

```swift
enum PostingState: Equatable {
    case editing              // 用户编辑中（默认态）
    /// 上传 OSS 进行中。
    /// `uploadedUrls` 是 idx → cdnUrl 已成功的映射；失败重试时跳过已成功 idx（v2 红队 #4）
    case uploadingImages(progress: Int, total: Int, uploadedUrls: [Int: String])
    case creatingPost(imgUrls: [String])  // create 接口进行中，imgUrls 已全部就绪
    case success              // 发布成功（等 dismiss）
    case failed(reason: FailureReason, uploadedUrls: [Int: String])  // 失败可重试，保留已上传 url
}

enum FailureReason: Equatable {
    case textEmpty            // 纯文本空（前端 guard，应 disable 按钮防出现）
    case noImages             // imgs 空（H5 是必填，Q3 用户决策）
    case credentialFailed     // STS 接口失败（含 2 次重拉耗尽）
    case uploadFailed(idx: Int)  // 第 N 张图上传失败（同时整体失败，不发 create）
    case createFailed(msg: String)  // create 接口失败 + 业务消息（含审核拒绝，v3 不区分）
    case network              // 网络兜底
}
```

### §4.1.1 ViewModel 守 stale callback 的 epoch（v2 红队 #6 high）

```swift
@MainActor
final class PostPublishViewModel: ObservableObject {
    /// 当前上传轮次。每次进入 uploadingImages +1（重试也算新轮次）。
    /// URLSession dataTask 完成回调里 guard `epoch == currentEpoch` 才推进状态机，
    /// 防止 cancel 后到达的 stale callback 错误推进（如 cancel 后第 5 张 success 误推到 creatingPost）。
    private var currentEpoch: Int = 0
    private var inflightTasks: [Int: URLSessionDataTask] = [:]
    ...
}
```

### §4.2 合法迁移

```
editing → uploadingImages (用户点发布 + guard 通过 + STS 凭证 OK)
                          ↓ epoch +1，inflightTasks 启动
uploadingImages → creatingPost(imgUrls) (全部图上传成功)
uploadingImages → failed(uploadFailed, uploadedUrls) (任一失败，保留已成功 url)
uploadingImages → uploadingImages(progress+1, uploadedUrls') (单张成功，epoch 同；progress 推进)
creatingPost → success (200 + code 0000)
creatingPost → failed(createFailed, uploadedUrls) (任何业务码非 0000 或网络错；含审核拒绝，按 message 显示 toast；保留 uploadedUrls 供重试 create)
failed → editing (用户点"再编辑"，回到编辑态保留文本)
failed → uploadingImages (用户点"重试"，epoch +1；跳过 uploadedUrls 已有 idx 仅传缺失图)
failed(createFailed) → creatingPost (用户点"重试 create"，直接重发不再上传图)
success → (dismiss，view 销毁，state 不再可达)
```

### §4.3 非法迁移（必须守住）

**已有**：
- `editing → creatingPost`（跳过 OSS 上传）
- `uploadingImages → success`（跳过 create）
- `success → editing`（成功后不可回编辑）
- 任何 → uploadingImages 当 imgs 为空（必须先 guard）

**v2 新增**（红队 #6 #9）：
- **stale callback 不可触发迁移**：上传完成回调 guard `callback.epoch == currentEpoch`，否则丢弃；状态机不前进
- **create 已发出后不可 cancel**：进入 `.creatingPost` 后 `cancelInflightForDismiss()` 仅取消未发的；create Task **不 cancel**，但允许 ViewModel deinit（dismiss 时 NotificationCenter 兜底 post `.momentPublished`，me sub-tab 仍 reload）
- **failed → uploadingImages 跨 epoch**：用户重试时 epoch +1，旧 epoch 的回调即使后到也被守住
