## §0 概述

### 0.1 业务定位

主播端与用户 1:1 消息对话页。**主播端典型形态**：主播被动接收用户的关注/送礼/文字，主动回复文字/语音/选择自有相册图片视频。**非用户端的通用聊天页**（用户端可上传相册；主播端只能选自己 profile 里 `pictures[]` / `videos[]` 已有资源）。

### 0.3 范围三圈

**含（MVP）**：
- 文字消息发送 + 接收（含 emoji Unicode）
- 语音消息录制发送 + 接收（按住录 / 松开发 / 上滑取消；1-60s；AVAudioRecorder m4a → NIM 上传）
- 图片/视频消息发送 + 接收（**从主播 `AnchorInfo.pictures[]` / `videos[]` 选择**，非上传新文件）
- 消息列表：LazyVStack 倒序 + 上拉 20 条/页分页
- 顶部导航：返回 + 对端头像 + 昵称
- 发送状态：sending / uploading / sent / read / failed / refused（拉黑）—— **6 态**
- 进页自动清 unread + 发已读回执给对端（两件事，分别调 API）
- 键盘处理：出现时消息列表随之上移
- 会话列表 lastMessage/unread 联动更新（chat store 主动通知 MessageSessionStore）
- 消息去重：clientMsgId 主键

**不含（推 H-3 或更后）**：
- 长按消息菜单（复制/撤回/删除/举报，用户明示不做）
- 私密付费图文（推 I 里程碑）
- 系统消息 in-chat 展示（attachType SEND_GIFT / MISSED_CALLS_RECORD / -4 关注等，推 H-3；本 spec 只**保数据**不展示）
- 送礼物入口（推 H-3；用户已在 Work/GiftMessage 有单独入口）
- 通话入口（推 H-3；会话列表可看在线状态）
- @提及、快捷回复、消息引用、表情包 sticker

**占位**（H-3+ 补但 spec 需预留扩展点）：
- 系统/礼物消息 raw：`ChatMessageContent.system(rawJSON:)` case 保数据不展示
- 双分支 attachType 解析器 `MessageAttachParser`：H-2 只跑通 text/audio/image/video；custom attachType 归 `.system` case

### 0.4 依赖 & 里程碑对应

- **必须新建**（H-1 会话级 delegate 不含消息级）：`NIMChatAdapter` conform `NIMChatManagerDelegate`（`onRecvMessages` / 发送 status 变化 / receipt 事件）
- **弱依赖**：`AnchorInfo.pictures[]` / `videos[]`（已存在，字段 `MediaAsset`，非 H5 picList 结构 —— §3.3 已对齐）
- **强依赖**：H-1 已 commit 的 `MessageSessionStore.shared` / `NIMSessionAdapter`（会话级）—— chat store 完成发送后需主动通知
- **产出到**：H-3 补齐 sysMsg in-chat 展示 + 长按菜单 + 礼物/通话入口 + refused 拉黑独立视觉

### 2.2 消息发送状态机（6 态）

```
初始 ─→ .sending (乐观入列表)
         │
         ├── 需上传？──→ .uploading(progress) ──→ NIM send ──┐
         │                                                    │
         └── 直发 ──────────── NIM send ─────────────────────┤
                                                              │
                            ┌─ SDK success ──→ .sent ─┐       │
                            ├─ err 7101 (拉黑) ─→ .refused (禁重发) │
                            └─ err other ─→ .failed(errorCode:) ─→ tap 重发 → .sending
                                                              │
                                              receipt.ts ≥ msg.ts ──→ .read
```

**关键**：
- `.uploading` 是可选中间态（audio 必经；image/video 依 S1 结果）
- `.refused` **禁重发**（拉黑不可能通过重发解决，UI 隐藏红叹号）
- `.failed` **可重发**（tap 红叹号 → 回 `.sending`）
- `.read` 只能从 `.sent` 迁移，非乐观（等对端 receipt）

### 2.3 页面状态机

```
.loading ──→ 成功 ──→ .loaded([msgs])
    │                    │
    │                    ├── SDK 增量事件 ──→ 合并入 loaded（clientMsgId 去重）
    │                    ├── loading 期入 pendingUpdates 队列 ──→ loaded 后合并（复用 H-1 模式）
    │                    └── IM 断连 + fetchAll 空 ──→ 保留旧 loaded（Q3 同款）
    │
    └── 失败 ──→ .error ──→ 用户点重试 ──→ .loading

.empty：仅 loaded 且 0 条历史（新加会话）
```

### 2.4 消息类型 attachType 占位

| attachType | 归入 case | H-2 展示 |
|---|---|---|
| `text` (NIM 内置) | `.text` | ✅ |
| `audio` (NIM 内置) | `.audio` | ✅ |
| `image` (NIM 内置) | `.image` | ✅ |
| `video` (NIM 内置) | `.video` | ✅ |

## §3 数据契约

### 3.1 NIM API 调用清单（**red team #4 / #9 修正**）

| 方向 | 方法 | 说明 |
|---|---|---|
| 拉历史（首屏） | `NIMConversationManager.messages(session, message:nil, limit:20)` | limit 20 |
| 上拉分页 | 同 + `message:` 传当前**最旧的 NIMMessage 实例** | anchor 用 NIMMessage 实例，避免同秒多条歧义（red team #14） |
| 发文字 | `NIMChatManager.send(NIMMessage)` | text object |
| 发音频 | S4 spike：若 SDK 内嵌上传 → `sendAudioMsg(filePath, dur)` 自动 upload；否则 `NIMResourceManager.upload(file)` → 拿 URL → 构 audio msg → send | dur 毫秒 |
| 发图片/视频 | S1 spike：若支持外链 URL → 构 image/video object with URL → send；否则下载 CDN → 本地临时文件 → upload → send | 二选一由 S1 决定 |
| **清本地 unread** | `NIMConversationManager.markAllMessagesRead(in: session)` | 进页调；只清 badge 不通知对端 |
| **给对端已读回执** | `NIMChatManager.sendMessageReceipt(NIMMessage)` | 参数是**最后一条非我消息**；对端收到后走 receipt 事件（red team #4） |
| 收增量 | **新建 `NIMChatAdapter`** conform `NIMChatManagerDelegate`（red team #1） | onRecvMessages / sendMessage 状态变化 / didFetchMessageReceipts |
| 通知会话列表更新 | 发送成功后 `MessageSessionStore.shared` emit `.update` 事件（chat store 主动 push，不依赖 SDK didUpdate 保证）| red team #6 |

### 3.2 iOS 侧数据结构

```swift
struct ChatMessage: Identifiable, Equatable, Hashable {
    let id: String                    // NIM messageId (SDK 唯一主键，跨端一致)
    let clientMsgId: String?          // 本地乐观发送时的临时 id（sent 后与 messageId 对齐）
    let from: String
    let to: String
    let content: ChatMessageContent
    var status: ChatMessageStatus     // var
    let timestamp: Int64              // ms
    let isOutgoing: Bool
}

enum ChatMessageContent: Equatable, Hashable {
    case text(String)
    case image(url: URL, size: CGSize?)
    case video(url: URL, thumbnail: URL?, dur: Int)
    case audio(url: URL, dur: Int)
    case system(rawJSON: String)      // H-2 只存不展示
}

enum ChatMessageStatus: Equatable, Hashable {
    case sending
    case uploading(progress: Double)  // 0.0-1.0（无进度 fallback 0.5）
    case sent
    case read
    case failed(errorCode: String?)   // 网络 / SDK 其他错误 —— 可重发
    case refused(reason: String)      // 7101 拉黑等 —— 禁重发
}

/// 从 AnchorInfo.pictures[] + .videos[] 组装（red team #2）
struct AnchorMediaItem: Identifiable, Equatable {
    let id: String                    // MediaAsset.assetId
    let mediaUrl: URL                 // .url
    let coverUrl: URL?                // .coverUrl（video 有 poster）
    let kind: MediaKind
    let dur: Int?                     // video 时长秒
}

enum MediaKind: Equatable { case image, video }
```

## §4 交互流程

### 4.1 进入私聊页（**red team #5 修正**）

**导航接线**：
- `MainTabView` 加 `@State var messagesPath: NavigationPath = .init()`（对齐 homePath/workPath/profilePath）
- Messages tab 内 `MessageListView` 包 `NavigationStack(path: $messagesPath)`
- `MessageSessionRow` **tap 行为改造**：短按 → push ChatDetailView；长按 → 保留现有 unstick/delete confirmation（**red team #5**）

**流程**：
1. tap row → path.append(peerYxAccId)
2. NavigationStack `.navigationDestination(for: String.self)` → `ChatDetailView(peerYxAccId:)`
3. ChatDetailView `.task` 触发 `P2PChatStore.load()`
4. store 并发：`fetchHistory(limit:20)` + `markAllMessagesRead(session)` + subscribe NIMChatAdapter
5. loaded → scroll to bottom
6. **loaded 完成后**：对 loaded[messages] 最后一条非我消息调 `sendMessageReceipt` 给对端

### 4.2 发送文字
1. 输入 + tap send
2. 乐观 `ChatMessage(status:.sending, clientMsgId:UUID)` 追加末尾
3. `provider.sendText(to:, content:)` → 拿 messageId → 更新 message + `.sending → .sent`
4. 失败：7101 → `.refused`；其他 → `.failed`
5. 成功后：**store 主动 `MessageSessionStore.shared.handleEvent(.update(session))` 通知 lastMessage 联动**（red team #6）

### 4.3 发送语音（**red team #7 修正**）
1. 长按按钮 → `VoiceRecorder.start()` (AVAudioRecorder m4a)
2. 手指上滑到 cancel 区松开 → 丢弃录音文件 + toast "已取消"
3. 松开（非取消）→ 停录
4. `if dur < 1s` → toast "录音太短" + 丢弃
5. `if dur >= 1s`：乐观追加 `ChatMessage(status:.uploading(0), ...)` → 上传 → `.sending` → send → `.sent`
6. **临时文件保护**：上传前先 copy 到 chat 目录持久化 → 上传完成删除；重发失败时源文件仍在（防应用切后台被系统清）
7. 失败：`.failed(errorCode:"upload")` 允许重发

### 4.4 发送图片/视频（**S1 决定路径**）
1. tap "+" → 底部 `MediaPickerSheet(items: AnchorMediaItem 列表)`（若 pictures/videos 未就绪显 skeleton；若确认空态 → toast "暂无相册"）
2. 单选 → tap send
3. **若 S1 spike 支持外链**：构 image/video NIMMessage with url = item.mediaUrl → send（零延迟）
4. **若 S1 不支持**：`.uploading(0)` → 下载 CDN 到临时 → NIM upload → send（fallback 路径）
5. 乐观 sending → sent / failed

### 4.5 接收对方消息（**red team #10 修正**）
1. `NIMChatAdapter` `onRecvMessages` fire → 派 `P2PChatStore.handleIncoming(_:)`
2. store 按 messageId 去重（loading 期入 pendingUpdates；loaded 期直接合并）
3. 若当前在底部 → scroll down；否则显示 "N 条新消息" badge
4. **若页面 active 且在底部**：调 `sendMessageReceipt(lastNonOwnMsg)` 给对端（非页面 active 时不发，避免"静默送达"被误判已读）

### 4.6 上拉加载 20 条（**red team #14 修正**）
1. ScrollView 顶部 sentinel view 出现 + throttle（首版 400ms，可 tuning）
2. `provider.fetchHistory(limit:20, anchor: currentOldest_NIMMessage_实例)` —— anchor 用实例
3. prepend + 保持滚动位置
4. 返 0 条 → `isEndReached = true`，UI 显示 "没有更多消息"，停止上拉

### 4.7 已读回读（**red team #9 修正**）
1. NIMChatAdapter `didFetchMessageReceipts` fire（receipt 带 timestamp）
2. store 遍历 state 中 `outgoing == true && status == .sent && timestamp <= receipt.timestamp` 的消息 → 迁移 `.sent → .read`（幂等）

### 4.8 view 生命周期与订阅（**red team #8 修正**）
- ChatDetailView `.onAppear` → subscribe NIMChatAdapter
- ChatDetailView `.onDisappear`：**加守卫** `guard scenePhase != .background else { return }`（对齐 swiftui-fullscreencover-hoist.md §2），只在真消失时 unsubscribe
- keep-alive tab 切走时：view 不 dismantle（NavigationStack 在 keep-alive 容器内），订阅保持；MainTabView tab 切走时靠 environment `isMessagesTabActive` 由 store 判断是否要静默订阅（对齐 swiftui-keepalive-publisher-isolation.md 方案 B）
