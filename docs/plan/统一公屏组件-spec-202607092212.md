# 统一公屏组件 · spec

> **里程碑**：跨 Live/Call/Party 三场景公屏消息整合 · 复杂度 A 档
> **产出**：`Sources/PublicChat/` 新模块 + 三场景 adapter + 全 16 变体 Row，替换 3 处旧实现
> **不做**：输入区统一 / 送礼动效浮层 / 翻译按钮实装 / @ 跳转 / 长按菜单

## §2 统一数据模型

### §2.1 主 model

```swift
@MainActor
final class UnifiedPublicChatFeed: ObservableObject {
    @Published private(set) var messages: [UnifiedPublicChatMessage] = []
    private let limit: Int
    init(limit: Int = 200) { self.limit = limit }
    func append(_ msg: UnifiedPublicChatMessage) { ... trim ... }
}

struct UnifiedPublicChatMessage: Identifiable, Equatable {
    let id: UUID
    let timestamp: Date
    let sender: SenderProfile?    // nil = 系统消息 / 非用户源
    let variant: PublicChatVariant
}

/// 各场景填充策略：
/// - Live：`userId` = nil（当前 `PublicChatMessage` 未持 userId，adapter 直提 senderNickname；未来 @ mention 落地时再补）
/// - Call：`userId` = nil（1v1，对端唯一，无需按 ID 消歧）
/// - Party：`userId` = 从 NIM `remoteExt["userId"]` 兼容 String/Int（见 [ios-decode-userid-compat.md](../../.claude/rules/ios-decode-userid-compat.md)）
struct SenderProfile: Equatable {
    var userId: String?
    var nickname: String
    var avatarURL: String?
    var userLevel: Int?           // H5 setLevelStyle 分档（tier = level/10 floor to 10）
    var isVip: Bool = false
    var isHost: Bool = false      // Live: 主播 · Party: 房主
    var role: PartyRole? = nil    // Party 独有：owner(1) / manager(2)
    var medals: [String] = []     // 勋章 URL 列表
    var chatBubble: String?       // VIP 花式气泡 borderImage URL
    var isPlatformAdmin: Bool = false  // Party 独有
    var isSelf: Bool = false
    var isNewUser: Bool = false   // Live H5 isNewUser 分支
    var nicknameColor: NicknameColor = .default
}

enum NicknameColor: Equatable {
    case `default`   // Live #1AFFCD 青绿 / Party #fff 白
    case anchor      // #FE00DE 粉
    case her         // #EE7A50 橙（Call 对方主播视角）
    case special     // 亮粉（SS 特殊）
    case host        // 房主橙
}

enum PartyRole: Int, Equatable { case owner = 1, manager = 2 }
```

```swift
enum PublicChatVariant: Equatable {
    case text(content: String, mentions: [Mention] = [], translation: String? = nil, replyToNick: String? = nil)
```

### §4.2 Adapter 契约

每个 adapter 是 pure function（`InputMessage → UnifiedPublicChatMessage?`），零副作用，全程 `@MainActor`。

**旧 model 处置**（配合 §7 Phase 1 P1.4 删除动作）：
- Live 侧 `PublicChatMessage`（[NIMChatroomManager.swift:9](Sources/Live/NIMChatroomManager.swift#L9)）在 Phase 1 内**保留**结构化字段（senderNickname/userLevel/isVip/isHost/senderAvatar/text），但 `messageType: PublicChatMessageType` 字段**改造为**承载**原始 payload**（如 `enum LiveRawPayload { case text(String); case gift(...); case pkNotify(...); ... }` —— 与 UI 分派枚举解耦）。Adapter `LivePublicChatAdapter.adapt(_:)` 读 `rawPayload + sender fields` 直接产出 `UnifiedPublicChatMessage`，**不再依赖旧 `PublicChatMessageType`（UI 分派枚举）**
- 旧文件 `Sources/Live/PublicScreen/PublicChatMessageType.swift`（77 行）Phase 1 内**删除**（枚举功能已迁到 `PublicChatVariant`）
- 旧文件 `Sources/Live/PublicScreen/UI/ChatRowSubviews.swift`（635 行）Phase 1 内**删除**
- Call `CallChatMessage`（结构已 Sender + Payload 分层）可**直接适配**，Phase 2 仅补 adapter，不改 model
- Party `PartyChatMessage`（当前仅 userId/nickname/role/text/msgType/isLocal/timestamp）**需补** `giftPayload / announcementText / modeSwitchKind / gameWinPayload / luckyGiftPayload` 5 类可选字段（Phase 3 时 `PartyMessageRouter` 层同步追加派发路径），adapter 读扩展字段派 variant

```swift
enum LivePublicChatAdapter {
    static func adapt(_ m: PublicChatMessage) -> UnifiedPublicChatMessage {
        let sender = SenderProfile(
            userId: nil,   // Live model 未持 userId（senderNickname 直提；@ mention 落地时再补）
            nickname: m.senderNickname ?? "",
            avatarURL: m.senderAvatar,
            userLevel: m.userLevel,
            isVip: m.isVip,
            isHost: m.isHost,
            role: nil,
            medals: [],
            chatBubble: nil,
            isSelf: false,
            nicknameColor: m.isHost ? .anchor : .default
        )
        let variant = mapVariant(m.rawPayload)   // 读原始 payload，不读旧 PublicChatMessageType
        return UnifiedPublicChatMessage(id: m.id, timestamp: Date(), sender: sender, variant: variant)
    }
    private static func mapVariant(_ t: PublicChatMessageType) -> PublicChatVariant { ... }
}
```

### §5.2 状态与副作用

- `PublicChatListView` 内 `@ObservedObject feed` → 只本 view 重算，不波及父树（继承 review P1-3 隔离）
- `autoScrollThreshold`：新消息 append 时，若滚动位置距底部 <threshold 自动滚到底；否则显示"新消息 ↓"跳转按钮（沿用 Live H5 L693 `showNewScreenMsg` 逻辑）
- Row 都是 struct View，避免 SwiftUI type-check timeout（[swiftui-body-type-check-timeout.md](.claude/rules/swiftui-body-type-check-timeout.md)）
- Variant switch 用独立 struct 承载子分支（不用 `Group { if...else }`）

### §5.3 国际化

- 所有新增文案走 `L10n.PublicChat.*` namespace（新建 3 语言 keys）
- RTL 用 `.leading/.trailing`
- 数字用 `Text(N, format: .number)` 按 Locale 渲染

### §5.4 性能

- `LazyVStack` + `ForEach(feed.messages.suffix(80))` 只渲染近 80 条
- `Equatable` conformance 严格，避免 diff 波及静态 Row
- Row 内图片走 `ImageCache` 复用现有基础设施
