## §1 范围与约束

### 1.1 in 范围

1. **被动接收直播私 call** —— 直播态下收到 RTM VideoCall 自动接听
2. **LiveStore.pauseForCall()** —— 直播暂停操作集（不销毁相机/美颜/IM 聊天室）
3. **LiveStore.resumeCall()** —— 通话挂断后 15s 倒计时回直播（对齐 H5 liveRoom.vue:220）
4. **RTC 频道 leave+rejoin** —— Agora B 方案（声网官方推荐路径）
5. **心跳互斥** —— HeartbeatController pause/resume，由 callState 驱动
6. **WSHeartbeat onlineStatus 联动** —— 通话/waitingReturnLive 期间发 CALLING(10000)
7. **CurrentCallInfo.frontGameType = .live** —— 标记本通通话来源
8. **callRate 上报开启**（callRateEnabled = true）

### 1.2 out 范围（已显式排除）

- 主播主动拨打 LIVE 通话（业务无入口）
- 派对房私 call（callerType=5，F 里程碑）
- 直播内 PK 状态切换（G 里程碑）
- 端侧通话计费心跳（后端契约：等心跳加入后再说）

### 1.3 强约束（不可改）

- **直播态下所有 RTM VideoCall 自动接听**：不区分 callType（RTM 协议无类型字段，业务保证用户端只在私 call 入口触发）
- **主播端不调任何起止接口**：起算由用户端 createCall、结束由用户端 apiCallOver（后端契约 A/B）
- **RTC 频道切换走 leave+rejoin**：用户决策；不做 setClientRole 切换（codec 互通未确认）
- **直播信息全程保留**：暂停时不清 `roomId/agoraChannelId/rtcToken/yxRoomId`，rejoin 时直接复用
- **相机/美颜/IM 聊天室全程保留**：避免重新申请权限 + 美颜首帧延迟 + 公屏中断

## §3 关键触发链路

### 3.1 自动接听（直播态收到 RTM VideoCall）

**入口**：`CallSignaling.didReceiveMessageEvent` → `CallStore.signaling(_:didReceive:from:)`

**改造点**：CallStore.handleIncomingVideoCall 中增加 LiveStore 状态判定：

```swift
private func handleIncomingVideoCall(_ msg: CallMessage) async {
    guard msg.remoteUserId == myUserId else { return }
    
    // D 新增：直播态优先走"私 call 自动接听"分支
    if LiveStore.shared.state == .living {
        // 不弹浮层；调 LiveStore.pauseForCall 内部驱动 CallStore.acceptIncomingFromLive
        await LiveStore.shared.pauseForCall(msg: msg)
        return
    }
    
    // C 已有逻辑：非直播态走 .idle 校验 + 弹浮层路径
    guard state == .idle else { ... 忙线拒接 ... }
    // ... 原 calling 状态机入口
}
```

**关键决策**：`LiveStore.pauseForCall(msg:)` 是协调者，**不让 CallStore 直接知道 LiveStore**——CallStore 只暴露 `acceptIncomingFromLive` 接口被 LiveStore 调用，保持模块单向依赖。

### 3.2 LiveStore.pauseForCall

```swift
@MainActor
extension LiveStore {
    /// 直播态下收到私 call 来电的暂停-接听编排。
    /// 严格对齐 H5 useCallApi.callInEnter 中"if (isLiving) await livingEnd(false)"路径。
    func pauseForCall(msg: CallMessage) async {
        guard state == .living, callState == 0 else { return }
        
        // 1) 停心跳（B 里程碑 HeartbeatController 内 stop() 会自动重置 failureCount=0，
        //    符合"通话期间不计直播心跳失败"的语义，无需新增 pause/resume 接口）
        heartbeatController.stop()
        
        // 2) 停网络监控（B 里程碑 NetworkQualityMonitor 同理）
        networkMonitor.stop()
        
        // 3) RTC leave 直播频道（保留 roomId/agoraChannelId/rtcToken 字段）
        liveAgora.leave()  // AgoraManager.leave 内 destroy 单例引擎
        
        // 4) 心跳/在线态切换
        callState = 1
        WSHeartbeat.shared.notifyCallStateChanged(callState: 1)
        
        // 5) 委托 CallStore 接听
        await CallStore.shared.acceptIncomingFromLive(msg: msg)
    }
}
```

### 3.3 LiveStore.resumeCall

**触发**：CallStore 通话挂断 → 通过 `CallStoreObserver` 协议回调 LiveStore

```swift
extension LiveStore {
    /// CallStore 通话结束回调，启动 15s 倒计时回直播（对齐 H5 liveRoom.vue:220）
    func resumeCall() async {
        guard callState == 1 else { return }
        
        isWaitingReturnLive = true
        returnLiveCountdown = 15
        
        // 15s 倒计时（每秒 -1，UI 显示用）
        for _ in 0..<15 {
            try? await Task.sleep(nanoseconds: 1_000_000_000)
            if returnLiveCountdown > 0 { returnLiveCountdown -= 1 }
        }
        
        // 倒计时归 0，重新 rejoin RTC 直播频道
        await rejoinLiveChannel()
        heartbeatController.start()    // B 里程碑 start 内会先 stop 再启动，安全
        networkMonitor.start()
        callState = 0
        isWaitingReturnLive = false
        WSHeartbeat.shared.notifyCallStateChanged(callState: 0)
    }
    
    private func rejoinLiveChannel() async {
        guard let channelId = agoraChannelId, 
              let token = rtcToken,
              let uid = SessionStore.shared.user?.userId else { return }
        liveAgora.join(channelId: channelId, 
                       token: token, 
                       uid: UInt(uid),
                       profile: .liveBroadcasting)
    }
}
```

**幽灵任务防御**：参考 CallStore 的修复经验，`returnLiveCountdown` 倒计时 Task 改为 `private var returnLiveTask: Task<Void, Never>?`，B 里程碑 `LiveStore.endLive()` 时显式 cancel，避免下播后倒计时仍触发 rejoin。

**与 H5 returnLive() 的差异说明**：H5 [liveRoom.vue:241](anchor-livechat-h5/src/views/liveSetting/components/liveRoom.vue#L241) 是调 `beginLiveOpen(currentLiveInfo)` 重新执行 RTC join + joinChatRoom + 启动 NetworkQualityMonitor 全套；iOS 这里拆成 `rejoinLiveChannel()` + 单独 start `heartbeat` / `networkMonitor`，行为等价。**两端都不需要调后端 beginLiveRoom 接口**（房间信息全程保留）。

### 3.4 CallStore → LiveStore 解耦回调

新增协议（只单向：CallStore 不引用 LiveStore，LiveStore 实现协议监听 CallStore）：

```swift
@MainActor
protocol CallStoreObserver: AnyObject {
    /// CallStore 状态变化（C 已有 @Published state，D 新增协议明确订阅点）
    func callStore(_ store: CallStore, stateDidChange newState: CallState)
}

// LiveStore conform CallStoreObserver
extension LiveStore: CallStoreObserver {
    func callStore(_ store: CallStore, stateDidChange newState: CallState) {
        // 只关心从 connected/connecting → ended → idle 的转换
        if (newState == .ended || newState == .idle) && callState == 1 {
            Task { await resumeCall() }
        }
    }
}
```

CallStore 内部维护 `weak var observer: CallStoreObserver?`，在 state Combine sink 或 state 切换处发送通知。**避免使用全局 NotificationCenter**（耦合度更低但难追踪）。

### 3.5 WSHeartbeat 联动

```swift
extension WSHeartbeat {
    /// 由 LiveStore 调用，根据 callState 切换在线态
    func notifyCallStateChanged(callState: Int) {
        if callState == 1 {
            sendStatus(.calling)  // 10000
        } else {
            sendStatus(.callEnd)  // 10001
        }
    }
}

// OnlineStatus 已有 .callEnd/.foreground/.background/.offline，新增 .calling
enum OnlineStatus: Int {
    case offline    = 2
    case calling    = 10000   // D 新增
    case callEnd    = 10001
    case foreground = 10002
    case background = 10003
}
```

WSHeartbeat.startPing 内的周期心跳仍发 `.callEnd`，但 `notifyCallStateChanged(1)` 时切到 `.calling`，下一周期心跳由 LiveStore 维持 `.calling`（通过状态变量）。

## §4 共享基建：是否抽 AgoraEngineFacade

### 4.1 现状

- C 里程碑：CallStore.agora 是独立 AgoraManager 实例（通信模式）
- B 里程碑：LiveStore.liveAgora 是另一独立 AgoraManager 实例（直播广播模式）
- **底层 AgoraRtcEngineKit.sharedEngine 是全进程单例**——两个实例 leave 时都调 `destroy()` 会**互相砍**

### 4.2 D 范围内的简单解决方案（不抽 Facade）

D 范围内**通话与直播严格互斥**（通话期间直播必然已 leave），所以**leave→destroy→sharedEngine 重创建**链路天然没冲突：

```
直播 join → 直播 leave + destroy → （通话期间）通话 join → 通话 leave + destroy → 直播 rejoin
```

**不抽 Facade**。把工作量留到 F 里程碑（PartyCall 抢占同样涉及多频道切换）一并做。

### 4.3 但要修一个细节

AgoraManager.leave 当前代码：

```swift
func leave() {
    guard let engine = engine else { return }
    // ...
    engine.leaveChannel(nil)
    AgoraRtcEngineKit.destroy()  // ⚠️ 全局 destroy
    self.engine = nil
}
```

`AgoraRtcEngineKit.destroy()` 是**类方法**，会销毁全进程单例。在 D 流程中：
- 通话 leave → destroy → 接下来 LiveStore.rejoinLiveChannel 调 `AgoraRtcEngineKit.sharedEngine(...)` 重新创建，但 LiveStore 持有的旧 engine 引用已野
- 同理 LiveStore.pauseForCall 时直播 leave + destroy → CallStore 通话 join 时新 engine

只要保证 leave 和 join 顺序串行就 OK。**D spec 明确：每次切换走 leave→等待 leaveChannel 回调→destroy→重新 sharedEngine→join 的完整链路**。
