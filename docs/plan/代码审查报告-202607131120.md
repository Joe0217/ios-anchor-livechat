## 二、必修（8 项）

### M-1 · ChatAudioPlayer 无 stale check，快速切换语音会 race

- **文件**：[Sources/Message/Chat/Services/AudioPlayer.swift:79-100](../../Sources/Message/Chat/Services/AudioPlayer.swift#L79-L100)
- **维度**：内存与资源
- **原始 severity**：P1
- **产品调用链**：ChatDetailView 长音频列表 → tap 音频 A → download A 完成后 URLSessionDataTask 已 completed，此时用户 tap 音频 B 或 stop —— `downloadTask?.cancel()` 对已完成 task 无效，A 的 completion 已 dispatch 到 main queue，guard 通过继续 `player.play()`，覆盖 self.player = A。
- **风险**：用户已 stop 或切 B，A 却响起；singleton 被 A 抢占后 stop 也失效。
- **修复**：加 `pendingKey: String?` state；closure guard `self.pendingKey == key`；或改 async/await Task + `stop()` 里 `.cancel()`。

### M-2 · NIMChatAdapter.downloadToTmp 在 MainActor 写盘阻塞主线程

- **文件**：[Sources/Message/Chat/Services/NIMChatAdapter.swift:157-166](../../Sources/Message/Chat/Services/NIMChatAdapter.swift#L157-L166)
- **维度**：Swift 并发
- **原始 severity**：P1
- **产品调用链**：`sendImage/sendVideo/sendPrivateImage/sendPrivateVideo` 均走此路径（line 135/144/178/199）。`NIMChatAdapter` 声明 @MainActor（line 15），static func 继承隔离，async 恢复后回 MainActor，`try data.write(to:)` 主线程同步落盘。视频转发几十 MB 时明显。
- **风险**：视频转发用户 tap 后 UI 卡顿 50-200ms，低端设备可能触发 watchdog。
- **修复**：`private nonisolated static func downloadToTmp(...)` — Data/String 都是 Sendable 签名兼容。或 `try await Task.detached(priority: .userInitiated) { try data.write(to: tmpUrl) }.value`。

### M-3 · VoiceRecorder 无 deinit + view onDisappear 未 cancel（麦克风隐私事故）

- **文件**：[Sources/Message/Chat/Services/VoiceRecorder.swift](../../Sources/Message/Chat/Services/VoiceRecorder.swift)（无 deinit）+ [Sources/Message/Chat/UI/ChatDetailView.swift:214-219](../../Sources/Message/Chat/UI/ChatDetailView.swift#L214-L219)（onDisappear 只调 store.teardown）
- **维度**：内存与资源
- **原始 severity**：P1
- **产品调用链**：用户按住录音期间左滑返回 / pop / 系统级切走 → view dismount。onDisappear 只调 `store.teardown()`，未调 `voiceRecorder.cancel()`。VoiceRecorder 亦无 deinit，AVAudioRecorder 未 stop，麦克风继续采集直到 60s auto-stop（VoiceRecorder.swift:142）。@StateObject 延迟 deinit 放大窗口（对齐 CLAUDE.md v5.3.1 已知坑）。
- **风险**：iOS 14+ 麦克风橙点持续 60s = 隐私事故 + m4a 残留 caches。
- **修复**：(1) VoiceRecorder 加 deinit（nonisolated stop + setActive(false) + 删残留文件）；(2) ChatDetailView.onDisappear 在 scenePhase 守卫下加 `if voiceRecorder.isRecording { voiceRecorder.cancel() }`。

### M-4 · ChatDetailView.handleVoiceStart 的 Task 未存 handle 也未 cancel

- **文件**：[Sources/Message/Chat/UI/ChatDetailView.swift:799-811](../../Sources/Message/Chat/UI/ChatDetailView.swift#L799-L811)
- **维度**：Swift 并发
- **原始 severity**：P1
- **产品调用链**：`handleVoiceStart` 内 `Task { @MainActor in for await sec in voiceRecorder.$currentSeconds.values { ... } }` 未存 handle。for-await 通过 AsyncPublisher 内部订阅强引用 voiceRecorder；onDisappear 也无 cancel。用户按住录音时左滑返回 → SwiftUI 释放 @StateObject 引用但 Task 持有 → VoiceRecorder 不释放。与 M-3 同源麦克风泄漏路径。
- **风险**：同 M-3；且高频按停会启动多个观察 Task 并行（各持 voiceRecorder 强引用）。
- **修复**：`@State private var voiceObserveTask: Task<Void, Never>?`，`handleVoiceStart` 首 cancel 再赋值；`handleVoiceEnd` / `onDisappear` 里 `voiceObserveTask?.cancel(); voiceObserveTask = nil`。或改 `.onReceive(voiceRecorder.$currentSeconds)`。

### M-5 · UI 文案硬编码英文未走 L10n（违反 i18n 铁律）

### M-6 · DiaReceivePopup 拆句 3 段 Text 破坏 RTL 顺序

- **文件**：[Sources/Message/Chat/UI/DiaReceivePopup.swift:43-48](../../Sources/Message/Chat/UI/DiaReceivePopup.swift#L43-L48)

### M-7 · ReplyPointsStore.onSendAnchorMsg 整块回写 stale state 覆盖并发更新

- **文件**：[Sources/Message/Chat/ReplyPointsStore.swift:191-220](../../Sources/Message/Chat/ReplyPointsStore.swift#L191-L220)
- **维度**：Swift 并发
- **原始 severity**：P2
- **产品调用链**：`guard var state = sessions[peer]` 快照 → await service.settleReplyPoints 挂起（网络往返）→ 同为 @MainActor 的 `autoClaimIfNeeded` 在挂起窗口内继续把 sessions[peer]?.messageBoxList[idx] 改成 .claimed → await 恢复后 line 219 `sessions[peer] = state` 用旧快照整块回写 → 覆盖 .claimed 让 auto-claim 可能再触发**重复领奖**调用。defer（203-207）用 `sessions[peer] ?? state` 读最新是对的，但 if res.settled 分支的整块回写没这么做。
- **风险**：settle vs autoClaim race → 重复领奖 API 调用（后端会拒但 UI 可能闪回）+ tips 里的 replyRemind 消失或反悔。
- **修复**：
  ```swift
  if res.settled {
      var s = sessions[peer] ?? state    // 读最新
      s.currentProgress = res.currentTotalPoints
      s.hasHistoryReply = true
      s.replyRemindBaseTs = nil
      sessions[peer] = s                  // 只覆盖本次相关 3 字段
      pendingSettleResult = res
  }
  ```

### M-8 · MessageSessionStore.load() state 以 .public 落 unified log（PII 泄漏）

- **文件**：[Sources/Message/MessageSessionStore.swift:195](../../Sources/Message/MessageSessionStore.swift#L195)
- **维度**：安全与隐私
- **原始 severity**：P1（Workflow 3 vote 降 P2；本次复查上溯回必修）
- **产品调用链**：`String(describing: self.state), privacy: .public`。state=.loaded([MessageSession]) 时通过默认 reflection dump 每个 session 全字段（peerNickname / lastMessage / peerAvatarURL / yxAccid / unreadCount）。load() 由 IM 重连 sink + 下拉刷新 + syncOK 频繁触发，1 小时可积上百条含对端昵称+聊天摘要的 unified log。sysdiagnose / Console.app / Apple 崩溃提交都会带上。
- **风险**：明确 PII 泄漏 + App Store 5.1.1 privacy manifest 未声明日志收集聊天内容。
- **修复**：改 `privacy: .private`，或派生 loaded(count) 短摘要再 log；grep `String(describing: self.state)` 类模式排除其他 store 复刻同款错误。

### M-9 · RewardRecordsPopup / ChatTimeSeparator DateFormatter 未设 timeZone

- **文件**：[Sources/Message/Chat/UI/RewardRecordsPopup.swift:152-158](../../Sources/Message/Chat/UI/RewardRecordsPopup.swift#L152-L158) + [Sources/Message/Chat/UI/ChatMessageRow.swift](../../Sources/Message/Chat/UI/ChatMessageRow.swift)（ChatTimeSeparator.formatted）
- **维度**：iOS 平台规范
- **原始 severity**：P2
- **产品调用链**：formatDate 用 DateFormatter().dateFormat = "yyyy-MM-dd" 无 timeZone，跟随设备本地时区。CLAUDE.md 「时区」明规：「业务时间点用 `Asia/Shanghai` 固定时区，**不用设备本地**」。奖励记录 23:00 CST 在美西显示前一天，与 H5 / 安卓端不一致，运营对账被误判漏发。ChatTimeSeparator 同款问题（未设 locale + timeZone）。
- **风险**：跨零点日期漂移 + 与 H5/安卓 UI 不一致 + 客户投诉/运营核错。
- **修复**：
  ```swift
  df.timeZone = TimeZone(identifier: "Asia/Shanghai")
  df.locale = Locale(identifier: "en_US_POSIX")
  ```
