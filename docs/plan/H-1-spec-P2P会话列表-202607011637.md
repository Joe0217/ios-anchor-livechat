## §1 业务契约 + H5 / 安卓二次校验

### 1.1 用户可见行为

用户点 MainTabView Messages tab → 看到 P2P 会话列表：
- 顶部 3 分类 tab：**Flame（火热）** / **Stranger（陌生）** / **Prime（优质）**
- 每 tab 内会话按最后消息时间倒序，未读数 badge
- 长按会话弹菜单：**置顶** / **删除**
- 首次拉取 loading skeleton；空列表显示对应文案；错误显示 retry 按钮
- 新消息到达时（NIM 长连接 push）实时插入/上移

### 1.2 三分类规则（H5 源码 session.js 实证，v2 修订）

**H5 双通道并集**（`anchor-livechat-h5/src/stores/modules/session.js:34-48, 141-154, 383-384`）：

- **通道 A：ext 标记**（本 MVP 实现）
  `checkSessionExtraIsFlame(ext)` = `ext.receivedGift === true || ext.called === true || (ext.received === true && ext.sended === true)`
  ⚠️ **boolean AND 不是数值 OR**（received & sended 是 Bool 不是 Int；v1 spec 错）
- **通道 B：flameUserIdList**（**MVP 排除，留 H-2**）
  `sessionFlameUserIdList = 关注列表 ∪ apiBatchQueryYxStat(idList) 返回的 flameUserId 集合`
  最终 Flame = 通道 A ∪ 通道 B

**MVP 已知产品缺口**（明示 scope 排除，v2）：仅通道 A 时，未收礼 + 未通话 + 未双向消息互动的**关注 / 好友**会被误归 Stranger。H-2 补 apiBatchQueryYxStat + FollowListService 复用。

**Prime**（H5 源码 `session.js:5, 583-625`）：
- API：`apiBatchQueryYxPrimeFilter` body `{yxAccId: [String]}` resp: `{result: [String]}` **已过滤后的 Prime yxAccId 数组**（不是字典）
- 拉取时机：拉取会话列表后按 sessionId 批量查；MVP 支持分批（每批 ≤50 uid）；H5 有 500ms debounce 合并策略
- 缓存：H5 无本地缓存每次重算，iOS MVP 对齐（缓存留 J 期性能批）

**Stranger**：其余（Flame 通道 A 不命中 && 非 Prime）

**互斥优先级**：Flame > Prime > Stranger（同 session 同时命中 → 归 Flame）

**安卓对齐**（`docs/plan/安卓主播端梳理/02-05-IM聊天消息.md`）：Flame 阈值一致；Prime 同 `apiBatchQueryYxPrimeFilter`；未见与 H5 冲突项

### 1.3 数据来源合约（v2 修订 NIM SDK 4.5.x 真实 API）

- **会话列表拉取**（`NIMConversationManagerProtocol.h:281-284, 798-807`）：
  - SDK 头文件明确警告 `allRecentSessions()` 数据量大时会**卡主线程**（老用户上万会话可能命中）
  - **MVP 决策**：evaluate `asyncLoadRecentSessionEnabled` 异步模式；若开启则等 `didLoadAllRecentSessionCompletion` delegate；否则 fallback `allRecentSessions()` **hop background queue** 调用避免卡主线程
- **增量更新**：`NIMConversationManagerDelegate`（`didAddRecentSession` / `didUpdateRecentSession` / `didRemoveRecentSession`）—— 回调**无线程保证**，Store 内统一 hop `@MainActor` 单串行队列（不用多队列避免顺序错乱）
- **未读**：`NIMSession.unreadCount`（SDK 单会话字段）；MVP **不做** MainTabView tabBar 全局 badge（scope 排除，留 H-2）
- **置顶**（v2 修订）：改用 SDK 官方跨端漫游 API `NIMChatExtendManagerProtocol.addStickTopSession(_:info:)` / `removeStickTopSession(_:completion:)` / `stickTopInfoForSession:`（`NIMConversationManagerProtocol.h:406-447`）；**不用** `NIMRecentSession.customExt`（SDK 4.5.x 无此字段，真实是 readonly `localExt` 或 `serverExt`）
- **删除**：`NIMSDK.shared().conversationManager.deleteRecentSession(_:)` + 本地列表移除
- **Prime 拉取**：调 `apiBatchQueryYxPrimeFilter`（Networking 层新建 `PrimeLevelService`）body `{yxAccId: [String]}` resp **APIClient 剥完 envelope + 解密后是 top-level `[String]` 数组**（**不是** `{result: [...]}` 包装，v3 spec v1 写错，v4 Step 3 真机反悔 #3 校正）；分批 ≤50 uid；失败降级见 R-1

## §2 数据 model + 状态机

### 2.1 Model

```swift
enum MessageSessionCategory: Equatable {
    case flame        // 火热
    case stranger     // 陌生
    case prime        // 优质
}

struct MessageSession: Identifiable, Equatable {
    let id: String                    // NIMSession.sessionId (yxAccid)
    let peerNickname: String          // 从 SessionStore 缓存 or SDK 拉
    let peerAvatarURL: String?
    let lastMessage: String           // 文本摘要（image → [图片] / audio → [语音] 等占位）
    let lastMessageTimestamp: Int64   // 毫秒时间戳
    let unreadCount: Int
    let isTop: Bool
    let category: MessageSessionCategory
    // ext 字段（H5 `session.ext`）
    let receivedGift: Bool
    let called: Bool
    let receivedCount: Int
    let sendedCount: Int
    let isPrime: Bool                 // 依赖 /api/user/primeLevel HTTP 补
}
```

### 2.2 状态机（3 态）

```
.idle → [onAppear/pull-to-refresh] → .loading
.loading → [success + 非空] → .loaded(sessions)
.loading → [success + 空] → .empty
.loading → [error] → .error(underlying)
.error → [retry] → .loading
.loaded → [NIM delegate 增量更新] → .loaded(newSessions)
.loaded → [category change (tab 切)] → .loaded(same 数据，view 层过滤)
```

**不变量**：
- 3 分类共享同一份 sessions 数据（内存中一份），tab 切换仅过滤显示，不重复拉
- `.loading` 期间 NIM delegate 增量更新入队 `pendingUpdates: [SessionEvent]`（**@MainActor 单串行队列**，非跨 actor 拷贝）；loaded 后按到达顺序合并
- **合并语义**（v2 明示）：同 sessionId 出现多条 `pendingUpdates`，按 add < update < remove 的终态优先级取最新一条（remove 吃掉先前 add/update；后到的 update 覆盖先到的 add）
- 置顶/删除操作乐观更新（本地立即改，异步同步 SDK 失败回滚）

## §3 验收清单

### 3.1 正向（F）— 全列

| # | 场景 | 验收 |
|---|---|---|
| F-1 | 冷启动首次进 tab | loading skeleton → 3s 内出列表 |
| F-2 | 三 tab 切换 | 数据不重拉，view 层瞬时过滤 |
| F-3 | Flame 分类命中 | 满足任一 receivedGift/called/(received+sended>0) 会话进 Flame |
| F-4 | Prime 分类命中 | `/api/user/primeLevel` 返 true 的 session 进 Prime |
| F-5 | 未读 badge | 与 NIM SDK `unreadCount` 一致，实时更新 |
| F-6 | 置顶操作 | 长按菜单 → 置顶 → session 移到列表顶 |
| F-7 | 删除操作 | 长按菜单 → 删除 → session 移出列表 + SDK deleteRecentSession |
| F-8 | 新消息到达 | NIM push → 列表实时上移对应 session + unreadCount +1 |
| F-9 | 空列表 | 对应分类无 session 时显示 empty 状态 + 提示文案 |
| F-10 | 错误 retry | 网络失败 → error state + retry 按钮 → 重拉成功 |
| F-11 | MainTabView keep-alive | 切走再回来滚动位置保留 |

### 3.2 反向 / 边界（R）— critical 3-5 条

| # | 场景 | 验收 |
|---|---|---|
| R-1 | Prime 接口失败 | **Prime tab 显示 empty**（无 Prime uid），Flame/Stranger 分类**不受影响**（对齐 H5 `session.js:611-626` 增量拉取保留旧值） |
| R-2 | Prime 分批 | userIds > 50 时分批调用 `apiBatchQueryYxPrimeFilter`，**任一批失败仅该批不进 Prime 集合，其他批照常**（不整批降级；对齐 H5） |
| R-3 | NIM delegate 与 loading 并发 | loading 中收到 delegate 事件按到达顺序入队 pendingUpdates；loaded 后按 §2.2 合并语义（add < update < remove 终态优先）合并；同 sessionId 冲突事件按到达顺序处理（remove 终态吃前值） |
| R-4 | 置顶失败回滚 | SDK `addStickTopSession` 失败 → 恢复本地 isTop 原值 + toast 提示 |
| R-5 | 会话峰值 300+ | 列表滚动 60fps 不卡顿；LazyVStack + Identifiable 保证 diff cost O(变化条数) |
| R-6 | flameUserIdList 通道缺失（scope 排除，明示） | MVP 仅 ext 通道 A 分类。**已知产品缺口**：无 ext 标记的关注/好友被误归 Stranger；用户可见"我关注的主播为什么不在 Flame"。留 H-2 补 `apiBatchQueryYxStat` + 关注列表并集 |
| R-7 | tabBar 全局未读 badge（scope 排除，明示） | MVP 不做 MainTabView Messages tab 的红点/数字 badge；进 tab 才看到各 session 未读数。留 H-2 |
| R-8 | IM 未登录时 fetch 空 → 登录后自动重试 | Store 订阅 `provider.isConnectedPublisher`；.connected 后 idle/error 态自动 load；loaded 态不重复 fetch |
