## 三、P2（信息级发现）

### P2-1 `Sharer.topRenderer` computed property 有副作用（`subscribers.removeAll`）

- **文件**：[BeautyPipelineSharer.swift:70-72](../Sources/Core/Media/BeautyPipeline/BeautyPipelineSharer.swift#L70)
- **维度**：ios-spec / correctness
- **具体现象**：
  ```swift
  private var topRenderer: (...)? {
      subscribers.removeAll { $0.renderer == nil }  // ← mutation
      return subscribers.reversed().compactMap { ... }.max { ... }?.1
  }
  ```
- **争议**：Swift 允许 class 的 computed property 内 mutation，但违反 pure computed getter 惯例
- **触发场景**：每次 `topRenderer` 被访问都触发 removeAll（`handleSettingsChanged` / `attach` / `setInterrupted` 内均调）—— 60ms throttle 下每帧一次
- **实际影响**：subscribers 数组通常 3-5 项，removeAll 是 O(N)，性能可忽略
- **复查后判定：信息**
- **可选替代**：改成 `attach` / `detach` 时统一清 nil（放 mutation 到显式变更点更符合惯例），或引入 `mutating func compactAndTop() -> ...?` 方法名明示 mutation
- **不建议改**：当前实现语义正确、无副作用外泄（subscribers 非 @Published）；替代方案增加代码面无实质收益
