### 蓝本核对结果

**安卓大厅结构**（`docs/plan/安卓主播端梳理/02-04-派对房.md` §2.1）：
- 4 个列表 Fragment：`AllPartyFragment / RecentPartyRoomListFragment / FollowedPartyRoomListFragment / PartyRoomListFragment`

- **保留**：主列表（对应 `getPartyRoomList` 或 iOS 现用 `room/list`）+ 创建入口 + 密码房锁标识

- **不做**：iOS 主播端 vs 安卓主播/用户端 —— 大厅本身语义完全同（主播浏览可入房的派对房），复用安卓字段/交互无差异

## §1 业务概念词表（不锁 protocol 名）

| 概念 | 语义 |
|---|---|
| **派对房大厅** | 主播端进入 party tab 后看到的顶级页面。展示当前平台内可入的派对房列表。用户可 tap 卡片进房、tap 右上角按钮打开创建流程。 |
| **房间列表快照** | 一次 `room/list` 拉取的完整或分页结果；后端返回 `snapshotId` 用于同一次翻页保持列表版本一致（防翻页时插入/删除数据抖动）。 |
| **分页游标** | `offset + pageSize` 语义：offset=已拉页数×pageSize，pageSize MVP 固定 20。 |
| **房间卡片** | 大厅列表中每条房间对应的视觉单元。展示：房间头像、房间名、在线人数、密码房锁标识。 |
| **密码房锁标识** | `PartyRoomInfo.lockFlag==1 \|\| needPassword==true` 时卡片右下 orange lock icon；MVP tap 后仍直接 push 进房 view，密码校验错误由 Store 层错误码兜底（**不弹前置密码框**）。 |
| **列表刷新** | 用户下拉手势触发；重置 offset=0 + 清 rooms + 重新拉首页。 |
| **列表加载更多** | 上拉滚到底部 sentinel 时触发；offset+=pageSize + 追加 rooms + 更新 hasMore。 |
| **列表空态** | `rooms.count == 0 && !isLoading && loadError == nil` 时显示"暂无派对房"引导。 |
| **列表错误态** | 首屏拉取失败时全屏错误 + retry；分页失败时底部小 banner + retry。 |
| **创建入口** | 大厅右上角 `plus.circle` 按钮，push 到 `PartyCreateRoomView`。 |
| **入房路径** | tap 卡片 push `PartyRoomView(roomId:)`；密码房也走同路径（Store 内 checkPassword）。 |
| **登出清理** | 用户主动登出/session 失效时，清 PartyListStore state + 若在房内触发 leaveRoom 兜底。 |
| **主 tab keep-alive 策略** | party tab 采 `if selection == .party` 销毁重建（vs. `home/messages` 的 ZStack opacity keep-alive）；节省内存，且大厅列表无需保留 scroll offset。 |

## §2 状态机

### PartyListStore.State

```swift
enum State: Equatable {
    case idle                                          // 未拉取
    case loading                                       // 首屏加载中（含刷新）
    case loaded(rooms: [PartyRoomInfo], hasMore: Bool) // 已加载
    case loadingMore(rooms: [PartyRoomInfo])           // 分页加载中（保留已有 rooms）
    case error(message: String, canRetry: Bool)        // 首屏错误
    case pageError(rooms: [PartyRoomInfo], message: String) // 分页错误，保留已有
}
```

### 迁移图

```
idle
  └─ startInitial() ──> loading
loading
  ├─ success(page, hasMore) ──> loaded
  ├─ success(empty) ──> loaded([], false)   [空态]
  └─ failure(err) ──> error
loaded
  ├─ refresh() ──> loading
  └─ loadMore() ──> loadingMore
loadingMore
  ├─ success(page, hasMore) ──> loaded(append)
  └─ failure(err) ──> pageError
error
  └─ retry() ──> loading
pageError
  ├─ retryPage() ──> loadingMore
  └─ refresh() ──> loading
```

### 不变量

- `loaded.rooms` 不含 nil id 项（decode 层 fallback stableListId）
- `hasMore` 由 `page.count == pageSize` 判定；后端返 < pageSize → 结束
- `snapshotId` 首次拉取时后端返值，之后分页请求携带；`refresh` 时清 nil
- 并发保护：处于 `loading/loadingMore` 时忽略新 `loadMore()` 调用
- 登出时 `reset()` 回 idle + snapshotId=nil + rooms=[]

## §3 接口契约

### `PartyAPI.roomList` 参数

| 参数 | 类型 | MVP 传值 | 备注 |
|---|---|---|---|
| `languageCode` | `String?` | nil | 后端 fallback 到用户默认 |
| `snapshotId` | `String?` | 首拉 nil / 分页传上次值 | 保证翻页数据快照一致 |
| `offset` | `Int?` | 首拉 nil / 分页 count | 分页起点 |
| `pageSize` | `Int` | 20 | 固定 |
| `queryParam` | `String?` | nil | F 期搜索使用 |
| `version` | `String` | "v2" | 现契约锁定 |

### 响应

- 成功：`[PartyRoomInfo]`（可能为空）
- 后端 envelope：`code==200` 视为成功；其他 `PartyAPIError.business(code, message)` 抛出
- decode 用 `PartyRoomInfo` v3 真值版（含 `stableListId` fallback）

### 错误映射

| 场景 | Store 结果 |
|---|---|
| 网络失败 (`.networkError`) | 首屏 → `.error("网络异常，请重试", canRetry: true)` / 分页 → `.pageError` |
| HTTP 非 200 | 同上 |
| envelope 解析失败 | 同上，message 携带 debug 描述（dev 可见） |
| 业务码非 200 | `.error(mapped_message, canRetry: true)`（业务码错误一般是 token 失效等 → APIClient 层已兜底触发登出，Store 只处理罕见情况） |
| decode 失败 | `.error("数据格式错误: \(PartyDecodeErrorDescriber.describe)", canRetry: true)`；上报 AppLogger.party 详细 codingPath |
| 空列表 | `.loaded(rooms: [], hasMore: false)` **非错误** |
