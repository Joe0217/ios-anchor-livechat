## §0.1 H5 / 安卓代码二次校验（强制前置）

### 结论
**H5 无派对房代码；安卓 `partyroom` 模块是唯一蓝本**（`docs/plan/安卓主播端梳理/04-iOS对齐安卓-派对房+机器人转盘+心跳-决策规格.md` §1.1）。iOS 决策规格文档对**大厅/列表页/主 tab 具体产品决策全空白**——**本 spec 是这些决策的首个书面来源**。

### 蓝本核对结果

**安卓大厅结构**（`docs/plan/安卓主播端梳理/02-04-派对房.md` §2.1）：
- 4 个列表 Fragment：`AllPartyFragment / RecentPartyRoomListFragment / FollowedPartyRoomListFragment / PartyRoomListFragment`
- 独立 `SearchPartyRoomActivity`
- 独立 `CreatePartyRoomActivity`

**iOS MVP 取舍**（本 spec §0.3 中圈）：
- **保留**：主列表（对应 `getPartyRoomList` 或 iOS 现用 `room/list`）+ 创建入口 + 密码房锁标识
- **推 F 期**：关注/最近/搜索 3 pill、密码房入房弹窗、创建流程完整体验
- **不做**：iOS 主播端 vs 安卓主播/用户端 —— 大厅本身语义完全同（主播浏览可入房的派对房），复用安卓字段/交互无差异

### 与安卓不明确点（记录不脑补）

| 项 | 安卓文档状态 | iOS 决策 |
|---|---|---|
| 大厅顶部 tab 数量/名字 | 未写清（4 Fragment 关系不明） | MVP 单列表页，无 pill；F 期加 3 pill |
| 房间卡片字段清单 | 未写（仅列 §2.1 Fragment 名） | **本 spec §5 定义**（延用现 MVP 字段） |
| 在线人数是否 WebSocket 推送 | 未涉及 | **MVP 拉取一次**（下拉/上拉刷新覆盖），无 WS 订阅 |
| 密码房小锁视觉 | 未写 | 复用现 MVP：`lockFlag==1 \|\| needPassword==true` → orange lock icon |
| 关注列表是否老后端 | §3.1 尾注"可能老后端" | F 期做时再对齐后端 |

## §1 业务概念词表（不锁 protocol 名）

| 概念 | 语义 |
|---|---|
| **派对房大厅** | 主播端进入 party tab 后看到的顶级页面。展示当前平台内可入的派对房列表。用户可 tap 卡片进房、tap 右上角按钮打开创建流程。 |
| **分页游标** | `offset + pageSize` 语义：offset=已拉页数×pageSize，pageSize MVP 固定 20。**snapshotId MVP 不使用**（v2: F-03，现契约无法拿到分页级 sid）。 |
| **房间卡片** | 大厅列表中每条房间对应的视觉单元。展示：房间头像、房间名、"预览用户数"（**非真实在线人数**，见下）、密码房锁标识。 |
| **预览用户数**（v2: F-15）| `PartyRoomInfo.onlineUserList?.count`。**注意**：这是后端返回的"前 N 位在线用户预览"（typically 6-12 位头像），**不是**真实在线人数。真实在线人数后端不返；`heatValue` 是热度分非人数。MVP 卡片展示此值，UX 需明示"预览"避免误导（如"6+" 或头像堆叠）。 |
| **密码房锁标识** | `PartyRoomInfo.lockFlag==1 \|\| needPassword==true` 时卡片右下 orange lock icon；MVP tap 后仍直接 push 进房 view，密码校验错误由 Store 层错误码兜底（**不弹前置密码框**，UX 有断层，见 §9 风险表） |
| **列表刷新** | 用户下拉手势触发；重置 offset=0 + 清 rooms + 重新拉首页。**refresh 覆盖 error/pageError/loaded/loadingMore 全状态**（v2: F-17）——若 loadingMore 中触发 refresh 则 cancel 旧 task 强夺（v2: F-04）。 |
| **列表加载更多** | 上拉滚到底部 sentinel 时触发；offset+=pageSize + 追加 rooms + 更新 hasMore。空态时 sentinel 不渲染（`hasMore==false`，v2: F-18）。 |
| **列表空态** | `rooms.count == 0 && !isLoading && loadError == nil` 时显示"暂无派对房"引导；空态下拉刷新触发正常 refresh 流程（v2: F-18）。 |
| **列表错误态** | 首屏拉取失败时全屏错误 + retry；分页失败时底部小 banner + retry。error 状态下拉手势也可触发 refresh（v2: F-17）。 |
| **创建入口** | 大厅右上角 `plus.circle` 按钮，push 到 `PartyCreateRoomView`。 |
| **入房路径** | tap 卡片 push `PartyRoomView(roomId:)`；密码房也走同路径（Store 内 checkPassword）。 |
| **登出清理** | 用户主动登出/session 失效时，`RootView.syncSessionDependent` else 分支：`PartyStore.forceLeaveRoom(.userRequest) + detachChatRouter()`（v2: F-05/F-06）；PartyListStore 因 MainTabView dismount 自然 deinit。 |

## §2 状态机（v2 加 cancel 边 + refresh 强夺 + error refresh）

### PartyListStore.State

```swift
enum State: Equatable {
    case idle                                          // 未拉取
    case loading                                       // 首屏加载中（含刷新）
    case loaded(rooms: [PartyRoomInfo], hasMore: Bool) // 已加载
    case loadingMore(rooms: [PartyRoomInfo])           // 分页加载中（保留已有 rooms）
    case error(message: String, canRetry: Bool)        // 首屏错误
    case pageError(rooms: [PartyRoomInfo], message: String) // 分页错误，保留已有
}
```

### 迁移图（v2 完整）

```
idle
  └─ startInitial() ──> loading

loading
  ├─ success(page, hasMore) ──> loaded
  ├─ success(empty)          ──> loaded([], false)   [空态]
  ├─ failure(err)            ──> error
  └─ cancel (deinit/user)    ──> idle                [v2: F-04]

loaded
  ├─ refresh()  ──> loading                          [取消并清 rooms]
  └─ loadMore() ──> loadingMore

loadingMore
  ├─ success(page, hasMore) ──> loaded(append)
  ├─ failure(err)            ──> pageError
  ├─ refresh() 强夺          ──> loading             [v2: F-04, cancel currentTask]
  └─ cancel                  ──> loaded              [保留已有 rooms]

error
  ├─ retry()    ──> loading                          [同 startInitial]
  ├─ refresh()  ──> loading                          [v2: F-17, 语义等价 retry]
  └─ cancel     ──> idle

pageError
  ├─ retryPage() ──> loadingMore
  ├─ refresh()   ──> loading                         [重新拉首页，弃已有]
  └─ cancel      ──> loaded                          [降回 loaded 保留 rooms]
```

### 不变量与并发保护（v2 明确）

- `loaded.rooms` 不含 nil id 项（decode 层 fallback stableListId）
- `hasMore` 由 `page.count == pageSize` 判定；后端返 < pageSize → 结束
- **snapshotId MVP 不启用**（v2: F-03，现契约无法拿到；`PartyRoomInfo.snapshotId` 是房间级，不是分页快照）
- **并发保护**：
  - `loading / loadingMore` 时忽略 `loadMore()` 调用（无 op）
  - `loading / loadingMore` 时收到 `refresh()` **强夺**：`currentTask?.cancel()` + reset state + 新任务
  - `error` 时 double-tap `retry()` 忽略（已有任务在飞时 no-op）
  - **每次入口**（`startInitial / refresh / loadMore / retry / retryPage`）**先** `currentTask?.cancel()` 再启新任务
  - **deinit 时** `currentTask?.cancel()`（v2: F-23）
- 登出时无需 `reset()` 显式调用（v2: F-02，view-owned @StateObject 随 MainTabView dismount 自然 deinit）

## §7 架构升级（v2 修订：view-owned + protocol 完整 + deinit + Fake）

### PartyListStore 骨架（v2）

```swift
@MainActor
final class PartyListStore: ObservableObject {
    @Published private(set) var state: State = .idle
    private let service: PartyListService
    private var currentTask: Task<Void, Never>?

    init(service: PartyListService) { self.service = service }

    deinit {
        currentTask?.cancel()          // v2: F-23
    }

    func startInitial() { /* idle → loading + 拉页 */ }
    func refresh()      { /* 任意态 → cancel + loading，重置 offset/rooms（v2: F-04, F-17）*/ }
    func loadMore()     { /* .loaded → loadingMore（loading/loadingMore 时 no-op）*/ }
    func retry()        { /* .error → loading（等价 startInitial, double-tap 忽略, v2: F-04）*/ }
    func retryPage()    { /* .pageError → loadingMore */ }
    // 无 reset()——view-owned @StateObject 生命周期自然 deinit
}

// 内部所有 async 操作模板：
private func performTask(_ closure: @escaping () async throws -> Void) {
    currentTask?.cancel()               // v2: F-04
    currentTask = Task { @MainActor in
        do {
            try Task.checkCancellation()// v2: F-20
            try await closure()
        } catch is CancellationError {
            // 静默；不改 state（避免撞死 view 刚 dismount）
        } catch { /* map to error state */ }
    }
}
```

protocol PartyListService: Sendable {

        offset: Int?,
        pageSize: Int,

struct PartyListServiceLive: PartyListService {
    func fetchList(languageCode: String?, offset: Int?, pageSize: Int, queryParam: String?, version: String) async throws -> [PartyRoomInfo] {
        try await PartyAPI.roomList(
            languageCode: languageCode,
            snapshotId: nil,                // v2: F-03
            offset: offset,
            pageSize: pageSize,
            queryParam: queryParam,
            version: version
        )
    }
}

// v2 新增：PreviewFake enum-driven（F-24）
struct PartyListServicePreviewFake: PartyListService {
    enum Kind { case success([PartyRoomInfo]), empty, delayThenSuccess([PartyRoomInfo]), networkError, decodeError, businessError(code: String, msg: String) }
    let kind: Kind
    func fetchList(...) async throws -> [PartyRoomInfo] {
        switch kind {
        case .success(let rooms): return rooms
        case .empty: return []
        case .delayThenSuccess(let rooms):
            try await Task.sleep(nanoseconds: 800_000_000)
            return rooms
        case .networkError: throw PartyAPIError.networkError(URLError(.notConnectedToInternet))
        case .decodeError: throw DecodingError.typeMismatch(...)
        case .businessError(let c, let m): throw PartyAPIError.business(code: c, message: m)
        }
    }
}
