## §0.1 契约层校验（H5 蓝本二次校验）

**蓝本文件**：`anchor-livechat-h5/src/views/liveSetting/components/liveRoom.vue:291-319` `sendMessage()`。

**通道**：云信 chatroom `.text` 消息（`chatManager.send` + `NIMSession(roomId, type: .chatroom)`）。**不是** custom / attachType 分支。

**payload**（严格对齐 H5 语义 + iOS SDK 类型）：
- `NIMMessage.text` = trim 后的文本
- `NIMMessage.remoteExt` = **`[String: Any]` NSDictionary**（`NIMMessage.h:174` `@property (copy) NSDictionary *remoteExt`），内容：`["userId": "<主播业务 userId>", "chatBubble": "<气泡 URL>"]`
  - H5 用 `JSON.stringify` 是因为 JS SDK 要求 String；iOS SDK 直接接受 NSDictionary，等价语义
  - iOS Party 参考实现 [`PartyRoomChatManager.swift:174-178`](../../Sources/Party/Chat/PartyRoomChatManager.swift#L174-L178) 也是直接给 dict
- 本轮 `chatBubble` 传空串（`""`）——主播端 iOS 目前无 mineInfo.chatBubble 数据源，v22 Phase 3 或 chatBubble 里程碑接入
- **不**附 fromNick / userLevel / isVip / isHost / fromIcon 字段（H5 蓝本也不带；观众端从自身 mineInfo/userStore 补齐）

**边界**：
- `text.trim()` 后空串静默 return（对齐 H5 `if (value)`）
- `hasJoined == false` 静默 return（未进房不允许发送）
- 长度上限 **200 字**（对齐 H5 `maxlength="200"`）：在 `sendText` 内 `String(trimmed.prefix(200))` 单点截断，UI 层不管
- catch 只 log，不弹 toast（对齐 H5 `catch (e) { console.warn(e) }`）

**明确不做（本轮排除，J/未来里程碑）**：
- `reportShuShuCustomEvent('h_hostmsg_send')` 数数埋点 → J
- `sendMessageToUser` @用户回复 → 待独立评估
- chatBubble 气泡真实值 → v22 Phase 3
- 失败重发 UI → 无（H5 也无）

## §1 数据模型

**PublicChatMessage 本地回显构造**（在 `NIMChatroomManager.sendText` 内组装）：

| 字段 | 值来源 | 备注 |
|---|---|---|
| `text` | trim + 200 字截断 | — |
| `isSystem` | `false` | — |
| `senderNickname` | `AnchorInfoStore.shared.displayName` 非空优先，fallback `SessionStore.shared.user?.nickname` | 主播自己昵称 |
| `senderAvatar` | `SessionStore.shared.user?.icon` | 主播自己头像 |
| `userLevel` | `AnchorInfoStore.shared.info?.level ?? .mine?.level` | 主播等级 |
| `isHost` | `true` | 硬编码——发送者是主播本人 |
| `isVip` | 硬编码 `false` | AnchorInfoStore/SessionStore 目前无 isVip 字段（grep 零命中）；观众端展示由观众端自身补齐 |
| `messageType` | `.regular` | — |
| `itemSmallImg` | `nil` | 座驾非本场景 |

**云信 remoteExt payload**（`[String: Any]` dict，直接赋值给 `NIMMessage.remoteExt`）：
```swift
msg.remoteExt = [
    "userId": anchorUserId,   // String
    "chatBubble": ""          // 本轮空串
]
```
**不**做 JSONSerialization → String 转换（iOS SDK 类型是 NSDictionary，转 String 会 SDK cast 失败静默丢 ext）。

## §3 验收标准

### F（Forward，正向必过）
- F1：主播在输入框输 "hello" → 回车 → 公屏立即出现一条 `.regular` 消息，`text="hello"`，头像/昵称/等级 = 主播自己
- F2：F1 后，输入框清空
- F3：主播点 Send 按钮（非回车）等同回车行为
- F4：主播发一条消息 → **另一台观众端**（H5 或 iOS）应在同房间收到 `.text` 消息，UI 展示为主播的文本
- F5：主播连续发 3 条 → 公屏依序出现 3 条
- F6：NIM log 观察 `NIMMessage.remoteExt` 为 dict 类型，含且仅含 `userId`（String）+ `chatBubble`（空串）两个 key

### R（Reverse，反向必挡，B 档 critical 3-5 条）
- R1：**空输入回车/点 Send → 静默 return**（无本地回显、无 NIM send、无 toast）
- R2：**全空白（空格/换行）回车 → 静默 return**
- R3：**未进房（hasJoined=false）状态下 sendText → 静默 return**（防 race）
- R4：**超长输入 250 字发送 → 本地回显 + NIM send 均为前 200 字**（对齐 H5 maxlength）
- R5：**IM 未登录 / NIM send throw → catch log；不清空 inputText（用户可重试）**

### 补充：视觉与操作
- V1：TextField 内输入时键盘 return 键显示 "Send"（`.submitLabel(.send)` 已在）
- V2：Send 按钮 icon 已存在（`liveRoomSendButton` asset），本轮不改

### F7 · 主播 echo 去重（P0 真机验证信号）
- **F7**：主播发一条 "hello" → 公屏**只显示 1 条**，不出现"本地回显 + NIM 回声 = 双显示"
- **依据不做过滤**：Party [`PartyRoomChatManager.sendText`](../../Sources/Party/Chat/PartyRoomChatManager.swift#L149-L186) 已生产验证 —— 本地 `push(local)` + `chatManager.send` 无 echo 过滤，用户零反馈双显示 → 说明 **NIM chatroom `.text` 消息 send 不回声给发送者**（iOS NIMSDK 10.10.0 行为）
- **实施阶段真机验证**：F7 是"不做 echo 过滤"这一决策的实测信号；若真机出现双条 → 立即在 `processIncoming` case `.text` 加 `guard m.from != NIMSDK.shared().loginManager.currentAccount()` 过滤（对齐 `im-payload-real-log-over-code-assumption` rule）

## §5 test 策略

**不抽独立 `LiveTextMessageBuilder`**（review 建议 #3 采纳）：

**验收路径**：全部真机验证 F1-F7 + R1-R5（见 §3），无独立单测。若真机 F/R 出现回归，再评估补测。

### 真机验证脚本（impl 后必跑）

1. 主播端登录 → 进直播 → 输入 "hello" 回车 → 公屏 1 条自己头像+昵称+等级（F1/F2/F7）
2. 主播端连续发 3 条 → 公屏 3 条依序（F5）
3. 观众端（另一台 iOS 或 H5）同房间进入 → 主播发送 → 观众收到（F4）
4. 输入 250 字发送 → 抓 NIM log 验证 `msg.text.length == 200`（R4）
5. 输入纯空白/空串回车 → 公屏无变化、无 NIM send log（R1/R2）
6. `AppLogger.im` filter：观察 remoteExt dataKeys 应为 `userId,chatBubble` 两项（对齐 §0.1）
